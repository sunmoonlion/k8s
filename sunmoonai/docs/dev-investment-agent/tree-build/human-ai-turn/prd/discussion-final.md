## 一、定下来的【定】

### 1.1 产品本质是「专家」

所有者原话：**"AI 如何一切都能做好，那还要我们这些产品干啥？"**产品存在的理由，就是在裸 AI 做不好的地方做好。
这个"做好"由三样东西支撑，缺一样就退化成一份能抄走的 prompt：

| 支撑 | 是什么 | 在哪 |
| --- | --- | --- |
| 专业知识 | 数据、口径、引用、领域工具 | 知识服务，经 MCP |
| 方法 | 拆步、给料、何时停下问人、验收、返工 | 后端编排（专家包） |
| 评测闭环 | 金标准、分段判定、每次改动回归、真实委托的返工与打回沉淀为样本 | 评测集，产品的地基 |

四家评审一致指出：方法文本本身抄得走，`methods.md` 早已承认；**可守的是三样捆在一起**。所有者的"方法是长期主体"在这个意义下成立：
方法要成为主体，前提是另外两样在。方法本身按易损件对待，模型每升一代重写一遍，重写有评测护栏。

对外定位可以用"给 AI 助手用的投研数据与口径，需要时提供可验收的研究流程"，所有者认为这不重要。
两层决策权分配是**内部设计语言**（Cursor、Qoder 的意见，所有者接受），不是宣传语。

### 1.2 两层，同一个 Codex 实例是必须的

| | 第一层 | 第二层 |
| --- | --- | --- |
| 谁驾驶 | 用户 | 顾问（supervisor + 专家包） |
| AI 在哪 | 用户电脑、用户 key、**同一个 Codex 实例** | 同 |
| 云端建单 | 不建 | 交出驾驶权时建 |
| 触发 | 默认 | 用户求助，或本机质量信号提示后用户求助（见 3.2） |

**同一实例是必须的**，所有者裁定，不再讨论。理由采 Qoder 的：目标用户是非开发者、Windows、没有现成 agent，我们的壳就是他们的第一个 agent，
不存在"换工具"的成本。Claude 原来的担心校准在了错误的用户上（见 2.5）。

Luna 提醒"同一"要拆清楚，写定稿时按这四层写明要求哪几层：**同一运行时 thread**（顾问接手时看得到用户已做的）、**同一工作区**（资料在原处）、
**同一模型账户**（用户的 key）；进程是否同一是实现细节。引擎中立的显式交接包作为保底路径保留（Kimi、Cursor），与同一实例共用一个交接包格式，
**不是前提，是保险**。

### 1.3 执行链：重构，不囿于现有

所有者裁定：**不要囿于现有的执行链，按新架构重构**。起点是 investment-app 现有的状态机、事件表、Outbox/Inbox（源码已接线，不重造），
按能力收窄：

| 首版 | 说明 |
| --- | --- |
| **只读** | 顾问驾驶的 Attempt 不写用户工作区之外、不做对外副作用；副作用账只需覆盖只读动作的上报 |
| **单委托** | 同一时刻一个设备、一个 Task、一个活跃 Attempt |
| **无并行** | 不开多方竞争、不开冗余 Attempt；`0008-competition` 对象模型留着、机制不建 |

现有 Pilot 链（云端调 LLM 出草稿）与新架构冲突（后端不调模型），**退役**；它的状态机、事件、检查点概念沉淀给 supervisor（Qoder 的意见）。
Luna 的边界同样成立：一旦自动驱动用户机器，**安全性质不能靠"首版"省掉**——拒绝过期指令、幂等、取消、预算硬停，首版就要有；
实现可以简化，性质不能缺。租约与 fencing 解决的是多写入者并发，单委托首版不需要它们的全部机制，但"拒绝过期指令"这一条要留。

### 1.4 B 类专家：现在就是简单流程

所有者裁定：B 类（云端专家 agent）**目前只是简单流程的体现**，即用问数五阶段做展示。不做独立的云端聊天专家（垫 token、上传资料、往咨询漂）。
Kimi、Cursor 指出 supervisor 的"下一步出什么"迟早由模型做，那就是 B 的正确位置——路线图上留位，不进第一期。

### 1.5 其余已定、本轮不变

- 问数（第 23 到 25 课）是一次性的最小编排实例：一份 Task Profile、五步 `step_contract`、二十题评测；跑通即可换掉，不是卖点。
- 客户三层（数据 / 专家包 / 合规模式），第一期只做第一层。
- 三个仓、九站、八块、规则、不变量 `I1` 至 `I20`、`F-POS-*` 不变。
- 真人专家只做"写包的人"，**永远不出现"真人在线答这一问"**（Cursor 建议立为硬规则，采纳）。

## 二、评审后改判的【改】

按改判三要素写：触发、原判断错在哪、新判断。

### 2.1 上传默认级

- 触发：四家全反对"默认第二级（问题 + 本机摘要）"。
- 错在哪：摘要是资料的派生物，默认上传等于默认打破 `I20`；它是朝省事方向的默认值，按 `P3` 必须人确认，却被写成默认。
- 新判断：**默认只有问题文本 + 结构化元数据**（用过哪些工具名、失败码、步数、耗时）；"试过什么"是步骤与工具清单，不是资料摘要；
  资料派生的任何内容只走**逐文件显式勾选**，发出前本机预览即将离机的完整内容；每次求助单独授权、按次过期。

### 2.2 预算进第一期

- 触发：Kimi、Luna、Cursor 都反对"预算可以晚"。
- 错在哪：与我自己的第三条担心（token 激励错位）矛盾——预算硬停是那个错位**唯一可执行的约束**，`RunBudget` 又已有雏形。
- 新判断：预算首版接线；每个委托设总预算，覆盖执行、验收、返工、工具费；超限进 `WAITING(RESOURCE)`（不新增状态词），交回用户；
  预算追加须用户明确批准。专家包发布时冻结 token 包络（按评测集跑出的分位数），超包络视为包失败，进质量门（Cursor）。

### 2.3 人肉实验：三臂加基线

- 触发：四家都指出两臂分不出赢的是数据还是方法。
- 新判断：三臂——裸 Codex / Codex + MCP 数据 / Codex + 数据 + 顾问方法；再加一条"分析师现状"基线（Luna、Qoder）。
  方法先写成文档，由**非作者**照文档驾驶（Cursor、Kimi、Qoder）；产出匿名盲评；付费意愿用真金测（预付、按价买这份）而不是口头问；
  顾问只能接触未来云端允许看到的输入，做不到就标为"人工服务上限实验"（Luna）；目标是**存在性证明**（存在一类任务差距大到有人付钱），不是平均效应；
  5 到 10 题只够证伪，2 周偏紧、3 到 4 周更实际。**成功标准：第三臂在费用可接受的前提下稳定优于第二臂，才进入第二层控制面的最小实现。**

### 2.4 "人肉不赢，自动化也不赢"

- 触发：Luna。
- 错在哪：自动化可能降低等待、人工成本和执行波动；反过来人肉赢也不证明可自动化。
- 新判断：实验分开识别"专业判断的贡献"与"可复制流程的贡献"；记录顾问怎么干活、每步耗时——**这是实验最重要的产出**（Qoder）。

### 2.5 用户画像与"同一实例"的理由

- 触发：Qoder 指出我的担心二校准在错误的用户上。
- 错在哪：拿"已经在用 CLI agent 的开发者不会换壳"质疑同一实例，但 PRD 的目标用户不是他们。
- 新判断：同一实例按 1.2 定。但 Cursor 与 Qoder 从相反方向撞到同一件事，进未决：**设计对象（非开发者投资经理）与第一层付钱对象（会配 key、会用 agent 的人）可能不是同一群人**，见 4.1。

### 2.6 两句说松了的话

- "内容寻址即幂等"：不成立。同一提交可被触发执行两次，外部写入仍要幂等键（Cursor）。
- "未提交 = 待审、已提交 = 定稿"：git 记版本不记批准，人没改也需要能表示"已审并接受"（Luna）。

## 三、吸收的共识【收】

### 3.1 评测集是一等公民

从验收矩阵的一条（`AT-36`）提升到 PRD 第一节。要有**负责人、预算行、时间表**（Qoder：没有这三样的东西不会自己长出来）。
真值定在查询层（第 24 课格式）；金标准来自公开现成的监管材料——问询函、更正公告、立案调查（Qoder）；
初始集是种子，真实委托的返工、终审改动、验收打回持续沉淀为样本；同时另留未见过的评测任务防止只优化题库（Luna）。
三道门分开：数据质量评测、方法包发布评测、单次结果验收（Luna）。

### 3.2 本机确定性质量信号替代领域识别

"不满意才求助"不够：投研最危险的是用户对错误答案满意（Cursor、Qoder、Kimi）。退役的领域识别由**本机确定性质量信号**接任：
引用数为零、与本地知识库矛盾、数据时点过期、勾稽不平、结论在我们数据里没有对应查询。不调云端、不调模型；
既在第一层制造"不满意"，又是第二层验收规则的雏形。这不是旧的通用/专业分类器，是证据网。

### 3.3 切口：勾稽异常筛查

三家收敛到检测型任务。第一包定为 **A 股非金融、年报与半年报：附注关键表提取，与已入库三大表勾稽，输出差异清单加原文引用，结论栏留空**（Cursor 的收窄）。
理由：产出是带证据的差异清单，`F-POS` 天然不触发；金标准公开现成；全年有量；正是单发提示最弱、编排最强的地方。
财报季覆盖放到后面当营销楔子（Kimi 的候选）；单公司深筛对应第二层按次求助，全市场监控是第一层数据产品。
初期异常只呈现为"待核实的差异"，不写成问题结论（Luna）。

### 3.4 token 激励

除 2.2 的预算外：评测加"费用"一列，更贵但只好一点点的方法判负，作为**发布门**不是仪表盘；第一期**禁止并行 Attempt 与竞争择优**；
步骤级超限交回用户，顾问不得自行加步；好方法应该省 token——口径计算放进 MCP，让模型少推一遍（Cursor）；
求助前显示顾问费、预计模型费及不确定范围、已用额度（Luna）。

### 3.5 交接面与交回物契约

- 交接（第一层到第二层）：问题、步骤与工具清单（非资料摘要）、授权范围（工作区、能力、预算、什么可以离机）。
- **交回物契约**（第二层结束或失败时，Cursor）：做了什么、什么已核实、什么仍未知、工作区如何恢复。顾问烧了 token 交回半成品，用户不能比求助前更糟。
- 交接后旧指令、在途工具调用、旧授权不得继续生效；用户与顾问不能同时改同一份产物；取消后迟到回包不能重新推进（Luna）。
- 授权粒度（原 U1）：按次授予一个有边界的服务契约，范围内只读步骤自动执行；扩大外发范围、增加预算、产生外部副作用、改变目标时再次授权（Luna、Cursor）。工具级审批永远在本机、永远是用户。

### 3.6 云端顾问不看正文，验收能判什么

Luna 第十二条，讨论稿的最大盲区。定稿里要把验收拆成四栏：

| 栏 | 内容 |
| --- | --- |
| 确定性检查 | 期间、单位、计算、来源定位、字段完整性；在哪跑 |
| 语义检查 | 论证是否充分、口径是否可比；由受限的本地检查步骤做，费用进预算 |
| 云端回执 | 能收到什么，怎样绑定任务、产物、验收规则版本，证明到什么程度 |
| 只能标注的 | "形式检查通过"、"仍需人工核实"；不得对用户宣称研究已正确 |

签名和哈希证明来源与版本，不证明分析正确。

### 3.7 两个生死项提前

Qoder：国产模型经 Codex（Kimi 直连为首个样本）跑不通，目标用户集体跑不起来；Windows 锁定办公机装不上 Electron。
从 `decisions.md` 的 ⚠ 清单拎出来，各做两天 spike，**先于任何桌面代码**。

### 3.8 D11、D12 不整项消失

旧的类别判定退出，但委托请求的受理、输入充分性、能力匹配仍在；通用/专业分类退出，但 workflow 清单与专家能力边界仍要定义（Luna）。

### 3.9 定位与数据的法务范围

D17 扩到**数据再分发**：info-app 采集经 MCP 卖出可能先撞数据许可（Cursor）；以及"底稿里已算 DCF、结论栏空着"算不算咨询。
数据盘点（原 U6）与 D17 绑在一起做。

### 3.10 市场面

Kimi：竞争面完全缺席——Hebbia、Rogo、AlphaSense 走的是相反路线（云端 agent + 云端数据 + 订阅），模型厂商每次升级都在内置拆步与验收。
"资料不出本机但你付 token"这个承重假设没有任何访谈证据：**U0，找 5 个目标用户把两个选项放他们面前听反应**，半天成本，先于代码。
第一层不按收入支柱规划（Qoder、Kimi）：它是漏斗顶、数据资产建设者、评测样本来源。

### 3.11 供给端与时效

写包的人从哪来、怎么分钱（Kimi）；包要简单到非工程师分析师能写；第二层的服务水平（多久交回）要定义，
`task-contract` 的 `requested_deadline` 按此设计。

### 3.12 开发流程（turn 机制）的补强

四家都指出四条补充规则只是纪律。要落的：改定稿 `PRD/`、`SDD/` 的提交说明模板检查；`ai:`/`review:` 提交前缀；
`user-message.md` 文首固定"当前请求"段，追加历史在下；删目录前留一行索引（日期、问题、结局），"做过选择的 turn 必须留"；
多方评审的去处约定为 `human-ai-turn/prd/reviews/`，文件名含工位名，由人择一写进定稿并在提交说明引用。这一次评审就是这样收的。
