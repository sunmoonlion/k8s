# turn 0001：编排要满足什么

上一层的设计把后端切成七块，分给这一块的是**编排**：workflow 游标、按步拆与派发、步骤契约、`escalate` 裁决、方法库与按步工具面。
边界（承担什么、不承担什么、为什么这么切）见 [`SDD/modules/0003-orchestrator.md`](../../../../../modules/0003-orchestrator.md)，
七块之间的关系见 [`SDD/architecture/blocks.md`](../../../../../architecture/blocks.md)。

这一问要的是：**这一块具体要满足什么、什么算满足**。

- 合同里归这一块的功能义务（`F-*`）与不变量（`I*`）分别是哪些，逐条列出；
- 输入与输出：从谁拿什么、给谁什么；
- 正向场景与反向场景：做对了是什么样，输入不对、依赖不可用、中途中断时该是什么样；
- 非目标：这一轮明确不做什么；
- 约束：上一层已经定死的（它决定「下一步是什么」，不负责送出去；方法工具经 runtime 代理回来时由它二次校验），以及只对这一块成立的；
- 允许的不确定性：哪些可以先不定，不定会影响什么。

**不要写怎么实现**——那是下一问（SDD）。上一层已经定的边界不要推翻；
认为边界划错了，停下来说，不要在答里自行改。
