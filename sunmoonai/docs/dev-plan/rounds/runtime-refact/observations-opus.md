**处置意向（③ 裁决时定）**：漏声明是**交付缺项**，不是违规——
F2 判的是「读了却不声明」。评审已提交，按协议「提交后不得再改」，不退回补写；
在处置记录里逐家登记，并作为下一轮通知的改进项：
**要求项若必须出现在产物里，应写进机械条（M 类）由脚本判，而不是只写在通知正文里靠人自觉。**
本轮 §8.1 的 M 类里**没有一条检查 `R2` 声明**——这是发起方的缺口，不是候选的。

### ⚠ 这份证据的等级，必须如实标注

上表「机器证据」一列是**组织者抓取的 stdout**，等级为 `reported`，**不是 `attested`**：

> 它显示的是**执行者打印了什么**，不是**执行者做了什么**。
> 内部的文件读取完全可以不出现在 stdout 里。
> **「日志里没有看到读取动作」≠「确认未读」**——后者是把「没查到」写成「没有」。

根因是投喂模式的可观测天花板就是 `process`（`agent-dev-refact.md` §2.4）：
看得见进程与产物，看不见工具调用，因而**既不能看也不能拦**。
走 SDK / 协议接入后，每次文件读取都是一个可见且可拦的工具调用，
这类检查不必靠事后 grep 日志。已立工作单元 `rounds/executor-adapter/`。

## O-2 ｜ 代提交的分布，影响 ③ 的可追溯性折算

| 家 | 产物 | 提交 | 可追溯性 |
| --- | --- | --- | --- |
| `cursor` | 自己写 | **自己提交**（所有者交互式跑） | 作者归属可从提交推出 |
| `luna` | 自己写 | 组织者代提交（`R7`；⚠ 首次代提交未用 `--author`，两字段同身份） | 归属只能靠 commit message 的文字 |
| `qwen` | 自己写 | 组织者代提交，已用 `--author=qwen (qoder)` | 归属可读 |

⚠ **`author` 字段在本机不构成证据**：无签名、各身份共用同一 git 身份，可随意填。
它只让归属**可读**，不让归属**可信**（`agent-dev-refact.md` §2.6）。
③ 处置记录须写明这一差异，**但不得据此调整评分**——
可追溯性弱是**组织者的执行条件**造成的，不是候选的质量问题。
