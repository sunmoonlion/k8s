# 现在做什么

> **这份是常驻入口，权威副本只有一份：`~/master/k8s/sunmoonai/docs/dev-plan/GO.md`。**
> 所有者在你的窗口里说「看一下 `~/master/k8s/sunmoonai/docs/dev-plan/GO.md`，照做」，
> 你就从这里开始。**每个环节都读主线那一份**，它会把你送到当前该做的那一步。
>
> ⚠ **你的 worktree 里也有一份同名文件，它是投影，且几乎一定是旧的。**
> 你的分支从 ① 起就不再跟进主线，所以那份停在你开工那一刻。
> **先自检再照做**：
>
> ```bash
> diff <(git -C ~/master/k8s show master:sunmoonai/docs/dev-plan/GO.md) \
>      sunmoonai/docs/dev-plan/GO.md >/dev/null \
>   && echo "本地 GO.md 与主线一致" || echo "⚠ 本地 GO.md 已过期——只认主线那份"
> ```
>
> 不一致**不要合并主线**（见第三节），改去读主线那份就行。
>
> ⚠ **所有者视角**：派发那句话不要手打，从模板取——
> `protocol/paste/`（模板，可手填）／`round-dispatch.py --paste [家名] [--stale]`（自动填）。
> 理由见 `rounds/dev-plan-refact/findings.md` **F-17**：靠人记得写对绝对路径，正是那次停摆的根因。
>
> ⚠ **2026-09-08，② 进行中改过一次**：第二节的判定命令由「绝对路径」改为「子壳 `( cd … && … )`」。
> 原写法在 cwd 不在任何 worktree 内时会 traceback（`round-status.py` 用 cwd 求仓根）。
> **这是修命令，不是改题目**——本环节要交什么、判据是什么，一个字没动。

## 一、你是谁

看你的工作目录：`~/worktrees/<名>/k8s` —— **那个 `<名>` 就是你**。

```bash
pwd && git rev-parse --abbrev-ref HEAD
```

⚠ **目录名是本地归属线索，不是经鉴别的 principal 身份**——但在本轮它是唯一可用的判别依据。
产品名、模型名、界面上写的是什么，**一律不是证据**。
分支应当是 `<轮次>/<你的名>`——**轮次名不在本文里，在第二节那条命令的输出里**。
不是的话**先停下来问**，不要自己切。

⚠ 本文**不写死任何轮次名**：写死了，下一轮开张时它会静默指错，
而「指错」的样子和「你切错分支了」一模一样。

**基线怎么确认：**

```bash
git rev-parse HEAD                 # 这就是基线
git log -1 --format=%h HEAD        # 短哈希
```

⚠ **`round.md` 的 `baseline` 字段记的是它的父提交**——一份文件不能包含自己的哈希，
所以记录性提交必然晚它一拍。**两者指向同一份输入，不是不一致。**
⚠ **通知与任务书里不再硬写哈希**（2026-09-08 起）：硬写的会随重定基线过期，
而**过期了不会有人发现**——本轮已经发生过一次，是 `luna` 按本文第五节报出来的。

⚠ **① 之后「基线」换了对象。**① 时你的 `HEAD` 就是基线；
从 ② 起你的 `HEAD` 是**你自己的产物**，而本环节要处理的对象由通知里的
**冻结表**指定（各家 commit + 行数 + sha256）。**以那张表为准，不以你的 `HEAD` 为准。**

## 二、现在是哪一轮、哪个环节

⚠ **在主线跑，不在你自己的工作区跑。用子壳 `( … )` 包起来。**

```bash
( cd ~/master/k8s && python3 sunmoonai/docs/dev-plan/protocol/round-status.py )
```

⚠ **两个括号不能省**，它们同时解决两件事：

| 不加括号会怎样 | |
| --- | --- |
| 直接 `cd ~/master/k8s` | **cd 过去容易忘了回来**，然后在主线里 `git add` —— 那就是写主线（第四节第 1 条） |
| 只写绝对路径、不 cd | **脚本会崩**。它用**当前目录**求仓根（`git rev-parse --show-toplevel`），你的 cwd 若不在任何 worktree 内（比如停在 `~/worktrees/<名>` 而不是 `~/worktrees/<名>/k8s`），直接 traceback |

子壳里的 `cd` 只在括号内生效，出了括号你还在原地。**且它读的是主线的 `round.md`**——
你工作区那份从 ① 起就不再跟进主线，可能已经过期。

它按**产物**推导，不看声明。输出里「当前环节：X」那一行就是答案，
「缺：……」列出还没交的家——**如果里面有你，这一步就是你的**。

⚠ **判据是产物出现，不是谁说了什么。**你自己那格是 ⬜ 就还没交，✅ 才算交了。

⚠ **为什么必须在主线跑**（2026-09-08 实测，`findings.md` F-13）：
一个仓的多个 worktree **各有一份脚本副本**，你那份可能是旧的。
而且这个脚本本身出过一次问题——它的 ref 列表里含 `HEAD`，
在参赛方自己的工作区里 `HEAD` 就是该家的分支，于是**只要一家交了，五家全绿**：

```text
同一个 commit、同一条命令
  在 ~/master/k8s          ① 提案  进行中  opus✅ luna⬜ kimi⬜ cursor⬜ qwen⬜   （对）
  在 ~/worktrees/opus/k8s  ① 提案  完成    opus✅ luna✅ kimi✅ cursor✅ qwen✅   （错）
```

主线那份已修。**在别处跑出的判定不作数。**

## 三、去读该环节的通知，照它做

⚠ **在主线 `~/master/k8s` 读，不在你自己的工作区读。用绝对路径，不要 `cd`。**

⚠ **不要自己拼路径。**第二节那条命令**已经把通知路径打出来了**——

```text
本环节通知：sunmoonai/docs/dev-plan/rounds/<轮次>/call-<环节>.md
  读它：cat ~/master/k8s/sunmoonai/docs/dev-plan/rounds/<轮次>/call-<环节>.md
```

**照抄那一行的命令**。它认两种命名（`call-③.md` 与 `<轮次>-call-③.md`），
轮次名也是算出来的——**本文不写死任何轮次名**，写死就会在下一轮静默指错目录。

打出「本环节通知：无」时，那**不等于**「不用读通知」，它会给你一条 `ls` 让你当场确认。

题目与工单同在那个目录下：

```bash
R=~/master/k8s/$(dirname <上面那行给的通知路径>)   # 或直接从通知路径里截
cat $R/round.md             # 工单
ls  $R/*.md                 # 题目、裁定、发现都在这儿
```

环节号就是上一步查出来的。**通知里写了交什么、交到哪、判据是什么。**

⚠ **不要凭「哪些环节历史上有通知」来推断本环节有没有通知。**
`runtime`、`runtime-refact` 两轮只有 `① ② ④ ⑤`，是因为那两轮的 ③ 由所有者亲自裁决、不派给 agent；
**这一条是那两轮的事实，不是规则**。`dev-plan-refact` 轮的 ③ 已全权委托给整合方，
所以那一轮有 `call-③.md`。

**判据是第二节那条命令的输出，不是记忆，也不是历史。**
2026-09-08 F-17 就是这么栽的：整合方凭「前两轮 ③ 没有通知」推理出本轮也没有，
停在原地——**推理没错，前提是旧的**。

**为什么在主线读**：通知是组织者的产物，写在主线上。你的分支从 ① 起就带着自己的产物、
不再跟进主线，所以**你的工作区里不会有当前环节的通知**——① 是唯一的例外（开工前刚被
供给到主线那一点）。

⚠ **不要把主线合并进你的分支**来「拿到通知」。你不需要它在你的分支上，
而合并会引入真实冲突：2026-09-08 实测，两家在 ① 期间按 `B3` 往 `findings.md` 追加过
发现，与主线同一份文件上的新增条目直接冲突。

`~/master/k8s` **可读不可写**：读通知、读任务书、跑判定命令都在那里；
**产物一律写回你自己的工作区**（见下第四节第 1 条）。

## 四、四条不能违反的

> ⚠ **本节不是规则的真源。**规则在 `protocol/round-protocol.md`，本节只是把
> 与本环节最相关的四条摘到手边。**两边冲突时以协议为准。**
> 每条都注明了出处 §，`doc-gate` 会核对那个 § 真的存在——
> 协议重编号而本节没跟上，门会报出来，不会静默漂移（`GO.md` 已进 `SELF_CONTAINED`）。


1. ⚠ **只写你自己的工作区。**不写主线、不写别人的 worktree、不写 `~/master/`。
   （出处：`protocol/round-protocol.md` §17）

   ⚠⚠ **本文让你读主线、在主线跑判定。读用绝对路径；跑判定用子壳 `( cd … && … )`。**
   裸 `cd ~/master/k8s` 容易忘了回来，然后在主线里 `git add` —— 那就是写主线。
   提交也写全路径，不靠当前目录：

   ```bash
   git -C ~/worktrees/<你的名>/k8s add <产物路径>
   git -C ~/worktrees/<你的名>/k8s commit -m "..."
   git -C ~/master/k8s status --porcelain      # 自证没写错地方：应为空
   ```

2. ⚠ **提案冻结前不得读其他候选**，也不得读发起方倾向。
   （出处：`protocol/round-protocol.md` §9）
   看到别人的答案之后产出的东西属于评审或改进，**不再是独立候选**。
3. ⚠ **交卷 = 你自己分支上的可达 commit。**未提交的工作区文件**不算交卷**——
   （出处：`protocol/round-protocol.md` §8「命令即判据」）
   它没有 commit、没有 digest、没有作者归属。
4. ⚠ **凡本轮只读输入之外的断言，附可复跑证据或标 ⚠。**
   （出处：`protocol/round-protocol.md` §12）
   不得写「我之前查过」——裁决方没有你的上下文，复核不了就等于没有。

## 五、卡住了就停下来说

> ⚠ **本文只服务交互通道**（人开着窗口）。本节这条指令在一次性命令行
> （`codex exec` / `agent -p` / `qoder -p`）上**必然失效**——那条路没有回话通道，
> 「说出来」只会说给没有人在听的 stdout，然后进程退出。
> 所以一次性命令行那条路的入口是 `protocol/round-protocol.md`，**它不指向本文，这是有意的**。
> 两条通道的能力差异有实测：`rounds/executor-adapter/task.md` §1.0。
> **不要为了「统一入口」把两份并掉。**

⚠ **所有者正开着这个窗口。**你遇到下面任何一种情况，**停下来把话说清楚，不要自己猜着往下走**：

- 判据看不懂、或两条判据互相矛盾；
- 需要的输入不存在、或与通知里写的不一致；
- 要动的东西超出「只写自己工作区」的范围；
- 命令失败了而你不确定为什么。

**这是交互会话，不是无人值守的批处理。**说出来当场就能解决，硬猜下去的代价大得多——
本仓已经为「凭印象继续」付过好几次账，逐条记在 `agent-dev-guide.md` §12。

## 六、交卷之后

```bash
# 提交：写全路径，不靠当前目录 —— 你可能还停在主线（第四节第 1 条）
W=~/worktrees/<你的名>/k8s
git -C $W add <你的产物路径>
git -C $W commit -m "<环节> <轮次> <产物名>（<你的名>）"   # 轮次名照抄第二节的输出

# 核验：在主线跑，子壳包起来（理由见第二节）
( cd ~/master/k8s && python3 sunmoonai/docs/dev-plan/protocol/round-status.py )

# 自证没写错地方：主线必须是干净的
git -C ~/master/k8s status --porcelain    # 应为空
```

⚠ **提交后再跑一次状态脚本。**它认不出你的产物（路径不对、分支不对）时，
你以为交了、其实没交——这种失败**不会有任何报错**。
