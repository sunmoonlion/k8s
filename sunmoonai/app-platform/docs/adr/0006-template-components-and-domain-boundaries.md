# ADR-0006：模板组件不定义领域边界

- 状态：已接受
- 日期：2026-06-11

## 背景

`tpl-app` 提供 Python/FastAPI、JavaScript/TypeScript/NestJS、Vue 和 Next.js 四种样板组件。组件目录使用 `admin` 和 `web` 命名，但不同领域 App 对语言、前端形态和运行方式的需求并不相同。

如果把模板名称直接解释为固定业务职责，就会迫使所有 App 使用同一种分层，并可能重复实现领域逻辑。

## 决策

- 领域 App 表达长期业务边界。
- `tpl-app` 组件表达可选技术栈和统一工程样板。
- API、Worker、Scheduler 和 Migration Job 表达运行角色。
- 每个 App 完整保留四个模板组件及其平台接入能力。
- 每个 App 根据功能选择当前需要实现业务代码的组件。
- 各组件的具体业务能力由其 `app` 目录代码决定。
- 组件是否运行只在 Kubernetes 部署阶段按集群控制。
- 具体业务数据归属在实现功能时确定，并遵守唯一权威写入原则。
- 模板组件名称、语言和 Deployment 数量不决定数据所有权。

## 结果

- 新 App 原则上继续从统一 `tpl-app` 实例化。
- 四个样板目录及平台接入配置完整保留，但不要求同时承载业务或在每个集群运行。
- 同一 Backend 源码可以按不同命令运行 API、Worker、Scheduler 或 Migration Job。
- 领域逻辑只能有一个明确所有者，不能因启用另一技术组件而复制一套主档和规则。
