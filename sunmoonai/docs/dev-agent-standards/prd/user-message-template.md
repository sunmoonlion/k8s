# PRD 用户消息模板

复制成 turn 里的 `user-message.md`。

这一段要产出什么、答要写成什么样，都在 [PRD 规则](prd-rules.md) 里，**用户消息只指过去，不复述**。
写多严见 [任务的生命周期](../lifecycle.md)「用户消息写多严」，字段的含义见同一份的「turn 的固定字段」。

```markdown
---
executor: <派给谁；还没派出去写 unassigned>
verifies: 无
---
# turn <四位号>：<短名>

## 依据
<以哪一份 `PRD/` 定稿、或哪一段 BRD 讨论为底；给出链接与提交>

## 要满足什么
<这一问要产出的需求：谁用、在什么场景下、要达到什么结果>

## 要不要拆模块
<这一问是只定需求，还是同时给出模块划分。要拆的话写清已知的边界或期望的粒度；
 每个模块要写什么、号与短名怎么排，见 PRD 规则，不在这里复述>

## 范围
- 包含：
- 不包含：
- 不包含的归谁：

## 约束
<必须遵守的规则、不能动的东西、外部限制>

## 怎么答
按 `sunmoonai/docs/dev-agent-standards/prd/prd-rules.md`「`architecture/` 写什么」「`modules/<模块>/` 写什么」与「纪律」。

**交回：写成这个 turn 的 `response.md`，由 discussion agent 交，不改代码。人读完定稿成 `SDD/`。**
```

这一段不写验收标准：答得合不合格看它能不能定稿成 `PRD/`——判据是 [PRD 规则](prd-rules.md)，不是这一问里临时立的条目。

不适用的栏写「不适用」及理由——空着与「忘了」无法区分。命中 T2 判据的任务每一栏都要填。
