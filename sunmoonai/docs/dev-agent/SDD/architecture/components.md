# 系统由哪几部分组成

**本轮要建的三块、各自跑在哪、以及不在本轮范围内的那几部分。**
一条请求怎么走完这九站见 [九站](../../../pipeline.md)；
模块之间的接口与约束见同目录的 [通道](channels.md)、[信任边界](trust.md)、[共同约束](engineering.md)；
各模块**自己是什么**见 [`../modules/`](../modules/)。

```text
用户电脑
┌──────────────────────────────────────────────────────────────────┐
│ 桌面应用（Electron）　三扇独立窗口，能力按窗口授予               │

│   审查窗口：Task 级审查（不挂本机能力）                          │

       ▼                   ▼                  ▼                   ▼
  ┌──────────── 后端（supervisor）────────────────┐   知识服务        模型厂商
```

各部件承担什么、不承担什么：本轮建的三块见 [`../modules/`](../modules/) 下各自那一份，
其余见下面「本轮范围外」。**Codex 不单列**——它随应用打包、由 runtime 驱动，归 `0003-runtime`。

## 本轮建哪几块

按**运行位置、信任域、发布方式**切——三者都不同就单列：

| 模块 | 是上图的哪一部分 | 跑在哪 | 各自是什么 | 子任务 |
| --- | --- | --- | --- | --- |
| `0001-backend` | 后端（supervisor） | 服务器 | [说明](../modules/0001-backend.md) | [子任务](../submodules/0001-backend/PRD/requirement.md) |
| `0002-desktop` | 桌面应用 | 用户电脑 | [说明](../modules/0002-desktop.md) | [子任务](../submodules/0002-desktop/PRD/requirement.md) |
| `0003-runtime` | 本地 runtime 与 Codex | 用户电脑 | [说明](../modules/0003-runtime.md) | [子任务](../submodules/0003-runtime/PRD/requirement.md) |

`0002` 与 `0003` 都在用户电脑上，**信任域不同**：runtime 碰得到 key 与结果正文，桌面应用碰不到。
这是它们分开的唯一理由，也是不能合并的理由。

## 本轮范围外

上图其余部分**沿用现状、本轮不开发**，所以不占模块：

| 范围外 | 承担什么 | 现在在哪 |
| --- | --- | --- |
| 八个既有 Next.js 前端 | 见下两行 | 四个 app 仓各一对：`tpl-`、`info-`、`knowledge-`、`investment-` 的 `*-web-frontend/` 与 `*-admin-frontend/` |
| 官网与下载页 | 产品介绍与下载；注册登录经认证服务的页面，支付经支付渠道的页面；**必须写明「key 只在桌面应用里输入」** | 上述 `*-web-frontend/` |
| 内部管理后台 | 内部人员的运营、客服、审计查询；**只见元数据，不见研究结果正文** | 上述 `*-admin-frontend/`，沿用平台模板 |
| 知识服务 | info-app 从合法来源采集；knowledge-app 建库、检索、领域工具，经 MCP 按查询下发；embedding 与 rerank 用自有模型。**不接触用户 key、不装观点类内容、不整批下发** | `info-app`、`knowledge-app`；Codex 经通道 ⑤ 直接调它 |
| 模型厂商 | 推理，由用户选择并付费 | 用户自选、自付；Codex 经通道 ⑥ 调 |


## 未决

判断要不要单列模块。
