# investment：聊天、工作、专家

> 属于 [三个应用的全局设计](README.md)。2026-09-29 所有者口述，远程整理。
> 所有者的话：「我要求 investment 有三个功能：前两个就像现在大部分 app 那样……分为：聊天和工作。周边是项目等等。但是，我们多了一个专家」；「大的方向肯定就是上面说的，至于细节再待定」。
> 凡是标「所有者定」的是大方向；标「远程的建议」的是细节，可以改。
> 它替换 [网页设计初稿](../../SDD/modules/0002-web-design.md) 的第二、三节和 4.1 至 4.3；初稿其余部分仍然有效，文中指过去。

## 一、三个功能

| | 聊天 | 工作 | 专家 |
| --- | --- | --- | --- |
| 是什么 | 和模型一问一答 | 交代一件事，代理在项目里动手做 | 把一件事整个交出去，专家按方法做完交回 |
| 谁拿主意 | 用户 | 用户 | 专家。结论永远是用户的 |
| 读项目里的文件 | 在项目里时能 | 能 | 能 |
| 改文件、跑命令 | **不能** | 能。要紧的先问用户 | 能。按专家包的规矩；越界的问用户 |
| 查我们的数据 | 能 | 能 | 能 |
| 要不要选项目 | 不必 | 要 | 要 |
| 要不要用户的机器在线 | 不选项目时不要 | 要 | 要 |
| 要不要沙箱和模型 key | 要 | 要 | 要 |
| 花费 | 实时显示，随时能停 | 实时显示，随时能停 | 实时显示，随时能停（不设预算上限，见 5.12） |
| 交回什么 | 回答 | 项目里的文件 | 底稿：结果、证据、局限、交回物 |
| 页面的样子 | 气泡对话 | 过程时间线 | 步骤进度，终点是底稿页 |
| 别的产品有没有 | 有 | 有 | 没有，这是我们的 |

状态：第一、二、三行是所有者定的。「聊天不能改文件、跑命令」是所有者定的（「只是不动手」）。「聊天在项目里能读文件」是远程的建议。

### 前两个和第三个的关系

| 规则 | 状态 |
| --- | --- |
| 专家有自己的入口 | 所有者定 |
| 聊天、工作里可以中途转给专家 | 所有者定 |
| 转过去的是整个项目：专家接着用户那条线做，项目里别的对话、别的文件都能读，用到才读 | 所有者定（丙） |
| 没选项目的聊天要转给专家：先让用户选一个项目或新建一个，这段聊天随之归入该项目 | 所有者定 |
| 专家做完，方向盘回到用户手里，用户在原来那段对话里接着说 | 已有（[方向盘](../../SDD/architecture/wheel.md)） |
| 聊天可以转成工作（要先有项目）；工作不转回聊天 | 远程的建议 |

## 二、层次

```text
用户
 ├─ 聊天（不属于任何项目）
 └─ 工作区（用户机器上的一个根目录）
     └─ 项目（工作区下的一个子目录）
         ├─ 对话：聊天
         ├─ 对话：工作
         ├─ 委托：专家在某段对话的线上做的一件事
         ├─ 底稿：专家交回的结果
         └─ 文件：在用户的机器上
```

| 词 | 是什么 | 后端里叫什么 | 状态 |
| --- | --- | --- | --- |
| 工作区 | 用户机器上的一个根目录，用户在本地代理里加进白名单 | 环境的 `roots` 里的一项 | 已有 |
| 项目 | 工作区下的一个子目录，加一个名字 | **新增** `workbench_projects` | 所有者定要有；表是远程的设计 |
| 对话 | 一段连续的聊天或工作，对应 Codex 的一条线 | `workbench_sessions`，加 `kind`、`project_id` | 已有，要加列 |
| 委托 | 专家受托做的一件事 | `Task` | 已有 |
| 底稿 | 专家交回的结果 | `Artifact` | 已有 |

给用户看的字眼：聊天、工作、专家、项目、工作区、对话、委托、底稿。不用「会话」「方向盘」「线」「Task」。

| 区 | 内容 | 状态 |

## 五、页面

每页按：做什么、有什么、几种状态、能做什么动作、数据从哪来。

### 5.1 首页 `/workbench`

| 项 | 内容 |
| --- | --- |
| 做什么 | 让用户立刻开始；一眼看到有没有事等他 |
| 有什么 | ① 三个功能的切换；② 大输入框；③ 选了「工作」或「专家」时，输入框上方多一行「在哪个项目里」；④ 待我决定（没有就不显示）；⑤ 最近的对话与底稿 |
| 状态 | 没有沙箱（提示先去设置里登记模型 key、拉起沙箱）；没有机器（聊天可用；工作、专家给出安装引导）；机器离线（同上，说明原因） |
| 动作 | 输入并发送：按当前选的功能新建对话并进入；选项目；新建项目；打开最近的对话 |
| 数据 | 沙箱、环境、项目、对话、待办 |

三个功能下，输入框的样子：

| 功能 | 输入框的提示 | 多出来的东西 | 发送之后 |
| --- | --- | --- | --- |
| 聊天 | 「问点什么」 | 可选：放进某个项目 | 进入聊天页 |
| 工作 | 「要它做什么」 | 必选：项目 | 进入工作页 |
| 专家 | 「要专家解决什么问题」 | 必选：项目；然后进入「请专家」页补全 | 进入「请专家」页，问题已带入 |

### 5.2 聊天页

| 项 | 内容 |
| --- | --- |
| 做什么 | 一问一答 |
| 样子 | 气泡对话。用户的话在右，模型的话在左；模型的话边出边显示 |
| 有什么 | ① 顶部：对话的名字（可改）、属于哪个项目（没有就显示「未归入项目」和「放进项目」按钮）、**花费钮**（见 5.12）；② 对话；③ 输入框；④ 输入框旁边两个按钮：「转为工作」「请专家」；⑤ 模型在答的时候，发送钮变成**停止钮**（见 5.12） |
| 对话里会出现的东西 | 用户的话；模型的话；查数据（折叠成一行：用了哪个工具、哪个数据集、哪个版本，可展开看查询与结果）；读文件（折叠成一行）；「没有数据」卡片（见 5.9）；系统行（断线、重连） |
| 不会出现的东西 | 改文件、跑命令、审批 |
| 状态 | 连接中；实时；离线重连；机器离线（在项目里时：「读不了项目里的文件，其余照常」）；模型想动手被拒（显示一行：「聊天里不动手。要它做，请转为工作」，带按钮） |
| 动作 | 发送；停止；改名；放进项目；转为工作；请专家 |
| 数据 | 对话、事件流 |

「请专家」在没有项目时：先弹出「选一个项目或新建一个」，选完才进入「请专家」页。

### 5.3 工作页

| 项 | 内容 |
| --- | --- |
| 做什么 | 看代理干活，随时插话，要紧的事由用户点头 |
| 样子 | 过程时间线。这一页有意不做成气泡：重点是「它在我的目录里做了什么」 |
| 有什么 | ① 顶部：对话的名字、项目、目录、**花费钮**（见 5.12）；② 状态带（见 5.10）；③ 时间线；④ 输入框；⑤「请专家」按钮；⑥ 代理在做的时候，发送钮变成**停止钮**（见 5.12） |
| 时间线里的东西 | 用户的话；模型的话；跑命令（折叠：命令、退出码、可展开看输出）；改文件（折叠：哪个文件、增删行数、可展开看改动）；查数据；等你决定（审批卡，可直接答，也可点开进审查面）；「没有数据」卡片；交接（转给专家、专家交回）；系统行 |
| 状态 | 与初稿 4.2 相同：连接中、实时、离线重连、正在连接你的 Codex、机器断线 |
| 动作 | 发送；停止；答审批；请专家；打开底稿 |
| 数据 | 对话、事件流、委托 |

专家处理期间，这一页的输入框禁用，旁边写原因：「专家正在处理，你可以看进度、答复待办或取消」（`F-WEB-03`）。

### 5.4 请专家

> 5.4 至 5.6 的详细设计与样稿在 [`investment-expert.md`](investment-expert.md)。两处不一致时以那一份为准。

两个入口，同一个页面。

| 入口 | 带入什么 |
| --- | --- |
| 侧栏或首页选「专家」 | 首页输入框里写的问题 |
| 聊天页、工作页点「请专家」 | 那段对话最近一条用户的话；并注明「专家会接着这段对话做」 |

| 项 | 内容 |
| --- | --- |
| 做什么 | 让用户清楚：交出去的是什么、花多少看得见、随时能停 |
| 有什么 | ① 问题（必填，可改）；② 专家包：每个带两句话「解决什么」「不解决什么」，不默认选中；③ 一句说明「花了多少会实时显示，你可以随时停下」（**不填预算上限**，所有者 2026-10-04）；④ 专家看得到什么：这段对话、项目里的文件、项目里别的对话和底稿（只读，列出数量）；⑤ 交出前的三行确认；⑥ 按钮「交给专家」 |
| 三行确认 | 「专家会接着做：{问题}」「花了多少实时显示在顶部」「做完把底稿交回给你，期间你可以随时停下」 |
| 状态 | 专家包不匹配（受理拒绝，显示原因，留在原处）；机器离线（不能交出，说明原因）；这段对话已有进行中的委托（不能再交出）；没有沙箱或没有模型 key（指到设置） |
| 动作 | 交给专家；取消 |
| 数据 | 专家包清单（新接口）；项目；对话 |

从「专家」入口进来时没有已有的对话：交出时新建一段「工作」对话并立刻交给专家，两件事一次提交。

按钮叫「交给专家」，不叫「交出方向盘」（2026-09-26 已定）。

### 5.5 专家处理中

就是工作页，多了三样：

| 项 | 内容 |
| --- | --- |
| 状态带 | 「专家正在处理：{专家包}」「第 k 步，共 n 步：{步名}」「已花 {x}」（实时跳）「停止」 |
| 右栏的委托卡 | 专家包、每一步的名字与状态（做完、在做、没做）、已花费、待办数、打开底稿 |
| 输入框 | 禁用，带原因 |

两种打断，页面都要说清楚发生了什么、用户要做什么：

| 打断 | 页面显示 | 用户能做 |
| --- | --- | --- |
| 等你决定 | 待办卡置顶 | 答复 |
| 机器断线 | 「你的机器断开了，专家在等它回来」 | 打开本地代理；停止 |

「预算用完」这种打断页面上不再出现：请专家时不填上限（后端仍然认上限，不给就是没有，见 5.12）。

### 5.6 底稿页

区块与初稿 4.5 相同：摘要行、结果、证据、局限与不确定性、交回物、工作区变更、我的结论、交回物版本。不重写。

| 与初稿不同的地方 | 内容 |
| --- | --- |
| 路径 | 挂在项目下面 |
| 「回到对话」 | 回到专家接手的那段对话，用户可以接着说 |
| 「重新请专家」 | 带入原问题，进入「请专家」页 |
| 结果里出现「没有数据」 | 显示「没有数据」卡片 |

`W3`（结果以表为主还是以文为主）所有者未定；远程建议表为主。

### 5.7 项目页

| 项 | 内容 |
| --- | --- |
| 做什么 | 一个项目里的东西都在这 |
| 开头的一句话 | 「一个项目是你电脑上的一个文件夹，加上你围绕它聊过的、做过的、专家交回的。」所有者 2026-10-04 定：项目的定义不动。别的产品里「项目」指团队协作的空间（见 [对照 WorkBuddy](reference-workbuddy.md)），所以这里先说清楚 |
| 有什么 | ① 项目名（可改）、工作区、目录、所在的机器及在线状态；② 三个按钮：新聊天、新工作、请专家；③ 对话列表：种类、名字、最近活动、有没有进行中的委托；④ 底稿列表：专家包、终态、费用、时间；⑤ 归档 |
| 状态 | 空项目（只有三个按钮和一句说明）；机器离线（可以看，不能新建工作、不能请专家） |
| 动作 | 新建三种；打开；改名；归档 |
| 数据 | 项目、对话、委托 |

项目页不显示文件列表：文件在用户的机器上，第一期不做远程浏览。

### 5.8 项目列表、新建项目

| 项 | 内容 |
| --- | --- |
| 项目列表 | 按工作区分组；每个项目一行：名字、目录、对话数、最近活动。归档的默认不显示 |

### 5.12 花费钮与停止钮

所有者 2026-10-04 定：不靠预算上限，改成**实时看得见花了多少，随时能停**。

| 项 | 内容 |
| --- | --- |
| 花费钮 | 聊天页、工作页、专家处理中的顶部都有。显示这段对话到现在花了多少（人民币）。模型每调用一次，数字跳一次 |
| 点开花费钮 | 按轮次列出：每一轮调用了几次模型、多少 token、多少钱；最下面写按什么单价算的、单价是哪天查的 |
| 「估算」两个字 | 一直带着。用的是用户自己的模型 key，真正的账单在模型厂商那边；我们按公开单价算 |
| 不认识的模型 | 没有单价的模型不给金额，只显示 token 数。不拿别的模型的单价来猜 |
| 停止钮 | 模型或专家在做的时候一直在。点了立刻停下正在跑的那一轮，不等它做完 |
| 停下专家 | 先问一句，写明「已经花的不退，做完的部分会交回」。确认后：正在做的那一步记为「已取消」，花了的照记，方向盘交回用户 |
| 停下之后 | 聊天、工作：可以接着说话。专家：底稿页看得到做完的那几步 |

数字从哪来：对话的事件流里，每一条用量事件都带 `cost`（这一次调用花了多少、这一轮到现在花了多少）。页面进来时先取一次 `GET …/usage` 得到合计，之后跟着事件流往上加。

单价放在配置 `WORKBENCH_MODEL_PRICES_JSON` 里（每百万 token，人民币）。现在只有 `kimi-k3` 一个：输入 20、命中缓存的输入 2、写缓存 20、输出 100（2026-10-04 查自 Kimi 开放平台公开价目）。

Codex 的 `turn/start` 每一轮都可以换目录、执行环境、沙箱策略、审批策略，并对之后的轮次一直有效（2026-09-29 在本机的 Codex 源码里核对过，提交 `7d6f808b97`）。所以同一条线上换功能不用换线。
