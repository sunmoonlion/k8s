# `0008-info` 数据源平台

> 内网；映射 `info-app`。我们自己的数据源：公开数据的采集，加上我们自建的数据。定位见 [决策](../../decisions.md)「已定：info 平台的定位」（2026-09-27）。
> 2026-09-28 之后的方向（全市场、全科目的三张财务报表，以及在别的公司上发现的问题）见 [`0008-info-statements`](0008-info-statements.md)。
> 本文先只写**最小可行产品**：所有者报一个证券代码，项目从 info 到知识服务到专家走完一个闭环。平台的模块划分与第一批数据项的全貌是 `D25`，不在本文定。

## 功能义务

| ID | 义务 |
| --- | --- |
| `F-INFO-01` | 按证券代码发起一次采集批次；批次有状态、有起止时间、可重跑，重跑不产生重复原文 |
| `F-INFO-02` | 每次请求的原始响应原样留存到对象存储，带 sha256、请求方式、地址、参数、采集时间；解析在留存之后做 |
| `F-INFO-03` | 每个来源登记可信等级、版权状态、条款地址；第三方网站来源标为「仅内部使用」（`D1`、`D2`） |
| `F-INFO-04` | 时间分三个记：数据所属期间、对外披露时间、我们的采集时间；披露时间只取自法定披露渠道 |
| `F-INFO-05` | 每个财务数值带口径：原始披露、追溯调整后、未核实；口径由与法定披露原文的比对得出，比不出来就是未核实 |
| `F-INFO-06` | 质量检查在入库前跑：结构、同期勾稽、跨期连续、来源间一致、口径标注、时点、新鲜度；结果随数据集一起留存 |
| `F-INFO-07` | 质量检查不通过的数据集不发布（最小可行产品阶段一律拦住，不做「标记后放行」） |
| `F-INFO-08` | 产出的数据集按内容定版本，连同清单（文件 sha256、数据版本、来源批次、质量报告）交给知识服务 |
| `F-INFO-09` | 参考了外部开源项目的接口知识时，在代码里注明参考的函数并保留对方的许可声明；产品运行时不依赖该项目 |

## 最小可行产品的闭环

```text
所有者报证券代码（命令行或管理接口）
  → info 采集批次：巨潮的年报公告与原文；三大报表的原始响应          （段一）
  → 结构化：建数据集，标口径，建披露日历，跑质量检查                  （段二）
  → 数据集文件进对象存储，向知识服务登记                              （段二 → 段三）
  → 知识服务：按数据集标识提供 MCP 工具                               （段三）
  → 专家：财报体检专家包七步，交回底稿，结论栏留空                    （段四）
  → 部署到集群，用 600009 跑通                                        （段五）
```

验收只看一家公司：`600009` 上海机场。代码按任意 A 股非金融公司写。

### 为了最小而不做的

| 不做 | 原因 |
| --- | --- |
| 用户问到未入库的公司时自动去采 | 采集由所有者手动发起；专家遇到未入库的代码答复「未入库」 |
| 年报 PDF 的全表抽取 | 只取「主要会计数据」一页，用来判口径和核对 |
| 附注、分业务收入、经营数据 | 第二步 |
| 季报与中报的口径判定 | 入库，口径记为未核实 |
| 行情、宏观、基金等 | 不在第一切口 |
| 平台的模块划分 | `D25`；代码先按 `info-backend` 现有分层放 |

## 段一：按证券代码采集

**入口**：命令行 `python -m app.cli.security_ingest --code 600009`；管理接口 `POST /api/admin/securities/{code}/ingestions`。两者调同一个应用层服务。

**沿用现有流水线的部分**：来源（`info_source`）、采集任务（`crawl_job`）、原文（`raw_artifact`）、对象存储、取数的安全约束（只许公网地址、限大小、限重定向）。

**新增**：

| 项 | 内容 |
| --- | --- |
| 取数支持 POST | `fetch_crawl_url` 增加请求方式与表单体；安全约束不变。巨潮的公告查询是 POST |
| 采集批次表 `security_ingestion` | 证券代码、状态、起止时间、各来源的任务与原文引用、计数、失败原因 |
| 证券采集器 | 两个，见下表。各自只负责「发哪些请求、原文怎么命名」，不解析业务含义 |
| 来源登记 | `cninfo`：法定披露渠道；`eastmoney-f10`：第三方网站，版权状态「未确认，仅内部使用」 |

| 采集器 | 请求 | 留存的原文 |
| --- | --- | --- |
| 巨潮披露 | 公告查询（POST，年报类别，近八年）→ 每份年报取文件地址 → 下载 PDF | 公告列表的 JSON；每份年报的 PDF |
| 东方财富 F10 报表 | 资产负债表、利润表、现金流量表：先取报告期列表，再按期分批取 | 每个请求的 JSON 响应 |

参考：接口地址与参数参考了 akshare 1.18.97（MIT）的 `stock_zh_a_disclosure_report_cninfo`、`stock_balance_sheet_by_report_em`、`stock_profit_sheet_by_report_em`、`stock_cash_flow_sheet_by_report_em`。运行时不依赖它。

**幂等**：原文的对象键含内容 sha256；同一内容重采不新增对象。批次重跑产生新的批次记录，引用已有原文。

**测试**：采集器的单元测试用录制下来的真实响应做夹具，不在测试里访问外网。另有一个手动跑的联网冒烟脚本，结果写进 `scripts/results/`。

## 段二：结构化与质量检查

放在 `info-backend` 的应用层。这是最小可行产品阶段的选择，不预设 `D25` 的答案。

**输入**：一个采集批次的原文。**输出**：一个 SQLite 数据集文件、一份清单、一份质量报告。

数据集的表（和 2026-09-27 探针产物同形，知识服务现有的查询类已验证能直接读）：

| 表 | 内容 |
| --- | --- |
| `balance_sheet`、`income_statement`、`cash_flow` | 报表行；每行有 `report_date`、`report_type`、`fiscal_year`、`basis`、`verified`、`verified_against` |
| `official_key_figures` | 从年报「主要会计数据」页取出的关键数字，带口径、报告名、披露日、页码 |
| `disclosure_calendar` | 法定披露日历 |
| `field_dictionary` | 字段的中文名与单位 |
| `metric_dictionary` | 口径表：公式、单位、时间口径、适用条件 |
| `reconciliation_rules` | 勾稽规则 |
| `dataset_metadata` | `data_snapshot_id`、期间、来源、重述说明、时点说明、使用权说明 |

**口径判定**（`F-INFO-05`）：

1. 从每份年报的「主要会计数据」页取数。该页的列有「本期」「上年」，发生追溯调整时上年拆成「调整后」「调整前」。
2. 报表里某年的值等于该年年报「本期」列的值：原始披露。
3. 等于后一年年报里「调整后」列的值：追溯调整后。
4. 两者都对不上，或该页解析失败：未核实。

解析失败不猜。

**质量检查**（`F-INFO-06`）：九条同期勾稽，一条跨期连续，关键科目与年报原文逐项比对，口径覆盖率，最新一期是否已采到。容差一元。任何一条同期勾稽不平，数据集状态记为 `quality_failed`，不发布。跨期不连续不拦，但必须在 `dataset_metadata` 的重述说明里能找到对应解释，找不到则拦。

**新增依赖**：PDF 文字抽取库，钉版本。

## 段三：知识服务支持多个数据集

现状：知识服务只装一个数据集，由配置指定路径与 sha256。

| 项 | 内容 |
| --- | --- |
| 数据集登记表 | 标识、数据版本、对象存储位置、sha256、状态、登记时间、来源批次 |
| 内部登记接口 | info 用服务间令牌调用；重复登记同一版本是幂等的 |
| MCP 工具 | 三个现有工具增加可选参数 `dataset`；不传时用默认数据集（第 23 课零售库），问数专家包与二十题不受影响 |
| 新工具 `list_datasets` | 列出已登记且状态可用的数据集：标识、证券、期间、数据版本 |
| 取文件 | 沿用现有的「从对象存储按 sha256 钉版取到本地」，按数据集缓存 |

令牌里的工具清单照旧按专家包步骤过滤（`F-KNOW-01`）。

## 段四：财报体检专家包

专家包 `FIN_REVIEW`，七步：定范围、数据摸底、勾稽、取数、算指标、对照官方、成稿。数据摸底与勾稽排在取数之前。

| 项 | 内容 |
| --- | --- |
| 数据集的选择 | 第一步从问题里取出证券代码；第二步用 `list_datasets` 找到对应数据集，找不到则交回「未入库」并交人 |
| 新验收规则 | `all_equal`：列表每一项的某字段等于给定值；`list_empty`：列表必须为空。都是确定性的纯函数 |
| 硬性要求 | 跨期比较先核对口径；披露时点只取披露日历；分母为负或近零的比率标为不适用；未核实的行要在提醒里写明；成稿不含买卖建议，结论栏留空 |

会计知识（例如新租赁准则使经营现金流前后不可比）的来源：写进数据集的说明，专家只引用，不凭模型自身知识断言。

## 停点

每段一个停点，各自单独提交。前四段在远程机上验，不需要集群。

## 待定与风险

- **数据使用权**：三大报表来自第三方网站，最小可行产品阶段仅内部使用（所有者 2026-09-27 定）；对外提供前按 `D1`、`D2` 处理。
- **接口会变**：第三方网站的接口没有稳定性承诺。采集器失败要明确报错并留下响应原文，不静默返回空。
- **年报版式**：「主要会计数据」页的版式各公司、各年份不完全相同。解析失败记为未核实，不影响入库，但影响口径覆盖率。
- **「结构化」的归属**、多来源取舍、财务指标是否自算、有版权的行业分类：`D25`，等开发 info 平台时定。
