### 根因诊断（只读复现，未改任何文件）

块提取正则 `(?ms)^  {app}:\n(?:(?!^  \S).*\n?)*` 里的 **`s`（dotall）标志使 `.*` 能匹配换行**，于是 `.*` 从 `  tpl:` 之后一路贪婪吃到文件末尾——「块」被捕获成了 tpl+knowfeed+knowbase+investment **全部 4 个应用块**。随后 `re.subn(rf"(?m)^(    parent_revision: )\w+", …)` 在这个大块里匹配到 **4 次**（每个应用块各一次），`n=4 ≠ 1`，触发 `assert n == 1, (app, field)`，报错 `('tpl', 'parent_revision')`。

只读复现证据（在真 `sources.yaml` 上跑，未写文件）：

```
手册正则 (?ms) 捕获块行数: 32 → parent_revision 出现次数: 4   ← n=4≠1，assert 失败
去掉 s   (?m)  捕获块行数: 8  → parent_revision 出现次数: 1   ← 只捕获 tpl 块，正确
```

`(?m)` 版捕获的正是 tpl 那 8 行（1 行头 + 7 行 revision），符合手册意图。

**修复方向（交 Opus 定夺，Qwen 不自行改手册脚本）**：把手册第 344 行的 `(?ms)` 改成 `(?m)` 即可让块正则按「2 空格缩进的应用头」正确断块。

### 同一 bug 的波及面

第 2 步改钉 `component-images.yaml`（手册第 365 行）用的是**同样的 `(?ms)^  {name}:\n(?:(?!^  \S).*\n?)*` 块正则**，`sandbox-provisioner` / `sandbox` 两块也会被 dotall 连成一片、`revision` 匹配次数 >1，预计同样触发 `assert n == 1, name`。建议 Opus 一并核改。
