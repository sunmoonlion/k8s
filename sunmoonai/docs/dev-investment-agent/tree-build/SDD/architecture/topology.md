# 部署拓扑：边缘 + 内网

> **这是正式拓扑，不是过渡。**所有者裁定：开发期这样，以后服务用户也这样。
> 公网只放薄边缘；一切业务在我们自己的内网站点；深处的组件只出站。

## 三个地方

```text
用户机器 ──出站──▶ 公网边缘 ◀──出站── 我们的内网站点（可多个）
                   （无状态）
```

| 地方 | 放什么 | 不放什么 | 谁能连它 |
| --- | --- | --- | --- |
| **公网边缘**（云 VM，可多台） | TLS 终止（Traefik）；会合点；frp 服务端 frps（内网 HTTP 的反向隧道入口，见下「边缘到内网」） | 业务逻辑；业务数据；模型调用；任何持久卷 | 所有人 |
| **内网站点**（我们的机房，kubeadm 集群） | 工作台后端；沙箱池；知识服务；Casdoor；PostgreSQL；对象存储；评测 | 任何被边缘依赖的入站端口 | 没有人。它连边缘 |
| **用户机器** | 浏览器；本地代理 | 任何监听公网的端口 | 没有人。它连边缘 |

## 两条不变量

| 不变量 | 内容 | 验收 |
| --- | --- | --- |
| **深处只出站**（`C-T7`） | 内网站点与用户机器只发起连接，不接受连接。边缘到内网的一切流量走内网发起的长连接 | `AT-23`：端口扫描证明 |
| **边缘无状态**（`C-T8`） | 边缘不存业务状态；令牌用公钥就地验；任一台边缘可替换，替换后会话与 Task 不丢 | `AT-22` |

推论：边缘是**唯一**的公网攻击面；边缘被攻破拿到的是流量与令牌，拿不到库；内网站点搬家、换机房、加第二个站点，只改部署清单，不改协议（`C-T9`）。

## 边缘上的会合点做什么

两类出站客户在这里配对，另有工作台的管理通道：

| 客户 | 从哪来 | 要找谁 | 令牌 |
| --- | --- | --- | --- |
| 沙箱 | 内网站点里的某个 pod | 该用户的本地代理 | 按用户 + 沙箱签发（`D10`） |
| 本地代理 | 用户机器 | 该用户的沙箱 | 按用户签发（`D10`） |
| 工作台（管理通道 `/admin`） | 内网站点 | 会合点本身：登记令牌、推公钥、吊销 | 管理令牌 |

沙箱与本地代理之间是 Codex 远端环境协议的透传，协议见 [`0004-relay`](../modules/0004-relay.md)。三者都是 `wss://` 出站连边缘，不经 frp：会合点要按用户验令牌、配对、核两端 Codex 版本，这是 frp 做不了的。

## 边缘到内网：frp 隧道（2026-09-26 所有者定）

浏览器的 HTTPS 请求要进内网，但内网不开入站端口（`C-T7`）。做法：内网里的 **frpc** 主动连边缘上的 **frps**，边缘把收到的 HTTP 请求沿这条长连接送回内网。用现成的 frp，不自研隧道协议；原设计里会合点的"站点"客户与站点令牌取消。

```text
浏览器 ──HTTPS 443──▶ 边缘 Traefik（TLS 终止、证书）
                          ├─ Host app.<域>、/api/、/auth/ ──▶ frps vhostHTTP 127.0.0.1:8080 ══隧道══▶ frpc（内网）──▶ 内网 Traefik ingress ──▶ 网页 / 工作台 / Casdoor
                          └─ /relay/* ──────────────────────▶ 会合点 127.0.0.1:47100（WebSocket）
内网 frpc ──TLS 出站 7000──▶ frps          本地代理、沙箱、工作台管理通道 ──wss 出站 443──▶ /relay/*
```

| 项 | 定法 |
| --- | --- |
| 走 frp 的 | 浏览器能到的一切 HTTP：网页、`/api/`、`/auth/`（Casdoor）。第一期整条域名交给内网 ingress，由它按路径分流，内网现有的 IngressRoute 一条不改 |
| 不走 frp 的 | 会合点的三类连接（上表）；`/mcp/` 第一期不对外（沙箱在内网直连知识服务），以后内网外有消费者再开 |
| 边缘上的端口 | 公网只开 443（Traefik）与 7000（frps，只给 frpc 连）；frps 的虚拟主机与代理端口、会合点、frps 面板都只绑 127.0.0.1 |
| frpc ↔ frps | 强制 TLS（`transport.tls.force`）；令牌认证，令牌 ≥32 字符、不进配置文件与日志，边缘放 systemd 环境文件（0600），内网放 Secret；钉版 frp 0.71.0，下载按官方 sha256 校验 |
| 内网一端 | frpc 做成集群里的 Deployment（新部署单元，走 bundle 与门禁），指向内网 Traefik 的 Service；两副本用 frp 的负载均衡组（`loadBalancer.group`），一个断了另一个接着转 |
| 边缘一端 | frps 用工具箱 `toolboxes/Vlinux/utils/set-up-tools/frp/install_frp.sh -m server`（systemd、加固单元）或同配置的容器；换边缘机只需重装、换 DNS，frpc 自动重连（`loginFailExit = false`） |
| 流式与长连接 | 会话页用 SSE、会合点用 WebSocket：边缘 Traefik 的读写空闲超时放宽到 ≥1 小时，不缓冲响应；frp 的 http 代理原样透传 `Upgrade` |
| 客户端地址 | 边缘 Traefik 写 `X-Forwarded-For/Proto/Host`；内网 ingress 只信来自 frpc 的这几个头；Casdoor 与网页的回调地址、Cookie 域都用公网域名 |

不变量怎么保：`C-T7` 由 frpc 只出站保证（内网仍无入站端口，`AT-23` 照测）；`C-T8` 由 frps 不存业务状态保证，代理注册是连接态，frpc 重连即恢复，边缘可替换。

新增的风险与处置：

| 风险 | 处置 |
| --- | --- |
| frp 令牌泄露：别人能冒充内网站点向 frps 注册同名域名，劫持流量 | 令牌只在边缘环境文件与内网 Secret；frps 只允许 `allowPorts` 列出的端口；定期换令牌（两端各重启一次）；边缘被攻破本就等于流量可见，不扩大攻击面到内网 |
| frps 或边缘宕机 | 整站不可达，内网不受影响；恢复靠重装边缘，frpc 自动重连；多台边缘时 DNS 轮询，每台一个 frps，frpc 各连一台 |
| 隧道把公网请求带进内网 | 进内网的只有边缘 Traefik 放行的域名与路径，落到内网 ingress 后与今天同一套认证 |

本地先验证再上云：KIND 当内网站点，另起一个容器当边缘（Traefik + frps + 会合点，自签证书，`/etc/hosts` 指域名），本地代理与浏览器都走 `wss://`/`https://` 边缘地址跑一遍 SMOKE。通过后再把同一份边缘装到云服务器。

## 多站点

内网站点可以不止一个：第二个机房、某个客户的私有化站点。每个站点出站注册，边缘按用户或租户把流量分到所属站点。第一期一个站点；分片规则记在 `0004-relay`。

## 这个拓扑的代价

| 代价 | 处置 |
| --- | --- |
| 内网上行链路是单点 | 专线或双路、UPS、告警送达，作为上线门（`D15`、`C-R9`） |
| 一次工具调用两段公网（沙箱 → 边缘 → 用户机器） | 每 turn 几十个串行来回；两机实测跨境单跳每请求约 420 ms（`runtime/probe/REPORT-2026-09-24-two-machine-latency.md`），所以边缘必须与用户同区域（`D19`） |
| 边缘要能撑住全部用户的长连接 | 会合点无状态，水平加机器 |

## 与现有部署的关系

内网站点用 `k8s` 仓 `infrastructure/` 的 kubeadm 那套；本机开发用 `kind-infrastructure`；ingress 用 `ingress-platform`。
边缘是新的一类部署单元：一份薄的 Traefik + 会合点 + frps；同样走 bundle 与门禁（`C-R*`）。内网多一个 frpc 部署单元。网页第一期仍在内网（经隧道访问）；以后把静态产物搬到边缘是纯优化，不改协议。
