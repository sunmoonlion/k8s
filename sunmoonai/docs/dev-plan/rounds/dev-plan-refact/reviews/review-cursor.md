## A. 自述（关于 cursor 的 ①）

### ①a 提出了什么

主干单位是一次 **Change**（人提出 → AI 做成可验收产物 → 人说过还是不过），不是一轮文档、也不是一份分类表。

- **常驻面**（不是阶段）：硬约束 / 协作协议 / 操作手册，每次 Change 都踩着走。
- **时间顺序**：提出 → 立约 → 定向 → 决策 → 本增量设计 → 实施 → 验证 → 验收 → 发布与交接。
- **两道总门**：G1 开工、G2 完工；T0/T1/T2 是同一条 Change 的厚度，不是三套流程。
- **文档类型从阶段推导**（12 类）：原始请求、产品合同、方向、决定记录、增量设计、任务计划、硬约束、协作协议、操作手册、证据、状态、索引。
- **对所有者映射**：采纳 PRD / ADR-载体 / TLD / 开发纪律；**异议** `protocol` 不是实施计划的一章（举证：两份文件各自声明的职责 + `README.md` 已有的混写后果）。
- **自造名「操作手册」**：AI 冷启动必须有一份「照做」入口；通行名 PRD/ADR/TLD/SDD 都装不下。

### ①b 怎么推导

先写归属判据（C-* ID），再写每份活文档的内部结构论证，再写拆并代价与 B2，最后才是 260 行落点表。`agent-dev-guide.md` 点名三类**寄居者**（运行时 TLD、证据采信、历史收据），本轮物理不搬家。内核 `request-lifecycle.md` 本轮零编辑。
