## 根因（已定位到源码）
`test-computer/workload.yaml.j2` 的 `run.sh` 里所有 cli.js 调用都是裸 node：`agent() { node /data/agent/app/dist/cli.js "$@"; }`、`agent init …`、`agent pair`、末尾 `exec node /data/agent/app/dist/cli.js start`——**都没带 `--use-system-ca`，也没设 `NODE_EXTRA_CA_CERTS`**。
而 `agent/src/siteTrust.ts` 的启动守卫 `installedLaunchError`：
- 第 79 行：`if (!process.execArgv.includes("--use-system-ca")) return "SITE_LAUNCH: 代理没有按安装包的方式启动…"`；
- 第 80 行：bundled-ca 模式还要求 `NODE_EXTRA_CA_CERTS` 经 realpath 等于 `site.caPath`。
dev-kind 站点是 `bundled-ca`（`sites/dev-kind.json`：`trust.mode=bundled-ca`、`ca_file=site/ca.pem`），安装布局 `<root>/site/{site.json,ca.pem}` + `<root>/app/dist/cli.js`，此处 `<root>=/data/agent`。所以第一次 `agent init` 就触发守卫崩溃，根本到不了配对。
参照正确起法：`agent/distribution/launch.mjs` 的 `nodeLaunch`（`execArgv:['--use-system-ca']`）与 `applyLaunchEnv`（删 `NODE_OPTIONS`/`NODE_EXTRA_CA_CERTS`，bundled-ca 时设 `NODE_EXTRA_CA_CERTS=site.caPath`）；`agent/src/resident.ts:85` 也是 `spawn(execPath,[...launch.execArgv, cli, "start", …],{env:applyLaunchEnv(...)})`。

## 建议修法（属 Opus 修模板范围，我没动组件源）
在 `test-computer/workload.yaml.j2` 的 `run.sh` 里，把**每一处** cli.js 调用都改成按安装包入口的方式起，即：
- `unset NODE_OPTIONS`；`export NODE_EXTRA_CA_CERTS=/data/agent/site/ca.pem`；
- 所有 `node /data/agent/app/dist/cli.js …` → `node --use-system-ca /data/agent/app/dist/cli.js …`（`agent()` 助手、`init`、`pair`、末尾 `exec … start` 全改）。
（若安装包在 Linux 侧已生成统一入口脚本，直接调用那个入口更稳，可免手工维护旗标。）
