# app-platform 摘要

> 快层：三分钟把握 App Platform 公共形态。深刻层见同目录 `架构.md`；平台间关系见
> `baseline/sunmoonai/architecture.md`。

## 1. 定位

App Platform = auth-app（身份基础）+ 三个领域 App（info / knowledge / investment）+ 约束
它们的公共形态与契约。本项不对应单个源码仓，而是"所有 App 共同遵守的形态"的权威描述；
模板的实现载体是 `tpl-app`，部署声明在 `k8s` 仓。

## 2. 核心决策速览

1. 三个领域 App 相互独立，不合并为巨型 App；
2. 每 App 一个规范 FastAPI Backend、一个逻辑数据库、一条 Alembic 迁移链；
3. 每 App 保留 Admin 与 Web 两个独立 Next.js 前端，共用统一 Backend；
4. Admin / Web / Internal 是同一 Backend 的接口分面，不是三套实现；
5. API / Worker / Scheduler / Migration 是同一镜像的运行角色，不是独立仓库；
6. App 间只经受版本控制的 API / 事件 / Artifact 契约协作，禁跨 App 读写数据库；
7. 共性能力先 tpl-app 过门禁，再按 info → knowledge → investment 串行同步。

## 3. 标准 App 形态

```text
Admin Next.js SSR ──┐
                    ├──▶ one FastAPI Backend ──▶ one logical App database
Web Next.js SSR ────┘        │
                             └──▶ API / Worker / Scheduler / Migration 角色
```
