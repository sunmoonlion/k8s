# 资料与知识服务

> **本轮范围外**：知识服务尚无模块落点，本文先把需求记住。
> 三块的划分见 [需求](requirement.md)「切成三块」。

| 资料 | 存放 | 如何给 Codex |
| --- | --- | --- |
| 用户自己的资料（研报、纪要、表格、内部数据） | 用户电脑上的本地知识库 | runtime 的本地 MCP |
| 公开资料（公告等） | 由 Codex 从官方渠道取回，存入本地知识库；我们不提供这类内容 | runtime 提供取数与解析工具；联网按白名单放行 |
| 自有数据 | 我们的云：info-app 采集，knowledge-app 建库 | 知识服务的远程 MCP，按查询以上下文下发，不整批同步 |

- **本地知识库**：资料**不上传我们的后端与知识服务**，存放在用户电脑上；向量化**可调用用户所选厂商的 embedding 接口**（走这条路时内容会发往该厂商，界面须按 `F-INTAKE-08` 告知），也可在本地运行小模型；团队共享与跨设备迁移后置；
- **公开资料取数**：取数与解析工具（按公司、日期、类型下载公告，解析 PDF 表格）由我们提供并随 runtime 更新，不让 Codex 临时编写爬虫；runtime 限速，遵守站点访问规则；
- **自有数据**：来源必须合法可追溯；只装数据不装观点（F-POS-01）；
- **按上下文下发**：每次只给最相关的片段，片段数与 token 有上限；每个片段带来源、时点与数据版本，进入证据账；
- **防批量抓取**：按设备发 token，可吊销，随设备配对签发；限流并监控异常调用；只返回所需字段与片段，不返回原文全文；必要时加水印；
- 核心检索与领域计算做成 MCP 工具；需要严格步骤的领域流程封装在工具内部，用固定逻辑执行。
