它是 `runtime` 轮走完七环节、经独立验收发布的稿子。问题不在流程，在**它的六处设计
都建立在没有核过的前提上**。今天下午逐条核查，每条都在两分钟内被推翻：

| # | 稿中的设计 | 核查结果 | 怎么复核 |
| --- | --- | --- | --- |
| 1 | Interaction 出向六字段 + 入向三值 + `amend` 载荷 + `amend_schema` + `amend.mode` + 过期校验 | 我们的基座库里，入向就是 `Command(resume=<任意值>)` **一个参数**；出向 `interrupt()` 收任意 dict。整套自定义协议没有对应物 | 在 **investment-app 仓**读 `investment-backend/app/app/infrastructure/graph/pilot_graph.py:59`，以及该仓内 `Command(resume=` 的全部实际调用 |

**六处的共同成因是同一个**：在没有用命令确认「这个动作现在实际发生在哪、由谁做、

分清这两部分，是本轮的主要工作量之一。

## 6. 身份判别（**开工第一件事**）

```bash
r=$(git rev-parse --show-toplevel 2>/dev/null) && basename "$(dirname "$r")" || echo "❌ 不在 git 仓内"
```

输出就是你的名字（`luna` / `kimi` / `cursor` / `fable` / `qwen`）。三条硬规矩：

1. **命令跑不出名字就停下问人**，不要继续；
2. **产品名、模型名、界面长什么样，一律不是身份证据**；
3. **只写自己路径下的文件。**

> 这三条来自一次真实事故：一家的判别命令在仓外一层执行，`git` 退 128 而管道吞掉错误，
> `basename` 对着报错文本输出一串 `.`；该家退回文本推理，据产品名推出自己是另一家，
> 并宣告正在写另一家的工作区。所有者当场发现，无污染。

## 11. 判据自身的失效条件

本判据表也要能在两个方向上失败：

| 情形 | 处理 |
| --- | --- |
| 某条判据下五家**全部满分或全部零分** | 该条无区分力，**作废、不计入**，裁决书说明 |
| 某条判据在五份候选上**都无法判定** | 说明它写得不可判定，**作废**，理由记入裁决书 |
| 五家**都没意识到** §1 指出的某个问题 | 责任在本文交代不清，**不扣候选的分**，记为发起方的改进项 |
| 出现本文完全没预料到的做法 | 计入加分（上限 10 分），标注「事后新增判据」 |

**加分与扣分不对称是有意的**：事先没想到的好做法应当被奖励，
事先没写的要求不得用来惩罚。
