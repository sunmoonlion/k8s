# PRD 用户消息模板

复制成 turn 里的 `user-message.md`。

本阶段的用户消息要写清什么，见 [PRD 规则](prd-rules.md)「这一段的用户消息」；写多严见 [任务的生命周期](../lifecycle.md)「用户消息写多严」，字段的含义见同一份的「turn 的固定字段」。
交回的 response 要能定稿成 `SDD/`，所以它要满足 [PRD 规则](prd-rules.md)「`architecture/` 写什么」「`modules/<模块>/` 写什么」与「纪律」。

```markdown
---
executor: <派给谁；还没派出去写 unassigned>
verifies: 无
---
# turn <四位号>：<短名>

## 依据
<以哪一份 `PRD/` 定稿、或哪一段 BRD 讨论为底；给出链接与提交>

## 要满足什么
<这一问要产出的需求：谁用、在什么场景下、要达到什么结果>

## 模块划分
<要不要拆模块。要拆的话，每个模块写清职责、从谁拿什么、给谁什么、验收；
 号与短名在同一父目录内从 0001 起连续，并与将来 `SDD/modules/` 下的同名目录一一对应>

## 范围
- 包含：
- 不包含：
- 不包含的归谁：

## 约束
<必须遵守的规则、不能动的东西、外部限制>

## 不要做的
- **不写怎么实现**：技术方案、数据结构、接口签名、依赖选型都属于 SDD，写进来也不作数；
- **不给倾向性结论**：把要求写清楚，把方案留给设计；
- 还没定的写进「未决」，并写明定不下来会影响什么。

**交回：写成这个 turn 的 `response.md`，由 discussion agent 交，不改代码。人读完定稿成 `SDD/`。**
```

这一段不写验收标准：答得合不合格看它能不能定稿成 `PRD/`——判据是 [PRD 规则](prd-rules.md)，不是这一问里临时立的条目。

不适用的栏写「不适用」及理由——空着与「忘了」无法区分。命中 T2 判据的任务每一栏都要填。
