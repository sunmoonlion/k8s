## 一、要解决什么

knowmart 现在只有一页「我的分身」：列出当前用户自己的分身和版本，从工作台跳来时多一个「请这位」（0027 P2）。按 2026-10-18 的几条决定，knowmart 要变成一个**专家目录**：每个用户看到自己的专家与公开的专家；公开的专家来自持证的发布主体；工作台不再列专家，请专家就到这里来选（决定记录「都叫专家」「knowmart 对标腾讯 WorkBuddy」）。

这份设计回答：目录有哪几页、每页摆什么、谁能看到什么、后台要补什么。

## 三、为什么照京东，不照咸鱼

| | 京东 | 咸鱼 | 对我们 |
| --- | --- | --- | --- |
| 供给 | 商家开店，平台审资质 | 个人对个人 | 能公开的投资类专家只来自持证的非个人主体，是京东的形态；个人做的投资类专家只能自用，咸鱼那种个人卖家正是我们不许公开的 |
| 商品 | 标准化：规格、参数固定 | 非标准：先聊再成交 | 专家是定好版本、定好输入输出的，不讨价还价 |
| 信任 | 店铺、认证标识、评价 | 个人信用分 | 发布主体与它的证照是信任的来源 |

借咸鱼一点：首页卡片流适合「发现」，公开专家多了以后可以加推荐流。

## 四、对象与属性（后台）

现有的专家记录（knowmart `knowbots`：所有者、名字、一句话介绍、版本与清单）上补三样，另加两张骨架表与一个开关。

| 补什么 | 放在哪 | 取值 | 现在 |
| --- | --- | --- | --- |
| **类目** `category` | 专家（每个专家一个） | 类目代码，见第六节 | knowlab 出专家时由运营选；交付带过来 |
| **可见范围** `visibility` | 专家 | `private`（自用）/ `public`（公开） | 一律 `private` |
| **发布主体** `publisher_id` | 专家 | 指向发布主体 | 自用的为空（作者就是所有者） |
| 发布主体表 `publishers` | 新表 | 主体类型（个人 / 非个人）、名称、实名状态、统一社会信用代码（非个人） | 建表，不开放入驻 |
| 资质表 `publisher_licenses` | 新表 | 主体、类目、证照名称与编号、有效期、审核状态与审核人 | 建表，不开放上传 |
| 平台开关 `public_market_enabled` | knowmart 配置 | 真 / 假 | 假 |

**谁能看到一个专家**（只在后端判，前端拿到什么就画什么）：

```text
看得到 = 所有者是我
       或（visibility = public
           且 public_market_enabled
           且 发布主体对这个专家的类目有审核通过、未过期的资质）
```

看不到的专家，详情接口回 404，不回 403，免得别人借此知道它存在。

## 五、页面

### 5.1 首页（专家目录）

菜单与筛选借鉴 tpl 的 Vue 版管理端（`repo-backup/tpl-admin-frontend-vue`，所有者 2026-10-18「特别是vue的版本，好像它的菜单和筛选不错」）：菜单用它的「混合」布局，筛选用它的「搜索 + 条件 + 重置 + 分页」一整套，改成卡片上方的筛选条。借的是交互，代码用我们现有的 Next.js + shadcn/ui 重写（Vue 版是 Vue + Element Plus，用不上）。

```text
┌──────────────────────────────────────────────────────────────────┐
│ knowmart │ 全部  金融  工具  商业服务 │ [搜索专家名或能做的事] 当前用户：xx │  ← 页头：一级类目横排
├───────────┬──────────────────────────────────────────────────────┤
│ « 收起     │ （从工作台来时）从工作台来：选一位，点「请这位」回去   │
│ 金融       │ 数据：[全部 ▼]  更新时间：[不限 ▼]       排序：[最近更新 ▼] │  ← 筛选条
│ ▸证券/期货 │ 已选：[金融 ×] [近 30 天 ×]  重置筛选                  │  ← 已选条件
│  投资咨询 1│ ┌────────┐ ┌────────┐ ┌────────┐                     │
│           │ │财务分析 │ │ ……     │ │ ……     │                     │
│ ← 左侧：当 │ │与预测   │ │        │ │        │                     │
│ 前一级下的 │ │一句话   │ │        │ │        │                     │
│ 二级类目   │ │类目·第1版│ │        │ │        │                     │
│           │ │[请这位] │ │        │ │        │                     │
│           │ └────────┘ └────────┘ └────────┘                     │
│           │                        共 1 位  ‹ 1 ›                │  ← 分页（专家多了再出现）
└───────────┴──────────────────────────────────────────────────────┘
```

**菜单（「混合」布局）**

- **页头横排一级类目**：「全部」加第六节里当前用户看得到专家的一级类目。点一个一级，左侧换成它下面的二级。
- **左侧列二级类目**：带数量，当前选中的高亮；只列看得到专家的二级（数量为 0 的不列）。选「全部」时左侧列所有看得到的二级，按一级分组。
- **左侧可折叠**：收起后只剩一条窄栏，和工作台的左侧导航一样（工作台 2026-10-17 已做）；折叠状态记在这台浏览器。
- **手机上**：一级类目在页头横向滚动；左侧二级收成筛选条里的一个下拉。

**筛选条**

| 部分 | 怎么做 | 现在 |
| --- | --- | --- |
| 搜索 | 在页头；按名字与一句话介绍查，简单的包含匹配 | 做 |
| 数据 | 全部 / 只用专家自带数据 / 需要你提供数据（看专家的「输入是什么」声明接不接受外来数据） | 先放「全部」与「只用专家自带数据」，第二期再加另一项 |
| 更新时间 | 不限 / 近 7 天 / 近 30 天 | 做 |
| 发布主体、资质 | 按发布主体、按有无某类资质筛 | 公开专家开放后才出现 |
| 已选条件 | 选了的条件排成一排小标签，每个可单独点 × 去掉；最后是「重置筛选」 | 做 |
| 排序 | 最近更新（默认）/ 名称 | 做 |
| 分页 | 每页 24 位；总数不到一页时不显示 | 做（现在专家少，看不到） |

筛选条件写进页面地址（`?category=&data=&updated=&sort=&page=`），刷新、分享、从详情页返回都不丢；类目与搜索也一样。

**其余**

- **卡片**：专家名、一句话介绍、类目、最新版本号。公开专家多一行发布主体名称与认证标识（现在没有）。**不贴「自用 / 公开」标签。**
- **「请这位」**：只在从工作台跳来时出现（现状），点了回到工作台。不是从工作台来时，卡片上是「去工作台请」，点了带去工作台，工作台再带回来（复用现成的跳转规则，见第八节）。
- **空态**：一个专家都没有时，说明「专家在 knowlab 做好、测试通过后出现在这里」，给去 knowlab 的链接；筛选后没有结果时，说「没有符合条件的专家」并给「重置筛选」。

### 5.2 专家详情页

```text
┌──────────────────────────────────────────────────────────────┐
│ 财务分析与预测                                      [请这位] │
│ 看清收入、成本、现金流的走势，给出可核对的预测                 │
│ 类目：证券 / 期货投资咨询   版本：[第 1 版 ▼]   最近更新：2026-10-18      │
├──────────────────────────────────────────────────────────────┤
│ 能做什么 │ 需要的数据 │ 交回什么 │ 版本记录 │（公开才有）发布主体 │
├──────────────────────────────────────────────────────────────┤
│ ……当前页签的内容……                                            │
└──────────────────────────────────────────────────────────────┘
```

头部像京东的商品主区：名字、一句话介绍、类目、**版本选择**（像选规格，默认最新可用版）、主按钮。页签像京东的「商品介绍 / 规格参数 / 评价」：

| 页签 | 内容 | 从哪来 |
| --- | --- | --- |
| 能做什么 | 解决什么、不解决什么、输入是什么、输出长什么样、怎样算做对；接什么、不接什么（受理关口的 `scope`） | 清单里的六问答案与 `scope` |
| 需要的数据 | 专家自带的数据（名字、版本，不给内容）；请的人要不要自己提供数据、提供什么（第二期起） | 清单 `data_bindings`；数据的名字向 knowlab 取 |
| 交回什么 | 交回的内容与形式（成稿文件、表格）；以后加样例成果 | 清单里每步的交回物与成稿文件 |
| 版本记录 | 各版本号、交付时间、是否可用；所有者在这里停用某一版（现有功能） | knowmart 版本记录 |
| 发布主体 | 主体名称、类型、证照名称与编号、有效期 | 发布主体表与资质表；自用专家没有这个页签 |

**公开专家只给结论性的说明**：方法的步骤与规则原文是作者的东西，详情页不展示；自用专家的所有者自己看得到全部（他本来就在 knowlab 写过）。

### 5.3 发布主体页（以后）

一个发布主体的所有公开专家，像京东店铺页：头部是主体名称、认证标识、资质，下面是它的专家卡片。等有持证合作方入驻再做。

### 5.4 页头

三个应用一致：左边应用名，中间搜索（仅 knowmart），右边「当前用户：显示名」与「退出登录」（2026-10-17 已做的共用组件 `SignedInAs`）。

## 六、类目

照腾讯 WorkBuddy 开放平台的服务类目取名与分级，只收我们用得到的；类目代码写死在 knowmart，名称可改。

| 一级 | 二级（代码） | 公开所需资质（照腾讯） |
| --- | --- | --- |
| 金融 | 证券 / 期货投资咨询（`finance.securities_advisory`） | 《经营证券期货业务许可证》 |
| 金融 | 公募基金（`finance.public_fund`） | 证券期货业务许可证（含基金）等 |
| 金融 | 私募基金（`finance.private_fund`） | 私募基金备案证明；只能展示、介绍、咨询 |
| 工具 | 办公（`tools.office`）、信息查询（`tools.lookup`）、计算器（`tools.calculator`）等 | 个人主体也可公开（以后） |
| 商业服务 | 企业管理（`business.management`）等 | 照腾讯 |

- 每个专家只属于一个二级类目，knowlab 出专家时由运营按方法内容选；用户不能自己改。
- 投资、财报、预测类专家一律归「证券 / 期货投资咨询」。
- 首页左侧只显示一级与二级里当前用户看得到专家的那些。

## 七、接口

| 接口 | 谁调 | 做什么 |
| --- | --- | --- |
| `GET /api/web/v1/knowmart/experts?category=&q=&data=&updated=&sort=&page=` | knowmart 网页 | 当前用户看得到的专家列表（按第四节的规则在后端过滤，再按筛选条件筛、排序、分页），每项带类目、最新版本；回总数 |
| `GET /api/web/v1/knowmart/experts/{id}` | knowmart 网页 | 详情：五个页签的数据；看不到回 404 |
| `GET /api/web/v1/knowmart/categories` | knowmart 网页 | 类目树，带当前用户看得到的数量 |
| `POST …/versions/{version}/summon-return`、`…/stop` | knowmart 网页 | 现有，不变 |
| `POST /api/internal/v1/knowmart/deliveries` | knowlab 后端 | 现有，多带 `category`；`visibility` 先不收（一律自用） |
| `GET /api/internal/v1/knowmart/owners/{owner}/knowbots/{id}@{version}` | 工作台后端 | 现有。公开专家开放后改成「按请的人有没有这份权益」核，不再只认所有者（第三期） |

清单契约 `knowbot-manifest/v1` 只加可选字段（`category`），按 0027 的规矩 v1 冻结后只增可选字段。现有的「我的分身」接口保留一段时间，前台换成新接口后再撤。

## 八、和工作台、knowlab 怎么接

- **工作台**：「请哪一位」改成「最近请过的」加一个「去 knowmart 选专家」（决定记录）。跳转仍用现成的 `CrossAppLink`（业务参数加 `from=knowbench`、`ref`，回跳地址只在服务端登记，链接里不带身份）；选定后回到工作台主页并选中这位专家。
- **knowlab**：出专家时多选一个类目（管理端「建草稿」那一步）。用户的 web端不显示类目。
- **管理端（以后）**：knowlab 管理端「分身草稿」列表变长后，照 Vue 版的表格筛选做按状态筛、搜索、分页；打开过的页面做成页签（Vue 版的做法）也只用在管理端，用户看的 knowmart 前台不用。

## 九、现有数据怎么办

- 已交付的专家：可见范围一律记 `private`；类目先记「证券 / 期货投资咨询」（现有的都是财务类），由运营在 knowlab 管理端补选。
- 「我的分身」这个页名作废，换成目录首页；按决定记录，不另设「我的专家」区。
