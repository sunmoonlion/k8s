# 设备身份、连接、安装与升级

> 由产品合同搬入（合同「去向」表登记）。本模块要满足什么见 [requirement.md](requirement.md)。

- **连接**：runtime 主动向后端建立 WSS，用户电脑不开放入站端口；后端维护设备在线状态，经已有连接派发；断线自动重连，重连后先对账（§8.3）；
- **常驻**：runtime 注册为用户级后台服务（Windows 用户态后台程序、macOS LaunchAgent），登录系统后启动并连接；关闭窗口后是否继续接收派发由用户设置；
- **首次安装**：官网下载桌面应用（内含 runtime 与 Codex）→ 用户确认安装（Windows 上同时批准一次管理员授权，用于 Codex elevated 沙箱）→ 注册后台服务 → 登录并配对 → 连接。安装包必须签名；
- **配对**：用户在应用里登录后，应用用桌面端 token 向后端申请一次性配对记录（含一次性 secret、5 分钟有效期、所属用户），经 ③ 交给 runtime；runtime 用设备私钥签名提交；后端校验正确、未过期、未使用、归属一致后绑定设备公钥，并立即作废 secret。不得把浏览器 cookie、密码或长期 token 写进 runtime 或安装包参数；
- **设备密钥**：runtime 首次启动生成密钥对，私钥只留本机（系统钥匙串）；建立 WSS 时用私钥证明身份；设备可在桌面应用里吊销，设备丢失时由客服在管理后台吊销；
- **多设备**：router 只选在线且已授权相应工作区的设备；Task 与设备的绑定写入路由决定；提交时可以指定设备；
- **升级**：桌面应用与 runtime **同版本号、同包发布、一起升**。③ 建立连接时校验版本，
  **不匹配即失败关闭**并提示用户重启修复——③ 是本机内部协议，不做跨版本兼容层，兼容层只会养出漂移；
- **升级按排空进行**：runtime 先停止接受新派发、停止续约并向后端报下线；在途 Attempt 等它跑完（有上限），
  超时则按断线处理，走 §8.3 的重连对账，**不另造机制**；fencing 保证旧进程的迟到写入被拒绝。
