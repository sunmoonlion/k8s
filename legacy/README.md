# 暂存旧实现：达到退出条件后删除

此目录按所有者决定设立。当前部署实现仍在 `sunmoonai/`；统一操作入口见 [根目录说明](../README.md)。这里不形成第二套可部署代码。

- `local/`：旧 KIND 建群/重建/自制节点镜像及旧 WSL/外置 Harbor 说明。等新本地迁移、真实消费者、重建独立性验收及观察期结束后，复核依赖再删。
- `cloud/`：旧集群 reset、运行时重装、全量镜像/物料清理。**历史路径，云上新路径实机验证前不删**；新云流程未经实机验证。清理类能力不得自动恢复，R3 节点镜像清理已取消。
- [manifest.json](manifest.json)记录原路径、原字节摘要、原提交、替代入口和退出条件。归档脚本加了最前置拒绝执行，原入口也是拒绝执行提示；即使手工 `bash` 或 `source` 也不会进入旧逻辑。
- 归档不是可直接运行的恢复包。需要历史代码时从清单的原提交恢复到单独审阅区，核全部依赖和实际资源身份后再形成执行方案；不要删除拒绝执行行后直接运行。
- 原脚本依赖的配置、仍供现有消费者使用的帮助工具和历史物料，不因归档部分脚本就删除。尚在原处的依赖列在各组 README，后续逐调用方整理。

**运行时资源没有移动进 Git，也不能通过删除本目录来清理资源。** 旧 `kind` 三节点（特别是 `kind-worker2`）、验证集群节点、Docker 卷、`/data/kind-local-storage`、Harbor 镜像与数据库/密钥/备份均原地保留。它们按具体 ID/挂载/摘要登记，退出时另做清单核验。

本地退出与云端退出分别判定；云端验收通过不会自动允许删除本地回退节点或卷。不得执行 system/container/volume prune，也不因文件归档释放数据目录。

本次追加归档旧 KIND 推送、远端 loadimage 和交互菜单；活入口转发统一 OCI 发布器。
旧发布工具的自动清理和失败后节点加载回退不得恢复。工具闭包及真实新发布链仍待验收，详见 [发布说明](../sunmoonai/registry-platform/docs/publication.md)。
