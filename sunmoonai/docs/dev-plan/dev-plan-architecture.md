## 0. 总览

### 0.1 归属判据（先给判据，再放结果）

每一节的落点由以下判据决定：

| 判据 | 说明 |
| --- | --- |
| **A** | 这节约束“要建成什么、用户可见行为是什么” → **REQ** |
| **B** | 这节描述“系统内部怎么组织、谁负责什么、接口怎么分” → **TLD** |
| **C** | 这节记录“已经做出的不可逆决策及原因” → **ADR** |
| **D** | 这节规定“多个 AI/人怎么协作、评审、裁决” → **PROTOCOL** |
| **E** | 这节回答“按什么顺序建哪些任务、里程碑是什么” → **IMPL** |
| **F** | 这节告诉执行者“接到任务后怎么操作、注意什么” → **HANDBOOK** |
| **G** | 这节规定“任何阶段都不能违反的长期纪律” → **RUN** |
| **H** | 这节投影“当前阻塞、下一步、已完成项” → **STATUS** |
| **I** | 这节只是目录入口或导航 → **INDEX** |

### 0.2 目标文档集合

| 文档类型 | 目标文件（相对 `sunmoonai/docs/dev-plan/`） | 来源 |
| --- | --- | --- |
| REQ | `working/request-lifecycle.md` | 原文件保留，内部标出 TLD 渗透节 |
| TLD | `working/technical-design.md`（新建）+ `development-plan.md` 架构部分 | 从 `agent-dev-guide.md` §2 和 `development-plan.md` 拆分 |
| IMPL | `development-plan.md`（路线图）+ `implementation-plan.md`（任务清单） | 两者保留但职责厘清 |
| HANDBOOK | `agent-dev-guide.md` | 保留为 AI 执行者操作入口 |
| PROTOCOL | `protocol/round-protocol.md` + `protocol/README.md` | 保留 |
| RUN | `constraints.md` | 保留 |
| STATUS | `handoff.md` | 保留 |
| INDEX | `README.md` | 保留 |
| ADR | `rounds/<轮次>/rulings.md` + `rounds/` 归档 | 保留，不内部重排 |

### 0.3 三句原则

1. **零丢弃**：260 节每一节都有落点；无“故意不要”。
2. **锚点优先**：带外部锚点的 `request-lifecycle.md` 不物理拆分，先标归属、后做锚点转发。
3. **同类聚合**：同一段落反复出现的主题（执行操作、协作规则、运行纪律）不再散在多个文件。

## 10. 拆并代价与锚点保全

### 10.1 `request-lifecycle.md` 不拆分，先标归属

**理由**：
- 该文件是内核，被 40 份文档引用、含 71 个带行号的外部锚点（B2）。
- 本轮任务书 §1.4 明确“不改任何结论，只改组织方式”。
- 物理拆分会导致大量外部链接断裂，修复成本超过本轮收益。

**处置**：
- 整体保留在 REQ；
- 在 `dev-plan-architecture.md` 中标注哪些节含 TLD 成分；
- 新建 `technical-design.md` 时，对渗透节建立引用而不是复制；
- 未来若真要拆分，采用“锚点转发文件”：原路径保留一个只含稳定 ID 锚点和跳转说明的文件，新内容在新路径展开。

### 10.2 `agent-dev-guide.md` 拆分 §2 到 TLD

**代价**：
- 读者路径变化：原先“开发指导”里读运行时结构，以后要跳 `technical-design.md`；
- 12 节内容需要在新文件中重建上下文；
- `agent-dev-guide.md` 内部对 §2 的引用需要改为跨文档引用。

**收益**：
- TLD 与 HANDBOOK 的读者不再互相污染；
- `agent-dev-guide.md` 真正变成“操作手册”，长度从 108 节降至约 90 节；
- 运行时结构的变更只需改一份 TLD，不会误动操作步骤。

### 10.3 `development-plan.md` 拆分 §2 到 TLD

**代价**：
- 需要把“智能体分两部分 / 四本账 / 执行层租用”三节迁入 `technical-design.md`；
- 读者习惯变化：以前一份“开发计划”读完路线和架构，以后要读两份。

**收益**：
- 路线图（IMPL）和架构取向（TLD）不再混写；
- `implementation-plan.md` 可明确只保留任务清单，与 `development-plan.md` 的路线图形成清晰层级。

### 10.4 `rounds/` 作为 ADR 归档，不内部重排

按 B4 / F4，已归档轮次不内部重排。`rounds/<轮次>/rulings.md` 就是该轮次的 ADR。未来若 ADR 编号撞车（Q9），通过给 rulings 加轮次前缀解决，例如 `dev-plan-refact/R1`。
