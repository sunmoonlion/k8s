# 通用规则

交给 agent 的每一件事都是一个**任务**。本文写所有 agent 开发任务及其交付共同遵守的基本理念与纪律，以及任务怎样随交付长出来、交付怎样验收、怎样记录、怎样返工。
每个 turn 的 `user-message.md` 按 [PRD 规则](prd/prd-rules.md) 写（模板见 [附录](prd/prd-template.md)），交付物按 [`deliverables/`](deliverables/) 的规范验收。其余规范见 [README](README.md)。

## 基本理念

**任务就是从入口进来、可能经过后端派发给模型的那段文本。**它可能只是一段自然语言，也可能是按规范严格写成的文本。
这里的规范必须对**没有任何格式**的一段话成立；严格写成的任务自然也满足。所以规范只规定「要表达出什么」，不规定「要用什么格式」，
也不假设有什么机制会替模型补上任务里没写的东西。

由此有一条贯穿全部规范的做法：**任务没说清、而会实质改变结果、权限、成本或风险的，停下来问，不自行假设；
无关紧要的，按最小、可逆的理解去做，并在交付里写明做了哪些假设。**下文凡说「按任务」「派工时的要求」，
指的都是派工时那段任务文本里说清了的内容。

## 总则

1. **每种交付都有三样东西**：交付物、验收条件（门）、没过门时退回哪一种任务。写完文字不等于过门。
2. **派哪几种任务、各交多深，由开发需要定。**小而可逆的改动可以由一次任务交齐所需内容，引用已有依据即算过门；
   但不能为了省文档，在没有依据时把某项填成「不适用」。
3. **开工条件与完成条件是两回事。**「候选验证通过」「指定版本发布成功」「需求满足」是三个不同的结论，
   状态记录必须说清是哪一个，不能都写「已完成」。
4. **门的执行归属分三档，不混进同一张「已保证」清单**：机器已能判；当前靠纪律、将来可机器化；
   本质上只能靠纪律（一直标 ⚠）。凡声称由机器判的，必须能写出一条跑出非平凡结果的命令。
5. **规则要有载体。**能跟着测试或提交自动跑的，做成自动检查；做不成的，老实标 ⚠ 并靠自检。
   要人记得去跑的检查，和写在文档里的规矩没有本质区别；检查的结论不能取决于某台机器的工作区状态。

## 执行者的共同纪律

不论单路还是并行，不论人还是 AI，八条都成立：

1. **不用计划覆盖原始需求**；
2. 只在范围、工具、数据、预算和副作用边界内行动；任务没说清边界、而越界会有影响时，先问；
3. **区分事实、推断、假设、缺失和未运行验证的结论**，不可混写；
4. 对可中断的工作持久化检查点；
5. 无法满足完成条件时请求输入或**明确失败**，不交半成品；
6. 在**最终固定版本**上运行与风险相称的验证；
7. 报告盲区、副作用和残余风险；
8. 未经授权不推送、合并、发布、删除远端资产或扩大外部影响。

第 3 条是 [UAT](deliverables/uat/uat-rules.md) 证据采信的前提：分不清事实与推断，采信分级就无从谈起。
