# 任务（task）

交给 agent 的每一个任务由 [PRD](prd/README.md) 描述；执行过程中还要有一份**持久记录**，
让任何人只凭它就能接着做。

## 任务持久记录模板

载体可以是数据库、Issue、PR、事件流或仓库文件，但**不能丢失原始请求、边界、验收、基线、
证据和改判历史**。**空栏必须写「不适用」及理由——空着与「忘了」无法区分。**

```markdown
# <任务编号>：<短名>

## ① 原始请求
<用户原话，不改写>

## ② 受理、边界和授权
- 规范化目标：            - 包含：                - 不包含：
- 不包含部分归属：        - 权限与批准点：
- 预算、期限和停止条件：  - 负责者 / 工作单元：
- 可写根与输出命名空间：
- 发布目标 / 整合者：

## ③ 基线与工作区
- 任务 / 尝试：           - 工作区：              - 来源引用：
- 基线提交：                                      - 适用指令：

## ④ 决策点
| ID | 问题 | 结论与理由 | 证据 |

## ⑤ 工作单元与落地去向
| 工作单元 | 负责者 | 分支/工作区/命名空间 | 产出提交/摘要 | 发布目标 | 状态 |

## ⑥ 验收标准与证据
| ID | 标准 | 判定 | 证据 |

## ⑦ 依赖、交互与副作用
- 依赖：                  - 澄清/批准：           - 副作用账：

## ⑧ 状态流转与改判
| 时间 | 状态/改判 | 触发 | 原判断错处 | 新判断 |

## ⑨ 交付与清理
- 最终提交 / 产物：                               - 来源 / 取代关系：
- 发布位置 / 发布者：                             - 未覆盖与残余风险：
- 交付通知：                                      - 工作区清理：
```

⑧ 的改判字段对应 [总则「改判」](../README.md) 的三要素——「原判断错处」写「当时信息不全」不算填，要写出具体哪一步推错了。
