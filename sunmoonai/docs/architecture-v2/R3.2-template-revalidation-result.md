## 1. 结论

R4 Info 的 Web/Backend 配对门禁发现模板 Web E2E 中的部署标识断言仍使用旧值
`playwright-web-e2e`，而运行配置已使用 `arch-v2-r2-web-e2e`。该问题属于模板缺陷，不能在
Info 实例中静默修补。模板先完成修正、完整源码门禁、镜像重建和 R3 集群复验，随后才同步回
Info。

构建复验同时暴露 Admin/Web 的 `build-image.sh` 没有把 Dockerfile 已声明的可选代理参数传给
BuildKit。两个脚本现统一接受显式 `BUILD_HTTP_PROXY`、`BUILD_HTTPS_PROXY` 和
`BUILD_NO_PROXY`；代理只存在于构建阶段，运行镜像代理泄漏检查通过。

R3.2 已取代 R3.1，成为 R4 后续同步的唯一模板源。它仍是候选发布：
`formal_release=false`，不得覆盖 v1 `1.0.0`，也不得在 R7 前晋级正式 `2.0.0`。
