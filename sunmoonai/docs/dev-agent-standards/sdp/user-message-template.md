# SDP 用户消息模板

复制成 turn 里的 `user-message.md`。**栏目是从 [SDP 规则](sdp-rules.md) 里长出来的**：
规则要求执行者守住什么、门禁要核对什么，问里就把它们的输入写全——
执行段和讨论段不同，**要执行者遵守的必须写进用户消息**，模型只知道这里写了的东西。
写多严见 [任务的生命周期](../lifecycle.md)「用户消息写多严」，字段的含义见同一份的「turn 的固定字段」。

```markdown
---
executor: <派给谁；还没派出去写 unassigned>
verifies: 无
---
# turn <四位号>：<短名>

## 依据
<以哪一份 `SDD/` 定稿的哪几节为底；给出链接与提交>

## 要什么
<做完之后什么变了>

## 工作区
- worktree：<在哪里建>
- 分支：<分支名；与交回时 `turn.md` 的 worktree 字段一致>
- 基线：<从哪个提交起>
- 可写的范围：<哪些仓、哪些目录>
- 不得触碰：<明确写出>

## 工作单元
<拆成哪几个单元。每个写清类型与优先级、范围、前置、目标、实施、测试、完成条件、回滚；
 目标、实施、完成条件、回滚缺一项就不算可开工的单元>

## 完成条件
1. <可判定的条件，做完能一条条对着勾。这一段必须写：执行者不知道做到哪算完，就只能猜>

## 预算与上限
<步骤数、时长、并发、费用；耗尽就停，不静默借用>

## 需要人批准的动作
<推送、合并、发布、迁移、删除远端资产等逐项列出；没有写「无」>

## 不要做的
- **不改设计**：设计不对就停下来问，不在实现里顺手改掉——改设计要回 SDD 段开新 turn；
- **不扩范围**：可写的范围之外一个字都不动；
- **未经批准不推送、不合并、不发布、不删除远端资产**。

## 怎么做
按 `sunmoonai/docs/dev-agent-standards/sdp/sdp-rules.md`「执行者的共同纪律」「工作区与分支」「两道门禁」。

**交回：产物在 worktree 的分支上，这个 turn 里不放 `response.md`；交回时在 `turn.md` 记分支与提交。合并到 master 要经审核与人的批准。**
```

## 栏目对着规则的哪一条

| 栏目 | 为什么有它 |
| --- | --- |
| 工作区（worktree、分支、基线、可写范围、不得触碰） | 「两道门禁」里开工门禁与写入前门禁逐项核对的就是这些；问里不给，执行者只能猜仓库、分支与目录，修改会落错可写面 |
| 工作单元 | 「工作单元」一节的九栏；缺目标、实施、完成条件、回滚任一项就不算可开工 |
| 完成条件 | 共同纪律第五条「无法满足完成条件时明确失败，不交半成品」——没有完成条件，这条无从执行 |
| 预算与上限 | 「停止与成本」：有上限、超时、需批准的动作必须在用户消息里写明，没写执行者不会知道 |
| 需要人批准的动作 | 共同纪律第八条与「三条硬禁令」第三条：不得把人的批准降级为自动批准 |
| 不要做的 | 这三条直接面向动手的人，不是答案提纲——执行段要当面看到 |
| 怎么做 | 八条共同纪律、门禁清单、并发与事故规程在规则里，不在这一问里 |

不适用的栏写「不适用」及理由——空着与「忘了」无法区分。
