# SDP 任务书模板

复制成 turn 里的 `user-message.md`。

这一问写几块、写多严，见 [任务书规则](../task-brief-rules.md)「完整任务书写这几块」与「写多严，按任务轻重」；字段的含义见 [任务的生命周期](../lifecycle.md)「turn 的固定字段」。
执行时要守的纪律见 [SDP 规则](sdp-rules.md)「执行者的共同纪律」；工作单元怎么拆见「工作单元」；工作区与分支见「工作区与分支」。

```markdown
---
deliverable: SDP
agent: execution
executor: <具体执行者；未定写 unassigned>
base: <发出时依据的提交>
sent_at: <发出时间>
---
# turn <四位号>：<短名>

## 依据
<以哪一份 `SDD/` 定稿的哪几节为底；给出链接与提交>

## 要什么
<做完之后什么变了>

## 工作区
- worktree：<在哪里建>
- 分支：<分支名；与交回时 `turn.md` 的 worktree 字段一致>
- 可改的范围：<哪些仓、哪些目录、哪些文件>
- 不得触碰：<明确写出>

## 工作单元
<拆成哪几个单元，每个写清类型与优先级、范围、前置、目标、实施、测试、验收、回滚；见 SDP 规则「工作单元」>

## 验收标准
1. <可判定的条件，做完能一条条对着勾>

## 约束
<必须遵守的规则；代码规则的链接；预算、超时与并发上限>

## 需要人批准的动作
<推送、合并、发布、迁移、删除远端资产等逐项列出；没有写「无」>

## 怎么做
- 守 [SDP 规则](sdp-rules.md)「执行者的共同纪律」八条；
- 每次落笔前过写入前门禁：当前目录、当前分支、目标路径在可写根内、路径上没有他人产物、不是宽泛写入；
- 分不清事实与推断就标出来，不把未运行的验证写成结论；
- 无法满足完成条件时明确失败或回来问，不交半成品。

**交回：SDP。产物在 worktree 的分支上，这个 turn 里不放 `response.md`；交回时在 `turn.md` 记分支与提交。**
```

不适用的栏写「不适用」及理由——空着与「忘了」无法区分。命中 T2 判据的任务每一栏都要填。
