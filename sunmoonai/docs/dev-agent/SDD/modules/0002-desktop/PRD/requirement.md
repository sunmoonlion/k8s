# 0002-desktop：要满足什么

> 依据：[产品合同](../../../../../product/product-contract.md) 的「责任投影」中的「桌面应用」。

同目录另有两份，由合同搬入：

| 文件 | 内容 |
| --- | --- |
| [`windows.md`](windows.md) | 主进程与三扇独立窗口、各自的能力边界；本地触发与云端触发分开实现；界面文字 |
| [`security.md`](security.md) | 界面随应用打包、contextIsolation、preload 只暴露具体函数、代码签名；登录与会话 |

## 职责

做用户唯一的工作界面：提交 Task、看进度与结果、审阅研究底稿、处理工具级审批与 Task 级审查、配置模型与 key、管理本地知识库与设备；拉起并监管执行端。

## 输入与输出

| 方向 | 内容 |
| --- | --- |
| 从用户收 | 任务、审批与审查的结论、模型与 key 配置、工作区授权、本地资料 |
| 从后端收 | Task 状态、事件流、结果密文、待审查提醒 |
| 从执行端收 | 工具级审批请求、本地确认请求、runtime 状态、解密后的本地内容 |
| 给用户 | 进度、研究底稿（本机解密后渲染）、费用与用量、设备状态 |

## 验收

- 合同的 `F-INTAKE-*`、`F-REVIEW-*`，以及 `F-DELIVERY-*` 中归客户端的部分；
- 合同「桌面应用」一节的安全要求（界面随应用打包、本机能力分窗口授予、preload 只暴露具体函数）；
- 合同验收矩阵中涉及客户端的场景：`AT-16`、`AT-17`、`AT-24`、`AT-29`、`AT-30`、`AT-31`。

## 约束

- key 只在本地窗口输入，只交给执行端，不进任何协议字段（I16）；
- 结果只在本机解密查看，不做网页端（合同 `F-CRYPTO-*` 与「资料与知识服务」一节）；
- 界面用业务语言，不出现命令、diff、工作区这类开发概念（`F-APPROVE-05`）；
- 遵守 [代码规则](../../../constraints.md)。
