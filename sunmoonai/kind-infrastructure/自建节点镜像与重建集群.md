# 自建 Kind 节点镜像并使用它重建集群

本文说明如何构建一个**已预装 Harbor、Traefik 等镜像**的 Kind 节点镜像，并在重建集群时直接使用该镜像，从而**无需每次重建后再执行 load-kind-images**。

## 思路

- 默认 Kind 节点镜像是“空”的，部署 Harbor 等前需要把镜像加载进集群（`load-images/load-kind-images.sh`）。
- 若先创建集群、加载完所有镜像，再对节点容器做 `docker commit`，即可得到一张“带预装镜像”的节点镜像。
- 在 `kind-cluster.yaml` 中为每个节点指定该镜像后，新建集群时所有节点都会自带这些镜像，重建后不用再跑一次镜像加载。

## 前置条件

- 已安装 `kind`、`docker`，可正常创建 Kind 集群。
- 用于加载的镜像 tar 已准备好：
  - 若通过 **deploy-kind** 流程：在 `deploy-kind/images-init-dir/` 中放入 `.tar`，并在 `deploy-kind.conf` 中配置 `DEPLOY_KIND_TAR_DIRS`。
  - 若仅用 **load-images**：在 `load-images/tar-default-dir/` 中放入 `.tar`，并在 `load-images/load-kind-images.conf` 中配置 `DEFAULT_TAR_DIR`。
- 构建脚本会调用 `load-images/load-kind-images.sh`，其使用的 tar 目录以该脚本的配置为准。

## 步骤一：构建自定义节点镜像

在 **kind-infrastructure** 目录下执行：

```bash
./deploy-kind/build-kind-node-image/build-kind-node-image.sh
```

脚本会：

1. 若当前没有 Kind 集群，则先用当前 `kind-cluster.yaml` 创建集群（此时仍用默认节点镜像）。
2. 调用 `load-images/load-kind-images.sh`，将配置中的镜像/tar 全部加载到集群各节点。
3. 对 `kind-control-plane` 节点执行 `docker commit`，生成新镜像，名称形如：**`kindest/node:v1.27.3-sunmoonai`**（具体以当前 Kind 默认节点版本为准，后缀由环境变量 `CUSTOM_NODE_SUFFIX` 控制，默认 `sunmoonai`）。

执行结束后会打印生成的镜像名及后续操作提示。

**可选环境变量：**

- `KIND_CLUSTER_NAME`：集群名，默认 `kind`。
- `CUSTOM_NODE_SUFFIX`：自定义镜像 tag 后缀，默认 `sunmoonai`。

## 步骤二：确认 kind-cluster.yaml 使用该镜像

当前 `kind-cluster.yaml` 中已为每个节点配置了 `image: kindest/node:v1.27.3-sunmoonai`。若你构建出的镜像名不同（例如 Kind 升级后为 `kindest/node:v1.28.x-sunmoonai`），请把 **所有节点** 的 `image` 改为脚本输出的镜像名，保证与本地构建出的镜像一致。

## 步骤三：删除旧集群并用新配置重建

1. 删除当前集群（若需保留可先备份或跳过删除）：

   ```bash
   kind delete cluster --name kind
   ```

2. 使用新配置创建集群（会使用自定义节点镜像，节点内已带预装镜像）：

   ```bash
   kind create cluster --name kind --config kind-cluster.yaml
   ```

   或使用本目录提供的入口脚本（若存在）：

   ```bash
   ./kind-up.sh
   ```

之后按需执行 deploy-kind、apply-kind-registry-config、apply-kind-node-harbor-hosts 等即可，**无需再执行 load-kind-images.sh**。

## 可选：将镜像推送到 Harbor

若希望把上述镜像 tar 也推到自建 Harbor，便于其他环境拉取，可使用与 load-images 平级的 **push-to-harbor**：

```bash
docker login harbor.sunmoonai.com:30443
cd push-to-harbor
./push-images-to-harbor.sh
```

推送使用的 tar 目录在 `push-to-harbor/push-images-to-harbor.conf` 中配置（默认 `push-to-harbor/tar-default-dir/`），与 load-images 的 tar 目录独立。详见 `push-to-harbor/README.md`。

## 相关文件与目录

| 路径 | 说明 |
|------|------|
| `build-kind-node-image.sh` | 构建“带预装镜像”的节点镜像 |
| `kind-cluster.yaml` | 集群配置；各节点 `image` 指定自定义节点镜像 |
| `load-images/` | 加载镜像到 Kind 的脚本与配置（被 build 脚本调用） |
| `push-to-harbor/` | 将 tar 中的镜像推送到 Harbor |
| `deploy-kind/` | 一键部署 Kind（含镜像预加载、Harbor 等）；可配置 `DEPLOY_KIND_TAR_DIRS` 指向 tar 目录 |

## 小结

1. 准备好镜像 tar，并让 **load-kind-images** 的配置指向对应目录。  
2. 执行 **`./deploy-kind/build-kind-node-image/build-kind-node-image.sh`**，得到自定义节点镜像。  
3. 确认 **kind-cluster.yaml** 中所有节点的 `image` 与该镜像名一致。  
4. **删除旧集群** 后使用 **kind create cluster --config kind-cluster.yaml**（或 `kind-up.sh`）重建，新集群即使用自建镜像，无需再跑 load-kind-images。
