# SunMoonAI K8s 项目整体架构

> 本文档描述稳定的架构结构与约束。  
> 可变的环境事实（IP、端口、凭据）见：`docs-cursor/环境事实表.md`

---

## 一、项目概述

**SunMoonAI** 是一个投资管理分析平台，基于 Kubernetes 部署，包含门户、孵化器、LLMOps 等多个子应用。

项目支持两种运行模式：

| 模式 | 说明 | 适用场景 |
|------|------|---------|
| **Local（Kind）** | Kind 集群运行在 WSL 内 | 本地开发调试 |
| **Remote（真实集群）** | 多节点真实 K8s 集群，支持 C1/C2 两套 | 生产/测试环境 |

两种模式的**基础设施部署方式完全不同**，但上层平台和应用的配置结构一致。

## 三、Local 模式（Kind）

### 3.1 特点

- Kind（Kubernetes in Docker）运行在 WSL 内
- 使用自定义节点镜像 `kindest/node:v1.27.3-sunmoonai`（预装 Harbor/Traefik）
- 存储：WSL 内本地 NFS（`/data/kind-nfs`）

### 3.2 集群拓扑

```
1 control-plane + 2 workers
```

### 3.3 端口访问方式

Kind 通过 `extraPortMappings` 将容器端口直接映射到 WSL 宿主机，**不需要 iptables 转发**：

```yaml
# kind-cluster.yaml 端口映射
containerPort: 30080  → hostPort: 80      # HTTP
containerPort: 30443  → hostPort: 443     # HTTPS
containerPort: 30444  → hostPort: 30444   # PostgreSQL
containerPort: 30445  → hostPort: 30445   # MongoDB
containerPort: 30446  → hostPort: 30446   # Redis
```

### 3.4 DNS（Local 模式）

WSL 的 `/etc/hosts` 指向 `127.0.0.1`：

```
127.0.0.1  harbor.sunmoonai.com
127.0.0.1  www.sunmoonai.com
```

### 3.5 一键部署流程

```
deploy-kind.sh
  1. 确保 WSL NFS 已启动
  2. 构建自定义 Kind 节点镜像（如未构建）
  3. 创建 Kind 集群
  4. 配置 containerd registry（指向 Harbor）
  5. 配置 hosts 和 TLS 信任
  6. 部署 Traefik + Harbor
```

## 四、Remote 模式

### 4.1 两套集群

项目维护两套真实集群 C1 和 C2，具体节点 IP 见 `docs-cursor/环境事实表.md`。

| | 集群 C1 | 集群 C2 |
|-|--------|--------|
| 节点数 | 1 control-plane + 2 workers | 1 control-plane + 2 workers |
| SSH 端口 | 1022 | 1022 |
| **Traefik** | ✅ 独立部署 | ✅ 独立部署 |
| **Harbor** | ✅ 部署在此 | ❌ 共用 C1 的 Harbor |

**Traefik 单副本约束**：C1 的 Traefik Pod 固定运行在 Worker1，DNS 必须指向该节点；C2 同理。跨节点转发在当前网络配置下会失败。

> 待改进：将 Traefik 改为 DaemonSet，每个节点都有 Pod，则 DNS 可以指向任意节点。

### 4.2 13 步基础设施安装

```
step00  重置节点
step01  OS 基线配置
step02  容器运行时（containerd）+ registry 镜像代理配置
step03  K8s 二进制（kubelet/kubeadm/kubectl）
step04  集群初始化（kubeadm init，control-plane）
step05  CNI 网络插件（Calico）
step06  Worker 节点加入集群
step07  创建命名空间
step08  集群验证
step09  云存储接入（NFS，火山引擎 VFS / 阿里云 NAS）
step10  节点管理
step11  预加载镜像（离线模式）
step12  CA 证书生成
step13  Traefik + Harbor 初始部署
```

### 4.3 kubectl 连接方式

Remote 模式通过 **SSH 隧道**访问集群 API，不是直接连接：

```bash
# SSH 隧道：本地 6443 → 远端 master 内网 192.168.2.50:6443
ssh -f -N -L 6443:192.168.2.50:6443 -i ~/.ssh/id_rsa zym@<master-public-ip> -p 1022
export KUBECONFIG=~/.kube/cluster-admin.conf
```

统一连接管理：
- 配置文件：`k8s/utils/k8s-admin.conf`
- 连接脚本：`k8s/utils/unified-deployment-template.sh`（各部署脚本 source 此文件）

### 4.4 端口访问方式（Remote 模式）

Traefik 以 NodePort 部署，需要在**每个节点**上配置 iptables 转发：

```bash
# 每个节点都要执行（Traefik 部署脚本会自动配置）
iptables -t nat -A PREROUTING -p tcp --dport 80  -j REDIRECT --to-port 30080
iptables -t nat -A PREROUTING -p tcp --dport 443 -j REDIRECT --to-port 30443
```

### 4.5 存储

- StorageClass：`nfs-2`（NFS 动态供应）
- 云厂商：火山引擎 VFS（默认）/ 阿里云 NAS

## 六、流量入口层（Traefik v3.5.2）

### 6.1 NodePort 端口映射

> Remote 模式通过 iptables 将标准端口转发到 NodePort；Local 模式由 Kind extraPortMappings 直接映射，无需 iptables。

| 服务 | NodePort | Remote iptables 转发 | Local Kind 映射 | 说明 |
|------|----------|---------------------|----------------|------|
| HTTP | 30080 | 80 → 30080 | hostPort: 80 | Web 入口 |
| HTTPS | 30443 | 443 → 30443 | hostPort: 443 | Web 入口（TLS） |
| PostgreSQL | **30444** | — | hostPort: 30444 | TCP 直通代理 |
| MongoDB | **30445** | — | hostPort: 30445 | TCP 直通代理 |
| Redis | **30446** | — | hostPort: 30446 | TCP 直通代理 |
| RabbitMQ | 无 | — | — | AMQP 不对外暴露 |

### 6.2 路由策略

- **Web 应用**：`Host + PathPrefix` 路由，统一域名下按路径区分
- **数据库/缓存**：TCP IngressRoute 透传到对应 ClusterIP Service
- **TLS**：统一在 Traefik 层终止，使用 TLSStore defaultCertificate

## 十一、认证架构（auth-app）

### 11.1 核心模式

`Authorization Code + PKCE`，BFF 托管会话，浏览器不持有 refresh token。

```
浏览器 → BFF(/auth/login) → auth-app 授权页 → 回调 BFF(/auth/callback)
                                                      ↓
                                             BFF 换取 token，写 HttpOnly Cookie
                                                      ↓
                              后续请求：BFF 凭 Cookie 恢复会话，自动刷新 token
```

### 11.2 调用分层

| 场景 | token 类型 | 获取方式 |
|------|-----------|---------|
| 用户请求 | access token（RS256） | BFF 会话中取 |
| 服务间调用 | machine token（client_credentials） | 单独申请，scope 最小化 |

业务服务验签：本地缓存 auth-app 的 JWKS 公钥，不每次回源 Auth。

### 11.3 各 app 接入规范

每个业务后端必须实现三个路由，逻辑委托给 auth-app：

```
GET  /auth/login      → 发起授权，重定向到 auth-app
GET  /auth/callback   → 换 token，建会话，写 Cookie
POST /auth/logout     → 撤销 token，清会话，清 Cookie
```

## 十二、源码与镜像管理

### 12.1 源码仓库与 k8s 仓库分离

源码和 K8s 部署配置**完全分开管理**：

```
源码仓库（独立 git repo，k8s 仓库之外）
  <app>-backend/             后端源码（NestJS / FastAPI / Flask 等）
  <app>-frontend/            前端源码（Nuxt 3 等）
        ↓  mybuild/build.conf 定义镜像名和 tag
        ↓  构建脚本 build → push
  harbor.sunmoonai.com:30443/k8s-images/<app-name>:<tag>
        ↓  k8s 仓库 generate-app.conf 引用 tag
  k8s 仓库（本仓库）
  sunmoonai/<app>/<component>/resources/k8s-resource/
        ↓  generate.sh → Deployment YAML（镜像引用 Harbor）
        ↓  deploy.sh → kubectl apply
  K8s 集群运行中的 Pod
```

### 12.2 应用组件目录结构（标准模式）

每个应用组件的目录结构（以通用 `<app>` 表示）：

```
<app-name>/
├── deploy-<app-name>/              # 部署控制层
│   ├── app/deploy-app/
│   │   ├── deploy-<app>.conf       # 开关、优先级（不含凭据）
│   │   └── deploy-<app>.sh         # 主编排脚本
│   ├── secret/<app>-secret/        # 凭据部署
│   ├── configMap/<app>-config/     # 配置部署
│   ├── namespace/                  # 命名空间
│   ├── ingress/                    # Traefik IngressRoute
│   ├── middleware/                 # Traefik Middleware（可选）
│   └── pvc/                        # 持久化存储（可选）
└── resources/
    └── k8s-resource/               # YAML 生成层（主力）
        ├── templates/              # 母版 YAML（不直接修改）
        │   ├── app/<app>.yaml      → Deployment + Service
        │   ├── configMap/          → ConfigMap
        │   ├── secret/             → Secret（敏感值）+ harbor-registry-secret
        │   ├── ingress/            → Traefik IngressRoute
        │   ├── namespace/
        │   └── pvc/
        └── custom-values/          # 按资源类型的生成器（在此填值）
            ├── app/generate-app/
            │   ├── generate-app.conf   ← 填镜像 tag、PVC 名等
            │   └── generate-app.sh     → envsubst → *-generated.yaml
            ├── secret/.../generate-*.conf  ← 填 JWT_SECRET、DATABASE_URL 等
            ├── configMap/.../generate-*.conf  ← 填 PORT、REDIS_HOST 等
            └── ingress/.../generate-*.conf    ← 填 NODE_IP、UNIFIED_HOST 等
```

> `*-generated.yaml` 被 `.gitignore` 排除，不进版本控制。

### 12.3 部署子组件优先级

```
namespace_priority=3000  → 最先（命名空间必须先存在）
secrets_priority=2000    → 其次（镜像拉取凭据 + 应用密钥）
configmap_priority=1900  → 再次（应用非敏感配置）
middleware_priority=1000 → Traefik 中间件
ingress_priority=100     → 最后（路由规则）
```

### 12.4 ConfigMap vs Secret 分工

| 放 ConfigMap | 放 Secret |
|-------------|-----------|
| PORT、NODE_ENV、REDIS_HOST | DATABASE_URL（含密码）|
| SESSION_COOKIE_NAME | JWT_SECRET、REDIS_PASSWORD |
| GRPC_PORT、CORS | SMTP_USER、SMTP_PASSWORD |
| 非敏感的域名、路径配置 | 所有凭据、Token、私钥 |

### 12.5 镜像命名规范

```
harbor.sunmoonai.com:30443/k8s-images/<app-name>:<tag>

示例：
  harbor.sunmoonai.com:30443/k8s-images/auth-app-bff:1.0.0
  harbor.sunmoonai.com:30443/k8s-images/auth-app-ssr:1.0.0
  harbor.sunmoonai.com:30443/k8s-images/toutiao-backend:1.0.0
```
