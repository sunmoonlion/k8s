# 需求：要满足什么

> 依据：[产品合同](../../product/product-contract.md)。本文只写**要什么**，怎么做见
> [设计层](../SDD/architecture/README.md)。

## 一、做的是什么产品

**提供 AI 研究能力与数据，类似金融数据终端，不做投资咨询。**用户用自己的资料、
在自己的电脑上、借助我们的数据与方法做研究；结论由用户下，不由系统下。

服务对象按**投资经理**的使用方式设计，能自己开通并配置模型 key 的个人投资者同样适用；
两类用户都不是开发者，都以**电脑桌面**为主要工作场所。

这个定位有四条硬约束，它们决定了整个架构的形状：

| 约束 | 架构后果 |
| --- | --- |
| 用户的资料与研究成果**不经过我们**——发给哪家模型由用户自选、自付 | 本地知识库；结果端到端加密，后端只存密文与元数据；界面须告知内容会发往用户选定的那家模型厂商 |
| 执行**在用户电脑上**，由用户发起和主导 | 需要一个常驻本地的执行端，不是云端跑 agent |
| 模型由用户**自选、开通、付费** | key 只在本机，我们不中转模型请求 |
| 我们只提供数据与方法，**不写判断规则** | 自有数据只装事实；方法库只写步骤与计算；输出要被检查拦截 |

定位约束的条文是 `F-POS-01` 至 `F-POS-05`（在合同里）。法律边界以法务结论为准（`D17`）。

## 二、整体要完成的功能

一句话：**用户在桌面应用里提出一个研究问题，系统把它变成一次可审计、可验收、
可恢复的执行，结果加密存放、只在用户电脑上可读。**

这条链路分九站，横跨三个模块：

| 站 | 在哪 | 要做到什么 |
| --- | --- | --- |
| 写 message | 桌面应用 | 写清问题、选或确认任务类别、选资料；**未经确认的类别预填不算数** |
| 提交 | 桌面 → 后端 | 幂等键唯一；同键同摘要返回原 `task_id` |
| 受理 | 后端 | 身份从认证上下文确定，**不信任客户端自报**；判不出类别交用户选 |
| 派发 | 后端 → 执行端 | 派发带签名、带租约；设备离线则等待，**不丢** |
| 执行 | 执行端 | 在独立工作区里跑；key 只在本机；本地资料不上传 |
| 中断 | 本地窗口 / 后端 | 工具级审批在本机闭环，Task 级审查经后端；**人不批就不动** |
| 封装 | 执行端 | 先本地内容检查，再加密；后端只拿到密文与元数据 |
| 验收 | 后端 | 确定性验收与回执核对；终态、结果、预算结算**一次原子提交** |
| 交付 | 后端 → 桌面 | 事件按 cursor 续传、重复幂等；密文在本机解密 |

九站的判据见 [请求生命周期](../SDD/architecture/lifecycle.md)；每一条功能义务 `F-*`
在承担它的那个模块的文档里（见下「三、切成三块」）。

**三件贯穿全程的事**：

- **四本账**——幂等、预算、副作用、证据——**必须落 PostgreSQL**，跨进程死亡仍正确；
- **状态与账只有一份**，在后端自己的库里，所有入口共用同一个转换函数；
- **人的批准点不能自动通过**：不设逾期默认，不预填同意，过期批准不能复活旧操作。

## 三、切成三块

按**运行位置、信任域、发布方式**切，不按功能切：

| 模块 | 跑在哪 | 信任域 |
| --- | --- | --- |
| [后端](../SDD/modules/0001-backend.md) | 服务器 | 持久化账的唯一权威写入面；看不到资料与正文 |
| [桌面应用](../SDD/modules/0002-desktop.md) | 用户电脑 | 碰不到 key；三扇窗口能力各不相同 |
| [本地 runtime](../SDD/modules/0003-runtime.md) | 用户电脑 | 三方里唯一同时碰得到 key 和结果正文的一方 |

第三块之所以必须与第二块分开，**只有一个理由**：它要同时碰 key 和正文，而桌面应用不能。

## 四、在什么基础上开发

**不是从零开始，但新增的那三块确实是从零开始。**现有源码的准确状况见
[项目总览](../../project-guide/overall-architecture.md)——那份只投影现有代码，
不按本文的目标态描述现状。

### 已经有的，要复用

| 已有 | 状态 | 怎么用 |
| --- | --- | --- |
| 五个协作仓与模板骨架（`tpl-app` 实例化出三个领域 App，`k8s` 管部署） | 在跑 | 后端继续按这套模板与发布门禁走，不另起一套 |
| `knowledge-app`：摄入与检索，两套跨仓契约的唯一提供方 | 在跑 | 在检索接口外封装 **MCP**，按设备 token 限流——这是第一期内容 |
| `info-app`：采集、抽取、去重、治理 | 在跑 | 自有数据的上游，不改 |
| **共享 Outbox/Inbox 原语**：命令与领域事务同提交、持久租约、死信/重放/对账 | **源码已接线** | 后端的可靠投递直接建在它上面，不重造 |
| `investment-app` 的 FastAPI 后端 | 在跑 | 改造成 supervisor 控制面 |
| 现有 Next.js 前端 | 在跑 | **保留但换职责**：官网、下载页、内部管理后台；**本轮不开发** |

### 已经有但不能直接用的

| 已有 | 为什么不能直接用 |
| --- | --- |
| Investment 的 **LangGraph Pilot** | 目标态是确定性控制面，**不在后端跑模型编排**；图框架的 checkpoint 与状态机会成为两个真源（`I13`） |
| `RunBudget` 四维限额 | 是**内存态**，随 graph state 传递，进程一死即失。载体要换成数据库，不是接线 |
| 旧的浏览器研究界面 | 研究工作改在桌面应用；网页端不做研究入口 |

### 完全新建的

- **桌面应用**（Electron + Vite + React Router）——一行都还没有；
- **本地 runtime**（TypeScript / Node）——一行都还没有；
- 后端的七块划分——现有后端要按它重构，不是新写一个。

### 还没接收的旧账

旧任务独立存在 [待接收清单](../../legacy-backlog/README.md) 的六组里，
**待架构落地后逐项接收**，不从 v4/v5 计划恢复工作。

## 五、范围

- **包含**：合同的全部 `F-*` 功能义务、`I1` 至 `I20` 不变量、`AT-*` 的验收；
- **不包含**：合同标为后置的能力（私有部署、企业网关、团队协作、统一分发、Linux 与信创）；
- **不包含**：附录 A 未定的决策事项——拍板后另建模块，不在本轮预留结构。

**分期不在这一层**：三期与人周以 [产品合同附录 C](../../product/product-contract.md) 为准。

## 六、约束

- [代码必须遵守的规则](../rules/constraints.md)——违反其中任一条的方案不进入讨论；
- 合同的不变量 `I1` 至 `I20`；
- 定位约束 `F-POS-01` 至 `F-POS-05`。

## 七、未决

以**合同附录 A** 为准，本文不另立清单。其中影响范围最大的两条：

- **`D17`** 定位的法律边界、备案与数据授权——它决定产品能不能这样卖；
- **`D10b`** 并行 Attempt 是冗余择快还是竞争择优——它决定编排的停止规则与验收的选取逻辑。
