# 0005-interrupt：中断与批准

**承担**：**停下来等人，等到了再往下走**——九站里的【中断】那一站，加上批准通过之后的执行。

- **Interaction 的创建与原子消费**：一次性令牌，在同一并发控制边界内消费，**只能消费一次**；
- 两层审批的后端侧：**Task 级**经这里落 Interaction；**工具级**只在本机闭环，后端只收摘要与结论存档；
- 审查投影：把等待具体化为可直接回答的输入或可明确批准的动作，向正确受众投影；
- **publisher**：不可逆副作用经 Task 级批准后执行。

**不承担**：

- 不替用户作工具级批准（`F-APPROVE-02`）；
- 不改状态，经 `0001-state`；`WAITING` 的原因码由状态机表达。

**边界要点**：**两条提交逻辑不得共用**——工具级的结论只能来自本地窗口或本地策略，
后端提供的内容不得借道本机通道批准本地操作。批准与执行分离：批准绑定这一版、这一项、有有效期，
**过期不等于拒绝，也不等于同意**。

**为什么不叫 interaction**：`Interaction` 在合同里是**核心对象**（「向用户或授权角色请求输入、批准，
以及对方的响应」）。这一块装着三样——Interaction、两层审批的后端侧、批准后执行副作用——
拿一个对象名去盖三件事，读的人会以为这里只是 Interaction 的增删改查。那个词留给对象本身。

**为什么 publisher 并在这里**：它的触发条件就是「Task 级批准通过」，和 Interaction 共享同一个
批准对象。拆开会让「问」和「照着做」跨两块，中间那道缝正是伪造批准最容易钻的地方。
