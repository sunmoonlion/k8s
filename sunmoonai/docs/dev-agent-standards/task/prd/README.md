# PRD：产品需求文档（Product Requirements Document）

PRD 就是**任务书**：交给 agent 的那一问。它是**人要完成的内容**——人写清楚要什么、做到什么算满足，agent 按它交付。

## 任务书写这四块

| 部分 | 写什么 |
| --- | --- |
| 要什么 | 这件事做完之后什么变了；为什么要做 |
| 范围 | 包含什么、不包含什么、不包含的归谁 |
| 验收标准 | 可判定的条件，逐条写；做完能一条条对着勾 |
| 约束 | 必须遵守的规则、不能动的东西、需要人批准的动作 |

## 谁写、怎么改

- **根任务的任务书由人写。**子任务的任务书来自父任务 SDD 里拆出的那一节，**随那份 SDD 一起经人批准后生效**，人在批准前可以修改。
- 派工之后再改任务书，就是出一个**新版本**：按 [总则「改判」](../../README.md) 写清触发、原判断错在哪、新判断；
  已交回的交付物按新版本重新验收，不能把旧版本下的「通过」沿用到新版本。
- 验收标准在派工前定下，**出题的人与答题的 agent 分开**；agent 不改任务书，发现任务书有问题时停下来问。

## 写任务书的人要做到

| 要求 | 做不到会怎样 |
| --- | --- |
| 写清**边界**：含什么、不含什么、不含的归谁 | 执行者会自行扩大范围，或漏掉本该做的 |
| 给**可判定的验收标准**，不给倾向性结论 | 产出向写任务书的人的结论收敛，等于白问 |

人这一侧的其余义务见 [人的批准点](../../approvals.md)「人这一侧的义务」。
