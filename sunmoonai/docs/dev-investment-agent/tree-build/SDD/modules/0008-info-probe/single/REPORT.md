# 探针报告：从年报 PDF 抽完整的三大报表

日期：2026-09-28。位置：远程机 `~/annual-report-probe/`。
**没有动任何仓库里的代码，没有访问任何网站。** 用的是 2026-09-27 采集时留存在本机的 600009 年报原件，只读。

## 结论

**在这一家公司、这九份年报上，这条路走得通。**

| 问题 | 结果 |
| --- | --- |
| 能不能定位到三张合并报表 | 9 份年报 27 张表，全部定位到 |
| 抽出的数自己平不平 | 勾稽检查 162 次，不平 0 次 |
| 和现有数据集一致吗 | 能比的 885 个数里 836 个相同；不同的 49 个全部有解释，没有一个是抽错 |
| 比现有数据集多什么 | 年报里带数字的行有 906 行，现有目录只覆盖其中 447 行 |
| 快不快 | 9 份年报抽三张表共 15 秒 |

只验证了一家公司。下面「没有验证的」一节列了不能从这次结果推出的事。

## 做法

```text
第一步  把每页的文字抽出来存盘                      约 3 分钟，只做一次
第二步  找到三张合并报表的起止页；按页面坐标抽每一行    15 秒
第三步  科目名称归一，对上目录；过勾稽；与数据集比对    1 秒
```

| 环节 | 做法 |
| --- | --- |
| 定位 | 找单独成行的「合并资产负债表」等标题，到「母公司资产负债表」等标题为止。取第一次出现的位置（后面附注里还会再出现） |
| 分列 | 数字是右对齐的，取每页上数字右边缘最集中的两处作为「本期」「上期」两列 |
| 认数字 | 只认带两位小数的金额。附注编号是不带小数的整数或中文数字，不会混进来 |
| 认科目 | 去掉序号、「其中：」「加：」「减：」、括号说明、附注编号；「所有者」与「股东」视为同一个词 |
| 折行 | 长科目名会折成两行，数字夹在中间。把上下两行只有文字的行拼起来再认 |
| 认不出 | 记下来，不猜 |

用的库是 pdfplumber 0.11.10，借用 info 后端现成的 Python 环境，没有新装任何东西。

分母是现有目录里的科目数（利润表不含扣非净利润，它不在报表里）。

**没对上的科目都不是漏抽**：共 48 处，其中 47 处是年报里那一行本来就是空的，数据集里也是空的
（例如这家公司没有长期借款、应付债券；2021 年起没有销售费用；租赁负债 2021 年才出现）。
剩下 1 处是 2017 年的「利息费用」：2017 年的报表格式里没有这一行，数据集里的那个数来自 2018 年年报的上期列。

### 二、勾稽

九条勾稽规则，对每份年报的本期列与上期列各查一遍，共 162 次，**全部平衡**，容差一元。

这一点是这条路最重要的依据：抽错任何一个合计数，勾稽都会不平。

### 三、与现有数据集比对

现有数据集的报表数来自东方财富。比对时，年报的「本期」列对当年，「上期」列对上一年。

| 年报的哪一列 | 能比的数 | 相同 | 不同 |
| --- | --- | --- | --- |
| 上期列 | 441 | 441 | 0 |
| 本期列 | 444 | 395 | 49 |

不同的 49 个：

| 数量 | 原因 |
| --- | --- |
| 48 | 2021 年。年报本期列是**原始披露**的数，数据集里 2021 年是**追溯调整后**的数。两边都对，口径不同。2022 年年报上期列的 50 个数与数据集完全相同，印证了这一点 |
| 1 | 2018 年营业总成本。见下 |

#### 2018 年营业总成本：一个值得记下的发现

| 来源 | 数 |
| --- | --- |
| 2018 年年报本期列 | 4,572,276,761.99 |
| 2019 年年报上期列 | 4,571,913,705.53 |
| 数据集（标为原始披露） | 4,571,913,705.53 |
| 两者之差 | 363,056.46，正好是 2018 年的资产减值损失 |

原因是报表格式在 2019 年改过：旧格式里资产减值损失算在营业总成本里，新格式单列。
2019 年年报列示上一年数字时，按新格式重新归类了。

这说明第三方数据在这一项上取的是**后一份年报重新归类后的数**，却和其他科目一起被标成了「原始披露」。
现在的口径是按整行标的，标不出这种单个科目的差别。

### 四、相邻两份年报互相印证

把上一年年报的本期列，和下一年年报的上期列放在一起比：

| 会计年度 | 不同的科目数 | 说明 |
| --- | --- | --- |
| 2017、2019、2020、2022、2023、2024 | 0 | 没有重述 |
| 2018 | 1 | 报表格式变化造成的重新归类 |
| 2021 | 48 | 同一控制下企业合并造成的追溯调整 |

也就是说，**只用年报自己，就能发现哪一年被重述过、重述了哪些科目**，不需要借助第三方数据。

## 遇到的问题与处理

| 问题 | 处理 |
| --- | --- |
| 同一张表跨两页时，两页的列位置不一样（2022 年利润表） | 每页单独判断列的位置 |
| 报表下方的说明文字里夹着金额（「被合并方实现的净利润为…元」），被当成了一列 | 只认右边缘落在两列位置上的数字 |
| 附注编号粘在科目名后面（「营业收入（六十一）」「货币资金五（一）」） | 认科目前去掉 |
| 长科目名折行，数字单独一行 | 把上下两行文字拼起来认 |
| 一行没对上目录时，错把下一行的标签拿来用，导致同一个科目对上两次 | 自己有标签的行不借用别人的标签；每个只有文字的行只能被用一次 |
| 前一页的表尾和后一张表的标题在同一页 | 从标题行之后才开始收 |

最后一条之前的五条都是跑的过程中发现并改掉的。它们说明这件事细节多，换一家公司大概率还会遇到新的。

## 对正式做的建议

1. **可以做，值得做**。勾稽全平、与第三方数据除口径外完全一致，说明年报原文可以成为主来源。
2. **先并行，不要直接替换**。两个来源逐项比对，统计一致率，用数据决定什么时候切换。
3. **口径要标到科目**，不只标到行。2018 年营业总成本的例子说明按行标不够。
4. **勾稽是硬门槛**。抽出的表不平就不发布，和现在的质量检查一致。
5. **扩大样本再定方案**。正式做之前，至少再拿十来家不同行业、不同交易所的公司试一遍，看这套办法要改多少。
6. **目录要扩**。年报里有的科目比现在目录多一倍。
