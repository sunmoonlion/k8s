# BRD 任务书模板

复制成 turn 里的 `user-message.md`。

本阶段的任务书要写清什么，见 [BRD 规则](brd-rules.md)「这一段的任务书」；写多严见 [任务的生命周期](../lifecycle.md)「任务书写多严」，字段的含义见同一份的「turn 的固定字段」。
这一段该问哪几件事，见 [BRD 规则](brd-rules.md)「这一段在问什么」；答要写成什么样，见同一份的「response 写什么」。

```markdown
---
deliverable: BRD
agent: discussion
executor: <具体执行者；未定写 unassigned>
base: <发出时依据的提交>
sent_at: <发出时间>
---
# turn <四位号>：<短名>

## 要讨论什么
<一句话说清这一问要弄清楚的是什么>

## 已知
<现在知道的事实、已有的决定、相关材料（给出链接）；分清事实、推断与假设>

## 要答什么
1. 要解决谁的什么问题：<用户是谁、现在怎么做、卡在哪>
2. 做成什么样算解决：<可判断的结果>
3. 边界：<这次做什么、不做什么、以后再说什么>
4. 约束：<资质、合规、平台、成本、时间上不能碰的>
5. 取舍：<有哪几条路、各自代价>
6. 未知：<现在答不了、需要去查或去试的>

## 范围
- 包含：
- 不包含：
- 不包含的归谁：

## 约束
<必须遵守的规则、不能动的东西；例如只交文本、不改代码>

## 怎么答
- 区分事实、推断、假设与未知，不把推断写成事实；
- 给取舍的理由与代价，不只给结论；
- 涉及外部规则时标明依据与出处，查不到写「未核实」；
- 不替人做决定：摆清选项与后果。

**交回：BRD，写成这个 turn 的 `response.md`，不改代码。**
```

不适用的栏写「不适用」及理由——空着与「忘了」无法区分。命中 T2 判据的任务每一栏都要填。
