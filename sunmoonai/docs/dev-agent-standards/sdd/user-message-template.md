# SDD 用户消息模板

复制成 turn 里的 `user-message.md`。**栏目是从 [SDD 规则](sdd-rules.md) 里长出来的**：
「设计必须满足」与「设计原则」要求设计守住什么，问里就把守它所需的前提摆出来；规则本身不抄进来。
写多严见 [任务的生命周期](../lifecycle.md)「用户消息写多严」，字段的含义见同一份的「turn 的固定字段」。

```markdown
---
executor: <派给谁；还没派出去写 unassigned>
verifies: 无
---
# turn <四位号>：<短名>

## 依据
<以哪一份 `PRD/` 定稿、或哪一份 `SDD/` 的哪几节为底；给出链接与提交>

## 设计到哪一层
<结构层（模块之间的关系与接口）还是模块内部。一问只做一层，别混>

## 必须跨运行成立的不变量
<跨进程死亡、断电、重放之后仍须正确的账：预算、幂等、副作用、证据。
 列出来，设计才知道哪些必须落到持久存储、不能放在执行进程本地>

## 已冻结、不许动的契约
<状态词、合法边、终态、接口签名、数据格式……逐项列出。
 要改必须提修订工作单元，不在配置、适配层或文档里偷加语义>

## 可以依赖的稳定接口
<已有的 SDK、端口、外部服务；能租用的不自建。
 没有列出来的依赖，设计里要写明为什么必须新引入>

## 要不要往下拆
<这一问是否要给出子模块的划分。要拆的话写清已知的边界；拆出的模块将成为 `SDD/modules/` 下的子任务>

## 范围
- 包含：
- 不包含：
- 不包含的归谁：

## 怎么答
按 `sunmoonai/docs/dev-agent-standards/sdd/sdd-rules.md`「`architecture/` 写什么」「`modules/<模块>/` 写什么」「设计必须满足」与「设计原则」。

**交回：写成这个 turn 的 `response.md`，不改代码。人读完定稿成 `SDD/`，`modules/` 下拆出的每个模块成为一个子任务。**
```

## 栏目对着规则的哪一条

| 栏目 | 为什么有它 |
| --- | --- |
| 依据 | 定稿要写明以哪个 turn 为底 |
| 设计到哪一层 | 规则说层次是相对的，总体还是详细由它在任务树里的位置决定——问里不定死，答会两层混写 |
| 必须跨运行成立的不变量 | 「设计必须满足」第一条：这类不变量**必须由持久存储承担**。问里不列，设计只能猜哪些算这一类 |
| 已冻结、不许动的契约 | 「改已冻结的契约」：先证明是契约缺口才能改。问里不划出冻结面，设计会顺手改掉它 |
| 可以依赖的稳定接口 | 「设计必须满足」第二、三条：依赖限定在稳定接口、能租用的不自建、领域概念不进通用端口的签名 |
| 要不要往下拆 | `modules/` 下就是子任务；拆不拆是这一问的取舍 |
| 范围三行 | 结构层要写清包含、不包含、不包含的归谁 |
| 怎么答 | P0–P5 与两节「写什么」在规则里，不在这一问里 |

这一段不写验收标准：合不合格看它能不能定稿成 `SDD/`。不适用的栏写「不适用」及理由。
