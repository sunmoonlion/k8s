# IMP：用户消息怎么写

IMP 这一类是**把东西做出来**。交回物怎么把关见 [IMP 把关](finalize.md)。

**规范不规定答。**要让答符合某种形式、走某条路、带某些东西，**就在这一问里提出来**——
规范里不替你规定，模型也不会自己知道。写进问里的才算数。

IMP 按定稿的 `SDD/` 把东西做出来：拆成工作单元，在自己的 worktree 里实现，交回分支与提交。
**本规则只讲单个执行者怎么做这件事。**

对每一段都成立的八条纪律见 [turn 的投影](../turn-project.md)「交给 agent 的活，八条都成立」。
多家各交一份候选再比较选定时，另按 [多方竞争协议](../competition.md)；
派工、取消、交付通知这些由驱动方管的事，不在本规则里。

## 这一类该问什么

**没有模板**，但比讨论段要说清的多——执行者是另一个进程，**它只知道用户消息里写了的东西**。
下面这些不说清就开不了工，也过不了下面的两道门禁：

| 问什么 | 说明 |
| --- | --- |
| 以什么为底 | 按 `SDD/` 的哪几节做；给链接与提交 |
| 要什么 | 做完之后什么变了 |
| **完成条件** | 做到哪算完。不写，八条纪律里的第五条「无法满足完成条件时明确失败」就无从执行 |
| **工作区** | 在哪里建 worktree、分支名、从哪个提交起（基线）、可写的范围、不得触碰什么 |
| **环境** | 要装什么依赖、跑哪条命令能冒烟通过；环境没验过就开工，失败会算到实现头上 |
| 工作单元 | 拆成哪几个、先后与依赖；谁做、谁验 |
| **预算与上限** | 步骤数、时长、费用——没写执行者不会知道 |
| **需要人批准的动作** | 推送、合并、发布、迁移、删除远端资产等逐项列出，没有写「无」 |

这一段不交 `response.md`。写多严见 [turn 的投影](../turn-project.md)「用户消息写多严」。

## 做到什么程度算够

**完成条件逐条满足、机械检查跑过、分支与提交交回**，这一类就问完了。缺一条只能报相应的中间状态，或按八条纪律的第五条明确失败。

**「需求满没满足」不由这一类判**——自己判就是替 UAT 干活，而且作者自检不能代替独立验收。
做的过程中发现设计不对，写进交回说明并回 SDD 开新 turn，不在实现里顺手改设计。

## 工作单元

把工作拆成能独立交付、验证、回滚的单元。下面这些是**人拆单元、审核交回物时**对照用的；平时几句话即可，
**目标、实施、完成条件、回滚缺了会影响结果的一项，就不算可开工的单元**：

| 栏 | 写什么 |
| --- | --- |
| 范围 | 涉及哪些仓或模块——跨仓必须列全，否则漏交 |
| 前置 | 依赖哪个单元做完、或哪条未决项定了才能开工 |
| 目标 | 一句话说清做完之后什么变了 |
| 实施 | 具体动什么。**不写「完善 X」这种没有终点的表述** |
| 测试 | 适用的测试层次（见下），**不能只写「补测试」** |
| 完成条件 | 可判定的条件，做完能一条条对着勾 |
| 回滚 | 出问题怎么退回去 |

测试层次：

```text
L1 Unit                    L5 Failure Injection
L2 Component Integration   L6 Evaluation/Quality
L3 Contract                L7 Deployment/Operations
L4 Cross-app E2E
```

写「测试」那栏时点名用哪几层，例如「L1 规则正反例；L2 身份与恢复；L5 受控故障」。

单元耗尽预算不得静默借用；连续做下去既关不掉阻断问题、也不新增可验证的进展时，停下来问。

## 在自己的 worktree 里做

- **一个独占 worktree、一条命名分支**；分支名与 `turn.md` 的 `worktree` 字段一致。
- 开工前确认：worktree 归属本任务、没有未提交改动、HEAD 等于基线；任一不满足就新建，**不暂存、不重置别人的修改**。
- 开工前确认 Git 真的能提交；提交不了就停下来说，不要把改动攒在工作区里当交付。
- **每次落笔前**：当前目录是本 worktree、当前分支是那条分支、目标路径解析软链和 `..` 之后仍在可写范围内、
  路径上没有别人的产物。**宽泛写入（批量生成、重定向、脚本扫写、先删后建）是覆盖事故的主因**，动手前先想清楚会写到哪些文件。
- **人的工作区里未提交的改动是人的**，不暂存、不重置、不覆盖。发现要改的地方已经被别人改了，停下来问，不自行合并。
- **以提交认主**：交付物是分支上的提交，不是磁盘上的最后一版。冲突不按时间新旧裁决。
- worktree 只隔离写入，不阻止读取：能读到的材料不等于有权使用。
- 同一分支不能被两个 worktree 同时检出；多仓任务逐仓固定提交，父仓不留指向未推送子仓提交的引用。

## 跨运行时 thread 续接

执行段常常跨好几个运行时 thread，交接靠落盘的东西，不是记忆。

- 判据只有一句：**把今天的记忆抹掉，另一个人只读持久载体能否接着做？不能，就是没落盘。**
- 检查点至少写下：做到哪个单元、当前提交与基线、已完成与剩余范围、决定与证据引用、命令与原始输出在哪、
  预算用了多少、卡在哪、下一步、哪些事实要重新核实。**检查点不保存凭据。**
- 恢复前重新确认：任务没进终态、授权仍有效、输入与依赖没漂移。

## 交回与证据

- 交回的是**分支与提交**，写进 `turn.md`；报路径不报提交不算交回。
- 机械检查先跑，剩下的交给 UAT；验收失败就开新的 turn 重做，**不改窄标准换取通过**。
- 留下能复核的证据：测试输出、关键命令与结果、迁移版本；**不得提交令牌、Cookie、密码或密钥**。
- 需要人批准的动作没批准就不做，**不把人的批准降级为自动批准**。
- worktree 可以清理，**提交不能跟着消失**：清理前分支或标签必须留下。

## 反模式

| 反模式 | 失败方式 |
| --- | --- |
| 执行者猜仓库、分支或目录 | 修改落错地方 |
| 把人的主检出当作干活的地方 | 覆盖人的未提交改动，被覆盖方无痕消失 |
| 交回报路径不报提交 | 路径会漂移、会被覆盖，验收对象丢失 |
| 只把进度留在对话里 | 换人或换一个运行时 thread 后现场无法恢复 |
| 删除分支或 worktree 前不留持久引用 | 提交与证据变成不可达 |
| 静默扩大范围 | 越权副作用无人批准 |
| 伪造完整结果掩盖缺口 | 验收被污染，下游按假结论继续 |
| 把所有资料塞进 worktree | 越权、泄密、上下文污染 |
