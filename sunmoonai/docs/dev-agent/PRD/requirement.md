# 需求：要满足什么

> **这一份是需求的真源**：要什么在这里，怎么做见 [设计层](../SDD/architecture/README.md)。
> 同目录另有 [核心价值与价值检验](value.md)、[资料与知识服务](knowledge.md)、[产品验收矩阵](acceptance.md)。
> 还没定与还没验的记在 [待定决策与未验证事项](../decisions.md)。

## 一、做的是什么产品

**提供 AI 研究能力与数据，类似金融数据终端，不做投资咨询。**用户用自己的资料、
在自己的电脑上、借助我们的数据与方法做研究；结论由用户下，不由系统下。

服务对象按**投资经理**的使用方式设计，能自己开通并配置模型 key 的个人投资者同样适用；
两类用户都不是开发者，都以**电脑桌面**为主要工作场所。

这个定位有六条硬约束，它们决定了整个架构的形状：

| 约束 | 落到哪 |
| --- | --- |
| 用户的资料与研究成果**不经过我们**——存在用户电脑上，发给哪家模型由用户自选、自付 | 本地知识库（[资料与知识服务](knowledge.md)）；结果端到端加密，后端只存密文与元数据（[不变量](../SDD/architecture/invariants.md)「问题侧明文，资料侧加密」）；界面须告知内容发往哪一家（`F-INTAKE-08`） |
| 执行**在用户电脑上**，由用户发起和主导 | 常驻本地的执行端，不是云端跑 agent（[`0003-runtime/PRD/codex.md`](../SDD/submodules/0003-runtime/PRD/codex.md)） |
| 模型由用户**自选、开通、付费** | key 只在本机，我们不中转模型请求（[`models-and-keys.md`](../SDD/submodules/0003-runtime/PRD/models-and-keys.md)） |
| 我们提供的是**数据**，不是观点 | 自有数据只装事实（[资料与知识服务](knowledge.md)） |
| 我们的编排与方法库只写**方法**，不写判断规则 | [`0003-orchestrator.md`](../SDD/submodules/0001-backend/SDD/modules/0003-orchestrator.md)、[`methods.md`](../SDD/architecture/methods.md) |
| 系统**不替用户下判断** | 输出检查（[`0007-delivery`](../SDD/submodules/0001-backend/SDD/modules/0007-delivery.md) 与 [runtime 的本地检查](../SDD/submodules/0003-runtime/PRD/functions.md)） |

定位约束的条文：

- **F-POS-01**：自有数据只包含事实与数据（结构化财务数据、产业链关系、另类数据、标签与指标），不包含评级、目标价、景气判断等观点；
- **F-POS-02**：研究流程与方法库只写研究步骤与计算方法，不写判断规则（如买卖标准、打分阈值）；用户自己的判断规则由用户编写，只对该用户可见；
- **F-POS-03**：研究产出是研究底稿：事实、数据、按用户给定假设的计算、方法应用的结果由 AI 给出；结论由用户填写，或明确标为用户的草稿；
- **F-POS-04**：对具体证券给出评级、目标价、走势预测、买卖建议或收益承诺的输出，必须由系统检查并打回或拦截，不能只靠提示词约束；拦截留痕；
- **F-POS-05**：必须留存定性依据：数据流图、「后端不保存哪些内容」清单、日志策略、方法库评审记录。

法律边界存在模糊地带，以法务结论为准（`D17`，见 [待定决策](../decisions.md)）。

**服务对象**：按**投资经理**的使用方式设计；能自己开通并配置模型 key 的个人投资者同样适用——
**不能自行配置 key 的用户不在服务范围内**。两类用户都不是开发者，都以**电脑桌面**为主要工作场所。
用户界面**只有桌面应用**：不做网页端，不做手机端。

**让用户能验证**：runtime 应该开源；二进制必须签名，应该可复现构建；必须公开 runtime 与
Codex 会连接的全部域名，以及 ① 与 ⑤ 的协议文档，证明**不存在把 key 与资料上传到我们这一侧的途径**
（⚠ 不是「不存在上传途径」——key 与被读取的内容会由本机直发用户自选的模型厂商，
见 [数据流与信任边界](../SDD/architecture/trust.md)）。
后端对仍能看到的内容（查询、元数据）以服务条款、隐私政策与数据处理协议约束。

## 二、整体要完成的功能

一句话：**用户在桌面应用里提出一个研究问题，系统把它变成一次可审计、可验收、
可恢复的执行，结果加密存放、只在用户电脑上可读。**

这条链路分九站，横跨三个模块：

| 站 | 在哪 | 要做到什么 |
| --- | --- | --- |
| 写 message | 桌面应用 | 写清问题、选或确认任务类别、选资料；**未经确认的类别预填不算数** |
| 提交 | 桌面 → 后端 | 幂等键唯一；同键同摘要返回原 `task_id` |
| 受理 | 后端 | 身份从认证上下文确定，**不信任客户端自报**；判不出类别交用户选 |
| 派发 | 后端 → 执行端 | 派发带签名、带租约；设备离线则等待，**不丢** |
| 执行 | 执行端 | 在独立工作区里跑；key 只在本机；本地资料不上传 |
| 中断 | 本地窗口 / 后端 | 工具级审批在本机闭环，Task 级审查经后端；**人不批就不动** |
| 封装 | 执行端 | 先本地内容检查，再加密；后端只拿到密文与元数据 |
| 验收 | 后端 | 确定性验收与回执核对；终态、结果、预算结算**一次原子提交** |
| 交付 | 后端 → 桌面 | 事件按 cursor 续传、重复幂等；密文在本机解密 |

九站的判据见 [请求生命周期](../SDD/architecture/lifecycle.md)；每一条功能义务 `F-*`
在承担它的那个模块的文档里（见下「三、切成三块」）。

**三件贯穿全程的事**：

- **四本账**——幂等、预算、副作用、证据——**必须落 PostgreSQL**，跨进程死亡仍正确；
- **状态与账只有一份**，在后端自己的库里，所有入口共用同一个转换函数；
- **人的批准点不能自动通过**：不设逾期默认，不预填同意，过期批准不能复活旧操作。

## 三、切成三块

按**运行位置、信任域、发布方式**切，不按功能切：

| 模块 | 跑在哪 | 信任域 |
| --- | --- | --- |
| [后端](../SDD/modules/0001-backend.md) | 服务器 | 持久化账的唯一权威写入面；看不到资料与正文 |
| [桌面应用](../SDD/modules/0002-desktop.md) | 用户电脑 | 碰不到 key；三扇窗口能力各不相同 |
| [本地 runtime](../SDD/modules/0003-runtime.md) | 用户电脑 | 三方里唯一同时碰得到 key 和结果正文的一方 |

第三块之所以必须与第二块分开，**只有一个理由**：它要同时碰 key 和正文，而桌面应用不能。

## 四、在什么基础上开发

**不是从零开始，但新增的那三块确实是从零开始。**现有源码的准确状况见
[项目总览](../../project-guide/overall-architecture.md)——那份只投影现有代码，
不按本文的目标态描述现状。

### 已经有的，要复用

| 已有 | 状态 | 怎么用 |
| --- | --- | --- |
| 五个协作仓与模板骨架（`tpl-app` 实例化出三个领域 App，`k8s` 管部署） | 在跑 | 后端继续按这套模板与发布门禁走，不另起一套 |
| `knowledge-app`：摄入与检索，两套跨仓契约的唯一提供方 | 在跑 | 在检索接口外封装 **MCP**，按设备 token 限流——这是第一期内容 |
| `info-app`：采集、抽取、去重、治理 | 在跑 | 自有数据的上游，不改 |
| **共享 Outbox/Inbox 原语**：命令与领域事务同提交、持久租约、死信/重放/对账 | **源码已接线** | 后端的可靠投递直接建在它上面，不重造 |
| `investment-app` 的 FastAPI 后端 | 在跑 | 改造成 supervisor 控制面 |
| 现有 Next.js 前端 | 在跑 | **保留但换职责**：官网、下载页、内部管理后台；**本轮不开发** |

### 已经有但不能直接用的

| 已有 | 为什么不能直接用 |
| --- | --- |
| Investment 的 **LangGraph Pilot** | 目标态是确定性控制面，**不在后端跑模型编排**；图框架的 checkpoint 与状态机会成为两个真源（`I13`） |
| `RunBudget` 四维限额 | 是**内存态**，随 graph state 传递，进程一死即失。载体要换成数据库，不是接线 |
| 旧的浏览器研究界面 | 研究工作改在桌面应用；网页端不做研究入口 |

### 完全新建的

- **桌面应用**（Electron + Vite + React Router）——一行都还没有；
- **本地 runtime**（TypeScript / Node）——一行都还没有；
- 后端的七块划分——现有后端要按它重构，不是新写一个。

### 旧账接收已经结束

旧 v5 的 N1～N6 不再形成第二份待办：交互、执行、Profile、子任务与验收目标已经进入
本文与各模块 PRD/SDD；知识生命周期归 Knowledge 现行职责；发布缺口归
项目指南“发布与门禁”；监控告警只保留独立任务 `N4-OPS-01`；没有触发条件的扩展项不建任务。
历史原文只按 [`v5-history.md`](../../project-guide/topics/v5-history.md) 取证，不恢复旧方案与编号。

## 五、范围

- **包含**：各模块 `functions.md` 的全部 `F-*` 功能义务、[不变量](../SDD/architecture/invariants.md) `I1` 至 `I20`、[验收矩阵](acceptance.md) 的 `AT-*`；
- 只做**下载即用**，不做私有部署；平台 **Windows 优先，macOS 其次**；
- **后置**：私有部署、企业模型网关、团队协作与共享（先按个人使用）、统一分发、Linux 与信创平台。涉及后置能力的条款在该能力启用时才适用；
- **不包含**：[待定决策](../decisions.md) 里还没拍板的事项——拍板后另建模块，不在本轮预留结构。

**分期不在这一层**：三期与人周见 [分期与工作量](../../project-guide/staging.md)。
