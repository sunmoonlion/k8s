# `protocol/` —— 流程规范和它的实现

规范和实现放在一起，因为改其中一样，另一样要跟着改。两边对不上时以规范为准。

| 文件 | 是什么 |
| --- | --- |
| `round-protocol.md` | 规范：一轮怎么走，谁能做什么 |
| `round-status.py` | 从 git 提交推出当前环节、本环节通知在哪、组织者是谁；`--verify` 判 ⑤ 里能机器判的部分 |
| `round-dispatch.py` | 打印投喂的话：`--paste [家名]`，不带家名则给当前环节还缺的每一家 |
| `round-review.py` | 开 / 关检视面：把各家产物挂成 `~/review/` 下的只读 worktree |
| `agents.toml` | 执行者登记（六家）和所有者的 git 身份；不含任何凭据 |

调用方式和退出码写在 `round-protocol.md` 的「8b. 两个脚本怎么调」。改了脚本参数，必须同步改那一节。

目录名 `protocol/` 与 `../rounds/` 只差一个字母：`rounds/` 放每一轮的产物，这里放流程本身。

## 改代码前先读的三条

1. **结论只看 git 提交，不看工作区。**同一个仓库状态，在哪台机器上跑都得到同一个结论。
2. **判不了就明说判不了。**标「人判」的项一律不算通过；假装判过了才是缺陷。
3. **空集合不等于全部完成。**`all({})` 为真。要跳过某个环节，必须在 `round.md` 写 `skip_stages`。

另外，状态只算一次：`round-dispatch.py` 取状态一律调 `round-status.py --json`，不自己重算。

## 不做的事

- **不替人投喂。**命令行一次性投喂会用权限开关把审批提前答掉，所有者当场批不了；2026-09-10 判定不用。投喂由所有者逐窗口贴 `round-dispatch.py --paste` 打印的那段话。
- **不判 ⑥ 确认的内容。**只判确认有没有落盘；确认得对不对是人的事。
- **不管文档门禁。**那是 `../doc-gate.py`（挂在 pre-commit）和 `../anchor-gate.py`（手工跑）。
