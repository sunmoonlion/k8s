# 核心价值与价值检验

> 卖点是什么、凭什么说它成立。定位与范围见 [需求](requirement.md)。

## 三元组，不是方法

| 类别 | 内容 | 由谁提供 | 能不能抄走 |
| --- | --- | --- | --- |
| 专业知识 | 自有数据、口径表、引用回源、领域工具 | 知识服务 | 有授权与积累壁垒 |
| 方法 | 按领域拆步、按标准验收打回、何时停下问人、哪些动作要批准 | 顾问 + 专家包 | **文本抄得走** |
| 评测闭环 | 金标准、分段判定、回归、真实委托沉淀的返工与打回 | 评测 | 抄不走：对手能抄 workflow，抄不到纠错记录 |

**方法是易损件**：模型每升一代，补模型短板的步骤就贬值。重写有护栏是它相对一份 skill 文件的真实优势；这个优势是工程性的，不是保密性的。
一个专家包至少要回答六问：解决什么、需要什么、不解决什么、何时算完成、何时应拒绝或交回、效果与成本如何。

## 价值检验

**去掉知识服务与顾问，用户用原版 Codex 能否得到同样的结果？答案为"能"的功能不作为卖点投入。**

检验用**三臂加基线**，不用两臂：

| 臂 | 条件 | 回答什么 |
| --- | --- | --- |
| 基线 | 分析师现在的做法，或其历史底稿 | 相对真实工作方式有没有价值 |
| A | 裸 Codex，同模型同配置 | 起点 |
| B | Codex + 我们的数据（MCP） | 数据贡献多少 |
| C | B + 顾问方法 | 方法有没有额外价值 |

规则：方法先写成文档，由**非作者**照文档驾驶；产出匿名盲评；付费意愿用真金测（预付、按价买这份），不口头问；顾问只能接触云端允许看到的输入；
目标是**存在性证明**（存在一类任务差距大到有人付钱），不是平均效应；5 到 10 题只够证伪。
**成功标准：C 在费用可接受的前提下稳定优于 B，才把第二层做成软件。**

评测三列：质量、引用、**费用**。更贵但只好一点点的方法判负，这是发布门不是仪表盘。

## 卖点与入口分开

| | 判什么 | 指标 |
| --- | --- | --- |
| 卖点 | 比原版 Codex 强多少 | 准确率、验收通过率、返工次数、引用完整度、耗时、费用 |
| 入口 | 用户自驾时能不能把人引到求助 | 本机质量信号的触发率、求助转化率、求助后底稿的验收通过率 |

入口指标不得给卖点背书。旧的"领域识别引流"退役；接任的是**质量信号**：引用数为零、与用户资料矛盾、数据时点过期、勾稽不平、结论在我们数据里没有对应查询。
它在云端按确定性规则算（云端看得到会话），不调模型；既制造"不满意"，又是验收规则的雏形。

## 评测集是一等公民

- 真值定在**查询层**（第 24 课格式：`truth_queries`、`result_fingerprint`、`tolerance`），不定在文字答案层；口径表随数据版本化；
- 金标准优先取公开现成的监管材料：问询函、更正公告、立案调查；
- 三道门分开：数据质量评测、方法包发布评测、单次结果验收；任一门 `undecidable` 即关闭发布，不折成通过；
- 真实委托的返工、终审改动、验收打回持续沉淀为样本；同时另留未见过的任务防止只优化题库；
- **要有负责人、预算行、时间表**（`D6`）。

## 定位约束

- **F-POS-01**：自有数据只包含事实与数据，不包含评级、目标价、景气判断等观点；
- **F-POS-02**：方法只写研究步骤与计算方法，不写判断规则；用户自己的判断规则由用户编写，只对该用户可见；
- **F-POS-03**：产出是研究底稿；结论由用户填写，或明确标为用户草稿；
- **F-POS-04**：对具体证券给出评级、目标价、走势预测、买卖建议或收益承诺的输出，必须由系统检查并打回或拦截，不能只靠提示词；拦截留痕。检查在云端做（隐私不作约束后不必在本机）；
- **F-POS-05**：留存定性依据：数据流图、日志策略、方法评审记录。

真人专家只做**写包的人**，产品里永远不出现"真人在线答这一问"。法律边界以法务结论为准（`D1`）。

## 第一个切口

**A 股非金融公司的年报与半年报：附注关键表提取，与已入库三大表勾稽，输出差异清单加原文引用，结论栏留空。**
理由：产出是带证据的差异清单，`F-POS` 天然不触发；金标准公开现成；全年有量；正是单发提示最弱、编排最强的地方。
财报季覆盖留作后面的营销楔子；全市场监控是知识服务的数据产品。初期异常只呈现为"待核实的差异"。
