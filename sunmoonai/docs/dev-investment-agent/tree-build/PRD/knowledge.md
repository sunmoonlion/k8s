# 数据与资料

> 知识服务要装什么、给谁、怎么给。模块本身见 [`0006-knowledge`](../SDD/modules/0006-knowledge.md)。

## 两类内容，一套检索

| 类 | 来源 | 进不进我们的库 |
| --- | --- | --- |
| **自有数据** | `info-app` 采集、治理、去重后分发；结构化财务数据、产业链关系、另类数据、标签与指标；口径表随数据版本化 | 是，`knowledge-app` 建库 |
| **用户的资料** | 用户在网页上传或勾选工作区目录（研报、纪要、表格） | 是。隐私不作约束，资料进库是为了顾问看得到、检索得到、跨设备与团队共享 |

第一期用户资料只做**显式上传与勾选**，不做整机镜像；量与同步另议（`D7`）。

## 怎么给 Codex

- 经 **MCP**：检索、领域工具、口径与计算。核心计算留在服务端工具内部，模型只见调用与结果；
- **按上下文下发**：每次只给最相关的片段，片段数与 token 有上限；每个片段带来源、时点、数据版本，进入证据账；
- **防批量抓取**：按用户与沙箱发 token，可吊销，限流并监控异常调用；只返回所需字段与片段；必要时加水印。

## 数据盘点先于定价

在写第一层的定价之前，先出一页：有什么、从哪来、使用权、历史跨度、版本修订与出处定位、和 Wind 差在哪（`D2`）。
数据再分发的法务边界与 `D1` 绑在一起。

## 最小实例的数据

问数用的零售经营库（第 23 课 `lesson23_business_analysis.sqlite`）作为一个**数据集**装进知识服务，经 MCP 提供 SQL 执行与口径表。它不是投研数据，换切口时换掉。
