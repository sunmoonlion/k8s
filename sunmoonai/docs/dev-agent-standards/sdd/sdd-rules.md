# SDD：软件设计说明（Software Design Description）

SDD 阶段回答「怎样满足需求」。问是 turn 里的用户消息，答是这个 turn 的 `response.md`；人读完定稿成 `SDD/`：

```text
SDD/
├── architecture/             模块之间的结构与关系、接口、共同约束与取舍（入口 README.md）
└── modules/<四位号>-<短名>/  子任务：模块内部结构、协议与数据、失败与恢复
```

- 模块的号与短名与 [`PRD/modules/`](../prd/prd-rules.md) 下的同名目录、实现时 worktree 里的模块目录**一一对应**；**以定稿为准**。
- `modules/<模块>/` 就是一个子任务目录，内部是同样结构的任务目录（`thread/`、`PRD/`、`SDD/`），按需要继续往下拆。
- 层次是相对的：一个模块再往下拆时，它自己的 `SDD/architecture/` 对子模块就是结构层。总体还是详细由它在任务树里的层次决定，不由名称决定。
- `architecture/` 是目录，入口文件 `README.md`，可以再拆多份；编号见 [命名与编号](../naming.md)。

## 这一段该问什么

**没有模板，也没有必填栏**，下面是这一段该落在哪些问题上；一问只做一层，别把结构层和模块内部混在一起。

| 问什么 | 说明 |
| --- | --- |
| 以什么为底 | 哪一份 `PRD/` 定稿的哪几节、哪一份 `SDD/`；给链接与提交 |
| 设计到哪一层 | 结构层（模块之间）还是模块内部 |
| **责任边界** | 这件事归谁做、不归谁做；跨模块时谁向谁提供什么 |
| **接口与数据** | 调用、数据、协议的形状；错误与版本规则 |
| **状态与不变量** | 哪些账跨运行、跨进程死亡仍须正确（预算、幂等、副作用、证据） |
| **失败与恢复** | 会怎样失败、失败后回到哪个状态、谁负责补偿 |
| **威胁与越权** | 被攻破、越权、伪造时会怎样，强制点落在哪 |
| 有哪几条路 | 各自代价，为什么选这条；拿不准时要不要先做个有预算和退出条件的 spike |
| 哪些契约已冻结 | 不许动的状态词、合法边、终态、接口签名、数据格式 |
| 要不要往下拆 | 拆出的模块将成为 `SDD/modules/` 下的子任务 |

**不把验收标准写成条目塞进这一问**，也不复述本规则的栏目与设计原则：合不合格看它能不能定稿成 `SDD/`。
写多严见 [任务的生命周期](../lifecycle.md)「用户消息写多严」。

## `architecture/` 写什么

| 部分 | 写什么 |
| --- | --- |
| 模块与关系 | 分成哪几块、各自承担什么、谁向谁提供什么 |
| 接口 | 跨模块的调用、数据与协议；字段与错误的形状 |
| 共同约束 | 各模块都要守的不变量、状态语义、命名与版本规则 |
| 取舍 | 有哪几条路、各自代价、为什么选这条 |
| 未决 | 还没定的事，以及定不下来会影响什么 |

## `modules/<模块>/` 写什么

| 部分 | 写什么 |
| --- | --- |
| 内部结构 | 分成哪些部分、各自职责 |
| 协议与数据 | 对外的接口、持久化的形状、版本规则 |
| 失败与恢复 | 会怎样失败、失败后回到哪个状态、谁负责补偿 |
| 只对本模块成立的约束 | 上层没写、这里必须守的 |

## 设计必须满足

- 跨运行、或跨进程死亡仍须正确的不变量（预算、幂等、副作用、证据等账）**必须由持久存储承担**，不能放在执行进程本地。
- 依赖边界**限定在稳定的接口**，经端口隔离，不直接依赖裸协议；能租用的能力不自建。
- 领域概念**不进入通用端口的签名**：端口接受通用输入、能力与结果，领域名词留在领域配置里。
- 一种能力的差异优先表达成**配置**，而不是复制一套代码。

## 设计原则

| # | 原则 |
| --- | --- |
| P0 | **只有一套状态机**，场景差异只体现在配置的约束、必需产物与中断策略；任何场景不得新增状态词 |
| P1 | **同一事实只有一个权威写入面**；两份同构文档即两个真源 |
| P2 | **方向不对称**：朝严谨可自裁，朝省事须人确认；默认值属于省事方向 |
| P3 | **判据必须声明覆盖范围**；覆盖不全比没有更危险 |
| P4 | 凡能落成代码、测试或门禁的纪律**必须落成**；文字只描述意图，不构成机制 |
| P5 | 设计机制前，**先核实它要处理的动作实际发生在哪里、由谁执行、经过什么路径**；未核前提只能标假设 |

两条推论：**一个只能靠人转述的环节等于没有环节**（P4）；对象各自的小生命周期是**对象属性**，不是第二套状态机——
把属性误认成状态机会让每个场景各造一套，把状态机误认成属性会让状态词失控增长。

## 改已冻结的契约

**修改已冻结的契约，要提交明确的修订工作单元。**先证明是契约缺口，不在配置、适配层或文档里偷加语义。至少写清：

| 项 | 要交代什么 |
| --- | --- |
| 原始请求与证据 | 谁提的、原话、可复核的缺口或拒收用例 |
| 改与不改 | 具体定义块、字段、编号；状态、合法边、终态、幂等与租约哪些保持不变 |
| 影响 | 各组成部分分别要改什么，不改会怎样 |
| 迁移与回滚 | 版本、读写兼容、活动对象处理和退出条件 |
| 验收 | 原有用例集、必要新增用例、一条可复现实验 |
| 旧语义的处置 | 原先是什么意思、为何不够、谁依赖它 |

新增字段以带版本的可选字段引入；旧数据标「旧格式」，**不回填为无法证明的新语义**；新写入方不得回写旧版本语义。
