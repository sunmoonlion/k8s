# Celery Worker 代码提取配置说明

## 概述

Celery Worker 通过 Init Container 从 Backend 镜像中提取任务定义代码。不同服务的镜像结构可能不同，因此需要灵活配置代码提取路径和目录。

## 配置项说明

在配置文件中可以配置以下代码提取相关参数：
- **单后端场景**：使用 `deploy-celeryworker.conf`（如果使用方案1：多 Worker Deployment）
- **多后端场景**：使用 `deploy-multi-celeryworker.conf`（当前实现，方案2：多 Init Container）

### 1. 源代码路径配置

```bash
# 源代码在 Backend 镜像中的路径
CODE_EXTRACT_SOURCE_DIR="/app/app"
```

**说明**：
- 不同服务的镜像结构可能不同
- `llmops-service` 使用 `/app/app`（两层 app 目录结构）
- 其他服务可能使用 `/app`（单层结构）
- 根据实际镜像结构调整

**示例**：
```bash
# llmops-service（两层结构）
CODE_EXTRACT_SOURCE_DIR="/app/app"

# 其他服务（单层结构）
CODE_EXTRACT_SOURCE_DIR="/app"
```

### 2. 目标路径配置

```bash
# 代码提取到共享卷的目标路径
CODE_EXTRACT_TARGET_DIR="/shared/app"
```

**说明**：
- 通常不需要修改
- 这是 Init Container 将代码提取到 emptyDir 卷的路径
- Worker 容器会挂载这个路径到 `/app/app`

### 3. 提取目录列表

```bash
# 需要提取的目录列表（用空格分隔）
CODE_EXTRACT_DIRS="worker core services db models schemas crud"
```

**说明**：
- 用空格分隔多个目录名
- Init Container 会遍历这些目录，如果存在则复制
- 如果某个目录不存在，会自动跳过（不会报错）
- 根据服务实际需求调整

**常见目录说明**：
- `worker/`：任务定义（必须）
- `core/`：Celery 配置（必须）
- `services/`：服务层（通常需要）
- `db/`：数据库连接（通常需要）
- `models/`：数据模型（通常需要）
- `schemas/`：数据模式（可选）
- `crud/`：CRUD 操作（可选）
- `utils/`：工具函数（可选，如果服务有）

**示例**：
```bash
# llmops-service（完整目录）
CODE_EXTRACT_DIRS="worker core services db models schemas crud"

# 其他服务（只有部分目录）
CODE_EXTRACT_DIRS="worker core services db models"

# 如果服务有额外的工具目录
CODE_EXTRACT_DIRS="worker core services db models utils"
```

### 4. 提取文件列表

```bash
# 需要提取的单个文件列表（用空格分隔）
CODE_EXTRACT_FILES="__init__.py celeryworker_pre_start.py"
```

**说明**：
- 用空格分隔多个文件名
- 如果文件不存在，会自动跳过（不会报错）
- 通常需要 `__init__.py` 来确保 Python 包结构正确

**示例**：
```bash
# 默认配置
CODE_EXTRACT_FILES="__init__.py celeryworker_pre_start.py"

# 如果服务没有 celeryworker_pre_start.py
CODE_EXTRACT_FILES="__init__.py"

# 如果服务有额外的配置文件
CODE_EXTRACT_FILES="__init__.py celeryworker_pre_start.py config.py"
```

## 配置示例

### 示例 1：llmops-service（默认配置）

```bash
# deploy-multi-celeryworker.conf（多后端）或 deploy-celeryworker.conf（单后端）
BACKEND_IMAGE="llmops-service"
BACKEND_TAG="1.0.0"

# 代码提取配置
CODE_EXTRACT_SOURCE_DIR="/app/app"
CODE_EXTRACT_TARGET_DIR="/shared/app"
CODE_EXTRACT_DIRS="worker core services db models schemas crud"
CODE_EXTRACT_FILES="__init__.py celeryworker_pre_start.py"
```

### 示例 2：其他服务（单层结构）

假设有一个 `other-service`，镜像结构是 `/app/`（单层），只有部分目录：

```bash
# deploy-multi-celeryworker.conf（多后端）或 deploy-celeryworker.conf（单后端）
BACKEND_IMAGE="other-service"
BACKEND_TAG="1.0.0"

# 代码提取配置
CODE_EXTRACT_SOURCE_DIR="/app"  # 单层结构
CODE_EXTRACT_TARGET_DIR="/shared/app"
CODE_EXTRACT_DIRS="worker core services db models"  # 没有 schemas 和 crud
CODE_EXTRACT_FILES="__init__.py"  # 没有 celeryworker_pre_start.py
```

### 示例 3：服务有额外目录

假设服务有 `utils/` 和 `config/` 目录需要提取：

```bash
# deploy-multi-celeryworker.conf（多后端）或 deploy-celeryworker.conf（单后端）
BACKEND_IMAGE="custom-service"
BACKEND_TAG="1.0.0"

# 代码提取配置
CODE_EXTRACT_SOURCE_DIR="/app/app"
CODE_EXTRACT_TARGET_DIR="/shared/app"
CODE_EXTRACT_DIRS="worker core services db models schemas crud utils config"
CODE_EXTRACT_FILES="__init__.py celeryworker_pre_start.py"
```

## 工作原理

1. **Init Container 启动**：
   - 使用 Backend 镜像（如 `llmops-service:1.0.0`）
   - 从环境变量读取代码提取配置

2. **代码提取**：
   - 从 `CODE_EXTRACT_SOURCE_DIR` 读取源代码
   - 复制 `CODE_EXTRACT_DIRS` 中存在的目录
   - 复制 `CODE_EXTRACT_FILES` 中存在的文件
   - 保存到 `CODE_EXTRACT_TARGET_DIR`（emptyDir 卷）

3. **Worker 容器启动**：
   - 挂载 emptyDir 卷到 `/app/app`
   - 使用提取的代码执行任务

## 调试技巧

### 查看 Init Container 日志

```bash
# 查看 Init Container 的提取日志
kubectl logs -n app-platform-dev <pod-name> -c extract-worker-code

# 应该看到类似输出：
# ==========================================
# 从 llmops-service 镜像提取任务定义代码
# ==========================================
# 源代码路径: /app/app
# 目标路径: /shared/app
# 提取目录: worker core services db models schemas crud
# 提取文件: __init__.py celeryworker_pre_start.py
# ==========================================
# 
# 开始复制目录...
#   ✓ 复制 worker/...
#   ✓ 复制 core/...
#   ...
```

### 检查提取的代码

```bash
# 进入 Worker 容器
kubectl exec -n app-platform-dev -it <pod-name> -c celeryworker -- bash

# 查看提取的代码
ls -la /app/app/

# 应该看到提取的目录和文件
```

### 常见问题

1. **目录不存在**：
   - 如果配置的目录在镜像中不存在，Init Container 会跳过（不会报错）
   - 检查日志确认哪些目录被跳过了

2. **路径错误**：
   - 如果 `CODE_EXTRACT_SOURCE_DIR` 配置错误，所有目录都会被跳过
   - 检查 Backend 镜像的实际结构：`docker run --rm <image> ls -la /app/`

3. **Python 导入失败**：
   - 确保提取了所有必需的目录
   - 确保提取了 `__init__.py` 文件
   - 检查 `PYTHONPATH` 环境变量（应该是 `/app`）

## 最佳实践

1. **统一配置管理**：
   - 在配置文件中集中管理代码提取配置（多后端使用 `deploy-multi-celeryworker.conf`，单后端需要单独创建配置文件）
   - 不同环境可以使用不同的配置文件

2. **目录列表**：
   - 只配置实际需要的目录，避免提取不必要的代码
   - 如果服务没有某个目录，从列表中移除（可选）

3. **路径验证**：
   - 部署前验证 `CODE_EXTRACT_SOURCE_DIR` 是否正确
   - 可以通过 `docker run --rm <image> ls -la <path>` 验证

4. **日志监控**：
   - 定期检查 Init Container 日志，确保代码提取成功
   - 如果看到大量 "跳过" 警告，检查配置是否正确
