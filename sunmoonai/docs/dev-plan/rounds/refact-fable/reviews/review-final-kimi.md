## 本轮新发现

### F1（需在 S1 验证）：回执仓判据"只验存在、不验签名"，挡不住 Windows 本地 agent 伪造推送

**问题**：§3.13.2 定调"白名单 = 所有者 GitHub 账户登记的签名密钥，`round-status.py` 判的是 tag 在回执仓存在，
不判本地验签"。存在即证据的前提是"只有所有者能写回执仓"。但 §3.13.4 第 2 条自己已把
**Windows 本地 agent** 列为威胁，而它的对策（gpg-agent TTL=0）只防**私钥**滥用——
Windows 上 Git Credential Manager 通常缓存着对 GitHub 的推送凭据，**不需要任何口令**就能
`git tag confirm/<id> <commit> && git push receipts`（一条**未签名**的 tag）。
判据不验签，这条 tag 与真回执不可区分。gpg TTL=0 防住了"伪造签名"，没防住"绕过签名直接 push"。

**建议**（二选一，S1 spike 内定）：
① 判据加"tag 必须是签名 tag，且签名密钥指纹 ∈ 白名单"。信任锚问题文档其实已答：
白名单=所有者账户登记的密钥，脚本可用 `gh api /user/keys`（或公开 `.keys` 端点）在线取指纹集
再本地验签——在线取指纹这一步 agent 无法伪造（除非已控制所有者账户，那是已登记的超范围风险）；
② 维持"只验存在"，则须在 Windows 侧消除缓存推送凭据（回执仓 remote 改用每次输口令的凭据，
或单独一把"仅所有者本人持有"的推送 key），并把这条写进 3.13.4 第 2 条。
我倾向 ①：它把边界从"推送凭据的缓存状态"（不可观测）移回"私钥在场"（pinentry 可观测）。

### F2（需在 R1 验收加一条）：T0 任务类包的 `paths` 与其 `gates` 脚本路径必须不相交

**问题**：`bundle.script-fix` 的 `paths = ["sunmoonai/docs/dev-plan/*.py"]`，而 `doc-gate.py`、
`round-status.py`、`round-dispatch.py` 恰在该目录。此包名下的 T0 工单可以**修改判定自己的脚本**
让 gates 全绿——diff ⊆ paths 照样成立。这不是假设漏洞，是把"改门禁"和"被门禁判"放进了同一个可写面。

**建议**：策略文件增加一条机械校验（可写进 `check-policy.py` 或并入 doc-gate）：
对每个包，`paths` 展开集 ∩ `gates` 脚本及其依赖文件集 = ∅；不相交性随策略签名一起冻结。
或者更简单：gates 脚本集中到 `scripts/gates/`，所有包的 `paths` 禁止覆盖该目录（一条规则，不用逐包算交集）。

### F3（文字级）：12:15 修订记录 (a) 的「H7 取消例外」与正文关系不明

修订记录写"所有 `auto_policy = 无` 的权力表行一律回执仓签名 tag（H7 取消例外）"——
可读作"H7 的例外被取消"（即 H7 也要签名 tag），但正文三处（§3.3 H7 行、§3.13.3 schema 注释、§8 第 6 条）
一致地**保留** H7 例外（`rulings.md` 一条即可，理由"伪造取消属失败安全方向"）。
建议把记录改为"H7（取消）保留例外"或"H7 为例外"，避免日后有人按记录倒推正文改错。
实体设计本身（H7 不锚仓外）我同意：伪造取消只停工，方向正确。

### F4（补强）：§8 第 4(b) 条"边 ⊆ 内核合法转换表"需要一份机器可读边表，注意别长成第二真源

"脚本判边是否合法"要求内核的合法转换表以机器可读形式存在于某处。
`request-lifecycle.md` 是自然语言文档，脚本若内嵌一份边表副本，即 P1 意义上的第二真源。
建议 R1 产物中明确：边表落成一个数据文件（如 `policies/state-edges.toml`），
文件头注明 `source = request-lifecycle.md @ <commit>`，且§8 第 4 条重跑时（3.1 内核修改后规则③）
第一步就是核对该 commit 与当前引用是否一致。这样第二真源被"按 commit 引用"纪律罩住，与 D4 的处置同构。

### F5（补强）：回执 schema 的 `expires` 缺默认窗指导

§3.13.3 引入 `expires`（过期重签），但没给取值指导。H3/H4 是中途裁定，人可能数小时后才签；
H1/H5 窗长不同。expire 太短会推高签名次数观察值并诱发"一次签长窗"的省事漂移。
建议给一句默认规则即可："`expires` 由收件箱条目的截止判据派生，缺省 = 落盘 + 24h；
H5 不得晚于待发布 commit 的下一个 commit 出现之前"。也可以接受留给 S1 数据说话——但要在文档里写明"留给 S1"。

## 明确同意的几处设计（记录，防后续轮次被改回去）

- **"covers 不做字面匹配，表达不了就不是 T0"**（3.6）：这是对"自然语言判不了"最诚实的处理，
  比任何 NLP 包含判断都可靠。T0 口径收窄是优点不是代价。
- **回执仓 tag 只增不改、纠错用新 tag**（3.13.2）：与 Event 只追加（I 系列）同构；
  "所有者自律"是已知软点，已被 `_probe` 漂移检测（每轮 ⑦ 重跑）部分覆盖，可接受。
- **arbiter 不兼 orchestrator**（3.9 硬约束二）：round-protocol 现状"通知由裁决方写"确实是把活塞给了角色，拆开正确。
- **bootstrap 档只用于 R0/S1 两行**（§6）：解决了"策略不存在时 T0 无法引用策略"的鸡生蛋问题，
  且自封"之后不再出现"，防止 bootstrap 变成常驻逃生门。
