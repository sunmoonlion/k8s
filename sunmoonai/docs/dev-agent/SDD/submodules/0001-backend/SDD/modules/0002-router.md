# 0002-router：受理与路由

**承担**：受理与路由——`F-ADMIT-*` 全部六条。

义务怎么做到是设计，以下是这一块**独有的设计决定**：

- 路由规则是**版本化配置**，变更落事件；依据、规则集版本、所选模型与拒绝原因入账；
- 类别三层判定里只有第三层在这里，前两层在桌面应用与 runtime（见 [`routing.md`](../../../../architecture/routing.md)）。

**必须做到**（定义原在 `PRD/functions.md`，ID 不变）：

- **F-ADMIT-01**：在可靠边界内完成认证身份绑定、幂等占位、Task 建单与首事件写入；
- **F-ADMIT-02**：输入不合规不得「尽量执行」；建单后的拒绝进入 `REJECTED`，协议层拒绝按 [`objects.md`](../../../../architecture/objects.md) 处理；
- **F-ADMIT-03**：所有客户端入口（桌面应用、受信服务入口）共享同一个应用用例，只在接口层解析身份：桌面应用的身份来自桌面端 token 会话，服务入口使用服务身份与受信委托上下文；不得复制 Task 状态或业务逻辑；
- **F-ADMIT-04**：路由按「用户所选 → 后端兜底 → 交用户选」进行（[`0001-backend/PRD/routing.md`](../../../../architecture/routing.md)）；路由规则是版本化配置，变更落事件；路由决定及其依据入账；
- **F-ADMIT-05**：执行设备只从在线、已授权相应工作区的设备中选择；用户指定设备时校验归属；
- **F-ADMIT-06**：类别判不出来时创建 Interaction 交用户选，不得默认判为通用，也不得回退到能力更大的 Profile。

- **F-CRYPTO-07**：问题侧的明文字段只容纳来自任务文本的内容；把本地资料内容、文件名或其派生特征写入任何明文字段都是违规，字段 schema 必须能拦住。
- **F-GUARD-04**：任务类别与 Profile 不授予数据权限：自有数据、领域工具与知识服务的访问由授权与订阅独立判定，自报的类别不能扩大可取数据的范围；

**不承担**：

- **不调用生成式模型**（v1 确定性规则，D11 未定之前不变）；
- 不推进 Attempt——契约固定后交给 `0003-orchestrator`；
- 不自己写状态与账，经 `0001-ledger`。

**边界要点**：身份与幂等必须在**同一个事务边界**内完成；一旦分配 `task_id` 并写首个事件，
后续业务或政策拒绝也必须形成**可审计的 `REJECTED` Task**，不能静默丢弃。
