# 多方竞争

**一段交回物由多个 agent 各交一份、再比较选定。**四个种类(PRD/SDD/IMP/UAT)都可能用到。
它不是另一条流程,是 [九站](../pipeline.md) 里**派发**那一格的一种形态:
同一问发给几家,多出互评、裁决、异议三个环节,到**交付**重新合流。

> **规则的真源是 [`protocol/competition-protocol.md`](protocol/competition-protocol.md),不是这一份。**
> 本文只回答「要不要开一次竞争、开了之后去哪读」。

## 要不要开

| 档 | 这件事怎么做 | 谁参与 | 什么时候用 |
| --- | --- | --- | --- |
| **T0 直做** | 一个执行者做完,无候选、无互评 | 执行者 + 独立验收者 | 可逆、单点、方向无争议 |
| **T1 单稿 + 独立评审** | 一家出稿,另一家按冻结判据评审并验收 | 出稿方、评审方、人(若不可逆) | 影响面跨多文件或多仓,但方向无争议 |
| **T2 完整多方竞争** | 七个环节 | 提案、互评、裁决、异议、验收、确认 | **命中下面任一条** |

**命中任一条即 T2**:

- **不可逆**——对外契约、编号体系、数据迁移与删除、**流程本身**;
- **权威层**——会成为其他文档或代码的依据;
- **已知对立**——开工前就有互不相容的主张;
- **判据未定**——连「什么算做对」都还没共识。

都不命中但影响面跨多文件或多仓的走 T1,其余 T0。**定档要留痕**:写明档位、理由与命中的判据。

⚠ **三条任何档位都不能省**:验收判据先于产出冻结;产出方不是验收方;不可逆动作由人确认。

## 开了之后去哪读

| 要什么 | 去哪 |
| --- | --- |
| 七个环节各做什么、各交什么 | [协议](protocol/competition-protocol.md)「七个环节」及其后各节 |
| 现在是第几环节、我该干什么 | [`GO.md`](protocol/GO.md) |
| 本次竞争的题目、参与方、判据 | 该次竞争目录下的 `round.md`(字段见协议「本次定义」) |
| 产物叫什么、放哪、怎么取 | 协议「产物、路径与命名」「取件与检视面」 |
| 多家并行写同一目标的纪律 | 协议「多家并行写同一目标时的纪律」 |
| 各家该不该用不同的模型 | 协议「各家应当用不同的模型或不同的 provider」 |
| 投喂、通知、所有者的确认 | [操作闭环](protocol/competition-operations.md) |

## 各任务自己要写什么

用到多方竞争的任务,在自己的目录里写明:用户消息格式、存放路径、判定工具与通知方式,并链接回协议。
**不要在任务目录里复述协议的规则**——那会产生第二份会漂移的真源。
