# 工作区

> 用户的文件、Excel、工具、做到一半的东西都在他的机器上。云端 Codex 按需读写，不要求整机上传。

## 三层：工作区、项目、执行根

| 层 | 是什么 | 谁定 | 落到 Codex 的哪里 |
| --- | --- | --- | --- |
| **工作区** | 用户机器上的一个根目录（如 `~/research`） | 本地代理白名单；用户在代理里加 | `runtimeWorkspaceRoots[]` |
| **项目** | 工作区下的一个子目录（如 `~/research/2025H1-annual`） | 用户在网页里选 | `cwd` |
| **执行根** | Codex 沙箱允许写的范围 | 本地上限：`workspace-write` 限在 `cwd` | executor 侧沙箱 |

流程：用户装好本地代理，在代理里把一到多个目录加入白名单；网页从工作台读该环境的白名单，用户选工作区、再选项目；Session 建立时工作台对 app-server 发 `thread/start`，`environments:[{environmentId, cwd, runtimeWorkspaceRoots}]`。

## 谁能改文件

| 方向盘 | 写范围 | 越出时 |
| --- | --- | --- |
| 用户 | 项目目录（`workspace-write`） | Codex 审批请求 → 用户答 |
| 顾问 | 项目目录 | 审批请求 → 转 Interaction（`AT-19`）；本地上限之外的被 exec-server 拒绝 |

顾问交回时必须列出改了哪些文件；有覆盖的，先落备份版本（Artifact），交回物里写恢复方式（`AT-25`）。

## 结果落两处

研究底稿同时存工作台（明文，`I6`）与项目目录（用户拿走就走）。工作台那份是真源，用于回放、验收证据、跨设备；工作区那份是用户的。

## 用户资料

第一期只做显式上传与勾选（`D7`）：用户在网页上传文件，或勾选项目目录下的文件由本地代理上送到知识服务。不做整机镜像；Codex 读本地文件走③，不经知识服务。

## 多台机器

一个用户可以注册多台机器（每台一个本地代理，一个 `environment_id`）。一个 Session 绑一台。第一期不做跨机器续跑。
