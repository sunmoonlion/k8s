# 多方竞争协议

一段交回物由多个 agent 各交一份、再比较选定时，按本规范进行；四个种类都可能用到。
各任务写明自己的用户消息格式、存放路径、判定工具与通知方式，并链接回来。

多方竞争只用于命中 T2 判据的任务，这类任务按最严格的写法写（见 [turn 的投影](turn-project.md)「用户消息写多严」）；下文「用户消息必给」等要求只对它们成立。

## 档位：这件事该走多重的流程

| 档 | 形态 | 角色 | 适用 |
| --- | --- | --- | --- |
| T0 直做 | 一个执行者做完，无候选、无互评 | 执行者 + 独立验收者 | 可逆、单点、方向无争议 |
| T1 单稿 + 独立评审 | 一家出稿，另一家按冻结判据评审并验收 | 出稿方、评审方、人（若不可逆） | 影响面跨多个文件或多个仓，但方向无争议 |
| T2 完整多方竞争 | 下文七个环节 | 提案、互评、裁决、异议、验收、确认 | 命中下列任一条 |

**命中任一条即 T2**：不可逆（对外契约、编号体系、数据迁移与删除、流程本身）；权威层（会成为其他文档或代码的依据）；
已知对立（开工前就有互不相容的主张）；判据未定（连「什么算做对」都没有共识）。都不命中但影响面跨多文件或多仓的走 T1，其余 T0。

- 定档必须可复核，裁定留痕：写明档位、理由与命中的判据。
- **升档不需要理由，降档必须写明理由并经人确认**；开工后只能升、不能降，已经在跑的重流程不得因为嫌慢而降档。
- 同一套流程靠参数覆盖不同协作形态：多家各出方案再合并、让另一家查一份已有产物、多家评审一份已有产物再由主方吸收，
  只是「提案方、基座、跳过哪些环节、谁验收」的不同取值，不是几套流程。跳过环节必须显式写明，留空不算数。
- **任何档位都不能省的三条**：验收判据先于产出冻结；产出方不是验收方；不可逆动作由人确认。

## 裁量权

流程不可能写死一切，所以裁量合法，但须**有边界、留痕、可推翻、可升级**。

- **不可裁量的下限**：不可逆动作由人确认（确认、写发布面、删除或迁移已有资产）；出题方不是答题方；验收判据先于产出冻结；
  已冻结的产物不得再改；提案期隔离。要改只能改本协议本身，而那属于 T2。
- 可裁量：档位升降、观察窗长短、环节合并或跳过、换角色、增减参与方、提前终止、初判某条标准已过期、认定逾期与弃权。
- **方向不对称**：朝更严谨的方向（升档、延长观察窗、增加评审、要求补取证、回退重做）自行裁量并记录即可；
  朝更省事的方向（降档、缩短观察窗、跳过环节、免除某家、减少参与方、提前终止）**须经人确认**并记录。自动化的默认漂移方向永远是省事。
- **未记录的裁定无效。**每条裁定记下：编号、事由、依据（须能独立成立，逾期类必须是观测值）、处置、方向、人确认、影响到谁。
- 人可以推翻任何裁定；受影响的参与方可以提异议（门槛同异议环节）。推翻追加记录，不覆盖原记录——作废的判断本身是证据。
- **裁量是规则的孵化器**：同一类裁定在两次竞争内出现两次以上，升级为规则；某条规则连续两次竞争都靠裁量豁免，降级或废除。

## 执行者与触发方式是两个轴

- 执行者：agent 或人。触发方式（只对人的动作有意义）：可自动或手动。
- 判据：**动作内容是常量、只是需要送达 → 可自动**（缺的是传输，不是判断）；**动作要在当下做一个不可复算的判断 → 手动**，永远由人做。
- 冻结题目与判据、最终确认、省事方向裁定的确认、推翻裁定，都是手动项；可自动项现在由人做是欠账，应登记待自动化，
  不得让人长期当传声筒；手动项不得因为流程自动化而被顺手代劳。判断属于哪一类用上面的判据，不用「现在是谁在做」。

## 七个环节（T2）

```text
① 提案   N 家各自写候选，互不可见                     产物：候选（提交即冻结）
② 互评   N 家各自读全部候选，评优并写评审              产物：评审
③ 裁决   裁决方定基座，逐条吸收                        产物：裁决稿 + 处置记录
④ 异议   被处置到的各家只就自己那条主张的处置提异议     产物：异议稿；触及基座结构的采纳 → 回到 ③
⑤ 验收   验收方按冻结的验收标准逐条判定                产物：验收稿；不通过 → 回到 ③
⑥ 确认   人读最终稿，确认或打回                        产物：确认；打回 → 回到 ③
⑦ 清理   清理各方本次产物，然后写入发布面               产物：定稿或主线提交
```

只有 ⑦ 写发布面——PRD、SDD 两类写定稿，IMP、UAT 两类合并到主线；其余产物留在各自的 worktree 与分支。**流程不是只会前进**——没有回退环节的流程，最终一定会把不合格产物推到底。

## 环节判定：命令即判据

- 各环节是否完成，**从已提交的产物反推，不看任何人的声明**；声明与计算对不上时必须显式报出，不许靠改声明让它消失。
- **没有参与方不等于该环节完成**（空集合为真）；要跳过必须显式写明。
- 枚举产物用固定的路径形状，不按印象列文件名；命中数与参与方数不符时**停下问人**，不自行猜哪一份算数。
- 产物可能落在参与方分支，也可能在收尾后归档进主线——判据只认其中一处，会把合规者判成没交，或把做完的判成没做。
- 最终确认的**内容**由人判，确认有没有**落盘**由命令判；对话里说「同意」不算。
- 拒绝要有区别于成功的退出码，否则调用方看不出自己被拒了。

## 判据自身的质量

**一个覆盖不全的检查，比完全没有检查更危险——它会报「通过」，把「未知」伪装成「已验证」。**

1. 判据必须声明覆盖范围：查了什么、没查什么；零命中要能区分「真的没有」与「没查到」。
2. 判不了的显式标出，不许默默不查。
3. 验证命令本身要先被验证；报出「不一致」时先用第二种写法交叉验一次——坏掉的检查会指使你去改错对的东西。
4. 新判据第一次跑，先与人工结论对照，对得上了再当门禁。

## 立判据的人怎么约束自己

- **只写判据，不写答案**：「必须给出 X 的结论与理由」是判据，「X 应该是 Y」是答案，不写。判据先于答案冻结，裁决时就不能按最喜欢的候选反推判据。
- 立据人的四条自我约束：判据冻结后不修改，发现问题在裁决书里追加说明；逐条对照判据给结论并附候选原文出处；
  超出事先判据的结论标注「事后新增判据」；**凡判据有、用户消息没有的要求，只可用于加分，不得用于扣分**。
- 难点清单：事先记下题目难在哪、不给解法；参与方都没意识到的难点，责任在用户消息，不扣候选的分。
- 通用扣分：没有准出判据的阶段不计分；锚点存在但不支持断言的，比没有锚点扣得更重；不可定位的落点按缺失计。
- 起草人回避：裁决方对某问题已有公开立场时，候选与之一致既不加分也不减分，判的始终是论证与锚点；列出自己拒绝预设立场的问题。
- 判据自身的失效条件：某条下全体满分或全体零分，无区分力，作废；某条在各候选上都无法判定，作废；
  出现判据没预料到的优秀做法，计入加分（设上限）。加分与扣分的不对称是有意的。
- 一票否决项（不进最终整合主干）必须事先写明，不得在裁决时临时宣布。

## 组织者的纪律

- **环节进行中，组织者不得写入参与方的 worktree**；同步只在环节之间做，做完再发下一环的通知。
- **写入之后必须验证写入成功**：不得丢弃输出、不查退出码；同步后逐个核对没有停在合并中途、没有未合并项、各家产物摘要未被改动。
- 代提交：执行者写得出产物但无法提交时由组织者代提交，必须**区分内容作者与提交者**，并在提交说明里写明作者、代提交者、原因与文件摘要，
  登记为人代行的欠账。作者字段只让归属**可读**，不让归属**可信**。
- 取件一律按提交，不看 worktree；跨分支对象写成「提交:路径」。每个环节的通知至少包含：带提交的取件方式、对象与摘要、范围与门槛、交回路径、截止判据。
  通知发布后不在同一环节偷偷改输入；必须重定对象时记录原版本、理由与受影响方，重发通知或回退。请求最终确认前，把可读的检视面准备好。

## ① 提案：隔离与冻结

- **候选完成前不得读其他方的 worktree。**理由不是保密，是信号质量：看到别人答案后写的内容是改写，问 N 家的成本花了，信息量却接近问一家。
- 可见性分阶段：提案时各家只见用户消息与只读输入；互评、裁决时解除。裁决可读全部候选，但不得直接拼接——别人的方案只作「该核对什么」的清单，结论回源取证重写。
- 用户消息**必给**：原始请求（原话）、列全的只读输入（漏列的材料不得事后用来扣分）、边界。
- **判据先于产出冻结，但不一定发给提案方**：发不发由出题方定。实现段（IMP）要发——执行者不知道做到哪算完就只能猜；
  讨论与设计段（PRD、SDD）不发——写成条目就把答案空间提前封死。未发出的判据只能用于加分，不得用于扣分。
  **不给**：其他家的候选、发起方自己的倾向或初步结论、指定的检查点。发出去的东西只描述「要什么」和「怎么算做到」，不描述「我觉得该怎么做」。
- 候选写完即提交，提交后不得再改；把候选的摘要与所在提交写进自己的评审。裁决方按摘要从提交取候选，不从 worktree 取。
- 隔离若只靠纪律、没有机制保证，必须如实声明为已知缺口；覆盖不全的隔离机制比没有更危险——它会让人以为这次竞争是隔离的。
- **各家应当用不同的模型或不同的 provider**：同一个模型跑 N 遍，共同盲区完全一致，N 份候选高度相关——
  钱花了 N 份，信息量接近一份。只能用同一模型时，必须如实声明**独立性降级**，并在评优时按降级对待，
  不得把「全体一致」当作证据。
- **隔离强度与独立性是竞争特有的两项采信维度**：[UAT 怎么验](uat/verify-rules.md)「证据采信」说采信取各项中最低的一项，
  在竞争里要把这两项一并计入——隔离没保证、或各家不独立，整份证据就按最低那一项算。

## ② 互评

评审四块，缺一块不计入裁决：

- **A 自述**：改了基座哪些部分、新增什么；哪些断言未验证；与基座的分歧；放弃了哪些本可写的内容及理由。
- **B 候选集冻结**：全部候选的位置、大小、摘要、所在提交；少一份，评分作废。
- **C 评优**：按验收标准对全部候选（包括自己那份）指出强项与缺陷，给完整排序及基座人选的理由；利益冲突必须声明；**事实题用证据裁，不用票数裁**。
- **D 值得吸收的点**：不管选谁当基座，逐条列出其他候选里值得并进最终稿的具体主张，写明出处与理由。

## ③ 裁决

一条主张一个提交；从选定候选的提交取基座，不从任何人的 worktree 取；逐条处置为「接受 / 部分接受 / 拒绝」，理由须能独立成立，
部分接受写清接受到哪、为什么止于此；**票数不是依据**。处置记录含一张机器可读的处置表（出处、条目、裁定）。

## ④ 异议：对整合权的唯一制衡

裁决方是唯一既读全部材料又执笔最终稿的角色；验收查「达标了吗」，查不到「某家的主张有没有被误读」——只有原作者知道自己原本想说什么。

| 项 | 规定 |
| --- | --- |
| 触发 | 只发给被处置到的家：判断被改动、主张被拒绝或部分接受的 |
| 范围 | 只就自己那条主张的处置提异议，不评整体、不替别家喊冤 |
| 门槛 | 处置条目 + 为什么错 + 应当是什么 + 可复跑证据；「读起来更好」不受理 |
| 效力 | 不是否决权；裁决方可以驳回，但必须逐条给理由，连同异议原文写进处置记录 |

异议必须在验收之前、必须冻结提交；没有异议的家要明确登记「无异议」——空回复与「还没看」无法区分。

## ⑤ 验收与 ⑥ 确认

- **验收方由处置表算出，不由裁决方指定**：不得是裁决方；不得是基座作者；在其余各家里取被接受与部分接受条数最少的一家（既得利益最小）；
  并列取候选最短者，仍并列由人裁定；都不可用时由人验收。名次与验收资格无关；指定结果与计算过程写进处置记录，不得事后更换。
- 验收方只按冻结的标准判定，不为通过而静默改标准；判定为「标准本身过期」时写明理由交裁决方处置。
- **确认必须是人的显式动作**，不得由固定指令推进，也不得由任何 agent 代行；人确认前不得写发布面。
- 定向审核分两阶段，防止被产出方锚定：先只给原始请求、产物位置与冻结判据做**独立审**；再给产出方的自陈盲区做**对照**，双向查漏。
- 验收通过只构成「**经过一次外部检视**」，不构成「已验证」的背书；发布说明与记录一律照此措辞。

## 停止、超时与回退

| 情况 | 处置 |
| --- | --- |
| 某家迟迟不交 | 按逾期判据处理；不要只说「快点」——模糊压力下执行者会砍掉最省事的部分，通常是取证与验证 |
| 异议被采纳且触及基座结构 | 回到裁决重整合，已做的验收作废重做 |
| 验收不通过 | 回到裁决；判为「标准本身过期」时由人决定改标准还是改产出 |
| 人打回 | 回到裁决 |
| 同一次竞争回退超过两次 | 停下，判断是题目有问题还是标准写错了，不做第三次重整合 |

- 每个环节的通知必须给出**截止判据**，且必须是**可观测、可复算的**，不是裸的时钟时间：停滞（一个观察窗内产物与分支都无变化）、
  未启动（观察窗内计算时间与输出都无增长）、同侪基准（半数交付后再等一个观察窗）。**观察窗由本次已交付各家的实际用时算出，不由任何人挑数字。**
- 零产出先分「没起来」还是「在跑」，单一信号不足以判，须多个信号联判；把一次观测直接升格成判据是反复出现的错误。
- 产物还在长就不算逾期；宣布逾期前必须跑一次判据并把观测值留痕。观察窗**可延长，不可缩短**（缩短须人确认）。
- 各环节逾期后果不同：提案逾期则该家退出、候选数减一，降到一家时停下问人；互评逾期则其评审不计、候选仍在池中；异议逾期视为弃权；
  验收方逾期视为不可用，按预先声明的顺位换人；**最终确认不设逾期默认**——人不确认就不发布。只有该环节之后仍有独立检查时，才允许默认放行。
- **弃权不等于同意**，留痕写「未响应」。换角色只有一个合法理由：该家不可用；不得以「对结果不满意」换人。

## 为什么必须分角色

裁决方不提案，所以整合可信；裁决方不验收，所以判定可信；来源方可提异议，所以整合的忠实度可查——三条缺一条，这次竞争的产物就没有可信来源。
整合方兼参赛方、没有互评、没有异议、没有独立验收，是角色不分的典型形态，会自裁自己、漏掉各家独有的发现、丢掉基座的长处。
**流程里没写下来的环节，等于不存在。**

## 候选、整合与发布

单个执行者的纪律见 [IMP 规则](imp/message-rules.md)；下面几条只在多家并行时成立。

- **三个路径不是一个**：候选路径（各自 worktree 内）、发布路径（整合者 worktree 内）、发布引用（最终提交或发布版本）。
  候选作者只提交自己的相对路径；由唯一整合者从冻结提交取内容写发布路径、跑最终门禁、形成最终提交。
- 顺序是：私有草稿 → 候选 → 冻结提交 → 选定 → 整合者 worktree → 最终提交 → 发布面。
  **人指定的最终文件名是发布目标，不是所有候选都可同时写的路径。**
- N 名写者建 N 个 worktree，另给整合者一个；只读者只取件。
- **整合前显式核对**：候选状态仍有效、提交仍可达、提出方未撤回、基线未失效；核对对象是提交与候选状态，不是分支。
- **发布必须带预期版本**（比较并交换）：目标已变化则发布失败，新建整合尝试重来；**不得以强推、无条件覆盖或先删后写绕过竞争**；
  发布重试用稳定的幂等键。人明确只要多个可比较草案时，发布目标是候选集合及其清单。
- 用**足以产生独立信号的最少候选**；顶层验收满足后，其余在途候选停止或降为无副作用的只读参考。
  完整交叉阅读是二次复杂度，候选多时平衡分配但评审覆盖相同；无法运行命令的评审必须标「未经事实验证」。
- 迟到候选只读保留；两个单元改同一文件交整合者；合并冲突由整合者解析并记依据，不按时间自动取新；
  删除与修改冲突交整合者裁决；整合从选定提交取内容，不拷任何人的未提交文件。

### 反模式

| 反模式 | 失败方式 |
| --- | --- |
| 所有候选直接写最终路径 | 路径成为竞态，选定在写入时被偷偷决定 |
| 发布时不校验目标版本、冲突后强推 | 静默覆盖别人的更新，抹掉并发历史和已评审对象 |
| 候选读取其他候选或偷看发起方倾向 | 独立信号退化成改写 |
| 作者自评自收、候选人互投 | 同一判断链为缺陷背书，独立性是假的 |
| 多数票覆盖失败测试，或全体一致的共同盲区 | 偏好压过事实；一致不等于正确 |
| 冻结后原地替换、只固定分支名 | 比较对象漂移，无法复核 |
| 大补丁混合多条主张 | 无法逐条处置，接受与拒绝被绑在一起 |

## 清理与发布

顺序是：**人确认 → 清理各方本次产物 → 写入发布面**。先清理再写入，避免候选与定稿同名同路径在后续同步时冲突；
清理后各分支重置到发布点。评审、异议、验收稿的结论已进处置记录，是否长期保留另行决定。

## 通用纪律

- 产物只写自己的 worktree，提案期任何人不得写主线。
- 候选绑定不可变提交，并声明覆盖与未覆盖范围、假设、盲区、缺陷与关键主张的证据；评审、异议、验收同样是产出，同样要自陈盲区。
- 做不成的老实标 ⚠；未验证的结论标注清楚，不把推断写成事实。
- **用户消息冻结后不得中途修改**；发现用户消息有错，记进处置记录，开新的 turn 时修。
- **引用本协议按标题，不按章节号**：章节会移动，标题不会；章节号是会静默腐坏的引用方式。

## 档位：T0 / T1 / T2

> 依据的通用规范：[多方竞争协议「档位」](competition.md)

三档共享同一工单 schema、状态机和发布门，只改变 guard、必需 Artifact 和 Attempt 组：

| tier | 执行形态 | 独立信号 | 人工门 |
| --- | --- | --- | --- |
| T0 | 做 → 独立验收 → 确认 | 一个产出、一个独立验收 | 开工可由已批准窄包自动决定；不可逆发布仍由人确认 |
| T1 | 单稿 → 独立评审 → 验收 → 确认 | 一稿、一评、一验 | 工单冻结与开工可合成一次明确确认 |
| T2 | competition-protocol 七环节 | N 份隔离候选、互评、裁决、异议、独立验收 | 题目/判据冻结与参与方/路线确认分开 |

产物命名、候选冻结、处置表和验收方算法见 [§3.19](protocol/competition-operations.md)–§3.22（已随标签 `backend-rules-archive` 归档），来源为现行 competition-protocol。状态脚本从 commit 反推，工作区
不参与判定；空参与方不是“完成”；脚本首次增加判据时先与人工结论对照，并列出未检查范围。

⚠ **档位是风险轴，「建不建 Git 工作区」是载体轴，两者正交，不可互相推导。**
载体判据是另一组：不改持久文件、单 Attempt 单会话可完成、不需要 worktree/回滚/diff/固定源码版本、
外部副作用为零或已有独立副作用账、验收可直接针对结构化结果完成——**全部满足才可不建工作区**；
多文件改动、跨步骤跨会话跨执行者跨仓、需要 checkpoint/回滚/diff/固定候选、需要 fan-out、
以代码或可复现实验交付、错误代价要求独立评审——**任一命中就要建**。

⚠ **「不建工作区」只决定载体，不降低授权、证据、预算或验收。**
载体判定必须可审计：**不能为省供给成本把复杂任务塞进无状态 Attempt，也不能为形式统一
给一次只读问数建立空仓库**。执行中发现判据不成立时，停止当前 Attempt 并保存 checkpoint 后升级，
**执行者不得私自在获准工作区之外建仓**。

⚠ 把载体轴写成档位轴，与 §2.5「风险档位不能反过来充当成本证据」是同一种循环。

## 被证伪的设计：防止再犯

**这一节是隔离区，不是设计菜单。**它存在的唯一理由是**防止再犯**——
一个被推翻的设计如果只是悄悄消失，下一个人会照着同样的推理再走一遍。
所以两条形状规矩：

- **被证伪设计的裁定集中在本节，执行规则不得复活它们**（`amend_schema`、回执仓、候选仓、三道边界一类）。
  源稿 9 节 的历史取证记录与 源稿 10 节 的源标题只作来源辨认，不产生执行效力；词面检查须区分规范与历史引用；
- 本节每条必须**「独立观察」与「结论与落点」相邻**——
  只写结论不写观察，读者无从复核；只写观察不写落点，读者不知道它改变了什么。
