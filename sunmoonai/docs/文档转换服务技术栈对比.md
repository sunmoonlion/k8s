# 文档转换服务技术栈对比

## 概述

项目中有两个文档转换服务，它们使用完全不同的技术栈：

1. **document-converter** - 基于 LibreOffice 的轻量级转换服务
2. **onlyoffice-docs** - ONLYOFFICE Docs 完整套件

## 技术栈对比

| 特性 | document-converter | onlyoffice-docs |
|------|-------------------|-----------------|
| **编程语言** | Python 3 | Node.js + .NET Core |
| **Web 框架** | FastAPI | 自有框架 |
| **转换引擎** | LibreOffice (headless) | ONLYOFFICE 自有引擎 |
| **容器基础** | Ubuntu 22.04 | 多个专用容器 |
| **镜像数量** | 1 个 | 6 个（docservice, proxy, converter, adminpanel, example, utils） |
| **外部依赖** | 无 | PostgreSQL, Redis, RabbitMQ |
| **资源占用** | 512MB-1GB 内存 | 4GB+ 内存 |
| **部署复杂度** | 低（单个服务） | 高（多个组件 + 数据库） |

## 详细对比

### 1. document-converter

#### 技术栈
- **运行时**: Python 3.11+
- **Web 框架**: FastAPI
- **ASGI 服务器**: Uvicorn
- **转换引擎**: LibreOffice (headless 模式)
- **容器**: Ubuntu 22.04
- **依赖库**:
  - fastapi
  - uvicorn
  - python-multipart
  - pydantic

#### 架构
```
┌─────────────────┐
│   FastAPI App   │
│   (Python 3)    │
└────────┬────────┘
         │
         ▼
┌─────────────────┐
│  LibreOffice    │
│  (headless)     │
└─────────────────┘
```

#### 特点
- ✅ 轻量级（单个容器）
- ✅ 无外部依赖
- ✅ 快速部署
- ✅ 资源占用低
- ⚠️ 转换质量取决于 LibreOffice 能力
- ⚠️ 不支持在线编辑

### 2. onlyoffice-docs

#### 技术栈
- **运行时**: Node.js + .NET Core
- **Web 框架**: ONLYOFFICE 自有框架
- **转换引擎**: ONLYOFFICE 自有引擎
- **容器**: 多个专用容器
  - `docs-docservice-de` - 文档服务
  - `docs-proxy-de` - 代理服务
  - `docs-converter-de` - 转换服务
  - `docs-adminpanel-de` - 管理面板
  - `docs-example` - 示例
  - `docs-utils` - 工具

#### 架构
```
┌─────────────────┐
│  Proxy Service  │
│   (Node.js)     │
└────────┬────────┘
         │
    ┌────┴────┐
    ▼         ▼
┌─────────┐ ┌─────────────┐
│DocService│ │  Converter  │
│(.NET Core)│ │  (.NET Core)│
└────┬────┘ └─────────────┘
     │
     ▼
┌─────────────────┐
│  PostgreSQL     │
│  Redis          │
│  RabbitMQ       │
└─────────────────┘
```

#### 特点
- ✅ 功能完整（在线编辑、协作）
- ✅ 转换质量高
- ✅ 支持实时协作
- ❌ 资源占用高
- ❌ 需要多个外部服务
- ❌ 部署复杂

## 使用场景

### document-converter 适用场景
- ✅ 只需要文档转换功能
- ✅ 资源有限的环境
- ✅ 快速部署需求
- ✅ 不需要在线编辑
- ✅ 不需要实时协作
- ✅ 批量文档转换

### onlyoffice-docs 适用场景
- ✅ 需要在线编辑功能
- ✅ 需要实时协作
- ✅ 需要 UI 界面
- ✅ 对转换质量要求高
- ✅ 资源充足的环境
- ✅ 企业级应用

## 部署对比

### document-converter 部署
```bash
# 1. 构建镜像（单个）
docker build -t document-converter:latest .

# 2. 部署（单个 Deployment）
kubectl apply -f deployment.yaml

# 3. 完成（无需数据库等）
```

### onlyoffice-docs 部署
```bash
# 1. 准备数据库（PostgreSQL）
# 2. 准备 Redis
# 3. 准备 RabbitMQ
# 4. 创建多个 Secrets
# 5. 部署 Helm Chart（多个组件）
helm install onlyoffice-docs ./chart
```

## 资源需求对比

### document-converter
- **CPU**: 0.5-1 core
- **内存**: 512MB-1GB
- **存储**: 1-2GB（临时文件）
- **网络**: 无特殊要求

### onlyoffice-docs
- **CPU**: 2-4 cores
- **内存**: 4GB+
- **存储**: 10GB+（数据库 + 文件存储）
- **网络**: 需要连接 PostgreSQL、Redis、RabbitMQ

## 成本对比

| 项目 | document-converter | onlyoffice-docs |
|------|-------------------|-----------------|
| **开发成本** | 低（简单实现） | 高（复杂架构） |
| **运维成本** | 低（单个服务） | 高（多个组件） |
| **资源成本** | 低（512MB-1GB） | 高（4GB+） |
| **维护成本** | 低 | 高 |

## 选择建议

### 选择 document-converter 如果：
1. ✅ 只需要文档转换功能（Word → PDF/HTML/TXT）
2. ✅ 资源有限
3. ✅ 需要快速部署
4. ✅ 不需要在线编辑
5. ✅ 预算有限

### 选择 onlyoffice-docs 如果：
1. ✅ 需要在线编辑功能
2. ✅ 需要实时协作
3. ✅ 需要 UI 界面
4. ✅ 对转换质量要求高
5. ✅ 资源充足
6. ✅ 企业级应用

## 总结

这两个服务使用**完全不同的技术栈**：

- **document-converter**: Python + FastAPI + LibreOffice（轻量级）
- **onlyoffice-docs**: Node.js + .NET Core + ONLYOFFICE 引擎（完整套件）

它们可以**同时部署**，根据不同的需求使用不同的服务：
- 简单转换 → document-converter
- 在线编辑/协作 → onlyoffice-docs
