## 二、用户的三页

截图在 [`PRD/apps/screens/`](../../PRD/apps/screens/)，`step8-info-` 开头的 10 张。

| 页 | 有什么 |
| --- | --- |
| 申请入库 | 填了六位代码立刻显示查到的情况：还没有数据（要不要等批准）；已有数据（版本、数据到哪一天、去看这个数据集、可以「申请更新」）；已经有人在申请（几个人要、「我也要」）；我自己申请过还在走（进度、去看进度）；我没走完的申请到上限了。申请理由可不填。从别的应用来的写明「从哪来」，有「回到原处」 |
| 我的申请 | 一个申请一行：代码、五站的进度线、现在到哪了、申请时间。有没走完的，页面每 15 秒自己刷新 |
| 一个申请 | 进度线；一句白话说现在到哪；被拒绝时显示管理员写的原因（看不到是谁）；可用之后显示数据版本并能去看这个数据集；批准之前能撤回；结束之后能再申请一次 |

| 守住的规矩 | 怎么守 |
| --- | --- |
| 链接带来的 `code`、`from`、`ref` 不可信（`F-INFO-31`） | `code` 不是六位数字就当没带；`from`、`ref` 原样交给后端认，页面不自己判断 |
| 「回到原处」的地址只从 info 自己的配置里取（`F-INFO-32`） | 页面只用后端给的地址；地址栏里带的任何地址都不用 |
| 用户只看得到自己的申请，看不到别的申请人（`F-INFO-29`） | 页面只显示「几个人要」 |
| 没登录的人打开申请页的链接，登录后回到申请页，参数还在（`AT-INFO-14`） | 见第四节 |

进度线五站：已提交 → 已批准 → 采集中 → 建库中 → 可用。「登记中」算在「建库中」这一站里。没到「可用」就结束的，停在那一站并标红；用户自己撤回的不标红。

没有做的：设计里「最近一次采集没通过质量检查」这种情况（说明没通过、哪天试的）。后端的「查到的情况」接口没有给这一项。

## 三、所有者的三页

| 页 | 有什么 |
| --- | --- |
| 申请审批 | 待批准：一家公司一条，几个人要、最早的申请时间、每个人的理由分开列、从哪个应用来、在不在关注清单里、有没有数据、去看这家的采集记录。动作：批准；批准并加入关注清单；拒绝（必须写一句原因）。已处理：可按状态筛，看谁处理的、什么时候、原因；关注清单里自动批准的写「系统（关注清单）」 |
| 证券采集 | 输入代码直接发起（不产生申请）；这家公司的批次（时间、状态、来源、出错原因，点开看每一项）；数据集（版本、状态、范围、没过的检查、建库时间、登记到 knowledge 了没有）；重新登记（只有发布了的版本能点） |
| 关注清单 | 清单里的公司、加入时间、谁加的、备注；加入（代码与备注）；移出（可写原因，移出不删行）；可以显示移出过的 |

三页只给 info 管理员：页面一道，后端另有一道。

## 五、代码怎么放

和 investment 一样：`features/<功能>/{api,model,ui}`，由同一份测试守着（`tests/unit/feature-boundaries.test.ts`）。网页端两个功能：`shell`、`requests`。管理端一个：`intake`。契约都对着真后端录下来的返回逐份检查。

管理端沿用它底座现成的样式（表格、按钮、对话框），没有引入网页端的组件。
