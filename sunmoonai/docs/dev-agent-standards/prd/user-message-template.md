# PRD 任务书模板

复制成 turn 里的 `user-message.md`。

本阶段的任务书要写清什么，见 [PRD 规则](prd-rules.md)「这一段的任务书」；写多严见 [任务的生命周期](../lifecycle.md)「任务书写多严」，字段的含义见同一份的「turn 的固定字段」。
交回的 response 要能定稿成 `PRD/`，所以它要满足 [PRD 规则](prd-rules.md)「`architecture/` 写什么」「`modules/<模块>/` 写什么」与「纪律」。

```markdown
---
deliverable: PRD
agent: discussion
executor: <具体执行者；未定写 unassigned>
base: <发出时依据的提交>
sent_at: <发出时间>
---
# turn <四位号>：<短名>

## 依据
<以哪一份 `PRD/` 定稿为底，或由哪一段讨论拆出；给出链接与提交>

## 要什么
<这一问要产出什么：要满足的需求、做到什么算满足>

## 范围
- 包含：
- 不包含：
- 不包含的归谁：

## 验收标准
1. <可判定的条件，做完能一条条对着勾>

## 约束
<必须遵守的规则、不能动的东西、外部限制>

## 怎么答
- **只写要什么，不写怎么做**：技术方案属于 SDD；
- 验收标准可判定，不写「响应要快」这类说法；
- 模块划分写清为什么这样分，以及模块之间谁向谁提供什么；
- 还没定的写进「未决」，并写明定不下来会影响什么。

**交回：PRD，写成这个 turn 的 `response.md`，不改代码。**
```

不适用的栏写「不适用」及理由——空着与「忘了」无法区分。命中 T2 判据的任务每一栏都要填。
