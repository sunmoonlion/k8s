## 职责

跑在用户电脑上的常驻后台进程。主动连后端，接收 Attempt 并驱动 Codex；向 Codex 提供本地 MCP
（本地知识库、`escalate`）与公开资料取数工具；做工具级审批与副作用记账的拦截点；保管 key；
定工作区与沙箱策略；对结果做本地内容检查与加密；上报事件、用量、副作用意图与回执；
**提交前按本机确定性规则预填任务类别**。

**它是三方里唯一碰得到模型 key 的一方**，也是结果**加密前**唯一碰得到正文的一方；后端两样都看不到。
⚠ **不能写成「桌面应用不碰正文」**——桌面应用要渲染研究底稿，它持有的是**解密后**的正文。
两边都碰正文，区别在**各持一把不同的密钥、互不持有对方那把**：
模型 key 只在 runtime，结果密钥只在桌面应用（`F-CRYPTO-01`、`F-CRYPTO-03`）。
逐跳边界见 [数据流与信任边界](../../../architecture/trust.md)「三把东西的逐跳归属」。

类别预填归到这里也是同一个理由：那一层要读用户的文件。

### 类别预填

三层判定的第二层（规则见后端的 [`routing.md`](../../../architecture/routing.md)，三层是一个整体，
本文件不重复那里的条文）。**算在这里，确认在桌面应用**：桌面应用经 ③ 把这次要带的本机文件与
任务文本交过来，这里按确定性规则算出类别送回去，由用户确认或改正后随提交上报。

## 输入与输出

| 方向 | 内容 |
| --- | --- |
| 从后端收 | 带签名的派发内容、租约与续约、取消、审批结论、厂商预设 |
| 从桌面应用收 | 工具级审批与本地确认的结论、key 与模型配置、工作区授权、本地知识库操作、**类别预填请求（提交前，带这次要带的本机文件与任务文本）** |
| 给 Codex | 运行时 thread 与 turn、本地 MCP 工具、取数工具、**后端方法工具的代理**、审批回调 |
| 给后端 | 事件与进度、副作用意图与回执、工具级审批结论摘要、用量、结果密文与本地内容检查回执、**方法工具的调用** |
| 给桌面应用 | 审批请求、本地确认请求、runtime 状态、**预填出的类别（只给类别，不给依据）**。⚠ **不给结果正文、不给结果密钥、不给本地资料内容**：结果以密文经后端流到桌面应用，由它自己解密（`F-CRYPTO-03`） |

## 验收

- `F-EXEC-*`；`F-APPROVE-01` 至 `F-APPROVE-04`；`F-INTAKE-07` 的预填侧；
  `F-GUARD-01` 至 `F-GUARD-03`、`F-GUARD-05`，以及 `F-EXEC-12` 的执行侧；
  `F-ACCEPT-02` 的检查与回执；`F-CRYPTO-01`；`F-DELIVERY-11`。定义见同目录 [`functions.md`](functions.md)；
- 不变量 `I14`、`I16`、`I18`、`I19`、`I20` 的执行侧成立；
- 合同验收矩阵中涉及执行端的场景可复现。

## 约束

- **不持有任何持久化账的权威副本**，也不自行决定 Task 状态（`I13`）；
- 方法工具**只代理不实现**：清单随派发下发、随换步失效，调用经 ① 转后端执行，本地不缓存；
- **key 只在本机**：存系统钥匙串，不写配置文件，不进任何协议字段（`I16`）；
- **预填只输出类别**：文件内容、文件名以及由它们派生的任何特征都不上报、也不交给桌面应用（`I20`、`F-CRYPTO-07`）；
  这一层不调模型（D11 未定之前）；未经用户确认的预填不算数（`AT-32`）；
- 与后端只有一条通道（①），主动外连，用设备私钥认证；
- **独立成仓（仓名 `runtime`）且开源**：二进制签名、可复现构建、公开会连接的全部域名（`C-T7`；合同「让用户能验证」）。随 `desktop-app` 打包分发，但两仓各自发版——版本配对靠发布清单一起钉住 runtime 版、① 协议版、desktop 版（`C-T8`）；与用户自装的 Codex 隔离；
- 遵守 [代码规则](../../../../rules/constraints.md)、[IMP 规则](../../../../../dev-human/imp/message-rules.md)。
