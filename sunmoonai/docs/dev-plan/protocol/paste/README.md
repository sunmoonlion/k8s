# 投喂话术模板 ｜ 交互会话用

## ⚠ 先说清楚：这不是同一件事的两种格式

`dispatch.md`（一次性命令行）与本目录（交互会话贴的话）**不是同一条路的两种写法，
是两条能力不同的通道**，产出也确实不同。这一点在 `rounds/executor-adapter/` 查过实测，
不是推断：

| | 一次性命令行 `codex exec` / `agent -p` / `qoder -p` | 交互会话（人开着窗口） |
|---|---|---|
| 回话通道 | **没有** | 有 |
| agent 需要一次往返（批准、澄清、追加权限） | **只能放弃并退出** | 当场解决 |
| 2026-09-06 实测端到端 | **没走完**，四个决策点全部回落到人 | **走完**：cursor 自己读、自己写、**自己提交** |
| `cursor` 提交行为 | `-p` 下**不提交**（三次） | 交互式跑一次即提交 |
| 成功判据 | **产物出现**，不是退出码（`-p` 拒绝执行仍返回 0） | 同左 |

原文：`rounds/executor-adapter/task.md` §1.0，以及所有者当时的定性——
「投喂和用 SDK 机制不一样吧……否则很多回复权限等如何解决？」

### ⚠ 2026-09-09 更正：上面那条差异**不该扩散到「该做什么」**

此前本节写的是「`GO.md` 只服务交互通道，CLI 那条路的入口是 `round-protocol.md`，
**这是有意的**」。**那个「有意」是我事后追认的，不是设计。**当天查实：

| CLI 通道的入口 `round-protocol.md` 里 | 处数 |
|---|---|
| 「你是谁」身份确认 | **0** |
| 怎么提交 | **0** |
| 卡住了怎么办 | **0** |

而 `executor-adapter` 记的现象正是「**`cursor` 写出产物但不提交（三次）**」。
当时归因给工具（「`-p` 非交互模式下就是不提交」）；
**从没测过另一个解释：它拿到的那份文档从头到尾没提过「提交」两个字。**

⇒ **通道不同 ≠ 该做什么不同。**现在两条通道说同一句话、指同一份 `GO.md`，
通道差异**只在 §五 一处**分支：

| | 交互 | 一次性命令行 |
|---|---|---|
| §五「卡住了」 | 停下来说 | **不停**：能做的做完照样交，把卡住处写进产物标 ⚠，绝不猜着往下走 |
| 其余五节 | 通用 | 通用 |

⚠ **仍然不要把 `GO.md` 与 `round-protocol.md` 并掉**——但理由不是通道，是
**法 ≠ 操作手册**：协议 944 行跨轮次常驻，`GO.md` 197 行是此刻要走的六步。
`GO.md` §四 已降为**被 `doc-gate` 核对的引用**（F-23），漂移会被报出来。

## 为什么路径全是写死的

`rounds/dev-plan-refact/findings.md` **F-17**：2026-09-08，整合方按 GO.md 停下，
报了四条「缺东西」，四条全部属实——**在它的分支上**属实。它的分支冻结在四小时前。

GO.md 里早就写着「通知去主线读」，**但那句话只存在于主线那一版上**：
要读到它，得先知道去主线读。**修「读错地方」的修法，写在了只有读对地方的人才看得见的地方。**

由此得出（`artifact-lifecycle-notes.md` §28 / L-7）：

> 真正的入口不是 `GO.md` 这份文件，**是所有者在窗口里说的那句话**。
> 它是全系统唯一一条**不经过任何投影**的通道——所以它必须自带绝对路径，
> 而不能靠人记得写对。

**所以模板里没有「路径」这个空。**要填的只有 `{家名}` `{环节}` `{轮次}`，填错了对方会立刻报错，
不会像 F-17 那样静默地读到一份旧的还以为是新的。

## 用哪一份

| 情况 | 文件 |
|---|---|
| 常规派发（任何环节） | `派发.txt` —— 通常整段贴，一个空都不用填 |
| 对方报「缺东西 / 字段是空的 / 没有这个文件」 | `过期投影.txt` |

⚠ **先别信「它搞错了」。**F-17 那次，对方报的四条全对。
拿到这种报告的第一动作是核实**主线上**是什么、**它分支上**是什么——两边不一样就是本文这一类。
