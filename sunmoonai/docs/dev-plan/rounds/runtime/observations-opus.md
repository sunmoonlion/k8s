# 本轮实测的失败模式 → 运行时必须具备的机制

> 裁决方登记 ｜ 2026-09-05 ｜ **观察值，不进验收**
> ⚠ **① 期间不发布到共享基线**：这是裁决方写的设计输入，给提案方看会污染本轮。③ 裁决后公开。
> 每条都是本轮真实发生的，不是设想。

## A. 判据给出假答案（三次，已达升级门槛）

| # | 边界条件 | 产出的假答案 | 后果 |
| --- | --- | --- | --- |
| A1 | 验收方未指派，`done` 为空字典 | `all({})` 为真 → ⑤ 报「完成」 | 当前环节会在 ①–④ 齐后**跳过 ⑤ 验收**落到 ⑥ |
| A2 | cwd 在 git 仓外 | `git` 退 128 被管道吞，`basename` 对报错文本输出一串 `.` | 不响亮失败，agent 退回文本推理 |
| A3 | 身份判别失败后 | 「我跑在 Cursor 产品里 → 我是 fable」 | `cursor` 自判为 `fable`，宣告要写他家 worktree |

**三次同源**：不是「检查漏了一项」，是「检查产出了一个可被下游继续推理的结论」。

**运行时要求**
- 每个判据必须能表达**第三态「不可判」**，且 `不可判 ≠ 通过`。布尔判据是缺陷，不是简化。
- 聚合判据（`all` / `any` / 全员完成）**必须显式定义空集合上的取值**，默认真是错的。
- 判据失败必须**响亮**：不得返回一个形状正确但内容错误的值。
- 对应本轮 §3.3 **P3**：这正是「可观测粒度」的判据侧——观测不到时必须说观测不到。

## B. 身份与归属

| # | 事故 |
| --- | --- |
| B1 | `cursor` 差点把候选写进 `~/worktrees/fable`（所有者当场拦下，无污染） |
| B2 | 裁决方据 `agent --list-models` 里有 fable 模型，推断 fable 走 CLI——**错**，它跑在 GUI |
| B3 | 裁决方据一段会话输出判定「那个窗口是 fable」——**说反了**，是 cursor |

**运行时要求**
- **身份不能由执行者自报。**必须由 orchestrator 在派工时绑定，并在**写入时强制**（写入路径鉴权），
  不是在提示词里叮嘱。
- **工作区独占必须是隔离，不是约定。**CLI 腿做不到（进程看得见整个文件系统），
  所以运行时必须在**外层**加写入边界——这正是本轮 P3 后果②说的：
  §3.13 三道边界是永久架构组件，不是 bootstrap 措施。
- **消歧文本会被当成推理前提。**写「A 是甲产品、B 是乙产品」意在防混淆，
  实际给了 agent 一条从产品推身份的路。**身份只能有一个来源，其余全部显式标为「不是证据」。**

## G. 一条元观察

本轮到目前为止，**裁决方犯的错（A1 A2 A3 的成因、B2 B3、C1 C2 C3、D1、E1）多于执行者犯的错。**
这与「运行时是可信控制面、执行者是不可信外围」的直觉相反。

若运行时按那个直觉设计——只防执行者、不防自己——它会在本轮这类问题上原样翻车。
**控制面自身的动作也必须留痕、可复算、可被他方推翻**，这正是权力表把
`enforcement_point` 放在凭据层而不是脚本层的理由的一般化。

## H. 人不能离开 —— 收益的真变量

2026-09-05 ② 环节现场：qoder 就一条**只读**命令
（`git cat-file -p <ref> | sha256sum`，qwen 在核 ② 通知里的候选校验和）弹出放行框。
该提示对运行时**完全不可见**——裁决方是所有者转述才知道的。

**所有者的判断（采纳为本轮核心观察）**：如果人必须守着逐次放行，那运行时的收益就很小。
「投喂几次」只是表象，**「人能不能离开」才是收益的真变量。**

### 两类打断必须分开计价

| 类 | 例 | 该不该打断人 |
| --- | --- | --- |
| 甲：执行者自带沙箱的放行提示 | qoder 问只读命令能否执行 | **不该**——这不是人要做的决定，是策略要做的决定 |
| 乙：H 类审批 | H1 冻结、H5 签发、⑥ 确认 | **该**——这就是它存在的意义 |

甲的存在是封闭 CLI 的直接后果：其沙箱有自己的策略引擎，运行时配不了，只能弹给人。
运行时自己的 agent（SDK 腿）在工具层按策略放行，人不在环里。
**这是 P3 从「人的成本」一侧看到的同一件事。**

### 放行粒度应按可逆性分，不按命令形状分

现有 CLI 的放行判据是**命令形状**（复合命令、`cd`、循环 → 弹框），
所以一条只读命令因为带了 `for` 循环就要人点一下。正确的轴是可逆性：

```
只读                          → 无限自动放行
写自己 worktree 内            → 自动放行
写他家 worktree / 出网 /
push / 碰凭据                 → 不该靠提示框拦，应在外层边界上不可能发生
```

### 由此重排优先级

**「放行面越宽，人越能离开；边界越弱」这个张力，不该在这条轴上取中点，应该换轴：
只要外层边界摆对，内层放行面就能安全放宽。**

而当前外层边界一个都没建（S1 未做，VM 的 `id_rsa` 仍可推主仓，见 `rulings.md` `R2`）,
那些提示框在兼职当唯一的安全网——**这才是人不能离开的根因，不是提示太多。**

结论：**S1 不是「以后要做的安全加固」，它是「让人能离开」的前提，应往前排。**

### 对必答 Q 的补充（观察值，不改冻结的题目）

`task.md` §3.4 必答 Q 问的是开销盈亏线。本条说明该线的计量里
**必须含「人被打断的次数」，而不只是「人主动动作的次数」**——
且甲类打断对运行时不可见，账本天然记不到它。
这与 `R2`「所有者没有 agent 够不着的操作面」是同一个盲区的两面。
