## 已确认的变化

产品合同已经改为桌面端、本地 runtime、后端 supervisor、知识服务；控制面使用状态机、
事务 outbox 和队列，不引入图执行框架。不能把旧“先补浏览器生产适配器”直接作为下一步，
也不能把现有 Pilot 的 LangGraph 断点与工具运行时扩大成新产品后端。

现行任务树与合同尚未完全对齐：根 PRD 仍写“前后端对接→agent→问数”，
Backend PRD 仍写“两部分”和“共享 Outbox 尚未接线”；后者也与已有投递代码不符。
合同附录 E 已明确这些是要修改的落点，因此不以旧 PRD 压过新合同。

## 为什么本轮不能标“已正式迁入”

1. 合同 D1 仍明确待定：任务树第一层继续前/后端两部分，还是桌面/runtime/后端三部分。
   新子任务只允许从定稿设计长出；执行者不能代拍 D1 或先建一套未批准的模块树。
2. D2/D3（审批与本地确认）、D7（桌面模板与现有前端去向）、D9（签发权）、D15
   （本地知识库）、D24（Windows 支持/沙箱）尚待决定，各自限制详细实现边界。
3. 原 N3 的失效传播、N4 保留政策与 N6 扩展触发条件还没有完整完成条件；
   “合同提到了”不是可派工的 IMP 包。N4-OPS-01 是目前唯一已落为独立待派工任务的旧子项。

因此本轮完成的是可复核的接收映射与冲突定位，不冒充新计划已定稿或产品已实现。
下一步需要用户确认任务树落点，再开对应 PRD/SDD turn 完成定稿；不改既有已冻结 turn。
无须为这个决定停止 B7 与新产品无冲突的隔离验证。
