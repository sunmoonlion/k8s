# App Platform 生产就绪标准

## 1. 目标

本文定义应用或重大功能进入生产环境前必须满足的共同条件。开发环境可以分阶段实现，但任何未满足项必须被明确记录，不能以“已经部署”代替“生产就绪”。

## 2. 责任与边界

- 有明确的领域所有者和维护责任人。
- 架构文档描述职责、非职责、数据所有权和依赖。
- API、事件和文件交换遵循平台集成规范。
- 不直接访问其他 App 的内部存储。
- 外部依赖和故障影响范围有记录。

## 3. 数据与迁移

- 权威数据、派生数据和临时数据已经分类。
- 数据库变更使用可追踪迁移。
- 发布过程定义向前兼容窗口和回滚策略。
- 关键写入具备幂等、审计和并发控制。
- 数据保留、删除、更正和归档策略明确。
- 重要计算支持按历史版本重现。

## 4. 可靠性

- 定义服务 SLI、SLO 和告警阈值。
- 定义可用性、RPO 和 RTO。
- Stateful 组件具备备份和恢复流程。
- 至少完成一次可验证的恢复演练。
- 外部依赖调用具备超时、有限重试和故障隔离。
- 异步任务具备死信、重放、对账和积压处理方案。
- 单实例或单节点故障风险被明确接受或消除。

PVC 的 `Retain` 策略不是备份，Kind 和 local-path 只作为开发环境能力。

## 5. 可观测性

- 应用输出结构化日志。
- 请求、任务和事件携带 `trace_id`。
- 暴露健康检查和业务指标。
- 建立服务、数据库、队列和关键业务流程仪表盘。
- 告警包含影响、定位入口和处理手册。
- 日志、指标和链路具有适当保留周期。

目标平台能力包括 Prometheus、Grafana、集中日志和 OpenTelemetry；在平台尚未建设完成前，各 App 仍需预留标准接口。

## 6. 安全

- 生产密码和密钥不以明文提交到 Git。
- 使用独立用户、服务身份和最小权限。
- 配置 NetworkPolicy 和 Namespace 隔离。
- Pod 使用非 root、只读文件系统等适用的安全配置。
- 镜像经过漏洞扫描，保留来源、版本和 SBOM。
- 外部及服务间通信根据风险启用 TLS。
- 认证、授权、管理操作和敏感数据访问进入审计日志。
- 敏感字段在日志、错误和监控标签中脱敏。

开发环境当前允许提交开发凭据，不代表生产环境可以沿用。

## 7. 交付

- 镜像使用不可变版本或 Digest，不依赖浮动 `latest`。
- Helm/Kubernetes 配置区分开发、测试、预发布和生产。
- 发布前执行配置校验、迁移检查和自动化测试。
- 发布过程支持健康判断和自动或人工回滚。
- 环境变更可审计，长期目标采用 GitOps。
- 第三方 Chart 和镜像具有固定版本及升级记录。

## 8. 容量与性能

- 给出正常和峰值负载估算。
- 设置合理的 requests、limits 和存储容量。
- 定义水平扩容条件及不可水平扩容的瓶颈。
- 对大文件、批任务和突发消息使用背压与限流。
- 完成关键路径的基准测试或容量验证。

## 9. 业务连续性

- 核心业务流程具有降级方式。
- 模型、搜索或 RAG 不可用时，不影响权威数据保存。
- 派生系统可以从主档重建。
- 关键第三方服务具备替代、暂停或人工处理方案。
- 灾难恢复流程明确恢复顺序和依赖。

## 10. 投资系统特别要求

- 研究结论保留资讯和数据版本。
- AI 结果记录模型、Prompt、参数和引用。
- 组合、估值、风险和决策变更可以审计。
- 金融计算使用确定性规则和基准样例验证。
- 证券主数据、交易日历、币种和公司行动有权威来源。
- 涉及真实交易前，单独完成合规、审批、职责分离和风控评审。

## 11. 上线检查

每次生产发布至少确认：

```text
[ ] 领域和数据所有权明确
[ ] 契约变更兼容
[ ] 数据迁移已验证
[ ] 自动化测试通过
[ ] 备份可用
[ ] 监控和告警可用
[ ] Secret 和权限符合要求
[ ] 容量满足预期
[ ] 回滚或补偿路径明确
[ ] 运维手册已更新
```

未满足项必须有责任人、风险说明和完成期限。
