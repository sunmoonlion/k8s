# turn 0001：多方竞争这一块要满足什么

上一层的设计把后端切成八块，分给这一块的是**多方竞争**：同一问派给几家、收齐后择优并记录处置。
边界（承担什么、不承担什么、为什么单列）见 [`SDD/modules/0008-competition.md`](../../../../../modules/0008-competition.md)，
块与块之间的关系见 [`SDD/architecture/blocks.md`](../../../../../architecture/blocks.md)。

这一问要的是：**这一块具体要满足什么、什么算满足**。

- 归这一块的功能义务（`F-*`）与不变量（`I*`）分别是哪些，逐条列出；没有现成的就说明要新增哪几条；
- 输入与输出：从谁拿什么、给谁什么；
- **并行 N 个 Attempt 时，隔离靠什么保证**——现在人这一侧是靠纪律，产品侧必须靠机制；
- 候选怎么冻结、怎么取件、摘要记在哪；
- 处置表的字段与机器可读形状；
- 验收方的算出规则怎么落成代码（既得利益最小的一家）；
- 异议的时机与效力；
- 哪些边界要等 `D10b` 拍板才能定，明确标出来，**不要替它拍**。

## 只读输入

- [多方竞争协议](../../../../../../../../../../turn/protocol/competition-protocol.md)——**人这一侧现行的规则**，
  1052 行。产品侧要满足的是同样的意图，不是照抄它的操作步骤；
- [多方竞争](../../../../../../../../../../turn/competition.md)——档位判据与导航；
- `others/` 下两份 **luna 的未生效草案**（`draft-luna-general.md`、`draft-luna-pro.md`）：
  ⚠ **是参考，不是依据**。它们写于「人版与 agent 版是两套流程」的旧前提下，
  而现在的模型是[同一条九站、每站谁做是变量](../../../../../../../../../../pipeline.md)。
  可借的是职责划分与失败模式，**不可直接采信其结论与编号**。

## 边界

- **不含**「这一步要不要走竞争」的判定——那归 `0003-orchestrator`；
- **不含**「做对没有」的判定——那归 `0006-acceptance`；本块只管「哪一份更好」；
- **不含**人这一侧的操作细则（投喂、GO、取件命令）——那些随「派发这一格谁做」变，
  见 [`turn/protocol/`](../../../../../../../../../../turn/protocol/README.md)。
