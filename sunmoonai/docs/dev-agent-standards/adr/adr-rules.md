# ADR：架构决策记录（Architecture Decision Record）

ADR 和 PRD、SDD、IMP、UAT 一样是一段任务，只是**粒度不同**：那四段对一大片做整体设计，
ADR 针对**一个具体问题**——在任何一段里冒出来、需要定下来、而且以后有人会问「为什么是这样」的那种。

定稿是 `adr/<四位号>-<短名>.md`，一个决策一份。

## 这一段的用户消息

要说清的只有两件：**要定的是哪一个问题**，以及**已知的事实与出处**（每条给出处，分清事实、推断与假设）。
没有模板，也没有必填栏。写多严见 [任务的生命周期](../lifecycle.md)「用户消息写多严」。

## response 写什么

这一问的回答：可以是分析、可以是方案对比、可以是把问题重新问清楚。要求：

- **区分事实、推断、假设与未知**，不把推断写成事实；
- 给出取舍的**理由与代价**，不只给结论；把否掉的选项也写出来；
- 涉及外部规则（资质、合规、平台限制）时标明依据与出处，查不到就写「未核实」；
- 不替人做决定：把选项和后果摆清楚，决定由人下。

## 定稿成一份 ADR

人读完 response，整理成 `adr/<四位号>-<短名>.md`：

| 部分 | 写什么 |
| --- | --- |
| 背景 | 什么问题、为什么现在要定；已知的事实与出处 |
| 决定 | 定下来的是什么，一句话能说清 |
| 否掉了什么 | 还有哪几条路、各自代价、为什么不选 |
| 后果 | 这么定之后什么变了、带来什么约束与风险、谁受影响 |
| 出处 | 定于哪个 turn（写「thread 号/turn 号」）；取代哪一份 ADR（有则写） |

- **编号在 `adr/` 内从 `0001` 起递增，不跳号、不复用**；
- **只增不改**：改主意就新写一份，写明取代哪一份；**被取代的那份留着不删**——作废的判断本身是证据；
- **和定稿目录不重复**：`PRD/`、`SDD/` 写「是什么」，ADR 写「为什么是它、否掉了什么」。定稿里引用 ADR 的编号，不抄理由。

## `adr/` 放在哪一层

放在任务目录里，与 `thread/`、`PRD/`、`SDD/` 并列。**影响多个模块的决策，放在它们共同的上层节点的 `adr/`**——
用任务树本身表达作用范围，不另立全局目录。
