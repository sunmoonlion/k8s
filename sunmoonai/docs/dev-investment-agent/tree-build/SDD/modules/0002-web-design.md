# `0002-web` 网页设计（初稿，待所有者改）

> 页表与义务在 [`0002-web.md`](0002-web.md)。这一份回答"用户在网页里怎么走、每页长什么样、什么状态下看到什么"。
> 依据：[需求](../../PRD/requirement.md)「两层决策权」、[方向盘](../architecture/wheel.md)、[审批](../architecture/approval.md)「Task 级审查必须表达」、[Task 契约](../architecture/task-contract.md)「结果信封」「交回物」、[工作区](../architecture/workspace.md)、[状态机](../architecture/state-machine.md)。
> 初稿由远程助手 2026-09-24 写；所有者改定后才动代码（先冻结契约，再按 `F-WEB-06` 生成客户端）。

## 一、六条设计原则

| # | 原则 | 由哪条需求来 |
| --- | --- | --- |
| P1 | **方向盘永远可见**。任何一页的顶部都答三个问题：谁在驾驶、在做什么、我现在能做什么 | 两层决策权是产品本质（需求 1.1，方向盘） |
| P2 | **数字可核查**。底稿里每个数字都能点开看到来源、时点、数据版本；没有来源的数字不加粗、不放表格 | 三元组里的"专业知识"；`F-KNOW-02`；`F-WEB-05` |
| P3 | **结论栏是用户的**。顾问从不写结论；页面上结论栏永远是编辑框，空着或标"用户草稿" | `F-POS-03`、`F-WEB-05` |
| P4 | **一次只问一件事**。等用户决定的事只有一个入口（待办），一个 Interaction 只开一个审查面，审查面必须五要素齐 | 审批「Task 级审查必须表达」；`F-WEB-04` |
| P5 | **本地代理离线不阻塞**。浏览、设置、底稿、历史都能看；只有"发 turn"和"求助"需要代理在线 | `F-WEB-07` |
| P6 | **文案说事实，不说判断**。状态词用产品语言（"专家驾驶中"），不用状态机词（`RUNNING`）；错误不泄露路径、凭据、他人信息 | Task 契约「失败结果」；`C-D9` |

## 二、三条旅程

### 旅程 A：自驾（第一层，不建单）

```
登录 → 工作台首页（我的机器 / 我的会话）
    → 新会话：选机器 → 选工作区 → 选项目目录 → 会话建立（thread/start）
    → 会话页：对 Codex 说话 / 看它做了什么 / 答工具级审批
    → 质量信号条出现（引用为零、时点过期…）→ 提示"可以问专家"（不强推）
```

用户看到的是"我的 Codex 在我的目录里干活"。工具级审批当面答（`approvalPolicy` 由设置页定）。这一层不出现任何"专家""任务""预算"字样。

### 旅程 B：求助（交出方向盘 → 拿回底稿）

```
会话页「问专家」→ 求助面：写清问题 / 选专家包 / 设预算 / 勾资料 → 交出
    → 方向盘状态带切换为"专家驾驶中"：第 k 步 / 已花费 / 取消
    → 期间三种打断：等我决定（Interaction）/ 预算用完 / 机器断线
    → 终态：方向盘交回 → 底稿页：结果 / 证据 / 交回物 / 工作区变更 / 我的结论
```

关键时刻只有两个：**交出**（用户明确知道自己让渡了什么、要花多少、随时能收回）和**交回**（用户明确知道做了什么、什么核实了、什么没核实、文件怎么恢复）。这两个时刻各有一个专门的界面（求助面、底稿页），不混在会话流里。

### 旅程 C：复盘与设置

```
工作台首页 → 历史会话 / 历史委托 → 底稿页（可再编辑结论、可重新求助）
工作台首页 → 设置：模型 key / 会话默认（模型、审批策略）/ 我的机器（白名单、在线状态）
首次进入且无机器 → 安装引导（下载代理、运行、白名单、回到网页看到机器上线）
```

## 三、信息架构

```
/                                公开首页（未登录也能看）：产品是什么 + 注册入口 + 申请邀请码
（登录、注册）                    Casdoor 托管页，不在本站路由里
/workbench                       首页：机器、会话、待办汇总、最近底稿
/workbench/sessions/{id}         会话页（旅程 A 主页面，求助面是它的侧栏/抽屉）
/workbench/tasks/{id}            底稿页（旅程 B 终点；也是历史委托的落点）
/workbench/tasks/{id}/review/{interactionId}   审查面（Interaction；可从待办、会话页、通知进入）
/workbench/settings              设置：key、会话默认
/workbench/machines              我的机器：代理状态、白名单、安装引导
```

导航只有一层：首页、设置、我的机器。会话页和底稿页从首页进入，彼此互链（会话页任务卡 → 底稿；底稿 → 回到会话）。

**全局元素**（每页都有）：
- 顶栏：产品名、当前机器在线状态点、待办数角标、用户菜单；
- **方向盘状态带**（只在会话页与底稿页）：见组件 K1。

## 四、页面规格

每页按：目的 → 区块 → 状态 → 动作 → 数据来源。

### 4.1 首页 `/workbench`

- 目的：一眼看到"有没有事等我"和"从哪继续"。
- 区块：① 待我决定（Interaction 列表，空则不显示）；② 我的机器（名称、在线/离线、最后心跳、白名单根目录数；无机器时整块换成安装引导）；③ 会话（项目目录、方向盘、最近活动时间、是否有进行中的委托）；④ 最近底稿（任务、专家包、终态、费用、时间）。
- 状态：无机器（引导）；有机器离线（黄点 + "代理离线，可浏览不可发 turn"）；无会话（"新建会话"大按钮）。
- 动作：新建会话（三步：机器 → 工作区 → 项目目录，目录从该机器白名单下拉，可手填子目录）；打开会话；打开底稿；处理待办。
- 数据：`/environments`、`/sessions`、`/tasks`、待办需要跨会话的 pending Interaction 列表（**契约缺口 G1**）。

### 4.2 会话页 `/workbench/sessions/{id}`

三栏：左 = 过程（时间线），右 = 侧栏（当前委托卡 / 求助面 / 待办），底 = 输入框。

- **方向盘状态带**（K1）置顶。
- **时间线**：只投影完成事件，按"你说 / Codex 说 / 做了（命令、改文件、查数据）/ 交接 / 步骤 / 等你决定"六类分色；命令与文件变更折叠显示；数据查询显示工具名与数据版本（P2）；delta 不显示；断线与重连显示为一条系统行。
- **输入框**：`wheel=user` 时可用；`wheel=advisor` 时禁用并显示"专家驾驶中，你可以看进度、答复待办或取消"（`F-WEB-03`）；代理离线时禁用并显示原因（P5）；发送中显示"已提交，等 Codex 接手"直到 `turn/started`。
- **质量信号条**：出现在时间线与输入框之间，一行：信号名 + 一句话 + "问专家"按钮 + 关闭。同一信号一次会话只提一次。（依赖 `F-SIGNAL-01`，**契约缺口 G2**）
- **侧栏**：
  - 无委托：求助面折叠为一个按钮"问专家"，展开见 4.3；
  - 有委托：委托卡（专家包、第 k/n 步与步名、状态、已花费/上限、取消、打开底稿）；
  - 有待办：待办卡置顶（K2 的摘要形态，点开进审查面）。
- 状态：连接中 / 实时 / 离线重连（右上角小字，`F-WEB-02`）；thread 未建立（"正在连接你的 Codex"）；机器断线（时间线系统行 + 输入框禁用）。
- 数据：`/sessions/{id}`、`/events` + SSE、`/tasks/{id}`。

### 4.3 求助面（会话页侧栏抽屉）

- 目的：让用户明确"我在让渡什么、花多少、能收回"。
- 区块：① 问题（默认带入最近一条用户消息，可改；必填）；② 专家包（列表带一句话"解决什么 / 不解决什么"，六问里的两问；判不出不默认，`受理`）；③ 预算上限（币种、默认值、说明"用完会停下来问你"）；④ 资料（勾选已上传的资料，或上传；第一期显式上传）；⑤ 交出前的确认块：三行固定文案——"专家将驾驶你当前的 Codex 会话，直到完成或你取消""专家可自动做：读文件、在项目目录内改文件；其余动作会问你""费用从你的模型 key 计，另计顾问费（第一期只记账）"。
- 动作：交出方向盘（幂等键由页面生成一次）；取消。
- 状态：专家包不匹配（受理拒绝，显示原因，留在第一层）；代理离线（不能交出）；已有进行中委托（不能再交出）。
- 数据：`/handover`；专家包清单需要接口（**契约缺口 G3**）。

### 4.4 审查面 `/workbench/tasks/{id}/review/{interactionId}`

按审批文档五要素逐块布置，每块一个标题，缺一不可（K2）：

| 块 | 显示 |
| --- | --- |
| 问询定位 | 哪个委托、哪一步、问的是什么主体（命令 / 文件 / 外发 / 预算 / 目标） |
| 待决内容 | 要决定什么；每个选项一行，后面跟"选它会发生什么"；证据等级；未知项列表 |
| 决定对象 | 涉及的文档版本与摘要值；改动摘要（命令原文、patch 摘要、金额）；有验收条时附冻结的验收条与当前结论 |
| 时效 | 截止时间；目标状态版本；过期后会怎样（不等于拒绝也不等于同意，委托停在等待） |
| 决定记录 | 提交后显示：谁、何时、选了什么、实际生效值 |

- 工具级审批（用户自驾时）用同一面的**简版**：定位 + 命令/patch + 允许/拒绝；不出现预算与验收条。
- 动作：每个选项一个按钮；资源类有金额框；提交后按钮变为记录。令牌失效（页面过期）提示刷新。
- 数据：`/interactions/{id}`（**契约缺口 G4**：现在 Interaction 只有 title/question/options/subject/unknowns，缺 evidence 等级、决定对象版本、时效、决定记录）。

### 4.5 底稿页 `/workbench/tasks/{id}`

- 目的：交回那一刻用户要的四个答案 + 一个属于他的编辑框。
- 区块（按结果信封）：
  1. **摘要行**：专家包、终态（成功 / 打回 / 失败 / 取消）、费用（已用 / 上限）、完成时间、数据时点 `data_as_of`；
  2. **结果**：`human_summary` 与 `structured_result` 的表；表中每个数字带来源角标，点开浮层显示来源、时点、数据版本、查询摘要（P2）；
  3. **证据**：`evidence[]/citations[]` 列表，每条来源、时点、版本；可按数据版本分组；
  4. **局限与不确定性**：`limitations[]`；
  5. **交回物**（handback，`AT-25`）：做了什么（步骤与结论）、什么已核实（带验收条）、什么未知、工作区怎么恢复；
  6. **工作区变更**：改了哪些文件、备份版本在哪、恢复按钮（第一期只显示，不做一键恢复）；
  7. **我的结论**：编辑框，标"用户草稿"，保存出新版本；从不预填顾问文字；
  8. **交回物版本**：每个 Artifact 的名字、版本、摘要值；点开看内容（JSON 折叠）。
- 状态：进行中（只显示摘要行 + 已完成步骤的交回物，其余灰）；打回/失败（显示稳定错误码与用户可理解说明、是否可重新提交、已发生副作用）；取消。
- 动作：保存结论；重新求助（带入原问题）；回到会话。
- 数据：`/tasks/{id}`、`/tasks/{id}/artifacts`、`PUT /conclusion`；证据角标需要 `evidence[]` 结构化到数字（**契约缺口 G5**）。
- 明确不渲染：`rating`、`target_price`、走势、买卖建议字段（`F-POS-04` 拦截在云端，页面再守一层）。

### 4.6 设置 `/workbench/settings`

- 区块：① 模型 key（厂商、key 密码框、提交一次；列表只显示厂商、末四位、状态、登记时间；撤销）；② 会话默认（模型、审批策略四选一，每项一句人话解释）；③ 顾问费与预算默认（第一期只记账，显示"暂不收费"）。
- 状态：凭据库未配置（服务端 503 → "此站点未开通 key 托管"）。
- 数据：`/prefs`、`/credentials`。

### 4.7 我的机器 `/workbench/machines`

- 区块：① 机器列表（名称、系统、代理版本、Codex 版本、在线状态与最后心跳、白名单根目录）；② 安装引导（三步：下载并安装签名代理 → 运行 `sunmoon-agent init` 登记 → 在代理里加白名单目录；每步一个"完成后这里会变绿"的检查点）；③ 本地上限说明（沙箱模式、网络、根目录只能在那台机器上改，网页只显示）。
- 状态：无机器 / 离线 / 版本不配（`AT-28`，显示要升级到哪个版本）。
- 数据：`/environments`；心跳与在线状态需要接口（**契约缺口 G6**）。

### 4.8 公开首页 `/` 与注册入口（2026-09-26 定）

注册是自助的，但要邀请码（`security.md`「账号与注册」）。注册入口只放两处：

| 位置 | 放什么 | 怎么实现 |
| --- | --- | --- |
| 公开首页 `/` | 主按钮「登录」；次按钮「有邀请码？注册」；一行小字「没有邀请码？申请一个」 | 注册按钮直接链到 Casdoor 该应用的注册页（`/signup/sunmoonai-investment-web`）；申请邀请码是 mailto 链接，收件地址由配置给（`WEB_INVITE_REQUEST_EMAIL`），主题预填「申请 SunMoon AI 邀请码」，正文预填几行让对方写称呼、机构、想用来做什么 |
| 登录页 | 「没有账号？立即注册」 | Casdoor 托管登录页在应用开注册后自动显示，不用我们做 |

不放的地方：登录后的所有页面（能进来就有账号）、管理端、info 与 knowledge 各应用（它们不开注册，放了误导）。

申请邀请码为什么先用 mailto 而不是表单：内测阶段所有者本来就逐个手工发码；mailto 不要后端、不存任何申请人信息、不招垃圾提交。申请量大到手工回不过来时，再换成一个只收邮箱和一句说明的表单（带人机校验，申请进工作台的一张表，所有者在管理端批）。

注册成功后回到哪：Casdoor 注册完成后回到本应用的登录回调，进 `/workbench` 首页；首次进入显示 4.7 的安装引导与 4.6 的「先登记模型 key」提示。

### 4.9 页面上的说明文字（2026-09-26 定）

用户不是开发者，"沙箱""本地代理""接入命令"这些词第一次出现的地方都要就地讲清楚，文字从 [`../../PRD/user-guide.md`](../../PRD/user-guide.md) 摘，两处保持一致：

- 设置 → 我的沙箱：一句话说明沙箱是什么；状态旁写"设置一次就一直在"；「更新沙箱」「回收沙箱」「换代理令牌」各带一句"什么时候用、会发生什么、不会发生什么"（如回收后研究记录保留、再拉起不给新命令）。
- 接入命令的框：醒目写"只显示这一次、不要发给别人；丢了点「换代理令牌」"。
- 我的机器（4.7）：离线时写"本地代理没在运行（电脑重启后要重新打开它）"；同一账号第二个代理上线时，写"另一台电脑接入了，这台已停下"。
- 新建会话下拉为空时：不只写"没有数据"，写出三种原因与去哪里处理（没拉起沙箱 / 没接入代理 / 登录的账号不对）。
- 未登录或登录过期（接口 401）：顶部提示"登录已过期，请重新登录"并给登录按钮，不静默失败（KIND 09 踩过）。

## 五、组件

### K1 方向盘状态带

一条横带，三段：
- 左：谁在驾驶（"你在驾驶" / "专家驾驶中：{专家包}"）；
- 中：在做什么（自驾：最近一个 turn 的状态；专家：第 k/n 步 + 步名 + 该步状态 + 已花费/上限）；
- 右：我能做什么（自驾：无；专家：待办数、取消）。
终态一刻变为"方向盘已交回：{终态}"并给底稿链接，五秒后回到自驾形态。

### K2 审查面五要素

见 4.4；作为组件供审查页、待办卡（摘要形态：只显示定位 + 待决内容第一行 + 截止）复用。

### K3 可核查数字

数字 + 角标；浮层四行：来源、时点、数据版本、查询摘要。无来源的数字不带角标且不加粗。

### K4 质量信号条

信号名、一句话事实、"问专家"、关闭。信号来自云端确定性规则，不来自模型。

### K5 时间线条目

六类分色；命令与文件变更折叠；数据查询显示工具与版本；系统行（断线、重连、交接）居中灰字。

### K6 安装引导步骤

带检查点的三步；每步完成由服务端事实判定（机器上线、白名单非空），不靠用户点"我完成了"。

## 六、文案原则

- 状态词：连接中 / 实时 / 离线重连；你在驾驶 / 专家驾驶中 / 方向盘已交回；等你决定；已完成 / 打回 / 失败 / 已取消。
- 不出现：`RUNNING`、`WAITING`、`Attempt`、`thread`、`cursor`、内部路径、异常文本。
- 费用永远带币种与"已用 / 上限"。
- 每个禁用控件旁边有一句原因。

## 七、与后端契约的缺口（设计定稿后一并冻结）

| # | 缺什么 | 影响页 |
| --- | --- | --- |
| G1 | 跨会话的待办列表接口 | 首页 |
| G2 | 质量信号事件（`F-SIGNAL-01` 未做） | 会话页 |
| G3 | 专家包清单接口（六问、预算默认、自动放行范围） | 求助面 |
