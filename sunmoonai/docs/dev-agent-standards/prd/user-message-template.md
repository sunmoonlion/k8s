# PRD 用户消息模板

复制成 turn 里的 `user-message.md`。**栏目是从 [PRD 规则](prd-rules.md) 里长出来的**：
规则要求 `PRD/` 定稿写成什么样，问里就留出让它写得出来的那一栏；规则本身不抄进来。
写多严见 [任务的生命周期](../lifecycle.md)「用户消息写多严」，字段的含义见同一份的「turn 的固定字段」。

```markdown
---
executor: <派给谁；还没派出去写 unassigned>
verifies: 无
---
# turn <四位号>：<短名>

## 依据
<以哪一份 `PRD/` 定稿、或哪一段 BRD 讨论为底；给出链接与提交>

## 谁用、什么场景、要达到什么结果
<需求的三件事。写结果，不写实现>

## 已知的边界与外部限制
<平台、合规、成本、时间、既有系统；这些进定稿的「约束」一节>

## 这一问覆盖哪些模块
<只定需求，还是同时给模块划分。要拆的话写清已知的边界或期望的粒度；
 每个模块要写什么、号与短名怎么排，见 PRD 规则>

## 范围
- 包含：
- 不包含：
- 不包含的归谁：

## 已经知道定不了的
<这一问答不了、要留到后面的；答里进「未决」，并写清定不下来会影响什么>

## 怎么答
按 `sunmoonai/docs/dev-agent-standards/prd/prd-rules.md`「`architecture/` 写什么」「`modules/<模块>/` 写什么」与「纪律」。

**交回：写成这个 turn 的 `response.md`，不改代码。人读完定稿成 `SDD/`。**
```

## 栏目对着规则的哪一条

| 栏目 | 为什么有它 |
| --- | --- |
| 依据 | 定稿要写明「以哪个 turn 为底、改了什么」；问里不给底，答无从对齐 |
| 谁用、什么场景、要达到什么结果 | `architecture/` 的「目标与范围」一行 |
| 已知的边界与外部限制 | `architecture/` 的「约束」一行 |
| 这一问覆盖哪些模块 | `architecture/`「模块划分」与 `modules/`：拆不拆是这一问的取舍，怎么写是规则的事 |
| 范围三行 | `architecture/`「目标与范围」要求写清包含、不包含、不包含的归谁 |
| 已经知道定不了的 | `architecture/` 的「未决」一行——问里不点出来，答会硬编一个结论 |
| 怎么答 | 纪律「只写要什么，不写怎么做」「不给倾向性结论」在规则里，不在这一问里 |

这一段不写验收标准：合不合格看它能不能定稿成 `PRD/`。不适用的栏写「不适用」及理由。
