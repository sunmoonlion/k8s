# `protocol/` —— 流程规范与它的实现

一个目录装两样东西，**因为它们必须一起改**：

- [`round-protocol.md`](round-protocol.md) —— **规范**，今后开发的指导。流程该怎么走由它说了算。
- 三个可执行文件 —— **目前在用的实现**，同时是将来把这套流程做进运行时的参考。

两者对不上时以规范为准，并按协议 §3 起一个工作单元去改。
**改了脚本的参数名或退出码，必须同步改规范的「8b」一节**——那一节里每条命令都以能实跑为准。

> 目录名是 `protocol/`（单数、无 s），与轮次档案目录 [`../rounds/`](../rounds/) 只差一个字母，
> 别混：`rounds/` 装的是每一轮的产物，本目录装的是流程本身。

| 可执行文件 | 是什么 | 对应协议哪一节 |
| --- | --- | --- |
| [`round-status.py`](round-status.py) | 从**产物**反推当前环节；`--verify` 把 ⑤ 里机器能判的部分判掉 | §8 环节判定、§8.1 判据自身的质量 |
| [`round-dispatch.py`](round-dispatch.py) | 算出「现在该叫谁、说什么」，**只生成命令不执行** | §6.1 环节通知 |
| [`agents.toml`](agents.toml) | 五家执行者登记：harness、调用方式、可观测粒度。**不含任何凭据** | §2.3 登记集合 |

调用方式与退出码写在协议「8b. 两个脚本怎么调」，那一节里每条命令都以能实跑为准——
**改了参数名必须同步改那一节**。

## 三条设计约束，改这里的代码前先读

1. **结论只依赖 git 提交，不看工作区。**一切判定走 `git ls-tree` / `git show`。
   同一个仓库状态在任何机器上给出同一结论。此前被删掉的两个脚本就是栽在这条上——
   同一份文档在三台机器上报 0 / 4 / 95 条失败。
2. **判不了的显式标出，不许默默不查。**判不了不是缺陷，**假装判了才是**。
   `--verify` 里标 🔶人判 的项一律不计入通过。
3. **空集合不是「全部完成」。**`all({})` 为真。要跳过某个环节，必须在 `round.md`
   明写 `skip_stages`；字段留空不算数。

## 单一真源

状态不各算各的：`round-dispatch.py` 一律调 `round-status.py --json` 取状态，
不自己重算一遍环节。轮次的全部参数在 `rounds/<round-id>/round.md` 的 ```toml``` 块里，
人读正文、机器读那个块——同一份文件，两个读者，不产生第二个会漂移的真源。

## 已知不做的事

- **不执行分发。**`round-dispatch.py` 只打印命令，粘贴由人做。理由在协议 §8.1 第 3 条：
  一个检查第一次运行时最可能发现的是它自己判错了，而分发脚本判错的代价是几家同时干错一个环节。
- **不覆盖 ⑥ 确认的内容。**它只判人的确认有没有**落盘**（读 `rulings.md` 的「人确认」列），
  内容对不对是人的事。
- **不管文档门禁。**那是 [`../doc-gate.py`](../doc-gate.py)（挂在 pre-commit）
  与 [`../anchor-gate.py`](../anchor-gate.py)（手工跑），与本目录无关。
