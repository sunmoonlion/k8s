# BRD 用户消息模板

复制成 turn 里的 `user-message.md`。**栏目是从 [BRD 规则](brd-rules.md) 里长出来的**：
规则要求答做到什么，问里就留出让它做得到的那一栏；规则本身不抄进来——抄提纲等于替模型把骨架列好。
写多严见 [任务的生命周期](../lifecycle.md)「用户消息写多严」，字段的含义见同一份的「turn 的固定字段」。

```markdown
---
executor: <派给谁；还没派出去写 unassigned>
verifies: 无
---
# turn <四位号>：<短名>

## 要讨论什么
<一句话说清这次要弄清楚的是什么。一问只谈一件事；有好几件就拆成几个 turn>

## 起因
<触发这一问的原话或现象，原样引；现在是怎么做的、卡在哪>

## 已知的事实
<每条给出处：文件与行、提交、链接、或「某人某时说的」。查不到出处的不放进这一栏>

## 已有的判断
<相关的已有结论，逐条标明它是事实、推断还是假设。别人的推断不标出来，会被当成前提继承>

## 这一问不谈什么
<明确排除的，免得讨论摊开到收不住。可以写只谈 BRD 规则那张表里的哪几行>

## 约束
<必须遵守的规则、不能动的东西；例如只交文本、不改代码>

## 怎么答
按 `sunmoonai/docs/dev-agent-standards/brd/brd-rules.md`「这一段在问什么」与「response 写什么」。

**交回：写成这个 turn 的 `response.md`，不改代码。人读完定稿成 `PRD/`。**
```

## 栏目对着规则的哪一条

| 栏目 | 为什么有它 |
| --- | --- |
| 要讨论什么 | 规则「这一段在问什么」有六行，一个 turn 只挑其中一部分问；不写这一栏，答就会六行平铺、哪行都不深 |
| 起因（原样引） | 规则要求**不篡改原始意图**；转述过的原话会把人的判断混进去 |
| 已知的事实（带出处） | 规则「response 写什么」要求**区分事实与推断**、外部规则**标明依据与出处**。问里不给出处，答只能凭印象 |
| 已有的判断（标事实/推断/假设） | 同上的另一半：上游没标的推断，会被当成前提继承下去 |
| 这一问不谈什么 | 规则要求答里给**边界**；问不划边界，讨论会摊到收不住 |
| 约束 | 规则「这一段在问什么」的「约束」一行 |
| 怎么答 | 判据就是规则本身，早已冻结——不在这一问里临时立条目 |

这一段不写验收标准。不适用的栏写「不适用」及理由——空着与「忘了」无法区分。
