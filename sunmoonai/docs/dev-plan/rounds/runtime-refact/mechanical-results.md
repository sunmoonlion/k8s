## 这份判据自己判错了四次，逐条记

按 `round-protocol.md` §8.1 第 4 条，新判据首跑最可能发现的是**它自己判错**。本次坐实：

| # | 我的检查器怎么错的 | 冤枉了谁 |
| --- | --- | --- |
| 1 | 落点表只认全名 `refact-fable` / `runtime-architecture`，不认 `F` / `R` 缩写。**任务书只规定了「\| 源 \|」这一格，没规定写法** | `cursor` 被判「落点表 0 行」 |
| 2 | M4 把「命中」直接判负，而任务书原文是「**出现必须在被证伪语境内并明确标注**」 | `kimi`、`cursor` |
| 3 | M5 同上，且我连「交人核」都没写 | `kimi`、`cursor` |
| 4 | M7 要求「没查」后紧跟冒号。实际有三种写法：`没查：…`、`**没查什么**：…`、以及**标题+列表**（`### 9.2 没查什么`） | 先冤 `qwen`，修一次后又冤 `luna` |

**四次全部是「覆盖不全」**——同一形态，同一夜，同一个人写的判据。
方向都在危险的那一侧：**不是漏报，是把合规的候选判成不合规**。

这不需要新规则。§8.1 第 1 条早写着「**零命中要能区分『真的没有』与『没查到』**」；
本次是执行者（裁决方）没照做。**记在这里，是因为下一轮的机械条大概率还由裁决方写。**

⚠ **首跑结果不得直接采信。**本文的四家全绿，是**修了四次之后**的结果；
若按首跑的七个 ❌ 直接进裁决，会有三家被无中生有地扣分。
