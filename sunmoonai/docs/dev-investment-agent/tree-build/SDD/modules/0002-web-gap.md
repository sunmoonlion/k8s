## 一句话

设计稿里的八个页面，现在做出来四个半；六个组件做出来一个半；设计稿列的七处后端契约缺口，一处都还没补。
已有的页面是照着后端接口直接写的：功能能用，但设计稿的六条原则里有三条（方向盘永远可见、数字可核查、一次只问一件事）还没有落到页面上。

## 三、后端契约的缺口

设计稿第七节列了七处。对照后端现有的 28 条路由：

| # | 缺什么 | 现在 | 卡住哪页 |
| --- | --- | --- | --- |
| G1 | 跨会话的待办列表 | 没有。待办只随会话视图返回 | 首页 |
| G2 | 质量信号事件 | 没有 | 会话页 |
| G3 | 专家包清单 | 没有。页面写死 | 求助面 |
| G4 | 待办的五要素（证据等级、决定对象、时效、决定记录） | 没有。也没有按编号取一条待办的接口 | 审查面 |
| G5 | 结果里证据与数字的对应、数据时点、工作区变更 | 没有 | 底稿页 |
| G6 | 机器心跳与在线状态 | 没有 | 首页、我的机器 |
| G7 | 委托的步骤总数与步名 | 没有。契约里只有当前是第几步 | 状态带、委托卡 |

这七处都要动后端。按设计稿的约定，设计改定之后先冻结契约，再生成前端的客户端。

## 四、哪些不用等后端

| 事项 | 说明 |
| --- | --- |
| 方向盘状态带（K1）的大部分 | 谁在处理、已花费与上限、取消，现有接口都给了。只有「第几步、共几步、步名」要 G7 |
| 路径与导航 | 改成设计稿的样子，只动前端 |
| 求助面的三行确认、预算的币种 | 只动前端 |
| 底稿页的摘要行、进行中与打回时的样子、重新求助 | 现有接口够用 |
| 公开首页与登录过渡页的文案、申请邀请码 | 只动前端 |
| 各处的说明文字（设计稿 4.9） | 只动前端 |
| 手机上能看待办和答复 | 只动前端 |

## 五、怎么看页面

现在看页面要部署到集群里。迁移期间测试轮次停着，这条路走不通。

建议给前端加一个预览模式：用固定的样例数据顶替后端，每个页面、每种状态都能打开。

| 项 | 说明 |
| --- | --- |
| 样例数据 | 按契约（`contracts/workbench.ts`）写，过同一套校验，所以样例和真实接口的形状一定一致 |
| 覆盖的状态 | 自驾、专家处理中、等我决定、预算用完、机器离线、已完成、打回、失败、已取消 |
| 怎么开 | 本地一条命令；不连后端，不连集群 |
| 不进正式构建 | 预览模式只在开发构建里有 |

它还能解决一个老问题：专家处理中、打回、超预算这些状态在真实环境里很难凑出来，设计和验收都看不到。

## 六、建议的顺序

| 顺序 | 内容 | 要不要动后端 |
| --- | --- | --- |
| 1 | 所有者定设计稿第九节的六件事（见 [近期要定的事](../../owner-decisions-now.md) W1 至 W7） | — |
| 2 | 预览模式与样例数据 | 不要 |
| 3 | 方向盘状态带、路径与导航 | 不要 |
| 4 | 首页：把已有接口能给的三块摆出来 | 「待我决定」要 G1，先用各会话的待办拼 |
| 5 | 底稿页：摘要行、各终态的样子 | 不要 |
| 6 | 求助面：三行确认、币种、专家包说明 | 专家包说明要 G3，先写在前端，接口有了再换 |
| 7 | 审查面单独成页 | 要 G4 |
| 8 | 我的机器与安装引导 | 要 G6 |
| 9 | 可核查数字 | 要 G5 |
| 10 | 质量信号条 | 要 G2 |

第 2 至 6 步不依赖后端，可以先做；第 7 至 10 步要先定契约。
