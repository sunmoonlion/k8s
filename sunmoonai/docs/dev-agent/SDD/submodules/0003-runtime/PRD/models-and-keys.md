# 模型与 key

> 本模块要满足什么见 [requirement.md](requirement.md)。

- key 只在桌面应用的本地窗口输入，经 ③ 交给 runtime，存入系统钥匙串，不写入配置文件；
- runtime 启动 Codex 时只通过环境变量把 key 传给 Codex 子进程，配置文件里只写环境变量名。
  ⚠ **继承边界未核实**（`P6`）：若 Codex 为工具调用启动的子进程继承同一套环境，
  工作区里的脚本就能读到 key——这与「key 只交给模型调用路径」的最小权限目标不一致。
  **验证办法**：在钉定版本上实测 Codex 工具子进程能否读到该变量。
  能读到就换成不向工具进程传播的注入方式，或明写承认并重定义威胁模型；**不得把未核前提留在这一句里**；
- ① 协议没有 key 字段；上报的日志与报错过滤请求头与环境变量；
- runtime 内置厂商预设（接口地址、模型名等不涉密字段），后端可经 ① 推送带签名的更新；
- 只用 API key，不提供用模型厂商的消费者账号登录；
- 桌面应用在配置时引导用户开通、粘贴后当场测试可用与余额；
- 提交前显示预估费用；用户可设单任务与每月上限；完成后显示实际花费（自报，只作展示）；
- 模型费用由用户直接付给厂商；我们收取编排、知识服务与数据的服务费；runtime 上报的用量不作计费依据；
- **可以配多个厂商的 key**：runtime 据此维护一份本机**可用模型清单**（厂商、模型名、是否测通），经 ① 上报；
  派发内容里写明这次用哪个模型与哪个 provider，runtime 按它启动运行时 thread，不自行改投（[执行端纪律](discipline.md) 的硬禁令第一条）；
- **并行竞争按份计费**：同一问发给几家就是几份模型费用，提交前的预估与完成后的实际花费都按总额显示；
- **模型接入**：Codex 只支持 Responses API。推荐清单只收能直接连接的厂商（如 Kimi 的 OpenAI 兼容接口），runtime 只生成配置，不带转换层；换模型必须用领域评测集实测，结果决定推荐清单与默认推荐（⚠ 第三方接口下的上下文压缩续跑、reasoning effort、工具调用稳定性）；清单外的模型标「未验证」。
