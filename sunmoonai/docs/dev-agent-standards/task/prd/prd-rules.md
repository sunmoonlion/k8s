# PRD 规则（任务书）

PRD 就是**任务书**：交给 agent 的那一问。它是**人要完成的内容**——人写清楚要什么、做到什么算满足，agent 按它交付。
每个任务目录里的 `task.md` 就是一份 PRD。

## 写多严，按任务轻重

大多数任务就是**一段话**，说清要什么即可；任务越不可逆、影响越大，写得越全。
[附录：PRD 模板](prd-template.md) 是**最严格的一种**，不是每个任务都要填。

| 程度 | 适用 | 至少写 |
| --- | --- | --- |
| 一段话 | 可逆、局部、方向明确（T0） | 要什么 |
| 加边界与验收 | 影响跨多个文件或多个仓（T1） | 要什么、范围、验收标准 |
| 完整模板 | 命中任一条 T2 判据：不可逆、权威层、已知对立、判据未定 | 模板全部 |

档位判据见 [多方竞争的轮次协议](../../protocol/README.md)「档位」。没写的基本信息取默认：父任务与来源由系统记录，返工上限为 2；
**需要人批准的动作按 [人的批准点](../../approvals.md) 执行，不因任务书没写而放宽。**

## 完整任务书写这四块

| 部分 | 写什么 |
| --- | --- |
| 要什么 | 这件事做完之后什么变了；为什么要做 |
| 范围 | 包含什么、不包含什么、不包含的归谁 |
| 验收标准 | 可判定的条件，逐条写；做完能一条条对着勾 |
| 约束 | 必须遵守的规则、不能动的东西、需要人批准的动作 |

另有几项基本信息：父任务、由什么产生、谁写的、交付物清单（及每项的形态）、需要人批准的动作、返工上限——见模板。
用完整模板时，不适用的栏写「不适用」及理由；空着与「忘了」无法区分。

## 谁写、怎么写、怎么改

- **根任务由人写**；子任务的任务书来自父任务 SDD 拆出的那一节，随那份 SDD 一起经人批准后生效，人在批准前可以修改。
- 任务越重，下面两条越要做到。**写清边界**：含什么、不含什么、不含的归谁——否则执行者会自行扩大范围，或漏掉本该做的。
- **给可判定的验收标准，不给倾向性结论**——否则产出向写任务书的人的结论收敛，等于白问。
- 验收标准在派工前定下；**出题的人与答题的 agent 分开**。agent 不改任务书，发现任务书有问题时停下来问。
- 派工之后再改任务书就是新版本：按 [总则「改判」](../../README.md) 写清触发、原判断错在哪、新判断；已交回的交付物按新版本重新验收。
- 人这一侧的其余义务见 [人的批准点](../../approvals.md)「人这一侧的义务」；任务的目录、状态与返工见 [任务的生命周期](../README.md)。
