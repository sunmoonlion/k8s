# turn 0001：交付要满足什么

上一层的设计把后端切成七块，分给这一块的是**交付**：事件流投影与 cursor 续传、结果密文存取、通知。
边界（承担什么、不承担什么、为什么这么切）见 [`SDD/modules/0007-delivery.md`](../../../../../modules/0007-delivery.md)，
七块之间的关系见 [`SDD/architecture/README.md`](../../../../../architecture/README.md)。

这一问要的是：**这一块具体要满足什么、什么算满足**。

- 合同里归这一块的功能义务（`F-*`）与不变量（`I*`）分别是哪些，逐条列出；
- 输入与输出：从谁拿什么、给谁什么；
- 正向场景与反向场景：做对了是什么样，输入不对、依赖不可用、中途中断时该是什么样；
- 非目标：这一轮明确不做什么；
- 约束：上一层已经定死的（它不解密结果，只存密文与元数据；先持久化后通知，通知失败可独立重试、不改变 Task 结果；用户换设备或重启后凭密钥可重新取得结果），以及只对这一块成立的；
- 允许的不确定性：哪些可以先不定，不定会影响什么。

**不要写怎么实现**——那是下一问（SDD）。上一层已经定的边界不要推翻；
认为边界划错了，停下来说，不要在答里自行改。
