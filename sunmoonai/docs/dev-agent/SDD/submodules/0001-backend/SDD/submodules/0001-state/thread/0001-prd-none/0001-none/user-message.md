# turn 0001：状态与账要满足什么

上一层的设计把后端切成六块，分给这一块的是**状态与账**：状态机与唯一转换函数、事件表、四本账、outbox 与投递器、任务队列、重启恢复。
边界（承担什么、不承担什么、为什么这么切）见 [`SDD/modules/0001-kernel.md`](../../../../../modules/0001-kernel.md)，
六块之间的关系见 [`SDD/architecture/README.md`](../../../../../architecture/README.md)。

这一问要的是：**这一块具体要满足什么、什么算满足**。

- 合同里归这一块的功能义务（`F-*`）与不变量（`I*`）分别是哪些，逐条列出；
- 输入与输出：从谁拿什么、给谁什么；
- 正向场景与反向场景：做对了是什么样，输入不对、依赖不可用、中途中断时该是什么样；
- 非目标：这一轮明确不做什么；
- 约束：上一层已经定死的（它不朝外，其余五块都经它改状态与写账；预算在派发时扣、验收时结算，都要落在这一块），以及只对这一块成立的；
- 允许的不确定性：哪些可以先不定，不定会影响什么。

**不要写怎么实现**——那是下一问（SDD）。上一层已经定的边界不要推翻；
认为边界划错了，停下来说，不要在答里自行改。
