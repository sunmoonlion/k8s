# 最终声明：合并将删除什么，什么必须在消失前留下（qoder）

> 取证时点：2026-08-27 晚 ｜ 作者：qoder
>
> 本文件是在 `sunmoonai-architecture/` 随合并从 `master` 消失之前的**最后书面意见**。
> 与 [`qoder.md`](qoder.md)（合并前评审清单）互补：那份讲"新集要补什么"，
> 这份讲"旧集消失会带走什么"。所有断言附取证命令。

## 1. 合并实际会发生什么

`opus` 分支的 `d7af5c2b` 已从 tree 中删除 `sunmoonai-architecture/` 全部 **32 个文件**；
opus 当前 HEAD 的 tree 中该目录**不存在**（`git ls-tree -r HEAD | grep sunmoonai-architecture`
仅命中 `.cursor/rules/` 的一条指针文件）。因此本分支并入 `master` 即意味着：

- `AGENTS.md`（协作治理总入口）
- `README.md`（目录说明与权威链：代码 > baseline > request）
- `baseline/` 全套（README、map、repos ×5、shared ×6、verify）
- `requests/` 全套（**REQ-001 至 REQ-010 的完整记录** + TEMPLATE）

从 `master` 主线消失。它们仍在 git 历史与其他四个分支上，
但**主线上将不再有任何指针指向它们**。

复核：

```bash
git -C k8s show --name-status d7af5c2b | grep -c '^D'     # 32
git -C k8s ls-tree -r --name-only HEAD | grep -c 'sunmoonai-architecture/requests/'  # 0
```

## 2. 我认同的部分

baseline 层被删除是**可以接受的**：新的 `architecture/` 不是对旧文的拼接，
而是重新对五仓取证的重写，且挖出了三份旧 baseline 都没抓到的事实
（`2.0.0.dev0` 与 `formal_release: true` 的矛盾、RAGFlow `CANCEL` 当成功、
`CLAUDE.md` 过期注入等，见 `verify.md` §3）。覆盖式重写本来就是本目录自定的
修改语义。**投影被更好的投影替换，不是损失。**

## 3. 但有两样东西被顺带带走了，它们不是投影

### 3.1 AGENTS.md：治理入口没有替代物

旧 `AGENTS.md` 是**工具中立的协作总入口**，且按其维护约定，各家助手的
长期记忆 / rules 里只留"指向本文件的一行指针"。合并后这些指针**全部悬空**：
新文档集里没有任何文件承担"治理规则 + 维护约定 + 动手前必读"的角色——
`overall-architecture.md` 描述的是项目，不是协作规则。

**要求**：合并前二选一并写进合并记录——
（a）在 `architecture/` 内立一份等价的治理入口，并把旧 `AGENTS.md` 中
仍有效的维护约定（治理文件禁改、权威链、指针不复述等）显式承接；
（b）若决定废弃该机制，必须逐家通知更新各自 rules 里的那行指针。
不做任何一件，合并当天所有助手的自动注入上下文同时失效。

### 3.2 REQ-001 至 REQ-010：决策历史被覆写式删除

新的 `request-lifecycle.md` 明文承认自己的规则来自这些请求：
"每一条都能反向追到一次**已经发生过的**后果"。这十条记录就是那个"已经发生"
的原始证据——包括 REQ-001 僵尸化、REQ-003→004 双向登记正反例。
把它们从 tree 删掉，等于把决策历史当投影覆写了，**违反的正是本目录自己定的规矩**：
ADR"只追加不覆写"的精神（`decisions/README.md`）与 R6 双向登记、
R7 改判追加不覆写（`request-lifecycle.md` §4）。

"git 历史里有"不构成豁免：本目录写文档的全部出发点，就是不让后来者
必须靠考古才能拿到上下文。

**要求**：合并前至少完成其中一件——
（a）`requests/` 目录以原样或只读形态保留进新结构（推荐：
`architecture/requests/`，标注"已归档，只追加"）；
（b）不保留文件，但在 `architecture/` 内立一份**取代记录**：十条 REQ 各一行，
写明终态、去向、以及在 git 历史中的取证位置（提交号 + 路径）。
合并提交信息里必须有一句声明该目录被删除及恢复方法。

## 4. 一句话总结

**新的投影更好，我支持合并；但 `AGENTS.md` 与 `requests/` 不是投影，
是历史与治理的载体。合并可以替换前者，不能无声带走后者。**
若时间上来不及处置，最低限度是：合并提交信息写明删除清单与恢复路径，
并把 §3.1、§3.2 的两条要求立为新结构里的第一条请求。
