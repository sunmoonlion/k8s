# 0010-acceptance：验收与交付

**承担**：合同 `control-plane.md` 里 **validator 与 acceptor 两个角色**，加上交付面。

- **validator**：按固定 Task Profile 版本做确定性验收；核对本地内容检查的签名回执；
- **acceptor**：需要语义判断的验收，作为**独立的验收 Attempt** 派出去（不同 Agent Profile、
  不同运行时 thread），不自己判；
- 终态提交的发起：终态、结果、预算结算**原子提交**——由 `0005-kernel` 一次转换完成；
- 交付：事件流投影与 cursor 续传、重复事件幂等、结果密文存取、通知。

**不承担**：

- **不解密结果**——只存密文与元数据，明文从不进后端；
- 不自己判语义——那要派 Attempt；
- 不自己写终态，经 `0005-kernel`。

**为什么验收与交付合成一块**：交付是验收通过之后的取件面，两者共享「结果」这一个对象。
分开会让结果的写入与读出跨两块。

**边界要点**：通知失败可以**独立重试，不改变 Task 结果**；有权用户在断线、重启或换设备后，
凭结果密钥可以**重新取得**结果。这两条是生命周期终点判据的一半。
