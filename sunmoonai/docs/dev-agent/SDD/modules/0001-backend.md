# 0001-backend：后端

**承担**：受理、路由、编排、派发、验收、持久化账与审计——合同里归后端的那部分。
它是**控制面**：按 workflow 确定性地推进，状态与账只有一份、在它自己的库里。

**不承担**：

- **不调用生成式模型**，也不请执行端代为判断；需要语义判断的环节派 Attempt 出去；
- 不中转模型请求，不接触用户 key；
- **看不到本地资料、文件名与结果正文**——结果到它这里已是密文。

**跑在**服务器上。**信任域**：持久化账的唯一权威写入面。

**和谁交互**：经通道 ④ 与桌面应用（提交、查询、取消、Task 级审查、结果密文），
经通道 ① 与本地 runtime（派发、续约、事件、副作用意图与回执）。接口见
[通道](../architecture/channels.md)，边界见 [数据流与信任边界](../architecture/trust.md)。

**要满足什么**、内部怎么分，见子任务 [`submodules/0001-backend/`](../submodules/0001-backend/PRD/requirement.md)。
