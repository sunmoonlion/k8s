# ai-dev-readiness — 定义「AI 执行开发」的完整流程

> 立项：2026-09-04

**本目录只解决一件事**：开发工作全部由 AI 助手承担时，
一个需求从提出到上线，该经过哪些阶段与门。

产物是一份 `pipeline.md`。讨论材料、任务书、定稿都在这里，**不散到别处**。

它和相邻两个目录的分界：

| 目录 | 管什么 | 判据 |
| --- | --- | --- |
| [`../dev-plan/`](../dev-plan/) | 代码要符合什么、接下来建什么 | 改了，**代码**要跟着改 |
| [`../project-guide/`](../project-guide/) | 项目现在长什么样 | 改了，只说明**代码先变了** |
| 本目录 | 流程与判据本身 | 改了，**怎么开发**要跟着改 |

## 文件

### 定稿与轮次产物

| 文件 | 内容 | 状态 |
| --- | --- | --- |
| `pipeline.md` | **本目录的最终产物**：阶段 × 谁做 × 产物 × 落点 × 准入准出 × 判据属哪一层 | **尚未产生**，由并行评优轮产出 |
| [`pipeline-task.md`](pipeline-task.md) | **轮次任务书**：发给四家助手，自足。九条已核事实、七个必答问题、三件结构问题、验收标准、角色与利益声明 | 待发起 |
| `pipeline-review-<助手>.md` | 各家评审（环节 ②） | 尚未产生 |

### 背景材料（三份，性质不同，别混用）

| 文件 | 性质 | 怎么用 |
| --- | --- | --- |
| [`standard-pipeline.md`](standard-pipeline.md) | 行业通用实践的整理，**外部参照系** | 当尺子用，**不是本项目规则** |
| [`readiness.md`](readiness.md) | 现状盘点与议题，**带取证** | **事实可采信**（`pipeline-task.md` 的已核事实是它的蒸馏）；**议题的结论不采信** |
| [`ai-pipeline.md`](ai-pipeline.md) | 起草人一个人写的一份改法 | **只作为产物形状的范例** |

**关于 `ai-pipeline.md` 的提醒**（与 `pipeline-task.md` 同步）：

> 它**不是基座**。八条改法未经任何评审或取证，其中一条判断已被起草人自己推翻
> （它说 REQ 模板"只有一半"，实际 `template-proposed.md` 已覆盖大部分）。
> **不得逐条继承它的判断。**候选与它冲突，不构成缺点。

## 现在的状态

**背景材料齐了，任务书写好了，轮次待发起。**

三份背景材料**都不承担规范效力**。定稿产生之前，本目录不约束任何开发行为。

## 定稿之后

`pipeline.md` 生效后：

- 变成**规则**的 → [`../dev-plan/constraints.md`](../dev-plan/constraints.md)
- 变成**任务模板栏位**的（DoR / DoD）→ [`../dev-plan/implementation-plan.md`](../dev-plan/implementation-plan.md)
- 变成**需求模板栏位**的 → `../dev-plan/working/request-baseline/TEMPLATE.md`
- 变成**会报错的东西**的 → 测试与门禁，**不是文档**

最后一条是本立项的主线。`readiness.md` 对本目录自己也立了同一条约束：

> 它的产出应当是一批会报错的东西，不是它的续集。

三份背景材料在定稿后降级为背景或归档，本目录不再增长。
