## 关键发现摘要

1. **A4：casdoor-tls 与 knowbase-tls 出示的是 `TRAEFIK DEFAULT CERT`**（不是 SunMoon Registry Local CA 签的证书）——traefik 没有为这两个 host 配上正确的 TLS 证书，所以客户端验 CA 失败。knowmart-tls 和 knowlab-tls 出示的是正确证书。
2. **A1：traefik 反复报 `ingress="knowbench-service-access" serviceName="knowbench-api" error="service not found"`**——knowbench-api Service 不存在（因 knowbench-runtime kustomization 未 Ready，Deployment/Service 未被创建）。
3. **A3：四张内部入口证书都由 `SunMoon Registry Local CA` 签发**，域名各自对应。但 A4 显示 casdoor-tls/knowbase-tls 实际出示的不是这些证书。
4. **A5：客户端 CA 是 `SunMoon Registry Local CA`（自签 CA）**——与 A3 的 issuer 一致，但与 A4 的 TRAEFIK DEFAULT CERT 不匹配。
5. **B1：knowlab 迁移 `2845ca9fa055-v1` 已 Complete，schema 到 `20261016_0006`** ✅。但 **knowlab-api 仍用旧镜像 `e4987b12b5cb`**（schema `20260911_0003`）——因 knowlab-runtime kustomization False（依赖 knowlab-knowmart-deliver-identity Job Failed），Deployment 未更新到新镜像，导致 `SchemaNotReady`。
6. **B1：`knowlab-knowmart-deliver-identity` Job 也 Failed**（非只 knowbench 的四个）——五个 service-identity Job 全失败，都是 ConnectError（经 traefik 内部 TLS 入口连 casdoor-tls，但 traefik 出示 DEFAULT CERT，CA 验不过）。
