# 三种对话、新建与转建、右边栏（0017）

> 状态：所有者 2026-10-11 定（「专家本质上同样是一对话」「转时原地变」「聊天不选工作区」「文件树按你的建议来」「终端做甲，先记账」），远程写设计，未实施。以现网 luna 分支的网页为基线。改写 0016 的顶部与项目行，接 0015（改动面板）与 `approval.md`。`PRD/apps/investment.md` 第五节与本篇不一致处以本篇为准，PRD 下次整理时改。

## 一、决定

| 项 | 定了什么 |
| --- | --- |
| 对话种类 | 三种：聊天、工作、专家。专家不再是「工作对话交出方向盘的一段」，而是和聊天、工作并列的一种对话 |
| 项目里装什么 | 三种对话混放，不限哪一种、不限几个。一个项目里可以有多位专家（专家团） |
| 新建 | 顶部三个标签就是新建入口。点标签，中间出对话框；选工作区、选项目、新建项目都在对话框里。侧边栏不再有「新建」按钮 |
| 转建 | 两种：由对话原地转（聊天→工作、聊天→专家、工作→专家，同一段对话、同一条 thread、只升不降）；由项目行右边的「+」在该项目里新建任一种 |
| 侧边栏项目下列什么 | 只列对话。点开在中间显示，就是原来聊天 / 工作 / 专家各自的工作位置 |
| 产出 | 工作与专家改的、建的、删的文件直接落项目文件夹（0015）。用户看文件走右边栏的文件树 |
| 右边栏 | 三个按钮：文件、改动、终端 |
| 项目的定义（修订 2026-10-04 的决定） | 装的东西上和 WorkBuddy 的「项目」几乎一样：资料 = 文件夹，指令 = 文件夹里的 `AGENTS.md`（Codex 原生读），专家 = 专家团，技能 / 定时任务 = 以后（账 66 那一路）。归属上仍不一样：一个用户、一台机器、没有成员 |

## 二、三种对话

| | 聊天 | 工作 | 专家 |
| --- | --- | --- | --- |
| 本质 | 一问一答 | 一问一答 + 文件系统 | 服务端先编排（选专家包、拆步、起 Task），再进入对话 |
| 谁先动 | 用户 | 用户 | 服务端 / 顾问先动；用户随后可插话、接管（两层方向盘搬到专家对话内部，9-23 的要求不变） |
| 文件系统 | 不改文件。挂在项目下且电脑在线时可只读看项目文件（现状 `CHAT_IN_PROJECT`，保留） | 项目文件夹可读写 | 项目文件夹可读写 |
| 要不要项目 | 不要。可事后「放进项目」 | 要 | 要 |
| 新建时要选什么 | 什么都不选，直接说话 | 工作区 + 项目（现有 / 新建 / 拉取仓库） | 工作区 + 项目 + 哪位专家 + 问题（即现在「请专家」页的内容，搬进对话框） |
| Codex 侧 | thread 设置 `read-only`、`never` | `workspace-write`、按设置的审批策略 | 同工作；编排层按 `approval.md` 工具级三档 |

记录上：`workbench_sessions.kind` 加第三个值 `expert`；`Session.wheel` 只在 `expert` 对话里有意义；`Mode.EXPERT` 由 kind 直接得出，不再靠轮次上的 `expert=True`。

## 三、新建

```text
点「聊天」 → 中间：输入框。写了就发。
点「工作」 → 中间：输入框 + 一行「在哪个项目」：[工作区 ▾] [项目 ▾ | 新建项目 | 拉取仓库]
点「专家」 → 中间：请专家面：问题 + 在哪个项目（同上）+ 哪位专家 + 右侧专家的承诺
```

| 规则 | 说明 |
| --- | --- |
| 标签就是入口 | 三个标签常显在侧边栏顶部；当前所在对话是哪种，哪个标签亮 |
| 撤「新建」按钮 | luna 现网标签下面那个「新建」撤掉；首页 `/workbench` 就是「聊天」标签的对话框 |
| 聊天 | 不选工作区、不选项目。没有电脑、没有工作区都能聊 |
| 工作、专家 | 必选项目。工作区下拉只列在线电脑的根目录；项目下拉列该工作区下的项目，另两项「新建项目」（现有三步对话框，机器只有一台时跳过那一步）、「拉取仓库」 |
| 拉取仓库 | 新的：填仓库地址，在所选工作区下 `git clone` 成一个新项目。clone 在用户电脑上跑，由本地代理执行；代理侧怎么跑、凭据怎么给，实施前另写一小节（见「六、要验的」） |
| 没有在线电脑 | 工作、专家的对话框里一行说明 + 「接入电脑」链接；聊天不提（账 76） |
| 专家 | 现在的「专家首页」（挑一位）与 `expert/new` 页合成这一个对话框。`routes.expert`、`routes.askExpert` 撤 |

## 四、转建

### 4.1 由对话原地转

| 从 → 到 | 现状 | 改成 |
| --- | --- | --- |
| 聊天 → 工作 | `POST /sessions/{id}/kind`，原地变，同一条 thread | 不变。没项目的聊天先选或建一个项目，这段聊天随之归入 |
| 聊天 → 专家 | 「请专家」页，把那段对话交出去（原地，同 thread） | 不变，入口改为对话里的「请专家」按钮打开请专家面（项目已定则不再选）；提交后 `kind` 变 `expert`，编排开始 |
| 工作 → 专家 | 同上 | 同上 |
| 反向 | 无 | 没有。专家交回后对话仍是专家对话，用户在里面继续说话就是接管后的两层方向盘；要「只聊天」就另开一段 |

### 4.2 项目行右边

| 钮 | 做什么 |
| --- | --- |
| `+` | 弹三项：聊天 / 工作 / 专家。项目已定，直接进中间的对话框（聊天直接开；工作直接开；专家进请专家面，项目锁定） |
| `…` | 打开项目页、改名、归档、专家交回的文件清单（0015 §3.3 的 `交回.md` 们）。以后技能 / 定时任务也挂这里 |

## 五、右边栏

工作对话与专家对话挂右边栏；聊天对话不挂。三个按钮常驻在右上角，面板可开合，一次只开一个。

| 按钮 | 内容 | 来源 |
| --- | --- | --- |
| 文件 | 文件树。**根是当前工作区的那几个根目录**（代理白名单），当前项目默认展开；点文件看内容，只读 | app-server `fs/readDirectory`、`fs/readFile`、`fs/watch`，经本地代理到用户电脑。代理 fs 读本来就限在根目录 + codex-home（luna `windowsPolicy.ts`），不放宽，所以不做「整盘」 |
| 改动 | 0015 §3.2 的改动面板，不变 | `fileChange` + `fs/watch` |
| 终端 | 用户电脑上的真 shell（甲），经中继与代理 | **第一期不做**，另写设计（账 83）：代理要新开一条协议通道，安全面最大，和现在「代理只转 Codex RPC、严格过滤」的原则要重新对齐 |

改动面板自动弹开的两个时机：① 本次打开页面后第一次出现改动（0015 已定）；② 有文件改动等人审批时（`approval.md` 工具级「问人」且请求是 `fileChange`），弹开并显示那份补丁的 diff 与四个按钮。事后已落地的改动只进列表，不弹。

## 六、专家团

| 项 | 规则 |
| --- | --- |
| 形态 | 一位专家 = 一段专家对话 = 一条 thread + 一个 Task + 自己的改动面板。不嵌套，没有「主专家」 |
| 并发 | **建议**同一项目同一时刻只跑一位，其余排队（同一个文件夹，两位同时改会互相覆盖，Codex 两边都看不见对方）。所有者未定，实施前要定 |
| 传递 | 专家之间只经项目文件：上一位的交回文件就是下一位的输入（0015） |
| 侧边栏 | 项目行的 ● 与数字按项目汇总；展开后每段专家对话各自带 ● / ▲ |
