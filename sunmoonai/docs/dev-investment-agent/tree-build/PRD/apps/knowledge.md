> **2026-10-04：页面与接口已按这一份做出来**，做成什么样、哪里和这一份不同，见 [`0006-knowledge-pages`](../../SDD/modules/0006-knowledge-pages.md)。所有者还没有看过。
> 知识服务装什么、怎么给 Codex 见 [数据与资料](../knowledge.md) 与 [`0006-knowledge`](../../SDD/modules/0006-knowledge.md)；多数据集与语义层见 [`0008-info`](../../SDD/modules/0008-info.md)「段三」、[`0009-semantic`](../../SDD/modules/0009-semantic.md)。这里不重复。

## 一、knowledge 在三个应用里的位置

| 项 | 内容 |
| --- | --- |
| 管什么 | 现在有哪些数据、数据到哪一天、每张表是什么、每个口径怎么算；把数据经工具给专家和代理 |
| 不管什么 | 数据怎么进来（info）；拿数据做研究（investment） |
| 谁来 | 用户来看有什么数据；所有者来看数据集的版本 |
| 别的应用怎么用它 | investment 的导航里有「数据目录」，用链接带过来 |

为什么要有页面：用户在 investment 里问一家公司之前，没有地方知道「有没有这家的数据、数据到哪一天」。现在只能问了才知道。

## 二、现状

| 项 | 现在 |
| --- | --- |
| 给专家的工具 | `list_datasets`、`describe_schema`、`metric_definitions`、`run_sql`、`query_metric`（语义层打开时才有） |
| 数据集 | 一个默认的（零售经营库，最小实例用）；登记进来的证券数据集，每家公司一个 |
| 登记 | info 调内部接口登记新版本；旧版本被取代 |
| 页面 | 2026-10-04 起：网页端有数据目录与数据集两页，管理端有数据集登记一页（此前只有模板带来的占位页） |
| 文档检索 | 有一个内部接口，唯一的调用方（investment 的旧运行时）已删除。**工具里没有文档检索**，专家读不到旧资讯线采到的文档 |

## 三、页面

### 3.1 用户：数据目录

网页端，路径 `/<语言>/catalog`，可带 `from`。

| 区块 | 内容 |
| --- | --- |
| 搜索 | 按证券代码或数据集名 |
| 列表 | 每个数据集一行：公司（证券代码）、数据从哪天到哪天、现行版本、更新时间 |
| 找不到 | 「没有这家公司的数据」；按钮「申请入库」（新标签页去 info 的申请页，带上搜索的代码与 `from=knowledge`） |
| 说明 | 一句话：这里列的是专家和代理查得到的数据 |

| 状态 | 页面 |
| --- | --- |
| 一个登记的数据集都没有 | 只显示默认数据集与一句说明 |
| 多数据集没打开 | 同上 |

### 3.2 用户：一个数据集

路径 `/<语言>/catalog/{数据集}`。

| 区块 | 内容 |
| --- | --- |
| 摘要 | 公司、数据集名、现行版本、数据从哪天到哪天、来源说明 |
| 表 | 每张表：名字、有几行、每一列的名字与类型 |
| 口径 | 每个口径：名字、中文名、怎么算、用到哪些表、适用范围 |
| 局限 | 这个数据集的说明里写的局限，例如哪些期被剔除了、为什么 |
| 动作 | 「申请更新」（去 info 的申请页）；从 investment 来的，「回到原处」 |

**只显示结构，不显示数据。** 看不到任何一行的数值。理由：防批量抓取（`F-KNOW-05`）；第三方来源的数据只限内部使用，再分发的边界没有定（`D1`、`D2`）。

### 3.3 所有者：数据集登记

管理端，路径 `/<语言>/knowledge/datasets`。

| 区块 | 内容 |
| --- | --- |
| 列表 | 每个数据集：现行版本、登记时间、文件的校验值与大小、存放位置 |
| 历史 | 某个数据集的各个版本：哪个是现行的，哪些被取代了、什么时候 |
| 状态 | 文件取回来没有；校验值对不对 |

只读。登记由 info 发起，回退由 info 的「重新登记」做，这里不提供改的动作。

### 3.4 旧的页面

| 页面 | 处理 |
| --- | --- |
| 网页端的仪表盘、工具箱 | 模板带来的占位页。导航里换成「数据目录」 |
| 管理端的参考页 | 留着 |

## 五、后端

| 接口 | 作用 | 谁能调 |
| --- | --- | --- |
| `GET /api/web/v1/catalog/datasets` | 数据集列表；可按代码或名字搜 | 登录的用户 |
| `GET /api/web/v1/catalog/datasets/{数据集}` | 一个数据集的摘要、表、列、口径、局限 | 登录的用户 |
| `GET /api/admin/v1/knowledge/datasets` | 登记表：每个数据集的现行版本 | knowledge 管理员 |
| `GET /api/admin/v1/knowledge/datasets/{数据集}/versions` | 一个数据集的版本历史：现行的与被取代的 | knowledge 管理员 |

| 规则 | 内容 |
| --- | --- |
| 数据从哪来 | 现有的数据集目录与查询服务：列表用登记表，表与列用 `describe_schema` 背后的同一段代码，口径用 `metric_definitions` 背后的同一段代码 |
| 不新增的东西 | 不新增表，不新增存储 |
| 不返回 | 任何一行数据；对象存储的位置（管理接口除外） |
| 限流 | 与工具的限流分开计 |
| 配置 | info 网页端的地址（拼「申请入库」的链接）；别的应用的名单与回跳地址 |

### 已知的缺口：文档检索

| 项 | 内容 |
| --- | --- |
| 缺什么 | 工具里没有「按问题找文档片段」 |
| 影响 | 旧资讯线采到的文章、以后年报的文字部分，入了库专家也读不到 |
| 为什么现在不补 | 年报的文字交给谁解析还没定（`T1`）；定了才知道片段长什么样 |
| 到时候要做的 | 一个工具 `search_documents`：问题、范围（哪家公司、哪个时段）；返回片段，每个片段带出处、时点、版本 |

## 六之二、知识库的三层（所有者 2026-10-07 定）

对用户的 Codex 来说，四处都是「可读的资料」，只是来路和边界不同：

| 层 | 谁的 | 放哪 | 谁能读 | 怎么进来 |
| --- | --- | --- | --- | --- |
| 公共知识库 | 我们（服务厂商） | 服务器 | 所有用户的 Codex、所有专家 | 我们建。现在是公开财报数据集；「申请入库」走这里 |
| 个人知识库 | 每个用户 | 服务器上该用户的私有区：独立存储前缀、独立索引、加密存放、可删除、有配额 | 只有这个用户的 Codex，和他请的专家在那次委托里 | **只有一条路：用户自己上传**。不想上传的就留在白名单里 |
| 工作区文件 | 每个用户 | 用户机器的白名单目录 | 这个用户的 Codex，经本地代理就地读 | 不上传，原则 |
| 专家知识库（后话） | 每位专家 | 服务器上该专家的私有区 | 只有这位专家在工作时 | 我们或专家维护：方法、清单、口径 |

规矩：白名单文件不会自动进个人知识库；个人知识库里的东西不进公共库，除非用户自己走「申请入库」。隔离靠沙箱的 MCP 令牌（按用户签，D10）：个人库按令牌里的用户过滤，公共库不过滤，专家库按正在运行的专家包过滤。

页面上「知识库」只指个人知识库（所有者 2026-10-07 定：「公共的没有必要让用户知道，工作区文件不是知识库文件，只有一块」）：一份用户自己上传的文件清单，每一条都写明「在服务端有一份只属于你的副本，可以删」。公共数据对用户是「问就有」，不以库的面目出现；白名单文件归「项目」与「我的机器」。「数据目录」是我们看公共库的页面，放 knowledge 管理端；「申请入库」在 info 管理端。两者都不在用户侧（所有者 2026-10-07 定）。

知识库的整套设计在 [`SDD/modules/0011-library.md`](../../SDD/modules/0011-library.md)：第一期就不是空的，专家交回的底稿和工作交回的文件自动归入；上传第二期；专家知识库同一套表、后话。
