# 审批

> 三条路：工具级、Task 级、本地上限。拆开写三份必然漂，所以合在这里。
> 工具级一节 2026-10-11 重写（所有者问「策略没涉及到的怎么办」后）：旧版「没写到就拒绝」改为「没写到就问人」，并把 Codex 的两种「不」都交给用户。

## 三条路

| 路 | 对象 | 从哪发起 | 谁决定 | 在哪决定 | 记录 |
| --- | --- | --- | --- | --- | --- |
| **工具级** | 单条命令、单个文件修改、联网 | app-server 的 `item/*/requestApproval`（②） | 先查策略：放行 / 问人 / 拒绝；**没写到的一律问人**。问人时由方向盘持有者答：自驾是用户，顾问驾驶也是用户（顾问没有替人答的资格） | 网页 | 每一次决定都记：摘要、结论、来源（策略 / 用户 / 任务内授权 / 超时）、方向盘、步骤、时间；用户看得见 |
| **Task 级** | 澄清、外发范围、外部副作用、预算追加、改目标、步骤交人 | 工作台 | 用户 | 网页审查 | Interaction，原子消费 |
| **本地上限** | 沙箱模式提升、新增根目录、放开网络 | 本地代理（exec-server 拒绝了沙箱的要求） | 用户，且只能在这台机器上 | 本地代理弹窗（⑧） | 上限变更记录，带请求摘要 |

**本地上限不是审批的一个等级，是另一条路。**云端任何一方都不能改它；它只能在用户机器上被用户抬高，抬高也只对当前项目、当前会话有效（[安全](security.md)）。本地弹窗第一期没有建，现在的本地代理是只读沙箱 + 严格过滤器，拦下就是拦下，不问也不记。

## 工具级：先弄清 Codex 给了什么

Codex 对一条审批请求只接受四种回答（app-server v2，`CommandExecutionApprovalDecision` / `FileChangeApprovalDecision`）：

| 回答 | Codex 内部 | 后果 |
| --- | --- | --- |
| `accept` | `Approved` | 做这一步 |
| `acceptForSession` | `ApprovedForSession` | 做，并且**这个 thread 以后同类请求不再问** |
| `decline` | `Denied("rejected by user")` | 不做这一步；工具调用以「被用户拒绝」作为结果回给模型，**这一轮继续**，模型自己决定怎么办 |
| `cancel` | `Abort` → `interrupt_task` | 不做，**整轮中断**，Codex 等用户下一句话 |

三个事实决定了下面的设计：

1. **拒绝不是停。** 模型拿到「被拒绝」后可能如实报告、可能换条路达到同样效果、可能带着缺口硬往下推。后面的步骤依赖被拒那一步时，用户要的其实是 `cancel`。所以两种「不」都要给用户。
2. **拒绝不是撤销。** 前面已批准的改动都留着，只有当前这一步没做。
3. **`acceptForSession` 记在 thread 上，而我们一条 thread 上有两个驾驶者。** 用户自驾时给的「以后都允许」，交出方向盘后顾问照样享用；反过来也一样。所以工作台**永远不向 Codex 发 `acceptForSession`**，「以后都允许」由工作台自己记、自己限定范围。Codex 这一端每次都问。

`accept` 与 `acceptForSession` 的差别保留给用户（「允许一次」与「这个任务里都允许」两个按钮），但落地只用 `accept`：

| | Codex 自己记（`acceptForSession`） | 工作台记（本设计） |
| --- | --- | --- |
| 范围 | 整个 thread，跨 Task、跨方向盘 | 当前 Task；自驾时到下一次 `wheel.handover` |
| 匹配 | Codex 的规则，看不见改不了 | 请求类别 + 命令前缀，与策略表同一套词汇 |
| 记录 | Codex 自行放行的请求不再发到工作台，没有日志 | 每条都过策略、每条一行 |
| 代价 | 不再问 | Codex 每次照问，一个来回 |

## 工具级：策略

策略是一张三档表，写在专家包里，步骤可以覆盖。

| 类别 | 含义 | 专家包默认 |
| --- | --- | --- |
| `file_change_in_project` | 改项目目录内的文件 | 放行 |
| `file_change_outside` | 改项目目录外的文件 | 拒绝 |
| `command` | 跑越出沙箱的命令 | 问人 |
| `command_allow` | `command` 为「问人」时仍可直接放行的命令前缀清单（逐个参数精确匹配） | 空 |
| `network` | 联网（Codex 的网络审批，接上后启用） | 拒绝 |
| 其他 | 上表没有的任何请求种类 | **问人**，不可配置 |

- 三档：**放行**（回 `accept`，来源记「策略」）、**问人**（挂起，开 Interaction）、**拒绝**（回 `decline`，来源记「策略」，并且在步骤视图上显示一行「顾问想做 X，按专家包规则拒绝了」）。
- 没有进行中的 Task、找不到专家包、找不到步骤：一律问人。这些是我们自己的状态不一致，不能让模型替我们吃掉。
- 步骤级覆盖写在 `StepContract.tool_policy`，只能比专家包**更严或更具体**（把放行改成问人，往 `command_allow` 加前缀），不能把问人改成放行以外的放宽。
- 用户自驾没有专家包：全部按「问人」，用户自己设的 `approvalPolicy`（`never` / `on-request` / `untrusted`）仍落在 thread 上，决定 Codex 问得多还是少。
- 聊天线不变：只读沙箱、`approvalPolicy=never`，Codex 从不问。

## 工具级：问人怎么问

不论哪个方向盘，问人都是同一条路，就是现在自驾那一支的做法，顾问驾驶不再另写一支：

1. app-server 的请求挂着不答；工作台建 `tool_approval` Interaction，顾问驾驶时 Task 同一提交边界进 `WAITING(APPROVAL)`（`AT-18`）。
2. 审查面必须给用户看：命令或补丁摘要原文、`cwd`、Codex 给的理由、属于哪一步、这一步之后还有哪些步骤依赖它。
   「依赖」分两层，谁知道谁说：步骤之间由专家包的 `input_refs` 机械算出（这一步的交回物被后面哪几步吃），工作台负责列出；一步之内这条命令要不要紧只有模型知道，审查面原样显示 Codex 请求里的 `reason`，不翻译、不担保。按哪个钮由用户定，工作台不替选。判断错了有兜底：拒错了，步骤产出缺东西过不了验收条，走 `on_reject`（返工一次，再不过停下问人）；停错了，用户多点一次继续。后者便宜，所以顾问驾驶且下游有依赖步骤时默认高亮「停下」。
3. 四个按钮：

| 按钮 | 工作台回 Codex | 之后 |
| --- | --- | --- |
| 允许一次 | `accept` | 继续 |
| 这个任务里都允许（自驾时：这段驾驶里都允许） | `accept`，并由工作台记一条授权：范围 = 当前 Task（自驾 = 到下一次 `wheel.handover` 为止），匹配 = 同一请求类别 + 同一命令前缀；以后匹配的请求工作台直接 `accept`，来源记「任务内授权」 | 继续 |
| 拒绝这一步 | `decline` | 这一轮继续；按钮旁要写明「顾问会继续做不依赖它的部分」 |
| 停下 | `cancel` | 整轮中断；顾问驾驶时 Task 进 `WAITING(USER)`，等用户决定改目标、换路或取消 |

4. 用户的决定原子消费，然后回答 app-server。
5. 等不到人：期限 1 小时（可配）。到期按**停下**处理，不按拒绝——拒绝等于让模型在无人看着时自由发挥。到期后 Task 进 `WAITING(USER)`，视图上写「等了 60 分钟没人答，已停下；点继续后顾问会重新请求」。用户点继续 = 同一 thread 新开一轮，Codex 会再问一遍，那时再答。工作台**不存「预先批准」**。
6. 断线、沙箱重启、接管：未决请求作废（现有 `_take_over` 逻辑），事件写明原因，恢复后由 Codex 重新发起。

## 工具级：被拒之后

Codex 没有「被拒后不得绕路」的内置规则（查过 `core/prompt.md`），我们不能改它，只能在每一轮工作线和顾问步骤的输入里写死一条：

> 如果某条命令或文件改动被拒绝，不要换另一种方式达到同样的效果。说明被拒的是什么、因此哪些事做不了，只继续做不依赖它的部分；没有可做的就停下。

这是约束模型，不是保证。硬的保证只有两环：沙箱（不问就做的事只能在沙箱允许的圈里，而那个圈是我们自己放行的）和审批（换个办法达到同样效果多半仍越出沙箱，必须回来再问）。在审批这一环上再加一条硬规则：**同一步里刚拒绝过，随后再来的任何请求，不论策略怎么写都改成问人**，审查面标「刚拒过类似的动作」并默认高亮「停下」。软的三样是轮次输入里那句话、可见性（下一节）和验收条。真正只能靠软的，是沙箱表达不了的语义禁令（例如「别碰这个文件」而它在项目目录内）。

模型可以绕，但绕不了不留痕：Codex 的每条命令执行与文件改动都有事件，拒绝之后这一步里发生的动作，步骤视图和交回物里单列一段「拒绝之后顾问又做了什么」。

顾问步骤里出现过拒绝时，这一步的交回物要带「未获准的动作」清单；验收条不因此自动放行或放宽。

## 工具级：改得不对，要改成另一个样

审批只能允许、拒绝、停下，表达不了「改成这样」。Codex 给的另一样东西是 `turn/steer`：往正在跑的一轮里插一句用户输入，不打断、不重开。用它接住三个时机：

| 时机 | 自驾 | 顾问驾驶 |
| --- | --- | --- |
| 落地之前 | 用户把 thread 的 `approvalPolicy` 设成 `untrusted`，每个补丁先问；审查面显示 diff，多一个钮「拒绝，并告诉它怎么改」= `decline` + `turn/steer` 送用户的话 | 同一个钮；用户的话同时写进这一步的审批记录 |
| 落地之后、本轮未完 | 「插话」= `turn/steer` | 「停下」可附一段话；这段话成为该步返工的输入（`advisor.compose` 加「用户的修改要求」一节），顾问带着它重做这一步 |
| 本轮结束之后 | 下一句话，同一 thread；不是新 Task | Task 级审查时改交回物再批（「原建议与改动」）；文件要改写进返工说明，或取消 Task 拿回方向盘自己改 |

现状缺两样：步骤交人的面只有「再试一次 / 停止」，答案不带话，返工输入里没有用户要什么；`turn/steer` 没接。都在待办 77。顾问驾驶期间 `steer` 不开放给用户直接用（`AT-06` 同一时刻一个写入者），只经上面两个钮，且每次都留记录。云端沙箱里的文件网页上没有编辑器，用户改不了，先不做。

## 工具级：看得见

现在审批日志只写不读，这一节改掉：

- 每一次决定一行，不论放行还是拒绝、策略还是用户：`session`、`task`、`step`、`wheel`、请求种类、摘要、决定（`accept` / `decline` / `cancel`）、来源（`policy` / `user` / `task_grant` / `timeout`）、时间。
- 步骤视图里按时间插在该步骤下；审查页列出整个 Task 的审批；交回物里带未获准清单。
- 策略放行的也显示，但折叠；用户答的和拒绝的展开。

## Task 级审查必须表达

| 要素 | 内容 |
| --- | --- |
| 问询定位 | Interaction、Task、被询问的主体 |
| 待决内容 | 要决定什么、各选项的后果、证据等级与未知项 |
| 决定对象 | 每份文档的版本与摘要值、改动摘要；有验收条时附冻结的验收条与结论 |
| 时效 | 截止时间与目标状态版本；过期不等于拒绝，也不等于同意 |
| 决定记录 | 经鉴别的主体、响应、实际生效值、原建议与改动 |

同一 Interaction 只开一个审查面；记录响应耗时与修改项数，只作观察，不自动放宽审批。

## 粒度

按次整包（`D8`）：用户交出方向盘时一次授予专家包声明的自动放行范围；扩大外发范围、加预算、外部副作用、改目标时再授权。工具级的「这个任务里都允许」是在整包之内再细一层，范围到 Task 终态为止，不跨 Task。
