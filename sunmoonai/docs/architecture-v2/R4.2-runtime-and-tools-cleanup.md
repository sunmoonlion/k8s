## 2. 冻结结论

- 每个 App 仍需要异步 Worker；
- API、Worker、Scheduler、Migration 来自同一个 Backend 源码和不可变镜像；
- 角色使用不同命令、ServiceAccount、数据库/消息身份、资源、探针和伸缩策略；
- Worker 不再是父仓顶层源码子模块；
- R4 隔离门禁已经验证 Info、Knowledge、Investment 的 API/Worker/Scheduler/Migration；
- `app-platform-dev` 的 v1 运行态是否切换属于 R5/R7，不能用源码清理提前替代。

   同时把默认 Backend 的构建、存储、检索和数据库接入身份统一为 `tpl-backend`；
5. 删除本地旧 `tools-app` 工作副本；
