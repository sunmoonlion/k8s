## 二、代码怎么放（所有者 2026-10-04 定，`I10`）

```text
app/            页面。只把功能拼起来，不写逻辑
features/
  <功能>/
    api/        取数：请求、缓存、改动之后让谁重取
    model/      状态：纯函数与状态库。不取数、不渲染
    ui/         渲染：组件。不自己发请求
    index.ts    出口。页面只从这里拿
lib/workbench/  几个功能共用的：收发、地址、共用的清单、一段对话的事件流
components/     共用的界面件：ui/（shadcn）、common/、workbench/
contracts/      接口的写法（zod）
```

| 规矩 | 谁拦着 |
| --- | --- |
| 功能之间不互相引用 | `tests/unit/feature-boundaries.test.ts` |
| 公共的部分不引用功能 | 同上 |
| 页面只从功能的出口拿东西 | 同上 |
| `model/` 不取数、不渲染；`api/` 不渲染；`ui/` 不自己发请求 | 同上 |
| 契约认得真接口的每一份返回 | `tests/unit/workbench-contract-samples.test.ts`，对着预览样例（真后端录的）逐份检查 |

一个功能要用另一个功能的东西时，由页面递进去。例：聊天页顶部的花费钮属于「花费」这个功能，是页面作为一个插槽交给聊天页的。

现在有七个功能：`shell`（框架与侧栏）、`home`（首页）、`chat`（聊天页）、`work`（工作页）、`expert`（专家的几页）、`projects`（项目）、`usage`（花费钮）。

聊天页和工作页都要用的东西不放在哪个功能里，放在公共的位置：把 Codex 的一件事变成一行（`lib/workbench/items.ts`）、一段对话上能做的动作（`lib/workbench/conversation.ts`）、输入框、一行命令或一次查数据的样子、「没有数据」卡片、对话的名字（都在 `components/workbench/`）。

这套放法先在 investment 里用。info、knowledge 做页面时（第 8、9 步）照此办，届时把检查搬进模板。

## 三之三、第 3 段甲做了什么

截图：`step7-3-run.png`（专家处理中）、`step7-3-run-step2.png`（点了第 2 步，看它交回了什么）、`step7-3-run-stop.png`（停止前问一句）、`step7-3-run-waiting.png` 与 `step7-3-run-waiting-review.png`（勾稽不平，停下来问我）、`step7-3-run-nodata.png`（没有数据）、`step7-3-work-stopped.png`（被我停下之后的工作页）。

### 后端（investment-backend `3883855`）

| 项 | 做法 |
| --- | --- |
| 「退回第 k 步」最多 1 次（`I7`） | 专家包的每一步多一项 `max_backs`，默认 1。退回过这么多次、回来仍然不过，就停下来问用户，不再自己来回。每次退回记一条事件 `step/went_back`。给用户看的说法跟着变：「重做，最多 1 次；仍不过，退回第 2 步，最多 1 次；仍不过，停下来问你」 |
| 每一步的「为什么」 | 专家包的每一步多一句 `why`。财报体检 7 步、问数 5 步，共 12 句，是远程拟的，所有者可以改（在 `domain/workbench/packs.py`） |
| 「现在」 | 步骤接口多一块 `now`：现在是哪一步和它的为什么；这会儿在干什么（在想、在查数据、在读文件、在写交回物、在验收、等你决定），是从事件里看出来的；是不是在重做；两个时间（这一次开做的时间、最近一次动静的时间）；后台是不是还握着沙箱 |
| 不做的 | 不放模型的思考原文（会复述专家包的方法）；不另外调模型来写解说 |

### 页面

| 项 | 有什么 |
| --- | --- |
| 顶部 | 「专家正在处理：问数」「第 3 步，共 5 步：执行 SQL」「已花 ¥0.150 估算」「停止」 |
| 进展条（所有者 2026-10-04 提的） | 第一行：现在在干什么。第二行：为什么要做这一步。第三行：这一步已经做了多久、最近一次动静在多久之前。超过一分半没有动静时说「后台还连着，多半是这一步要想得久一些」；后台没有握着沙箱时如实说，不说「还在进行」。在重做时加一句「重做是按规矩来，不是出错」 |
| 左：步骤轨 | 每一步一个记号（通过、在做、在重做、退回了前面、等你决定……），做过不止一次的写「做了 n 次」。点哪一步，中间就显示哪一步；点过之后专家做到下一步，页面不自己跳走（`AT-INV-29`） |
| 中：这一步 | 用了什么（前面哪一步的交回物、哪些工具各几次、哪个数据集哪个版本）；每一次交回了什么；验收的每一条，没过的标红并写原因。还没做到的步骤写它做完会检查什么、不过的话怎么办 |
| 右：委托单 | 问题；已花，分成做完的和在做的；数据；已用时间 |
| 停止 | 先问一句，写明已花的不退、做完的部分会交回。确认才停 |
| 审查面 | 摆在停住的那一步下面：为什么停、哪几条没过、每个选项后面写着选了会怎样、这个问题保留到什么时候。没有数据时带去申请入库的链接。就地答复。这些话都是后端写的 |
| 地址 | 还是这段对话的地址。专家拿着的时候显示这一页；交回之后变回工作页 |

| 请专家 `/workbench/projects/{项目}/expert/new` | 左边是用户填的：请哪一位、要解决什么问题、在哪个项目里、花费的两句说明、专家看得到什么（只数数量）。右边是专家的承诺：每一步的名字、一句白话、不过时怎么办；它不会做什么；做完交回什么。换一位专家，右边整个换掉（`AT-INV-18`）。底部三行确认与「交给专家」 |
| 请专家：没有预算一栏 | 所有者 2026-10-04 定。交出去的请求里也不带上限 |
| 请专家：带入问题 | 从首页来，带入首页写的那句；从对话里来，带入那段对话里用户最近说的一句，并写明「专家会接着这段对话做」 |
| 请专家：交不出去的时候 | 机器没在线、这个项目里专家还在做（带一条过去的路）、没有沙箱（指到设置）：按钮禁用，旁边写原因 |
| 审查面 `/workbench/review/{待办}` | 先说清这件事在哪（项目、对话、哪件委托；命令的话还有命令与目录），再摆审查面。答完回到那段对话 |
| 侧栏与首页 | 「专家」切到专家首页；专家拿着对话时高亮的是「专家」；首页选「专家」可以开始了；首页的「待我决定」每一条都点得进审查面 |

没有做的：专家包不匹配被打回时「留在这一页并显示原因」。受理是交出之后才做的，页面这时已经进了对话；打回的原因在专家首页「最近交回的」里看得到。要留在原页显示，得让交出的接口等受理做完再答复，是后端的改动，记在细节清单。
