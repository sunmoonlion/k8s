# SunMoonAI K8s 项目整体架构

> 本文档是对 `~/k8s` 项目的全面分析，覆盖基础设施、平台层、应用层、运维工具的完整视图。

---

## 一、项目概述

**SunMoonAI** 是一个投资管理分析平台，基于 Kubernetes 部署，包含门户、孵化器、LLMOps 等多个子应用。

项目支持两种运行模式：

| 模式 | 说明 | 适用场景 |
|------|------|---------|
| **Local（Kind）** | Kind 集群运行在 WSL 内 | 本地开发调试 |
| **Remote（真实集群）** | 多节点真实 K8s 集群，支持 C1/C2 两套 | 生产/测试环境 |

两种模式的**基础设施部署方式完全不同**，但上层平台和应用的配置结构一致。

## 三、Local 模式（Kind）

### 3.1 特点

- Kind（Kubernetes in Docker）运行在 WSL 内
- 使用自定义节点镜像 `kindest/node:v1.27.3-sunmoonai`（预装 Harbor/Traefik）
- 存储：WSL 内本地 NFS（`/data/kind-nfs`）

### 3.2 集群拓扑

```
1 control-plane + 2 workers
```

### 3.3 端口访问方式

Kind 通过 `extraPortMappings` 将容器端口直接映射到 WSL 宿主机，**不需要 iptables 转发**：

```yaml
# kind-cluster.yaml 端口映射
containerPort: 30080  → hostPort: 80      # HTTP
containerPort: 30443  → hostPort: 443     # HTTPS
containerPort: 30444  → hostPort: 30444   # PostgreSQL
containerPort: 30445  → hostPort: 30445   # MongoDB
containerPort: 30446  → hostPort: 30446   # Redis
```

### 3.4 DNS（Local 模式）

WSL 的 `/etc/hosts` 指向 `127.0.0.1`：

```
127.0.0.1  harbor.sunmoonai.com
127.0.0.1  www.sunmoonai.com
127.0.0.1  www.sunmoonai.com
```

### 3.5 一键部署流程

```
deploy-kind.sh
  1. 确保 WSL NFS 已启动
  2. 构建自定义 Kind 节点镜像（如未构建）
  3. 创建 Kind 集群
  4. 配置 containerd registry（指向 Harbor）
  5. 配置 hosts 和 TLS 信任
  6. 部署 Traefik + Harbor
```

## 四、Remote 模式

### 4.1 两套集群

| | 集群 C1 | 集群 C2 |
|-|--------|--------|
| Master | `115.190.64.131`（hsy-local-1） | `115.190.37.57` |
| Worker1 | `101.126.151.0`（hsy-local-2）⭐ | `115.190.153.150` |
| Worker2 | `115.190.61.238`（hsy-local-3） | `115.190.86.211` |
| SSH 端口 | 1022 | 1022 |
| 用户名 | zym | zym |
| **Traefik** | ✅ 各自部署 | ✅ 各自部署 |
| **Harbor** | ✅ 部署在此 | ❌ 共用 C1 的 Harbor |

⭐ **C1 的 Worker1（`101.126.151.0`）是 Traefik Pod 实际运行的节点**（单副本 Deployment）

### 4.2 13 步基础设施安装

```
step00  重置节点
step01  OS 基线配置
step02  容器运行时（containerd）+ registry 镜像代理配置
step03  K8s 二进制（kubelet/kubeadm/kubectl）
step04  集群初始化（kubeadm init，control-plane）
step05  CNI 网络插件（Calico）
step06  Worker 节点加入集群
step07  创建命名空间
step08  集群验证
step09  云存储接入（NFS，火山引擎 VFS / 阿里云 NAS）
step10  节点管理
step11  预加载镜像（离线模式）
step12  CA 证书生成
step13  Traefik + Harbor 初始部署
```

### 4.3 kubectl 连接方式

Remote 模式通过 **SSH 隧道**访问集群 API，不是直接连接：

```bash
# SSH 隧道：本地 6443 → 远端 master 内网 192.168.2.50:6443
ssh -f -N -L 6443:192.168.2.50:6443 -i ~/.ssh/id_rsa zym@115.190.64.131 -p 1022
export KUBECONFIG=~/.kube/cluster-admin.conf
```

统一连接管理：
- 配置文件：`k8s/utils/k8s-admin.conf`
- 连接脚本：`k8s/utils/unified-deployment-template.sh`（各部署脚本 source 此文件）

### 4.4 端口访问方式（Remote 模式）

Traefik 以 NodePort 部署，需要在**每个节点**上配置 iptables 转发：

```bash
# 每个节点都要执行（Traefik 部署脚本会自动配置）
iptables -t nat -A PREROUTING -p tcp --dport 80  -j REDIRECT --to-port 30080
iptables -t nat -A PREROUTING -p tcp --dport 443 -j REDIRECT --to-port 30443
```

### 4.5 DNS（Remote 模式）关键约束

**C1 集群**：Traefik 单副本运行在 Worker1（`101.126.151.0`），跨节点转发在当前网络配置下会失败，DNS 必须指向此节点：

```
101.126.151.0  www.sunmoonai.com
101.126.151.0  harbor.sunmoonai.com
```

**C2 集群**：有自己独立的 Traefik，运行在 Worker1（`115.190.153.150`），DNS 指向此节点。C2 不部署 Harbor，镜像从 C1 的 `harbor.sunmoonai.com:30443` 拉取。

> 待改进：将 Traefik 改为 DaemonSet，每个节点都有 Pod，则 DNS 可以指向任意节点。

### 4.6 存储

- StorageClass：`nfs-2`（NFS 动态供应）
- 云厂商：火山引擎 VFS（默认）/ 阿里云 NAS

## 六、流量入口层（Traefik v3.5.2）

### 6.1 NodePort 端口映射

> Remote 模式通过 iptables 将标准端口转发到 NodePort；Local 模式由 Kind extraPortMappings 直接映射，无需 iptables。

| 服务 | NodePort | Remote iptables 转发 | Local Kind 映射 | 说明 |
|------|----------|---------------------|----------------|------|
| HTTP | 30080 | 80 → 30080 | hostPort: 80 | Web 入口 |
| HTTPS | 30443 | 443 → 30443 | hostPort: 443 | Web 入口（TLS） |
| PostgreSQL | **30444** | — | hostPort: 30444 | TCP 直通代理 |
| MongoDB | **30445** | — | hostPort: 30445 | TCP 直通代理 |
| Redis | **30446** | — | hostPort: 30446 | TCP 直通代理 |
| RabbitMQ | 无 | — | — | AMQP 不对外暴露 |

### 6.2 路由策略

- **Web 应用**：`Host + PathPrefix` 路由，统一域名下按路径区分
- **数据库/缓存**：TCP IngressRoute 透传到对应 ClusterIP Service
- **TLS**：统一在 Traefik 层终止，使用 TLSStore defaultCertificate


### 7.3 Redis 关键配置

- 单节点（无 Sentinel / Cluster）
- 持久化：AOF（everysec）
- 禁用：`FLUSHDB, FLUSHALL`
- 最大内存：512MB，策略 `allkeys-lru`

### 7.4 RabbitMQ 访问限制

- AMQP（5672）：ClusterIP only，集群外无法直接连接
- 管理界面：通过 Traefik HTTPS 路径路由（`/rabbitmq`）
- Celery Worker 在集群内通过 Service 名访问

## 十、应用层

### 10.1 架构模式：SSR + BFF

```
用户浏览器
    │
    ▼
[SSR 层] Nuxt.js（服务端渲染）
    │  页面渲染，调用 BFF 获取数据
    ▼
[BFF 层] NestJS 或 FastAPI
    │  业务逻辑，数据聚合
    ▼
[auth-app-bff]  统一认证服务（FastAPI）← 所有 BFF 依赖
```

### 10.2 应用清单

| 应用 | SSR | BFF | 说明 |
|------|-----|-----|------|
| **portal-app** | Nuxt.js | NestJS | 门户，链接各子应用 |
| **auth-app** | Nuxt.js | FastAPI | 统一认证 |
| **llmops-app** | Nuxt.js | FastAPI | 大模型管理平台 |
| **incubator-app** | Nuxt.js | NestJS | 孵化器应用 |
| **document-converter-app** | — | NestJS | 文档转换服务 |

### 10.3 Celery Worker

- `celeryworker-llmops`、`celeryworker-incubator`
- Broker：RabbitMQ（集群内 Service 名访问）
- Backend：Redis
- 监控：Flower（`/flower` 路径）

### 10.4 认证

- Session Cookie 名：`sunmoonai_session`
- auth-app-bff 集群内地址：`http://auth-app-bff:3030`
- 数据库：PostgreSQL `auth_db`

## 十一、部署架构规范

### 11.1 递归式配置驱动

```
组件名/
├── deploy-组件名[-all]/
│   ├── deploy-组件名.conf    # 配置：开关、凭据、优先级
│   └── deploy-组件名.sh     # 部署脚本
├── resources/
│   └── custom-values/       # Helm values.yaml
└── *.yaml                   # 直接部署的 K8s 资源
```

### 11.2 子组件部署优先级

```
secrets_priority=2000    → 最先部署（依赖关系最强）
middleware_priority=1000
ingress_priority=100     → 最后部署
```

### 11.3 Secret 管理

凭据存放在 `deploy-xxx/secrets/xxx/deploy-xxx.conf`，脚本读取后生成 K8s Secret：
- PostgreSQL：键名必须**小写**（Chart 要求）
- Redis / RabbitMQ：键名使用**破折号**（Chart 要求）
