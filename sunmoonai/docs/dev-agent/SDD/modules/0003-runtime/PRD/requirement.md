# 0003-runtime：要满足什么

> 依据：[上层设计](../../../architecture/README.md) 与 [产品合同](../../../../../product/product-contract.md) 的「责任投影」中的「本地 runtime」。

## 职责

跑在用户电脑上的常驻后台进程。主动连后端，接收 Attempt 并驱动 Codex；向 Codex 提供本地 MCP
（本地知识库、`escalate`）与公开资料取数工具；做工具级审批与副作用记账的拦截点；保管 key；
定工作区与沙箱策略；对结果做本地内容检查与加密；上报事件、用量、副作用意图与回执。

**它是三方里唯一同时碰得到 key 和结果正文的一方**——桌面应用不碰，后端看不到。

## 输入与输出

| 方向 | 内容 |
| --- | --- |
| 从后端收 | 带签名的派发内容、租约与续约、取消、审批结论、厂商预设 |
| 从桌面应用收 | 工具级审批与本地确认的结论、key 与模型配置、工作区授权、本地知识库操作 |
| 给 Codex | 运行时 thread 与 turn、本地 MCP 工具、取数工具、审批回调 |
| 给后端 | 事件与进度、副作用意图与回执、工具级审批结论摘要、用量、结果密文与本地内容检查回执 |
| 给桌面应用 | 审批请求、本地确认请求、runtime 状态、解密后的本地内容 |

## 验收

- 合同 `F-EXEC-*`；`F-APPROVE-01`、`F-APPROVE-03`、`F-APPROVE-04`；
  `F-GUARD-01`、`F-GUARD-02` 与 `F-EXEC-12` 的执行侧；`F-ACCEPT-02` 的检查与回执；`F-CRYPTO-01`；
- 合同不变量 `I14`、`I16`、`I18`、`I19`、`I20` 的执行侧成立；
- 合同验收矩阵中涉及执行端的场景可复现。

## 约束

- **不持有任何持久化账的权威副本**，也不自行决定 Task 状态（`I13`）；
- **key 只在本机**：存系统钥匙串，不写配置文件，不进任何协议字段（`I16`）；
- 与后端只有一条通道（①），主动外连，用设备私钥认证；
- 独立成仓；随桌面应用打包分发，但与用户自装的 Codex 隔离；
- 遵守 [代码规则](../../../constraints.md)、[IMP 规则](../../../../../dev-human/imp/message-rules.md)。
