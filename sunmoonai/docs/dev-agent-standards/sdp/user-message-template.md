# SDP 用户消息模板

复制成 turn 里的 `user-message.md`。

本阶段的用户消息要写清什么，见 [SDP 规则](sdp-rules.md)「这一段的用户消息」；写多严见 [任务的生命周期](../lifecycle.md)「用户消息写多严」，字段的含义见同一份的「turn 的固定字段」。
执行时要守的纪律见 [SDP 规则](sdp-rules.md)「执行者的共同纪律」；工作单元怎么拆见「工作单元」；工作区与分支见「工作区与分支」。

```markdown
---
executor: <派给谁；还没派出去写 unassigned>
verifies: 无
---
# turn <四位号>：<短名>

## 依据
<以哪一份 `SDD/` 定稿的哪几节为底；给出链接与提交>

## 要什么
<做完之后什么变了>

## 工作区
- worktree：<在哪里建>
- 分支：<分支名；与交回时 `turn.md` 的 worktree 字段一致>
- 可改的范围：<哪些仓、哪些目录、哪些文件>
- 不得触碰：<明确写出>

## 工作单元
<拆成哪几个单元，每个写清类型与优先级、范围、前置、目标、实施、测试、验收、回滚；见 SDP 规则「工作单元」>

## 完成条件
1. <可判定的条件，做完能一条条对着勾。这一段必须写：执行者不知道做到哪算完，就只能猜>

## 约束
<必须遵守的规则；代码规则的链接；预算、超时与并发上限>

## 需要人批准的动作
<推送、合并、发布、迁移、删除远端资产等逐项列出；没有写「无」>

## 不要做的
- **不改设计**：设计不对就停下来问，不在实现里顺手改掉——改设计要回 SDD 段开新 turn；
- **不扩范围**：可改的范围之外一个字都不动；
- **未经批准不推送、不合并、不发布、不删除远端资产**。

## 怎么做
- 守 [SDP 规则](sdp-rules.md)「执行者的共同纪律」八条；
- 每次落笔前过写入前门禁：当前目录、当前分支、目标路径在可写根内、路径上没有他人产物、不是宽泛写入；
- 分不清事实与推断就标出来，不把未运行的验证写成结论；
- 无法满足完成条件时明确失败或回来问，不交半成品。

**交回：产物在 worktree 的分支上，由执行 agent 做，这个 turn 里不放 `response.md`；交回时在 `turn.md` 记分支与提交。合并到 master 要经审核与人的批准。**
```

不适用的栏写「不适用」及理由——空着与「忘了」无法区分。命中 T2 判据的任务每一栏都要填。
