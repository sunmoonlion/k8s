## 五、页面

### 5.1 用户：申请入库

路径 `/<语言>/requests/new`，可带 `code`、`from`、`ref`。

| 区块 | 内容 |
| --- | --- |
| 证券代码 | 六位数字。从链接带来时已填好，可改 |
| 查到的情况 | 填完立刻显示，见下表 |
| 申请理由 | 可不填，最多 500 字 |
| 从哪来 | 只读。例如「从 investment 来」。没有就不显示 |
| 要等多久 | 「批准之后通常 5 到 10 分钟」；清单外的另加一句「要等管理员批准」 |
| 按钮 | 提交；回到原处（有 `from` 时才有） |

| 查到的情况 | 页面显示 | 能不能提交 |
| --- | --- | --- |
| 代码格式不对，或不是沪深京 A 股 | 当场提示 | 不能 |
| 已有数据 | 数据版本、数据到哪一天；链接「去看这个数据集」（knowledge） | 不生成新申请。按钮变成「申请更新」，见 5.6 |
| 已有进行中的申请 | 它的进度；「还有 n 个人也要」 | 按钮变成「我也要」 |
| 最近一次采集没通过质量检查 | 说明没通过、哪天试的 | 能。批准后重新采 |
| 都不是 | — | 能 |
| 我的未完成申请已有 5 个 | 说明上限 | 不能 |

### 5.2 用户：我的申请

路径 `/<语言>/requests`。

| 区块 | 内容 |
| --- | --- |
| 列表 | 每个申请一行：公司、申请时间、状态、最近更新 |
| 进度线 | 已提交 → 已批准 → 采集中 → 建库中 → 可用 |
| 终点不是「可用」时 | 一句白话：被拒绝（带管理员写的原因）；没通过质量检查；失败；已撤回 |
| 可用之后 | 数据版本、数据到哪一天；链接「去看这个数据集」；有 `from` 时「回到原处」 |
| 动作 | 撤回（只在批准之前）；再申请一次（终态之后） |

页面打开着的时候每 15 秒自己刷新一次进度；终态之后不再刷新。

### 5.3 所有者：申请审批

管理端，路径 `/<语言>/info/requests`。

| 区块 | 内容 |
| --- | --- |
| 待批准 | 每个申请一行：公司、几个人要、最早的申请时间、理由（每个人的分开列）、从哪个应用来 |
| 参考 | 这家公司以前采过没有、上次的结果；在不在关注清单里 |
| 动作 | 批准；拒绝（必须写一句原因，用户看得到）；批准并加入关注清单 |
| 已处理 | 可按状态筛；看谁批的、什么时候 |

### 5.4 所有者：证券采集

管理端，路径 `/<语言>/info/securities`。把现有的五个管理接口做成页面。

| 区块 | 内容 | 用哪个接口 |
| --- | --- | --- |
| 发起采集 | 输入代码，发起 | `POST /api/admin/securities/{代码}/ingestions` |
| 批次列表 | 某家公司的批次：时间、状态、采了几项、失败几项 | `GET /api/admin/securities/{代码}/ingestions` |
| 批次明细 | 每一项：来源、种类、大小、是否与已有原件相同、状态码；失败的原因 | `GET /api/admin/security-ingestions/{批次}` |
| 数据集列表 | 版本、状态、没过的检查、建库时间、登记的结果 | `GET /api/admin/securities/{代码}/datasets` |
| 重新登记 | 向 knowledge 重新登记某个版本 | `POST /api/admin/security-datasets/{记录}/registration` |

所有者直接发起的采集不产生申请，不占任何人的名额。

### 5.5 所有者：关注清单

管理端，路径 `/<语言>/info/watchlist`。

| 区块 | 内容 |
| --- | --- |
| 列表 | 公司、加入时间、谁加的、备注、最近一次采集的结果 |
| 动作 | 加入（填代码与备注）；移出（写原因） |

### 5.6 已有数据的公司申请更新

| 项 | 内容 |
| --- | --- |
| 什么时候用 | 用户觉得数据旧了，例如新的年报出来了 |
| 怎么处理 | 和普通申请一样走：清单里的自动批准，清单外的要批准 |
| 页面上 | 申请页显示现有的数据版本与数据时点，按钮是「申请更新」 |

### 5.7 旧的页面

| 页面 | 处理 |
| --- | --- |
| 管理端「Info crawl」（2026-07，旧资讯线） | 留着，不动。旧资讯线先不做申请（`P8`） |
| 网页端的仪表盘、工具箱 | 模板带来的占位页。导航里换成「申请入库」「我的申请」 |

## 八、验收

| # | 情形 | 期望 |
| --- | --- | --- |
| `AT-INFO-01` | 用户申请一家清单外、没有数据的公司 | 申请进入待批准；没有开始采集 |
| `AT-INFO-02` | 所有者批准 | 开始采集；用户的进度随之变化，直到「可用」 |
| `AT-INFO-03` | 用户申请一家关注清单里的公司 | 不经批准直接排队；批准人记为系统 |
| `AT-INFO-04` | 所有者拒绝并写了原因 | 用户看到「被拒绝」和原因；看不到是谁拒绝的 |
| `AT-INFO-05` | 第二个用户申请同一家进行中的公司 | 没有第二次采集；两个人都看得到同一个进度 |
| `AT-INFO-06` | 两个人都要，其中一个撤回 | 申请仍然有效 |
| `AT-INFO-07` | 唯一的申请人在批准前撤回 | 申请变成已撤回；所有者的待批准里不再出现 |
| `AT-INFO-08` | 用户已有 5 个未完成的申请，再提一个 | 被拒，说明上限 |
| `AT-INFO-09` | 申请一家已有数据的公司 | 页面显示数据版本与数据时点；不生成申请；可以「申请更新」 |
| `AT-INFO-10` | 采集完成但没通过质量检查 | 用户看到「没通过质量检查」；knowledge 里没有这个数据集 |
| `AT-INFO-11` | 链接里 `code=abc` | 页面照常打开，代码栏是空的 |
| `AT-INFO-12` | 链接里 `from=不认识的应用` | 页面照常打开，不显示从哪来，没有「回到原处」 |
| `AT-INFO-13` | 链接里带了 `return_to=https://别处` | 被忽略 |
| `AT-INFO-14` | 没登录的人打开申请页的链接 | 先登录，登录后回到申请页，参数还在 |
| `AT-INFO-15` | 普通用户调用管理接口 | 被拒 |
| `AT-INFO-16` | 用户甲读用户乙的申请 | 读不到 |
| `AT-INFO-17` | 所有者在证券采集页直接发起 | 开始采集；不产生申请 |
| `AT-INFO-18` | 整条链在本机联调里跑：申请 → 批准 → 采集 → 建库 → 登记 → 专家经工具查得到 | 通过 |
