# 文档 thread 与文档 turn 的编号

> 依据的通用规范：[任务的生命周期「turn：一问一答」](../dev-agent-standards/lifecycle.md)

只用四个词：**文档 thread**、**文档 turn**（我们的记账单位，就是下面这些目录）、**运行时 thread**、**运行时 turn**（执行环境里的东西，只有 id）。

## 名字

**每一级目录名 = 四位本地号 + 运行时 id。**

```text
0002-01k8f3m2qz
└┬─┘ └────┬───┘
 │        └ 运行时 id：回溯执行环境原始记录的入口
 └ 本地号：排先后、给人引用
```

- 两者合起来唯一——这是唯一性的全部来源，不靠别的。
- 本地号四位数字，按派出顺序递增，从 `0001` 起，**不跳号、不复用**；中断、失败、被替换的照样占住自己的号。
- id **写全不截断**：截断了就对不上执行环境的记录，这个后缀也就白带了。
- 派出时可以先只用本地号建目录；**写 `turn.md` 时必须已经带上 id**。执行环境不给 id 的写 `-none`。
- 改名只发生在交回之前。带了 `turn.md` 的目录连同名字一起冻结。

## 形状

```text
<节点>/thread/
├── 0001-01k8f3m2qz/            文档 thread
│   ├── 0001-01k8h2r5bb/        文档 turn
│   │   ├── user-message.md     这次发出的任务书
│   │   ├── turn.md             交回时写的回执
│   │   └── sdd/                交回物按交付物类型分：sdd/、sdp/、uat/
│   └── 0002-01k8h9t1cc/
│       ├── user-message.md
│       ├── turn.md
│       └── sdp/
└── 0002-01k8p0p0p0/            换了运行时 thread，就是新的一个文档 thread
    └── 0001-01k8q1q1q1/
```

- 一个节点下可以有几个文档 thread；**文档 turn 的号在每个文档 thread 里从 `0001` 重起**。
- 交回物跟着交它的那个 turn 走，按类型放进 `sdd/`、`sdp/`、`uat/`；任务书和回执是这一问一答的骨架，不进这三个目录。
- 引用写 `0001/0002`（第 `0001` 个文档 thread 的第 `0002` 个 turn），不带 id 后缀；验收 turn 的 `verifies` 也这么填。跨节点引用的写法见下文「子任务也编号」。

## 与运行时怎么对

| 方向 | 关系 |
| --- | --- |
| 一个文档 thread → 运行时 thread | 一对一：一个目录对一个运行时 thread |
| 一个文档 turn → 运行时 turn | 一对多：工具往返、自动接着跑、重试都算这一次派工；名字里带的是**入口**那个 |
| 反过来 | 一般不发生；真出现就是异常，交人看 |

**运行时换了 thread，就新开一个文档 thread 目录**：resume、fork、上下文压缩后重开各是一个新的运行时 thread——同一份工作接着做，但交回物是另一批，不挤进原目录续写。接着做什么，写在新文档 thread 第 `0001` 个 turn 的任务书里，不另设记录文件。

运行时 id **不参与任何层级判断**，只作回溯锚点：层级由本地号定。

## 并行

同一问发给几家，就是几个文档 thread 各开一个 turn——各家本来就在各自的运行时 thread 里。任务书各存各的：确实是各发了一次，各自冻结。

## 子任务也编号

子任务目录名是「四位号 + 短名」。**号只在同一个父节点下递增**，每一层都从 `0001` 起；项目本身不编号。

三级编号各管各的范围，合起来就是一条路径，唯一性由整条路径保证：

| 哪一级 | 在哪个范围内递增 |
| --- | --- |
| 子任务 | 同一个父节点下 |
| 文档 thread | 同一个节点内 |
| 文档 turn | 同一个文档 thread 内 |

```text
dev-agent-task/                         项目，不编号
├── thread/0001-…/0001-…/
├── composition/
└── components/
    ├── 0001-backend/
    │   ├── thread/0001-…/0001-…/
    │   └── components/
    │       ├── 0001-intake/            下一级重新从 0001 起
    │       ├── 0002-agent-execution/
    │       ├── 0003-interrupt-resume/
    │       └── 0004-acceptance-commit/
    └── 0002-frontend/
```

**不在整棵树里统一编号**：那样要有一处统一取号，几个分支同时建子任务就会抢号；子树挪了位置，号也跟着失效。按层编号只看自己的父节点，互不干扰。

跨节点引用时前面带上子任务路径，如 `0001-backend/0002-agent-execution` 的 `0001/0002`；同一节点内只写 `0001/0002`。

## 门禁查这几条

编号规则要能被机器判，[`../tools/doc-gate.py`](../tools/doc-gate.py) 查：

| 查什么 | 判据 |
| --- | --- |
| 名字格式 | 文档 thread 与文档 turn 的目录名都是 `<四位数字>` 或 `<四位数字>-<运行时 id>`；有 `turn.md` 的必须带 id |
| 层数 | `thread/` 下正好两层：文档 thread、文档 turn；交回物在 turn 目录的 `sdd/`、`sdp/`、`uat/` 里 |
| 编号连续 | 文档 thread 号在节点内、文档 turn 号在各文档 thread 内，都从 `0001` 起不跳号、不复用 |
| 名字唯一 | 同一个本地号只有一个目录；同一个运行时 id 不出现在两处 |
| 验收指向 | `verifies` 写成 `0001/0002` 且指到存在的 turn |
| 子任务编号 | 子任务目录名合乎「四位号-短名」，号在同一个父节点下从 `0001` 起连续、不复用；项目本身不编号 |
