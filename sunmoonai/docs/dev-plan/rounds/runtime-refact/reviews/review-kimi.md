### 排序与基座建议

**1. luna ｜ 2. cursor ｜ 3. kimi（自评）｜ 4. qwen。建议以 luna 为基座。**

- **luna 第一**：全部判断条通过且无一处违反证据纪律；唯一把 `refact-fable` §6 实施路线
  吸收成 G0–G5 带退出条件的候选——源稿删除后这条依赖顺序只存在于它这份里（「漏了就
  没了」）；648 行覆盖了 cursor 用 921 行覆盖的范围，按 F5（同等质量更短更好）占优。
  相对 cursor 的短板：§7 对接库原语的五步法没有 cursor 细，缺 `NotImplementedError`
  那层读法——这是可吸收的局部（见 D），不是结构性差距。
- **cursor 第二**：§7 的证据链全场最好（含测试级与基类读法）、§12 证伪专节让 D2 最干净、
  §13.2 未决登记（尤其 #8 H5 轮内发布 vs 最终发布）有独到观察。**但 §4.1 登记表给
  别家填了无取证的模型值，违反本轮最核心的纪律（J5 加重档）**，且与它自己的 ⚠ 声明
  自相矛盾。整合时若吸收其登记表，必须先删这两处取值。
- **kimi 第三（自评，同标准）**：登记表纪律干净、等效判据与引用纪律保留完整；
  扣分项：① §1.1 第 3–5 条复核受沙箱限制，强度弱于前两家（J3）；② 实施路线整体
  「故意不要」判得过宽，luna 证明它可以且应该被重排保留（J4 边缘）；③ 未自跑两道
