# 定稿

**定稿是人对「答」的采纳**：读完 turn 的 `response.md`，决定采哪一版、怎么改，整理成 `PRD/` 或 `SDD/`。
这是人的动作，人对定稿负责——不是 AI 交了就算。

和另外两件事分清楚，三者不能互相代替：

| | 对什么 | 谁做 | 在哪 |
| --- | --- | --- | --- |
| **定稿** | 对**答**（`response.md`）的采纳 | 人 | 本文 |
| **批准** | 对**动作**的放行：合并、推送、发布、追加预算、改判 | 人（principal） | [人的批准点](approvals.md) |
| **验收** | 对**交回物**按已冻结的完成条件判定 | 未参与实施的一方 | [UAT 怎么验](uat/verify-rules.md) |

定稿不等于批准：采纳一份设计，不等于批准了照它动代码——动代码是另一件事，要另外说。
定稿也不等于验收：验收判的是「做出来的东西满不满足」，定稿判的是「这个答要不要采纳」。

## 三步

| 步 | 人做什么 |
| --- | --- |
| **审读** | 自己把 response 读完。别只看结论——理由、否掉的路、标为未验证的地方，都是要判的 |
| **取舍** | 哪几段采纳、哪几段不要、哪几段要改。并行发给几家时，写明以哪一家为底 |
| **整理** | 把采纳的部分写进 `PRD/` 或 `SDD/`，并**写明以哪个 turn 为底、改了什么** |

整理是重写，不是搬运：response 是给人读的一篇答，定稿是给下一段当输入的那份东西，结构不一样。

## 不满意怎么办

- **开新的 turn**，理由写进新的 `user-message.md`：哪一条没满足、证据在哪、要改什么。
- **不在已交回的 turn 里改任何东西**——`response.md` 是当时交回的原物，改了就没有原物了。
- 也不在定稿里悄悄替它补：补了就分不清哪些是它答的、哪些是人自己写的。要补就自己写明是人补的。

## 定稿时对照看什么

各类规则里那张表是对照用的，看有没有明显的空当：[PRD](prd/finalize.md)、[SDD](sdd/finalize.md)。
**那张表不写进用户消息**，也不作为判 response 合不合格的条目——缺哪一项是开新 turn 去问，不是让模型照着填。

## 定稿之后

- **子任务从 `SDD/submodules/` 长出来**：只有定稿设计里拆出的模块才建子任务目录，同时写好它第 `0001` 个 turn 的 `user-message.md`。**不预先建还没派出的子任务。**
- 定稿改版后拆分变了：新多出来的模块建新目录；不再需要的**不删目录**，由上层定稿写明「第 n 版起取消」及原因，该子任务不再开新的 turn。
- `SDD/` 定稿之后就该动代码：走 [IMP 规则](imp/message-rules.md) 的 worktree。**这一步要另外批准**，定稿本身不构成批准。
