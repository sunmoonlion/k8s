# 2026-10-11 架构重构总览（给实施者的路线图）

> 所有者 2026-10-11 一晚定下的一组改动，从审批聊起改到应用边界。一句话：**从「工作台替用户收着结果」改成「一切落在用户的文件与对话里，平台只提供专家与审批」**。每一节只写以前 / 现在和落点，细节在各篇 SDD；做的时候以 SDD 为准，本页只管方向与顺序。

## 一、对话与项目（`SDD/modules/0017`，账 82）

| 以前 | 现在 |
| --- | --- |
| 对话两种（聊天、工作），专家 = 工作对话交出方向盘的一段 | **三种并列的对话**：聊天（一问一答）、工作（+ 文件系统）、专家（服务端先编排再对话）；两层方向盘搬到专家对话内部 |
| 项目 = 文件夹 + 围绕它的对话与底稿 | 项目 = 文件夹 + 三种对话混放，可有**专家团**（同一项目一次一位、其余排队） |
| 侧边栏「新建」按钮、专家首页、请专家独立页 | **顶部三个标签就是新建**：聊天什么都不选；工作 / 专家在对话框里选工作区 + 项目（现有 / 新建 / 拉取仓库）；专家框内「选专家」跳市场 |
| 转建：原地转（聊天→工作、→专家） | 不变，加工作→专家；另加项目行 `+` 与 `…` |
| 项目定义「不像 WorkBuddy」 | 装的东西像 WorkBuddy 的项目，归属仍是一个用户、一台电脑 |

## 二、产出与界面（`0015`、`0016`，账 80、81）

| 以前 | 现在 |
| --- | --- |
| 底稿页、结果页、底稿边栏、交回物只在数据库 | **产出就是项目文件**；唯一的产出视图是右边栏「改动」面板（补丁 + `fs/watch`），首次改动与审批时弹出 |
| 侧边栏：工作区下拉混放所有电脑 | **按真源分层**：电脑（在线灯、管理）→ 工作区 → 项目（● 在做 / 等你件数、`…` `+`）→ 对话；树下「聊天」节放未归入项目的聊天 |
| 底部：待我决定、知识库、我的电脑、设置 | 待我决定（弹层指针表）、**本地知识库、信息采集、长期记忆**、设置 |
| 右边栏只有结果 | 三钮：**文件**（根 = 工作区根目录 + 本地知识库）、**改动**、**终端**（用户电脑真 shell，账 83 另写） |

## 三、审批、澄清、插话（`SDD/architecture/approval.md`，账 77、78、79）

| 以前 | 现在 |
| --- | --- |
| 顾问驾驶越出 `auto_allow` 两个布尔就 `decline` | 三档策略表（放行 / 问人 / 拒绝，没写到的问人），越出就走问人那一支 |
| 审批 = 接受 / 拒绝 | 四钮：允许一次 / 这个任务里都允许（工作台自记，不发 `acceptForSession`）/ 拒绝这一步 / 停下；「拒绝并告诉它怎么改」= decline + steer |
| 模型中途不能问人 | 接 Codex `request_user_input` → Task 级提问卡 |
| 单独审查页、收件箱 | **答题只在事发处**；「待我决定」只剩数字与指针 |

## 四、知识与专家（`0018`、`0019`，账 84、85；`0011` 作废）

| 以前 | 现在 |
| --- | --- |
| 知识库三层：公共 / 用户私有云端库（上传、底稿自动归入）/ 工作区文件 | Codex 可读四处：**公共数据**（knowbase）、**选定专家的云上知识库**（advisor）、**项目目录**、**本地知识库**（用户电脑上的目录）。用户不再上传任何东西到云端 |
| 专家包内置在 knowbench 后端，专家首页挑一位 | **专家市场 advisor-app**（tpl-app 第四个实例）：宏观 / 行业 / 上市公司 × 专家；一位专家 = skill（profile 内化成的工作流）+ 云上知识库（专家资料夹 + 作者私有知识库）；advisor 自存自索引、自出 MCP；编排仍在工作台 |
| 一套账号 | **两套账号体系**：投研用户与专家作者各自 Casdoor 组织，不互认；市场面验投研会话 |
| 无 | 信息采集（云端替用户取公开资料，经代理写进本地知识库 `采集/`）；长期记忆（第一种：关于用户的事实，模型提议、用户确认） |
