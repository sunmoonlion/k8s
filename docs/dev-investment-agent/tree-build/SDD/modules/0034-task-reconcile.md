## 二、根子

「这个委托有没有人在推」只存在 runner 进程的内存里（`driving` 字典），库里没有。系统只能靠一次性的信号推动：一条命令、一次接管、`acquired_at` 不到 1 秒。信号丢一次——进程重启、协程崩了、同名接回租约——委托就永远停着，没人发现。

测试推进器（conductor）没卡，因为它本来就是每 5 秒按库里的状态算一遍该做什么；卡的是委托这一层，它靠命令触发。

**反例**：Opus 先写的补丁（重启后把手里的沙箱都当新接管，重推 RUNNING 的委托）在全量测试里挂了一条（`test_advisor_policy_lets_in_project_file_changes_through_without_asking`）。重推 RUNNING 的委托等于从当前步重开一轮，而 Codex 那一轮可能还在跑：双跑、双花钱，或者撞上还没结束的那一轮而失败。补丁没提交，存档在远程机草稿目录。

## 三、做法

前提：**现在只有一个 runner**（部署 `replicas: 1`、`strategy: Recreate`，新 Pod 起来前旧 Pod 已经停了）。所以「库里要人推、本进程没在推」就一定是没人推。多 runner 之前要先做第五节的心跳。

**时限一览**（都有自动测试断言，见第六节）：

| 名字 | 值 | 管什么 |
| --- | --- | --- |
| 对账间隔 | runner 轮询间隔（集群 1 秒） | 每轮都对一遍账 |
| `STOP_CONFIRM_SECONDS` | 60 秒 | 接手没人推的委托时，停下残留那一轮后等它确认停下 |
| `TURN_HOLD_SECONDS` | 900 秒（= 每一步的时限） | 委托收了尾、Codex 那一轮还没确认停下时，项目最多占这么久不放行下一位 |
| 测试排队上限 | 这次测试的 `timeout_seconds` | 用例的委托排在别人后面最多等这么久 |
| `RECONCILE_ALERT_ROUNDS` | 3 轮 | 对账连着出错这么多轮记错误日志 |

### 1. 记账收尾与放行下一位分开

- **取消直接收尾**：`request_cancel` 同一事务里写成 CANCELLED；委托不论在跑还是在等，只要有打开的那一轮尝试就一起关（记 CANCELLED、`failure_code=cancelled`；这时不知道这一轮花了多少，`consumed` 填 0，预留全部退掉）；`turn.interrupt` 照发。
- **锁的顺序**：先锁尝试、再锁委托，和结算一轮（`attempt_transition`）同一个顺序，取消与结算并发时不会互相等死。没人推的委托收尾（`settle_unattended`）同样。
- **放行要等那一轮确认结束**：委托在跑、或等着 Codex 那一轮里的请求（审批、反问）时取消，Codex 里那一轮可能还在跑。账马上收，但委托原始输入上记一笔 `turn_open`（那一轮的尝试编号、时间），**项目照样算被占着**，不放行下一位。确认结束的三条路：推它的程序这一轮跑完（补记花费时）、或撞上终态安静停下时 `release_turn`；没人推的由 runner 停下并确认（第 2 条）。都没有就等 `TURN_HOLD_SECONDS`，到点放行，记一条 `turn/hold_expired`（「费用待核对」：那一轮花了多少拿不到了）。中断都带那一轮的编号，不会误停新的一轮。
- **项目有没有被占着，只有一条判法**（`repository.py` `_OCCUPYING`）：没结束的委托（排在别人后面的不算），或刚结束、`turn_open` 还在时限内的。提交（`handover` 判要不要排队）、放行（`_start_next_queued`）、对账都用它。
- **放行在一个事务里做完**：锁住项目、按上面那条判没人占着、选最早排队的、交接方向盘、排 `task.drive`。原来的放行不再检查，A 在跑、B 和 C 排队时取消 B 会把 C 放进来与 A 同跑（评审第 2 条），现在不会。
- **推它的程序还活着时怎么停（点名）**：这一轮跑完要写尝试，读到尝试已关、或写的时候撞上 `InvalidTransition`（取消插在读和写之间），就补记这一轮的费用并 `release_turn`，返回终态；`_drive` 另外接住 `StaleStateVersion`（`repository.py` 537、917）与 `InvalidTransition`，重读委托，已是终态就记一行 info、`release_turn`，不记平台失败。
- **补记费用只记一次**：同一事务里先锁尝试再锁委托，加进委托的 `budget.used` 与那一轮尝试的 `budget_consumed`（步骤上看得到这一步花了多少），记一笔 consume 和一条 `attempt/late_cost`；**按那一轮的编号去重**（已在尝试的 `turn_ids` 里就不再记），重复回报、结算后重试都不重复扣账。预留已在取消时退了，补记不碰预留。
- `fail_after_crash` 看到 `cancel_requested_at` 有值时写 CANCELLED，不写 FAILED。
- 测试超时（`test_runs.py` `_time_out`）走同一条取消路径，不另写。

### 2. runner 每一轮对账

`run_once` 领完命令后对一遍账（`_reconcile`），**每件各用自己的事务、出错只跳过这一件**，一件坏了不拖住别的；连着出错 3 轮记错误日志（目前没有监控栈，靠日志）。

- **拿租约**：沙箱上有待办命令、或有委托要人推（受理、核验中、排队、在跑、等待），都去拿（没有租约、租约过期、或本来就是这个名字的）。本进程新拿到的都接管，含同名上一任留下的。
- **作废随旧连接消失的工具审批**：进程新拿到一个沙箱时，以及**每次实际建一条新的 app-server 连接时**（同一进程里断了再连也算），作废它上面 pending 的 `tool_approval`、发 `interaction/expired`，内存里等着答的也放掉。Codex 是否会在新连接上重问，**由演练确认**（第四节 7、7b）：重问了，用户能答、委托接着走；没重问，推它的程序等这一步的时限（15 分钟）到了按验收不过走，有出口。
- **每种没结束的状态的去向**（「本进程没在推」= `driving` 里没有，或协程已结束）：

| 状态 | 条件 | 去向 |
| --- | --- | --- |
| RECEIVED | 排在项目队列里（带 `queued_behind`） | 不动，等放行 |
| RECEIVED | 没排队（受理了、命令丢了） | 没有 pending / claimed 的 `task.drive` 就排一条：还没开工，不会双跑 |
| VALIDATING | 核验中进程没了 | 同上 |
| QUEUED | — | 同上 |
| RUNNING | — | **不重开**：交 `_settle`——按那一轮的编号停下它，读线程（`thread/read`）确认停了，最多 `STOP_CONFIRM_SECONDS`；然后收成 FAILED（记着取消的收成 CANCELLED），原因「推它的程序重启了，这一步没做完」，带尝试编号、那一轮编号、`cost: unknown`；`failure_code=platform`。确认停了才放行下一位，确认不了记 `turn_open`、按第 1 条最多占 `TURN_HOLD_SECONDS` |
| WAITING | 等的是 Codex 那一轮里的请求（交互带 `request_id`） | 同 RUNNING：那一轮的驾驶者随上一任没了 |
| WAITING | 委托级的等待（开步前的提问、返工交人、追加预算、等机器上线） | 不动：本来就没有驾驶者，回答后排 `task.drive` 接着走 |

- **项目排队**：每轮看一遍「有排队、没人占着」的项目，放行最早的一件；`turn_open` 过了时限的先 `release_turn(expired=True)`。
- 推它的协程崩了而进程还活着，下一轮对账同样收住。

### 3. 有上限、看得见

- **测试超时不算排队时间，但排队有上限**：用例的委托排在别人后面时，`waiting_since` 照问用户那样计入 `waited_seconds`；排队本身超过这次测试的 `timeout_seconds` 就按超时收尾，原因写「queued too long behind task X」。
- **管理端看得见在等什么**：135 的 `progress` 加可选字段 `queued_behind`（只有一个委托编号，C-L5），管理端写「在排队：排在测试账号前一个委托后面」；运行方还没开跑时写「已受理，还没开跑：等测试电脑接手」，开跑时间用运行方的，不拿提交时间冒充（账 136 第 ②）。契约照规矩先 knowlab 后 knowbench。

### 4. 部署前看一眼

发布卡在「提交、发布」之前加一步只读查询：有没有 RUNNING、或等着 Codex 那一轮里请求的委托。有就停，交所有者定等它跑完还是照部署（照部署它会按第 2 条收尾、写明原因）。以后这就是 Jenkins 流水线第 1 步「核对」的一项（0033，fable 分支 `85265f5a`）；两页互相引用，不各写各的——0033 合进来后在它那边补一句指回本页。

## 四、故障演练（本地集群，正跑着测试时做）

每一种都要在第三节的时限内要么接着跑、要么结束并在管理端写清原因；不许「一直测试中、没原因」，不许两轮并跑，费用不重不漏。

| # | 制造什么 | 应当看到 |
| --- | --- | --- |
| 1 | 删测试电脑 Pod | 代理用持久卷上的凭据连回；正跑的一轮断了之后怎么收（步骤时限 15 分钟到了是重试还是判失败）**由演练确认**——代码里 `_requeue` 只在几种可重试失败时调，没证实会重试 |
| 2 | 边缘断开 5 分钟（不碰现网边缘，办法另定） | 代理在边缘回来后 30 秒内重连（账 136 代理修复，0.5.1） |
| 3 | runner 同名重启时正跑着任务（10-19 这个洞） | 60 秒内停下并确认残留那一轮，委托收成 FAILED（平台、原因带尝试与那一轮编号），测试接着下一条用例 |
| 4 | 推它的协程崩了、进程还活着 | 同 3 |
| 5 | 正跑着时取消、或测试超时 | 委托马上 CANCELLED；那一轮结束后才放行下一位；那一轮的花费补记一次 |
| 6 | 排在一个卡住的委托后面 | 管理端写「在排队」；排队不算进测试超时；排队超过测试时限按超时收、原因写明 |
| 7 | runner 同名重启时一件委托正等工具审批 | 旧审批作废、发 `interaction/expired`；委托按第 2 条表收尾；**记下 Codex 有没有在新连接上重问**（评审第 6 条要的运行证据） |
| 7b | 不重启 runner，只断它到沙箱 app-server 的连接（一件委托正等工具审批） | 重连时旧审批作废；**走到新审批出现、用户回答、委托接着走**，或 15 分钟时限到了按验收不过走 |
| 8 | 让中断不管用（残留那一轮停不下） | 委托收尾但项目占着、下一位不开跑；900 秒后放行，有 `turn/hold_expired`（费用待核对） |

## 五、这一版不做

- **委托心跳**（`driver_id`、`driver_heartbeat_at`）：多 runner 之前必须有，单 runner 时对账已够。
- **接回正在跑的那一轮**：重启后不重开、也不判失败，而是接上 Codex 那一轮等它结束取结果。要先查 Codex app-server 能不能按 `turn_id` 查一轮的状态，单独设计。做之前，部署时正在跑的委托会明确失败（第三节第 2 条）。
- **runner 名字改用 Pod 名**：只修重启这一种情况，修不了协程崩了；对账之后不需要。

## 六、测试

knowbench 后端（真库）：

- 同名重启：委托 RUNNING、记着取消、没有待办命令 → 一轮后 CANCELLED。
- 同名重启：委托 RUNNING、没取消、Codex 里那一轮还在跑 → 按那一轮编号中断、确认停了、FAILED（平台），原因带尝试与那一轮编号；没有新开一轮（假 app-server 没收到第二个 `turn/start`）。
- 同名重启：委托等 Codex 那一轮里的审批 → 旧审批 expired、有 `interaction/expired`，委托收尾。
- 同一进程里沙箱连接断了再连、正等工具审批 → 旧审批 expired。
- RECEIVED（命令丢了）、VALIDATING 进程没了 → 各排一条 `task.drive`；委托级的 WAITING 不动。
- 委托 QUEUED、没人推 → 连跑三轮只有一条 `task.drive`。
- A 在跑、B 和 C 排队，取消 B → C 不放行（评审第 2 条）。
- 取消在跑的委托 → 马上 CANCELLED、尝试关、预留全退；那一轮补记后 `budget.used` 多出这一轮的钱、预留不变；补记、`release_turn` 之后才放行下一位。
- 同一轮的花费回报两次 → 只记一次。
- 取消与完成并发 → 只有一个终态（原有测试，按新取消改过）。
- 中断不管用 → 委托收尾、下一位不放行；`turn_open` 过了 900 秒才放行，有 `turn/hold_expired`、`cost: unknown`。
- 对账时一件出错 → 别的照推，连着出错的轮数记下。
- 崩溃时委托记着取消 → `fail_after_crash` 写 CANCELLED。
- 测试：用例排在别人后面 → 进度带 `queued_behind`、排队不算进超时、排到时限按超时收、原因带挡路的委托编号。
- knowlab：`progress.queued_behind` 过 schema、只许一个委托编号；管理端草稿带运行方状态与开跑时间。管理端组件：「已受理，还没开跑」、「在排队」。

## 七、代价

- knowbench 后端：`ledger.py`（取消直接收尾）、`runner.py`（对账、作废旧审批、`_drive` 撞终态安静停下）、`advisor.py`（`fail_after_crash` 见取消写 CANCELLED）、`repository.py`（租约、查没人推的委托）、`test_runs.py`（排队不计时、`queued_behind`）；knowlab 后端与管理端（契约可选字段、显示）。没有迁移。
- 部署时正在跑的委托会失败（原因写明），直到第五节「接回那一轮」做完。
