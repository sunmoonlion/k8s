## 2. 修订结论

1. Next Web Frontend 继续与同产品 Web Backend 成对发布和验收；配对由 surface、contract、
   audience、cookie、部署和回滚 tuple 决定，不由后端语言决定。
2. 现有 Nest `tpl-web-backend` 必须先完成 B2~B4，固定证据后改名
   `tpl-web-backend-nest`，作为受维护可选模板。
3. canonical `tpl-admin-backend` 必须先从三套已通过 P0-005 的业务 Admin Backend
   反向补齐通用安全和基础设施能力；不得直接复制当前旧模板，也不得带入领域代码。
4. 新 canonical `tpl-web-backend` 使用 FastAPI，继承修复后母版的全部已验证通用能力，
   再替换为 Web 专属 audience、cookie、session namespace、allowlist 和 DAL contract；
   它是默认 Web Backend profile。
5. `tpl-admin-frontend + tpl-admin-backend`、`tpl-web-frontend + tpl-web-backend` 是两套默认
   发布单元；Admin/Web 即使都使用 FastAPI，仍保持独立信任面和发布边界。
6. FastAPI/Nest 必须通过同一语言无关契约；P0-008C 和后续三个业务 App 只使用 FastAPI
   默认 profile，Nest 不作为业务主线完成证据。
