拍板的框架**。起草者没分这两类。

**二、`pipeline` 那道题不是另一轮，是本轮 ① 的第一步。**

事实 5、6、7 合起来：题目正确的那份任务书没跑完，而 2026-09-07 另起的任务书把题目

因此不复活独立轮次，材料并入本轮。

**三、根因是次序，不是理解。**

v1 让候选**直接立文档类别**。文档类别是为流程服务的，脱离流程去立类别，只能立出
自洽但悬空的东西——两份候选都是这个形状。正确次序是：**先有流程结构，文档类别从中
推导**。这一点写进新任务书 §2。

## R4 · 2026-09-08 · 指定 `cursor` 为整合方

**裁定：`integrator = "cursor"`。**已写入 [`round.md`](round.md)。

### 依据

所有者 ③ 之前指定。协议对 `integrator` **没有任何约束条款**（见 §附，登记为 F-16），
故本条按 §13 给 `acceptor` 立的同一原则类推：**判据是既得利益，不是质量。**

cursor 在两条轴上都干净：

| 轴 | cursor |
| --- | --- |
| 是否基座作者 | **不是**（它自己推荐 luna 当基座） |
| 是否持有组织者角色 | **不持有**（本轮任务书、通知、`inventory.md`、归档均由 opus 产出） |
| 是否有贬低基座的动机 | **没有**——它把 luna 排第一 |
| 是否读透了全部材料 | 其 ② 评审 294 行，逐份给了正文反例 |

**未选 opus 的理由**（起草者自己提出，记在此以备复核）：

> ④ 异议只拦「少吸收」，不拦「多塞」。异议的触发条件是「主张被拒绝或被部分接受」；
> 整合方若往稿里塞自己的新材料，**没有任何一家的主张被处置，因而没有人被触发**。
> opus 的偏差方向恰好是 ④ 查不到的那一种——而协议 §12 称异议是
> 「**对整合权的唯一制衡**」。绕过唯一制衡，等于没有制衡。

⚠ 且 opus 已持四重角色（参赛方 · 起草者 · 组织者 · 评优方），再加整合方
即本轮全部非裁决角色由一家独占。

**未选 luna 的理由**：若基座为 luna，则整合方＝基座作者。
协议 §13 第 2 条禁 `acceptor` 兼基座作者，理由是「**验自己的稿子等于自检**」；
该逻辑对整合方同样成立——整合方决定把别家的什么吸收进**自己的**稿。

### ⚠ 条件：本项在一种情况下必须重议

**cursor 当前推荐的基座是 luna。**若 ③ 最终选中 **cursor 自己的稿**作基座，
则整合方＝基座作者，正是上一段反对 luna 的同一配置。**届时本项须重议。**

### ⚠ 同时需要所有者明裁的一处歧义

协议 §13「⑤ 验收方由处置表算出」的规则 1：

> 1. **不得是裁决方**——**整合方不能自验**，这是分角色的全部意义；

⚠ **这句在「裁决方兼整合方」的旧轮次里无歧义；本轮两者已分开**
（裁决方＝所有者，整合方＝cursor），它到底排除谁？

- 按**字面**：排除裁决方（所有者）——但所有者本来就不产出整合稿，排除它无意义；
- 按**理由**（「整合方不能自验」）：排除**整合方**（cursor）。

`round.md` 第 32 行现在写着「⚠ 排除 integrator 而非 arbiter」——
**那是起草者当时的解读，不是裁定。**请所有者明裁；在明裁之前，
⑤ 的验收方计算按「排除整合方 cursor **与**基座作者」执行，即取两者的并集排除。

### 配套要求（因整合方兼参赛方）

本轮五家全参赛，故任何整合方都同时是参赛方——2026-09-03 失败的第一条正是这个形状。
其余三道闸必须完整走完，不得裁掉：

1. **④ 异议不得跳过**，且五家都要明确回「有异议」或「无异议」——
   协议原话：**空回复无法与「还没看」区分**；
2. **⑤ 验收方按 §13 的算法算出，不由裁决方凭印象指定**，并排除见上；
3. **⑥ 确认必须是人的显式动作**，不得由任何 agent 代行。
