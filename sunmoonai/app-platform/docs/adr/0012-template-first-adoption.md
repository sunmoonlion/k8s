# ADR-0012：共同底座模板优先并立即完整同步实例

- 状态：已接受
- 日期：2026-08-01
- 强化：既有模板优先原则

## 背景

过去模板和实例交错演进，实例可能只继承安全片段而遗漏菜单、组件、错误处理、审计、任务、
构建或运维能力。继续在旧实例底座开发会扩大不可解释漂移。

## 决策

- 所有共同能力先在 tpl-app 实现和验收；
- 默认模板收敛为 `tpl-backend`、`tpl-admin-frontend`、`tpl-web-frontend`；
- 模板发布生成包含 commit、tree、镜像 digest、契约版本和测试证据的 release manifest；
- 模板完成后立即按 Info -> Knowledge -> Research 串行完整同步；
- “完整同步”包含工程、认证、授权、错误、日志、审计、配置、任务、存储、UI 通用能力、
  构建、部署和测试，不只是安全文件；
- 实例领域代码通过显式 extension point/overlay 保留，禁止清空覆盖；
- 每个实例必须生成模板对齐报告，把差异分类为领域扩展、配置、暂时兼容或违规漂移；
- 三实例共同底座完成前暂停新业务功能开发。

## 门禁

- 模板自身 clean-room 和 Admin/Web 双配对通过；
- 每个实例独立完成静态、单元、契约、配对、KIND、身份和回滚测试；
- 一个实例失败不得推进下一个；
- 父仓 gitlink 和 release manifest 一致。

## 结果

模板重新成为事实源，实例可扩展但不再形成私有基础设施分叉。
