# PRD：产品需求文档（Product Requirements Document）

回答「要什么、做到什么算满足」。由**规划 agent** 整理交付；① 原始需求由人给出。分两部分，**两部分的生命周期不同**：

| 部分 | 写什么 | 怎么改 |
| --- | --- | --- |
| ① 原始需求 | 提出者的原话、来源与背景、意图、范围与边界、授权、待澄清的歧义，以及与已有需求和决定的关系 | **冻结后只追加澄清，不改写**——防止整理者用自己的理解覆盖原话 |
| ② 需求与验收合同 | 正向与反向场景、功能要求、不做什么、约束、验收标准 | 按版本修订；验收判据在这里冻结，出题与答题分开 |

## 提出需求的人要做到

| 要求 | 做不到会怎样 |
| --- | --- |
| 写清**边界**：含什么、不含什么、不含的归谁 | 执行者会自行扩大范围，或漏掉本该做的 |
| 给**可判定的验收标准**，不给倾向性结论 | 产出向提出者的结论收敛，等于白问 |

人这一侧的其余义务见 [人的批准点](../../approvals.md)「人这一侧的义务」。
