## 2. 设计原则

### 2.1 子 Agent 即 Run

子智能体是一个带 `parent_run_id` 的 Run。由此免费继承：Run 状态机（七态、四终态不可转出、
`validate_run_status_transition`）、事件流与 SSE 回放、LangGraph 检查点、
cancel 的每步检查。父子关系用**物化路径**表达，既支持路径寻址，也支持库内子树查询。

不另建实体的理由：任何新实体都要重新实现上述四项，且与现有 SSE 契约不兼容。

`RunBudget` **不在继承清单内**——它当前未被任何生产链调用（见 §1），须先接线再谈继承，
见 §2.2 的前置条件。

### 2.2 预算预扣，不用共享池

**前置条件：先让单 Run 预算真正生效。**当前两条生产链都不调 `budget.check()`，
父 Run 自身没有有效余额，因此预扣与退回都无从测起。次序必须是「单 Run 接线 → 父子语义」，
不可颠倒（归属见 REQ-006 ④ D7）。

接线之后：派生子 Run 时从父 Run 的四维余额中**划走**一份，子 Run 完成时将未用部分退回。

共享池的两个问题：并行消费有竞态；无法保证任何单个子 Run 能跑到完成（可能全部中途
`budget_exceeded`）。预扣制保证「派出去的每个子 Run 都有确定的完成能力」。

推论：`spawn` 时必须显式给出子预算，父余额不足则派生失败而非降级。

### 2.3 等待语义做全，不留给调用方

wait-any 与 wait-all 都做成一等原语，quorum 视 D5 决定。参考实现只提供 wait-any，
代价是每个调用方自己写循环、且受单批八目标上限约束——从零设计无此包袱，不要复制它的缺陷。

### 2.4 Registry 独立于会话

编排状态（节点、边、状态、产物指针）单独存储，不塞进 `session_events`。
依据参考实现的教训：会话记录存的是对话，业务 DAG 是另一个状态容器，
靠翻会话记录还原「工作流跑到第几步」迟早出问题。

`tool_side_effects` 已是独立记账表，说明该分离直觉在本仓已有先例。

### 2.5 复核者拿不到父上下文

复核子 Run 不继承父 Run 的消息历史，只接收产物与验收标准，结论用契约 DTO 回，
不退回自然语言摘要。

两条依据：REQ-002 中 C7 由「错误」被人工改判为「含糊」，说明产出方不能自验；
参考实现亦有同一结论（刚写完代码的会话倾向确认自己的判断）。

### 2.6 副作用与 cancel 的多智能体语义

- 副作用：并行分支可能重复触发同一副作用。语义（exactly-once 或 at-least-once + 幂等键）
  必须在写第一行编排代码前定死，见 REQ-006 ④ D3。
- cancel：须沿父子树传播。参考实现中「能掐子 Agent、掐不掉另一个持久任务」的不对称性
  是其历史遗留，不予继承。

## 3. 验收标准

1. 子 Run 复用 Run 状态机，无新增并行状态机（可代码审查判定）。
2. **单 Run 预算已生效**：两条生产链均调 `budget.check()`，超限时 run 进入 `budget_exceeded`
   且该状态在生产中可达（当前唯一写入方是非生产图 `first_m1_graph.py:36`）。
3. 预算预扣可测：父余额不足时派生失败；子 Run 未用额度在终态时退回父。
4. wait-any 与 wait-all 均为一等原语，调用方无需自写循环；无隐含目标数上限。
5. Registry 与 `session_events` 分离存储；从 Registry 单独可答「当前哪些节点 ready」。
6. 复核子 Run 的上下文不含父 Run 消息历史（可测）；复核结论为契约 DTO。
7. cancel 父 Run 后，全部子孙 Run 在有界时间内进入 `cancelled`。
8. 副作用语义有明确文档与测试：同一副作用在并行重试下不产生重复业务效果。
9. 编排内核不含投资研究领域概念（为与 REQ-005 共用内核留出边界，见 REQ-005 ④ D8）。
