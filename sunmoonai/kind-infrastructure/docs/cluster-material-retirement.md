# 集群升级物料对应与最终清理

2026-09-27。目标：**以后只有一套部署代码，加上两种建集群的方式。本地把平台和应用跑通，云上除了建集群那一步，其余走的是同一条路。**

## 1. 本次整体替换的边界

升级整套集群物料，不能只换 kubectl。不同组件按兼容关系固定各自版本，不使用“全部 latest”，也不要求所有组件的数字相同。

| 物料 | 旧云端物料 | 本次目标及取得状态 |
| --- | --- | --- |
| kubeadm / kubelet / kubectl | 1.30.4 deb | 1.36.4，三个二进制已下载并核验；systemd 单元及 OS 依赖闭包待补齐 |
| Kubernetes 控制面 / kube-proxy | 1.30.4 | 1.36.4，新版 kubeadm 输出的4个镜像已归档、回传并核验 |
| etcd / CoreDNS / pause | 3.5.12-0 / 1.11.1 / 3.9 | kubeadm 1.36.4 指定 3.6.8-0 / 1.14.2 / 3.10.2，三镜像归档已回传并核验 |
| Calico 清单与网络镜像 | 3.28.2、旧 Tigera operator 路径 | 3.32.2；KIND 已备齐 CNI、node、kube-controllers 并验证；云端复用同一来源与摘要，部署接线未完成 |
| containerd / runc | nerdctl-full 2.1.3 内嵌组件 | 2.3.4 / 1.4.3，与实际新 KIND 节点对齐，独立包已下载核验 |
| nerdctl / crictl | 2.1.3 / 1.30.x | 2.3.5 / 1.36.0，已下载核验 |
| KIND / 节点镜像 | 旧业务节点仍运行 1.27.3 | KIND 0.33.0 / kindest/node 1.36.4；独立验证批次已备齐并通过基础验收，正式三节点重建尚未进行 |
| OS 辅助依赖 | conntrack、socat、NFS 等 deb | 按目标 OS 与新版工具补齐依赖；不能看到旧文件名就当废包 |
| PostgreSQL、Redis、MongoDB、Elasticsearch、RabbitMQ、Harbor 等 | 原平台版本 | 保留版本、chart、镜像与恢复依赖；仅有 1.36 实际安装失败证据时才另记最小升版理由 |

新版采用的 Calico manifest 当前只引用三种镜像。旧 operator、Typha、CSI 等归档不能机械地全部下载新版：先按最终选定的网络功能确认所需镜像集合，补齐该集合，再退役已不使用的路径。网络功能发生变化须在部署方案明确，不以删包替代设计。

KIND 节点镜像包含节点内 Kubernetes 和运行时；云端 kubeadm 要独立准备二进制和控制面镜像。两种方式版本一致，不表示可拿同一个 node.tar 代替云端全部安装物料。

清单真源：[云端集群锁](../../infrastructure/materials/cluster-artifacts.lock.json)、[KIND profile](../isolated/profile.json)。`closure_complete=false` 表示还没配齐，禁止宣称云端离线部署已可用。云端代码及部署流程**未经实机验证**。

## 2. 只读盘点与候选量

本次目录 `~/packages-to-be-installed`，截至本轮工具和镜像回传后约 **40.81 GiB** 分配量（文件/目录按 inode 去重，不跟随符号链接，未计文件系统元数据）。

| 类别 | 分配量 | 处理 |
| --- | --- | --- |
| 25 个旧集群物料文件 | 1,016,045,568 字节，约 **0.946 GiB** | 整套新版及脚本接线验收后，进入最终清理复核 |
| 已被分拆方案替代的 nerdctl-full 2.3.5 | 287,174,656 字节，约 **0.267 GiB** | 独立组件及依赖闭包完成后，进入最终清理复核 |

| 旧 images 总目录 | 约 15.35 GiB | 包含上述候选及大量原版本平台/应用镜像，不能整目录删除 |

分类之间有包含关系，不能把表中每行相加作为收益。Docker 内镜像/缓存与这些 tar 文件也是不同对象；本清单只计算物料目录。

逐文件大小、SHA-256、替代关系、字面引用位置与通配符路径线索见 [物料退役候选清单](../../scripts/results/luna-material-retirement.20260927.json)。空引用列表只表示没查到完整文件名；脚本可能拼接版本或用通配符，不能因此自动删除。

## 3. 目录整理方式

- 新集群物料放 `releases/kubeadm-1.36.4-linux-amd64/` 与 `releases/kind-1.36.4-calico-3.32.2-linux-amd64/`，采用明确的批次路径和摘要；共享物料优先引用已核验内容。
- 原 `images/debs/tars/charts` 保持原位，先修正部署入口的引用，再按逐文件清单退役；现在移动它们会使旧脚本失效。
- 原平台服务保持版本。Node/Python 构建镜像、Helm、local-path、NFS 等不按“集群版本旧”整批剔除，逐个确认用途。
- 旧集群 kubectl 1.27.3 继续保留，当前业务 inbox 仍需要它。
- 原冷备、已验收物料锁、下载来源、校验结果与小型故障记录保留；不能只保留一份正在使用的 Harbor 数据就删除唯一冷备。
- 新下载的半文件不会被视为已完成物料；续传后仍须完整 SHA-256 核验。东京仅用于公开物料下载，不部署云集群。

## 4. 最终清理门禁和方法

所有者已要求最后一起清理且必须清理，本轮只盘点，不删除、不移动。收尾时：

1. 核对正式 Harbor、入口、正式 KIND、平台与最终 CI/CD 验收；确认回退观察期要求。
2. 验证新批次所有必需文件与镜像摘要、依赖闭包及安装引用；云端未经实机验证的旧历史安装路径继续保留。旧材料是否仍为其唯一恢复输入须逐件记清，不为了腾空间删除唯一来源。
3. 重新运行下面的只读盘点命令。比对候选的路径、SHA-256、inode/硬链接和最新引用；出现变化停止该项，重算数量。
4. 仅回收达到条件且在授权内的明确文件，不对目录通配删除。不触碰任何容器、卷、旧节点、Harbor 冷备或平台服务唯一物料。
5. 按类别记录删除文件数、文件分配量、ext4 前后 `df -B1`；并行写入产生的差值如实说明。未达条件项写清保留原因，不虚报已释放。
6. Windows C 盘回收由所有者在既定维护窗口关闭 WSL 后手动压缩 VHDX；不启用自动收缩。ext4 空间释放不能等同于 C 盘文件立即缩小。

本清单并入 [最终空间回收计划](wsl-space-reclamation-plan.md)，不会替代原 R1/R2/R4 的条件。新版工具回传证明见 [七文件核验结果](../../scripts/results/luna-cloud-cluster-tools-aligned.20260927.json)。

规则自检：C-D1 保留权威备份及无法重建内容；C-R1/C-R2 用具体版本、文件摘要与镜像摘要形成可追溯物料，不把“下载成功”当作完整部署验收。
