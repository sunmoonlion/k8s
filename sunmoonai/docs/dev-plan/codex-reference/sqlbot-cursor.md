## 结论

SQLBot 是「prompt 链 + RAG 校准」的 ChatBI。我们问数走 Wren 语义层受管 SQL。
两条是竞争路线，**不切换**。机制可借，代码不可搬。

财务域怕的是同一指标两个口径。SQLBot 把口径放进提示词里的 DDL、术语和示例，
没有强制语义层。这正是不换路线的原因。

它的核心链在单文件 `llm.py` 里拼消息：检索注入 → generate_sql → check_sql →
执行 → 出图。声明了 langgraph，源码里没用。无图、无 checkpoint、不可当金标准
回归——和我们说的反面形态是同一类。langchain 0.3 / Python 3.11 钉死，和仓里
langgraph 1.x 不兼容，不要移植。

## 如何借鉴

四样都挂在**已经选定的问数静态图**上，不另开一条 SQLBot 式 prompt 链。
借的是注入点和交付形态，不是它的编排。挂法：

```text
用户问题
  → 术语解析（新，借术语库）
  → 取 MDL 上下文 + 召回示例（few-shot，P0 即可轻量）
  → 生成候选（只许对 MDL 提问）
  → wren_dry_plan 预检
  → 受管执行
  → 写出 ChartSpec / 数字 Artifact
  → （可选）SSR 出图给 IM
```

术语解析失败、示例过期、dry_plan 不过，都停在图上，写事件，不要退回「模型
直接写 SQL」。

### 1. 术语库

SQLBot 把业务叫法检索进 prompt。我们缺的是「人怎么叫 → 标准口径」这一跳，
不是再塞一段 DDL。

**记什么。** 一条术语不是一段解释文，是一条解析记录：

- 别名：ROE、摊薄 ROE、加权 ROE、净资产收益率
- 落到哪个 MDL 指标 / 模型 / 列（只许引用已有 id）
- 适用 as-of、主体范围（集团 / 母公司 / 单季 / TTM）
- 状态：生效 / 已废止；废止的必须带替代 id
- 谁确认过（人），何时

MDL 改了指标定义，术语行要么改指向，要么废止。禁止在术语行里写 SQL、写公式
「约等于」。公式只活在 MDL。

**挂在哪。** 问数图第一个节点：输入自然语言 → 输出 `resolved_metrics[]`。
命中则把标准名和约束交给下一节点（list_models / fetch_context），prompt 里
只出现已经解析后的名字。未命中：停下来问人，或标「未解析」禁止往下生成。
模糊命中（摊薄 vs 加权都像）必须问人，默认不可猜。

**不要做成。** 不要把术语库当第二套 schema 检索；不要用术语解释代替 MDL
描述；不要在术语里夹私货口径。检索只做别名对齐。

**何时做。** 轨 B 选定数据源之后就可以建表和人工录第一批高频词。20 题里
凡是「同一指标多种叫法」的，先靠术语解析，不靠把 DDL 整段塞进 prompt。

### 2. 示例 few-shot（越问越准的轻量形态）

SQLBot 的 data_training 是「问过的 NL→SQL 再检索回来当例子」。Wren 已有
同构工具：`wren_store_query` / `wren_recall_queries`。P0 不必等
`AgentMemory` 全套，先把这条用起来。

**存什么。** 只存**人确认过、dry_plan 通过、数字对过金标准**的对：

- 用户原话
- 解析后的指标 id（来自术语节点）
- 当时的 MDL 版本
- as-of / 数据域
- 受管 SQL 或 Wren 查询句（哪一种以现活 Wren API 为准）
- 证据 id

没确认的对话轮次不要入库。错例可以另存「负例」供回归，不要当 few-shot
正例召回。

**怎么用。** 术语解析之后、生成之前：按解析后的指标 + 问题向量召回 1～3
条。prompt 里的例子必须带「本例 MDL 版本 / as-of」。当前 MDL 对不上的
直接丢掉，当没召回。召回是提示，不是指令；dry_plan 仍是硬门。

**失效。** MDL 发版时批量作废旧示例，或标过期不可召回。口径一改还在教
模型，比没有示例更糟。

**和术语的分工。** 术语解决「这个词是哪个指标」。示例解决「这类问法通常
怎么取、怎么过滤」。两者都解析到 MDL，都不定义口径。

### 3. 图表 SSR

SQLBot 的 g2-ssr 是独立 Node 服务，把图渲成图片。第 25 课已经有 ChartSpec
（单位 / 系列 / 证据引用）。借的是「服务端出图」这个交付形态，不是把
@antv/g2 钉死成唯一实现。

**产物分层。**

1. 查询 Artifact：SQL / Wren 句、行数据引用、as-of、evidence_id
2. ChartSpec：给 Web 的契约，客户端或前端可自己画
3. 可选 png/svg：SSR 只吃 ChartSpec，输出对象存储 id

下游（研究节点、thesis、复盘）认 1 和 2。IM、邮件、需要「一张图」的通道
才要 3。没有 ChartSpec 不许直接从行数据渲图——否则图上的口径无法回溯。

**服务形态。** 独立小服务即可：输入 ChartSpec，输出图片字节或对象 id。
问数图最后一个可选节点调用它；失败时 Web 仍能靠 ChartSpec 画，IM 则明确
说「图没渲出来、数字在」。不要把渲染进程塞进 celery worker，也不要在
LLM 进程里起 canvas。

**何时做。** 浏览器问数先走 ChartSpec。企业微信 / 其它 IM 要发图时再立
SSR。P0 spike 不依赖出图。

### 4. 问数当 MCP 工具

SQLBot 用 fastapi-mcp 把问数暴露给 n8n / Dify / 其它 Agent。我们对外输出
时也可以，但只能是**现有受管问数控制面的另一扇门**。

**暴露什么。** 与浏览器同一套：按术语解析 → dry_plan → 执行 → 读回
Artifact / ChartSpec。工具名跟现活代码走，不要为 MCP 再做一套「generate_sql」。
需要的话再加 `wait` / `cancel`，和 Agent 控制面四件套对齐。

**不暴露。** 任意 SQL 执行、绕过 dry_plan、不带 as-of 的取数、把自由文本
当指令写回决策。MCP 调用方是另一个 Agent，更要 schema，更不能认聊天。

**鉴权。** 与浏览器同一用户 / 工作空间 / 数据域权限。MCP 不是内网免检。
预算和取消记在同一棵 `RunLineage` 上，避免「外面一个 Agent 问一次就打穿
限额」。

**何时做。** 问数主链在浏览器里 20 题过了之后。先做人机路径，再开机器入口。

### 建设顺序（只对这四样）

1. 轨 B 有样例库之后：术语表 + 人工录词；示例只手塞金标准题，召回可先
   关键词 / 指标 id，不必先上向量。
2. 接 `wren_store_query` / `wren_recall_queries`（或等价物）：人确认才存。
3. 问数图写出 ChartSpec；Web 能画。
4. IM 要发图再加 SSR。
5. 主链稳定后再挂 MCP。

前两步提高「问对」的命中；后两步是交付和对外，不提高口径正确性。
不要为了借鉴把问数主链先做成 SQLBot 那样的单文件消息链。

## 不借

- 1978 行单文件 prompt 链当问数主链
- 它的依赖栈和实现代码
- 「越问越准」代替语义层：运营沉淀示例可以提高命中，不能定义指标
