## 1. 仓库定位

这个仓库是 **sunmoonai 平台的部署编排仓 + Architecture v2 重构的施工控制中枢**。双重身份：

1. **部署编排**：KIND 本地集群上各平台（数据/消息/网关/CI-CD/认证）的部署清单与运维脚本。
2. **重构控制面**：Architecture v2 的全部权威文档（阶段计划、迁移矩阵、阶段结果、证据、门禁脚本、数据迁移方案）都在 `sunmoonai/docs/architecture-v2/`，三个领域 App 的 v2 声明式部署 bundle 在 `sunmoonai/app-platform/<app>/architecture-v2/`。**源码本身不在这个仓库**，它控制的是各源码仓的施工节奏与验收门禁。

## 4. overall-architecture.md 七个核心决策

1. 三个独立领域 App（Info/Knowledge/Investment），各有界上下文。
2. 每 App 一个 FastAPI Backend + 一个 PostgreSQL 逻辑库 + 一条线性 Alembic 链。
3. 双 Next.js 前端（Admin/Web）共用统一 Backend：SSR 走 server-only `BACKEND_INTERNAL_URL`，浏览器只走同源 `/api`（Traefik 高优先级直达 Backend）；前端不是数据所有者。
4. Admin/Web/Internal 是**接口分面**（`/api/admin/v1`、`/api/web/v1`、`/api/internal/v1`、`/api/auth/{admin,web}`），用例只实现一次。
5. 四运行角色（API/Worker/Scheduler/Migration）= 同一不可变镜像不同命令，不共享进程/ServiceAccount/全部凭据。
6. 跨 App 只走三类公开契约：同步 API、异步事件（Transactional Outbox + Inbox 幂等 + 对账）、Artifact（对象引用 + 内容哈希 + 版本）。主链路：Info Artifact/Outbox → Knowledge Ingestion/Retrieval → Investment evidence/citation。
7. 共性先过 tpl-app 门禁再串行同步到实例，禁止在三个实例里分别修同一个底座问题。

标准源码拓扑：`<app>-app/{<app>-backend, <app>-admin-frontend, <app>-web-frontend}`。旧的独立 Admin/Web Backend、Celery/Node Worker 仓不属 v2 拓扑。数据库角色模型：`{app}_backend_user`（DML 无 DDL）+ `{app}_backend_user_migration`（唯一 DDL/owner）。

## 5. R4 实例同步规则与结果

规则（R4-instance-sync-runbook.md）：`sync_r4_instance.py` 三方比较（实例原继承 commit / release manifest 新 commit / 实例当前 commit）；差异必须归入 `domain-extension`、`deployment-config`、`temporary-compatibility`，未分类即 `prohibited-drift`，**计数非零禁止写入**；冲突处理 target/local/merge/skip_template 均须写明原因；**禁止全局 tpl→app 正则替换**（会破坏 `grid-template-columns`、`@babel/template` 等合法标识，只允许精确字符串白名单）；R4 不拼接模板 Alembic root（模板 auth/outbox migration 由 skip_template 记录，R5 再以实例 head 为 down_revision 重建）；执行顺序 plan → 临时工作区 apply → 测试 → 实例 apply → 提交 → 证据固化。

结果：

## 6. R5 数据迁移（三份独立计划）

通用方法论：V0 基线冻结 → V1 源码迁移链 → V2 角色目标库 → V3 平行候选（Worker/Scheduler 0 副本、候选队列，不产生第二写者）→ V4 切读写封锁旧写 → V5 回滚前滚演练 → V6 声明式收口。**短写冻结、单写者，禁止双写/CDC 换"无停机"表象**。私有 custom-format 备份 0700/0600 不进 Git/镜像/Secret/日志。回滚保留 additive migration，不让旧镜像 downgrade 它不认识的新 revision。

- **Info**：`info_admin` 是规范库（名中 admin 仅历史遗留）；`delivery_outbox_message` 与通用 `outbox_message` 语义不同禁止合并；10 张业务表（raw_artifact 56、extracted_content 30、crawl_job 25 等）；切换顺序：冻结写→排空→备份→旧六组件缩 0→转移 owner/grants 封锁旧角色→启用统一三角色→Ingress 切 `/api`+`/` 双路由→旧前端缩 0→验证 fail-closed。
- **Knowledge**：RAGFlow 是外部 Provider 不是领域库；领域 ID 与 Provider binding 分别对账。
- **Investment**：从 `research_admin`（11 表：agent_runs 28、agent_sessions 29、session_events 278、checkpoint_writes 363、checkpoints 160 等，head `20260712_0002`）迁至新建 `investment_admin`；唯一 Alembic 链 `20260708_0001→20260712_0002→20260729_0003_agent_pilot→20260809_0004_outbox_primitives`；检索身份正式改为 `sunmoonai-investment-knowledge-retrieve`（旧 `sunmoonai-research-knowledge-retrieve` 仅为回滚保留）。旧 research-app 与未来 research-app 严格区分：当前"研究能力"属于 investment-app；未来 research-app 必须从已验收模板全新实例化，不得复用旧身份。

## 8. 部署 bundle 结构（每 App `architecture-v2/`）

五件套 YAML：`00-prerequisites.yaml`（ServiceAccount/Secret 引用/NetworkPolicy）、`10-migration.yaml`（一次性 Job）、`20-runtime.yaml`（API/Worker/Scheduler + HPA/PDB）、`30-network-policies.yaml`、`40-ingress.yaml`（严格 TLS、`/api` 高优先级 + `/` 低优先级双路由）；加 `release.json`、`render-formal.py`、`deploy-formal.py`。通用门禁：`app-platform/scripts/verify-architecture-v2-instance.py`。

每 App 发布输入 `release-inputs.json`（schema_version 1）：stage、formal_release=false、模板版本（r3.2 / scaffold `7f2942c`）、三镜像 digest（只收 `repository@sha256`）、rollback_baseline、gate 结果。流程：源码仓构建不可变镜像 digest → 写入 release-inputs.json → k8s-scaffold-v2 render/deploy → R7 晋级模板镜像。**版本语义**：`1.0.0` 是旧架构回滚基线；v2 全部门禁通过后同一验收 digest 晋级 `2.0.0`，禁止为正式版本重新构建再打 tag、禁止用可变 tag 替代 digest。

## 9. 证据分层与禁止事项

**证据分层 L1-L7**：L1 静态 → L2 单元 → L3 契约 → L4 角色/DB 集成 → L5 配对 → L6 KIND/严格 TLS/真实 Casdoor/回滚 → L7 跨 App E2E/观察窗。smoke 通过不得宣称完成。

**禁止事项速查**：master 施工；先改实例后补模板；批量替换三实例；三套 application；合并三 App 数据库；Next.js 当数据所有者；覆盖 1.0.0；删镜像锁 digest；无备份合并库；R7 前删旧资产/旧数据库/Secret/PVC；双写/CDC；全局 tpl 正则替换；宽泛 `tests/test_*` 规则掩盖漂移。

## 10. 边界与衔接

- 本仓库不含任何 App 源码；源码在 `~/tpl-app`、`~/info-app`、`~/knowledge-app`、`~/investment-app`（见各自摘要）。
- auth-app（Casdoor）是身份提供方，不套三仓模板，单独部署；它提供 OIDC 但不替代各 Backend 的资源级授权。
- research-app 目录仅剩 LEGACY-ROLLBACK-ONLY 回滚面，R7 完成前保留；未来 research-app/tools-app 必须从已验收模板全新实例化，不从旧目录复制。
- 当前集群为 KIND 开发环境（namespace `app-platform-dev`），生产 NetworkPolicy 门禁由一次性 Calico 集群单独闭合。
- **权威文档时效性**：两份总体架构文档（`sunmoonai-architecture/architecture/`）已于 2026-08-12 修订（前端技术栈更正为 shadcn/@base-ui，迁移快照更新至 R6 完成/R7 进行中）并于同日迁入本仓纳入 Git；仓内旧源 `app-platform/docs/overall-architecture.md` 与 `docs/sunmoonai·-architecture.md` 已删除，内容以迁入的修订版为唯一权威。
