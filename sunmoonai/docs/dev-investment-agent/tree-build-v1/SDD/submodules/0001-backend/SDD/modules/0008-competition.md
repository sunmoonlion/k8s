# 0008-competition：多方竞争

**承担**：同一问派给几家、收齐后择优并记录处置——[多方竞争](../../../../../../turn/competition.md) 在产品侧的实现。

- **并行派发的竞争形态**：同一步派 N 个 Attempt，各自隔离，**全部做完再比**（不是首个通过即停，那是冗余形态）；
- **候选的冻结与取件**：候选绑不可变提交，按摘要取，不从工作区取；
- **择优与处置**：逐条判为接受 / 部分接受 / 拒绝，处置记录机器可读；
- **角色算出**：验收方由处置表算出（既得利益最小的一家），不由裁决方指定；
- **异议**：被处置到的家可提异议，异议在验收之前。

**不承担**：

- 不决定「这一步要不要走竞争」——那是 `0003-orchestrator` 按 workflow 定的；
- 不自己派发、不自己送达——派发经 `0004-bridge`；
- 不改状态、不写账，经 `0001-ledger`；
- 不判「做对没有」——那是 `0006-acceptance`；本块只判「哪一份更好」。

**为什么单列**：它横穿**派发**与**验收**两站，不属于其中任何一站；
按 [七块怎么切](../architecture/blocks.md)「凡横穿的不摊进任何一站」单列。
摊进 `0003-orchestrator` 会让编排同时背上候选冻结、处置表、角色算法，
而那三样与「下一步派什么」是两件事。

**未决**：`D10b`（并行 Attempt 的两种含义：冗余择快 / 竞争择优）未定之前，
本块的停止规则与 `0006-acceptance` 的择优边界都定不下来。见 [待定决策](../../../../../decisions.md)。
