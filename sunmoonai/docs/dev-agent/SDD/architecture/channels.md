# 通道

> 由产品合同搬入。部件的定义见 [请求生命周期](lifecycle.md)。


| # | 两端 | 协议 | 内容 | 安全要点 |
| --- | --- | --- | --- | --- |
| ① | runtime ⇄ 后端 | WSS，runtime 主动外连 | 派发 Attempt（带签名，含**本步方法工具清单**）、取消、续约、事件与进度、副作用意图与回执、工具级审批结论摘要、用量、厂商预设（带签名）、`escalate` 转交、**方法工具的调用与结果** | 设备私钥认证；协议不设 key 字段、不设本地资料内容与文件名字段 |
| ② | runtime ⇄ Codex | Codex Python SDK（子进程 stdio） | 启动或恢复运行时 thread、下发运行时 turn、事件、审批请求、中断 | 仅本机；Codex 不开端口 |
| ③ | 桌面应用 ⇄ runtime | 渲染进程 → preload → 主进程 → 本机管道（stdio 或仅本用户可访问的本地套接字） | 工具级审批、本地确认、key 与模型配置、工作区授权、本地知识库、结果解密与预览、runtime 状态 | 不开 TCP 端口；只有随应用打包的本地窗口挂这类 preload（它是独立窗口，不与主窗口共用 webContents） |
| ④ | 桌面应用 ⇄ 后端 | HTTPS + 事件流（cursor 续传） | 提交、查询、取消、Task 级审查、结果密文、设备与计费、「有待审查」提醒 | 桌面端 token；每次读取重新授权 |
| ⑤ | Codex ⇄ 知识服务 | HTTPS（MCP） | 检索、领域工具、按需取方法 | 按设备发 token、可吊销、限流 |
| ⑥ | Codex ⇄ 模型厂商 | HTTPS | 推理 | 用户自己的 key，只在本机 |
| ⑦ | 管理后台 ⇄ 后端 | HTTPS | 运营、客服、审计查询 | cookie 会话 + CSRF；内部人员权限；只见元数据 |


用户侧没有网页端，网页与用户电脑之间不存在通道；本机的一切交互都在桌面应用里。

设计上还要落实这几件事：

| 交互 | 设计要点 |
| --- | --- |
| 提交 | 客户端生成幂等键，后端在可靠边界内建单并写首事件（`F-INTAKE-01`、`F-ADMIT-01`） |
| 事件与结果 | 先持久化后通知；客户端按 cursor 续传，重复事件幂等（`F-DELIVERY-02` 至 `F-DELIVERY-05`） |
| 审批与审查 | 工具级只在本机闭环，Task 级经后端 Interaction 原子消费；两条提交逻辑不得共用（`F-APPROVE-*`、`F-REVIEW-*`） |
| 结果 | 执行端本地检查后加密，后端只存密文与元数据，客户端本机解密（`F-CRYPTO-*`） |

谁对哪条要求负责，以合同「责任投影」为准，本文不复制第二份。
