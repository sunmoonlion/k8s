# 收尾验收：镜像持久化与长期空间管理

目标：只有一套部署代码，加上本地 KIND 与云端 kubeadm 两种建集群方式；本地先跑通平台与应用，云端除建群外走同一条路。

2026-09-28 所有者追加的交付要求。下列项目属于本次完成条件，不能推迟为无日期的“以后优化”。
本页是实施/验收清单，**不是已通过的结果**。现场迁移仍暂停；新统一空间命令尚未实现，删除策略尚未批准。

## 一、镜像持久化必须有运行证据

沿用 [Harbor 备份恢复](../registry-platform/docs/host-backup.md)、[入口维护窗口](../registry-platform/docs/entry-maintenance.md)与[正式集群交接](../kind-infrastructure/docs/luna-handoff-and-inbox-targets.md)。挂载 UUID、目录和 Docker 服务视角核对只是前置条件。

### 基线与通过条件

1. 记录外置 Harbor 实例标识、版本、数据路径、证书指纹，KIND 名称/UID、节点 ID、kubeconfig 与 kubectl 绝对路径。只导出脱敏清单，不写口令、令牌或私钥。
2. 暂停会修改仓库的 CI、推送、复制、保留/GC 任务，确认没有上传任务，保存可恢复的数据库逻辑导出、身份/加密密钥及镜像层备份。不能拿已过时备份覆盖新写入。
3. 导出全部项目/仓库的 tag→digest、无标签 artifact、OCI index 及子 manifest 关联；包括 app-images、k8s-images 和所有其余项目。记录分页完成状态，漏页、权限不足或读失败均不能作为完整基线。
4. 对停止写入后的整个 registry 文件目录生成排序清单：相对路径、文件类型、大小、SHA256、权限与所有者；前后比较同一范围，报告缺失、新增、内容不同。不是抽样，也不要求运行中 PostgreSQL 物理文件逐字节不变。数据库用逻辑内容、项目/仓库/身份及实际认证结果核验。
5. 各场景完成后重做目录与 API 全量比对，manifest/index 摘要逐项一致。实际以现有账号/机器人身份认证拉取，但凭据只通过私有文件或标准输入使用。
6. 从每个新节点拉取指定平台/应用镜像，按 digest 固定，并记录 CRI 实际 imageID 与平台子 manifest 对应关系。多架构 index digest 与子 manifest digest 分开记录；不得误判成相同字段。
7. 完整性由全目录与全 artifact 摘要负责，节点拉取负责验证可用性。拉取通过仍不能代替完整性检查；只在 WSL 主机执行 docker pull 也不能代替节点拉取。

### 三个场景分别出具结果

| 场景 | 动作与观察 | 必须留下的证据 |
| --- | --- | --- |
| WSL 重启 | 维护窗口停止工作、关闭并启动 WSL；验证开机挂载/服务恢复顺序，无一分钟弹窗轮询 | 前后目录/API 清单差异、服务日志、挂载服务视角、实际认证拉取；挂载缺失时服务不得落盘到系统目录 |
| KIND 停止再启动 | 只停止/启动批准的受管新集群；同时持续记录宿主 Harbor 可达性 | Harbor 独立服务不随集群停止、摘要完整、节点恢复 Ready 后拉取成功 |
| KIND 删除重建 | 明确目标名称、UID、节点 ID 和准入配置后删建；优先用一次性验收集群，正式 main 删建需对应维护窗口批准 | 删除期间 Harbor 可用、全量前后比对；重建后 UID/节点容器 ID 改变；新节点无目标缓存情况下从 Harbor 拉取且 Pod 可启动 |

删除重建验收**不能**删除旧 kind、旧 kind-worker2、保护中的容器/卷，也不复用旧节点缓存证明拉取成功。验收集群必须消费同一个外置 Harbor 和统一入口/证书/信任配置。正式 main 若未实际删建，最终报告只能写“验收集群已通过、正式 main 未执行”，不能混写。

WSL 关闭会中断助手会话：动作前将恢复步骤、证据路径和失败回退写入持久化记录；重启由维护窗口执行，返回后续验。失败保留数据和证据，不自动用恢复掩盖差异。每场景记录开始/结束时间、命令、返回码、基线/结果文件摘要及判定；私有原始证据存 Git 外，仓库只存脱敏回执。

## 二、统一日常空间入口（待实现）

入口继续用根目录 `./sunmoon`。以下是接口契约，**现在不能当作已存在的命令运行**：

| 拟定命令 | 用途 | 副作用边界 |
| --- | --- | --- |
| `./sunmoon space status` | 容量、告警、上次成功盘点时间/数据陈旧、保护集和任务状态 | 只读，凭据不回显 |
| `./sunmoon space preview --scope <范围>` | 生成候选 ID、原因、保护排除项、共享内容去重后的释放估计及计划摘要 | 保存预览记录；不删除；Harbor 原生 dry-run 可能创建任务/日志，须标明 |
| `./sunmoon space apply --plan <文件> --approval <批准记录>` | 仅执行经批准的候选清单 | 执行前重核身份、保护集、恢复来源；计划过期或状态变化即拒绝 |
| `./sunmoon space policy show` | 显示实际生效策略、版本、自动任务、禁用项 | 只读，不能把方案数值当作已生效 |
| `./sunmoon space monitor <status/install/disable>` | 管理后台只读容量监控 | install/disable 显式执行；无窗口弹出；不附带删除权限 |

scope 分 Harbor、构建缓存、日志、备份、本次 refactor 临时物料。代码归属仍在现有模块，operations 负责调度；不再复制一套 Harbor 管理实现。配置、批准记录、盘点报告与执行回执分开存储，不以编辑 plan 等同于取得批准。

### 监控与告警

- 同时看 C 盘可用量、WSL 系统 VHDX 实际大小/文件系统用量、100 GiB 数据 VHDX 实际大小/文件系统用量与 inode、Harbor/备份/缓存/日志的增长。识别 bind 与硬链接，避免重复累加空间；镜像共享层释放量报告保守区间，不把镜像展示大小相加。
- C 盘按“当前可用－数据 VHDX 剩余最大增长－本次操作临时峰值”预算，结果仍须至少 50 GiB。数据盘继续沿用现有恢复/建群脚本的 20 GiB 常驻余量及额外操作额度，不能被百分比阈值弱化。
- 建议只读监控在 WSL 启动后与每小时运行，重任务前额外检查；目录深度盘点每天一次。容量达到 70% 提醒，80% 或触及操作保留量阻止新增的大型备份/导入/构建，90% 记为紧急。最终值集中配置；停止服务与恢复操作不得被低空间门禁阻断。
- 监控不删除，不反复调用可见 Windows 窗口。C 盘指标使用隐藏只读采集；WSL 停止期间没有持续监控，启动后补测并标明空窗。不得显示过期绿色状态。
- 本地状态页/报告与 CLI 显示告警、采集失败、预计耗尽趋势、最近成功盘点和处理建议；交付前验证阈值告警及任务失败能被看见。外部通知落点待所有者定，未配置时明确标注“无机器外告警”，不发送未授权消息。

## 三、删除策略草案：必须先交所有者确认

下面的天数、份数和自动执行范围**只是待确认提案**，不继承为清理授权。已有 R1/R2/R4 批准与前置条件仍按[空间回收方案](../kind-infrastructure/docs/wsl-space-reclamation-plan.md)执行，不能扩大到新对象。

### 先算保护集，再算候选

- 在用镜像包括所有目标集群工作负载模板（含缩容为 0、CronJob、初始化容器）、运行 Pod 的实际 digest、宿主 Harbor/入口/扫描器等服务，以及发布清单、回退清单和离线建群物料。不能只按最近拉取时间或当前 Running Pod 判断。
- 已下线/不可连接集群、离线云环境，以锁定的物料/发布清单保护；信息不完整时停止对应清理，不能当作“没有使用”。
- 回退版本建议至少保留最近两次成功发布且覆盖观察期，显式保留的版本永久排除，退出条件由所有者确认。index 子 manifest、共享 blob、签名与关联制品按关联保护。
- 保护至少一份完整且恢复验收通过的 Harbor 备份及迁移前回退备份；~/private 不作为临时清理目标。旧节点/卷保护期不变。

| 范围 | 候选草案 | 自动/人工提案 | 影响与恢复 |
| --- | --- | --- | --- |
| Harbor 开发镜像 | 保护集外，超过30天且不在每仓最近10个成功版本中的制品 | 初期只自动预览，逐次人工批准；平台/建群镜像不套此规则 | 删除后本地重推必须有原 digest 来源；不能保证可重建出同一摘要 |
| Harbor GC | 已批准删除之后的无引用 blob；默认不勾选“清理无标签 artifact” | 初期人工批准，先 native dry-run，再执行；保留任务记录 | 不手工删除 registry 目录；GC 后要靠备份恢复，停止任务不会撤销已删内容 |
| 构建缓存 | 指定 builder 中未使用、超过7天、可再取得输入的缓存 | 构建结束自动生成预览；批准明确范围后才启用构建后清理 | 下次构建变慢、可能重新下载；网络不稳定且只有缓存作为输入时排除 |
| 容器/服务日志 | 建议容器每文件20 MiB、最多5份；普通文件日志每日轮转、14天、总量上限 | 策略批准后自动轮转；审计/故障证据单独保留 | 轮转删去的历史日志不可逆；Harbor 文件日志、Docker 日志、节点 Pod 日志分别配置 |
| 常规备份 | 建议最近2份恢复核验通过的完整备份，并保留当前变更前一份 | 初期只预览、人工删；新备份失败/未恢复核验时不轮换 | 不为满足份数强行挤爆100GiB；备份依赖/硬链接/唯一来源先核清 |
| 本次临时物料 | 逐个登记本机目录、临时容器/工具、中转包、东京下载目录及替代来源 | 最终验收后给精确清单，再按现有授权/补充批准执行 | 只删本次创建且不再必需的对象；保护中的节点/卷与必要离线物料排除 |

Harbor 的保留规则选择“保留哪些”，多个规则按并集生效，同 digest 多标签需整体考虑；不能直接把保护 digest 清单等同于原生 tag 规则。实施时先证明原生策略不会触及保护集，否则拒绝执行。[Harbor 2.13 保留规则](https://goharbor.io/docs/2.13.0/working-with-projects/working-with-images/create-tag-retention-rules/)

删除 tag 不等于空间已经释放；GC 负责无引用 blob 回收。它支持 dry-run，停止 GC 不会恢复已删除内容。[Harbor 2.13 GC](https://goharbor.io/docs/2.13.0/administration/garbage-collection/)

Docker 日志参数对已有容器不会自动生效，需分批在获准的维护窗口更新受管容器；不得为了日志轮转重建旧保护节点。[Docker 日志配置](https://docs.docker.com/engine/logging/configure/)

禁止 docker system prune、docker volume prune、docker container prune；不清理将重建节点内部镜像（R3 已取消）。本次回收记录逻辑用量和 C 盘实际释放量分别计算，VHDX 压缩仍由维护窗口关闭 WSL 后执行，不启用自动收缩。

机器外备份仅针对数据库、对象存储、~/private，落点待所有者选移动硬盘或加密对象存储；接口预留，但未选落点/未完成首次恢复不能标成已实现的灾备。镜像备份不擅自扩展到机器外。两块 VHDX 在同一物理 C 盘上，同盘备份不防硬件故障。
