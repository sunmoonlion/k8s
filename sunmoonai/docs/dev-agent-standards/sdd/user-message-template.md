# SDD 用户消息模板

复制成 turn 里的 `user-message.md`。

本阶段的用户消息要写清什么，见 [SDD 规则](sdd-rules.md)「这一段的用户消息」；写多严见 [任务的生命周期](../lifecycle.md)「用户消息写多严」，字段的含义见同一份的「turn 的固定字段」。
交回的 response 要能定稿成 `SDD/`，所以它要满足 [SDD 规则](sdd-rules.md)「`architecture/` 写什么」「`modules/<模块>/` 写什么」「设计必须满足」与「设计原则」。

```markdown
---
executor: <派给谁；还没派出去写 unassigned>
verifies: 无
---
# turn <四位号>：<短名>

## 依据
<以哪一份 `PRD/` 定稿、或哪一份 `SDD/` 的哪几节为底；给出链接与提交>

## 设计到哪一层
<结构层（模块之间的关系与接口）还是模块内部。一问只做一层，别混>

## 必须给出的
- **模块之间**：谁向谁提供什么、接口与数据的形状、错误与版本规则、跨模块的共同约束；
- **模块内部**：内部结构、状态与持久化、**失败与恢复**（会怎样失败、失败后回到哪个状态、谁负责补偿）；
- **取舍**：有哪几条路、各自代价、为什么选这条；
- **要不要往下拆**：要拆的话给出子模块的四位号与短名——它们将成为 `SDD/modules/` 下的子任务。

## 不能动的契约
<列出。要改必须按 [SDD 规则](sdd-rules.md)「改已冻结的契约」提修订工作单元，
 不在配置、适配层或文档里偷加语义>

## 范围
- 包含：
- 不包含：
- 不包含的归谁：

## 验收标准
1. <可判定的条件，做完能一条条对着勾>

## 不要做的
- **不写实施步骤与排期**——那是 SDP；
- **不新增状态词**（P0）；**不制造第二个真源**（P1）；
- 跨运行仍须正确的不变量交给持久存储，不放在执行进程本地；
- 领域概念不进通用端口的签名。

**交回：写成这个 turn 的 `response.md`，由规划 agent 交，不改代码。人读完定稿成 `SDD/`，`modules/` 下拆出的每个模块成为一个子任务。**
```

不适用的栏写「不适用」及理由——空着与「忘了」无法区分。命中 T2 判据的任务每一栏都要填。
