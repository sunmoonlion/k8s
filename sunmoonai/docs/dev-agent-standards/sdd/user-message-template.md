# SDD 用户消息模板

复制成 turn 里的 `user-message.md`。

这一段要产出什么、设计要守什么，都在 [SDD 规则](sdd-rules.md) 里，**用户消息只指过去，不复述**。
写多严见 [任务的生命周期](../lifecycle.md)「用户消息写多严」，字段的含义见同一份的「turn 的固定字段」。

```markdown
---
executor: <派给谁；还没派出去写 unassigned>
verifies: 无
---
# turn <四位号>：<短名>

## 依据
<以哪一份 `PRD/` 定稿、或哪一份 `SDD/` 的哪几节为底；给出链接与提交>

## 设计到哪一层
<结构层（模块之间的关系与接口）还是模块内部。一问只做一层，别混>

## 要不要往下拆
<这一问是否要给出子模块的划分。要拆的话写清已知的边界；拆出的模块将成为 `SDD/modules/` 下的子任务>

## 约束与不能动的契约
<必须遵守的规则、外部限制；以及哪些已冻结的契约不许动——
 要改必须按 SDD 规则「改已冻结的契约」提修订工作单元，不在配置、适配层或文档里偷加语义>

## 范围
- 包含：
- 不包含：
- 不包含的归谁：

## 怎么答
按 `sunmoonai/docs/dev-agent-standards/sdd/sdd-rules.md`「`architecture/` 写什么」「`modules/<模块>/` 写什么」「设计必须满足」与「设计原则」。

**交回：写成这个 turn 的 `response.md`，不改代码。人读完定稿成 `SDD/`，`modules/` 下拆出的每个模块成为一个子任务。**
```

这一段不写验收标准：答得合不合格看它能不能定稿成 `SDD/`——判据是 [SDD 规则](sdd-rules.md)，不是这一问里临时立的条目。

不适用的栏写「不适用」及理由——空着与「忘了」无法区分。命中 T2 判据的任务每一栏都要填。
