# `0002-web-preview` 预览：不连后端看页面

> 属于 [`0002-web`](0002-web.md)。所有者 2026-09-29 定的调试方式：迁移期间做网页用预览模式，不往旧集群部署（[决策](../../decisions.md)）。
> 对应 [先后顺序](../../PRD/apps/README.md) 的第 6 步。用法在各网页端仓库的 `app/preview/README.md`。

## 一、它是怎么回事

```text
浏览器 ──> 前门（preview/server.mjs，一个端口）
             ├─ /api/…      样例：从真的后端录下来的返回
             ├─ /__preview  目录页：有哪些情景，每个情景里有哪些页面
             └─ 其余        Next（网页端原样的代码）
```

| 项 | 做法 | 为什么 |
| --- | --- | --- |
| 网页端的代码 | 一行不改，没有任何预览的分支。它以为自己连的是真的后端 | 预览不进正式构建；也不随前端的目录怎么排而变（账本 D1 还没定） |
| 样例 | 不手写。由后端在测试库里把各种状态造出来，把接口的真实返回录下来 | 样例和真接口的形状一定一致；后端改了接口，重录一遍就跟上 |
| 情景 | 一个情景一个目录。点目录页上的链接切换 | 「专家处理中」「打回」「预算用完」这些状态在真实环境里很难凑出来 |
| 登录 | 替身。点「登录」就算登录了；可以切到没登录的样子 | 预览不验登录 |
| 跨应用跳转 | 替身，规则和后端相同。别的应用的地址指向它们各自的预览 | 三个应用的预览同时开着，可以互相点过去 |
| 实时推送 | 把录下来的事件一帧一帧重放 | 页面的事件流代码照常走 |
| 改动类的请求 | 录过的按录下来的答；没录过的答 501 并说明 | 不装作成功 |
| 没有样例的请求 | 答 404，终端里打印，目录页最下面也列出来 | 做页面时照着它补样例 |

## 二、怎么开

```bash
export PATH=$HOME/.nvm/versions/node/v24.21.0/bin:$PATH   # 要 Node 24
cd <应用>-web-frontend/app && pnpm install --frozen-lockfile
pnpm preview            # 开发模式：改了页面马上看到
```

| 应用 | 地址 |
| --- | --- |
| investment | `http://localhost:3100/__preview` |
| info | `http://localhost:3110/__preview` |
| knowledge | `http://localhost:3120/__preview` |
| 模板 | `http://localhost:3190/__preview` |

远程机上开着的预览，所有者要在自己的浏览器里看，需要把端口转出来（例如 SSH 端口转发）。远程自己看页面用无头浏览器截图。

## 三、样例

### investment

| 情景 | 内容 | 接口返回 | 事件流 |
| --- | --- | --- | --- |
| 什么都有（默认） | 十个项目；委托的各种状态：进行中、等我决定（勾稽不平）、没有数据、做到一半被用户停下、已完成两份（一份重做过一次，一份用户写了结论）、失败、已取消、打回；三段对话：不属于项目的聊天（问到一家没有数据的公司）、项目里的聊天、工作（有一条命令等着批准） | 197 | 12 |
| 刚注册 | 没有机器、没有沙箱、没有项目 | 12 | 0 |
| 机器离线 | 一个项目、一份底稿、一段聊天，机器不在线；请专家交不出去 | 42 | 2 |

| 项 | 做法 |
| --- | --- |
| 各种状态怎么来 | 真的 runner、真的账、真的接口。对面是一个重放的假 app-server |
| 聊天与工作里的事件 | **真的 Codex 0.155.1 加 kimi-k3 跑出来的**，录成「磁带」存在后端仓库里，以后离线重放。七轮对话，含一次真的审批请求 |
| 专家各步的交回物 | 照专家包的格式写的样例。**公司是真名字，数字是编的**（由几个参数算出来，所以三张表对得上）。数据集的说明里写明了是样例，底稿的「提醒」里会带上 |
| 编号 | 换成固定的。重新录一遍，地址不变 |
| 增量事件 | 没有录。账里不记它（账本 H27）；页面要流式显示时再补 |

### info

| 情景 | 内容 | 接口返回 |
| --- | --- | --- |
| 什么都有（默认） | 一个申请过十一家公司的人：十一种进度各一个；其中一个是别人也申请了的；第六个未完成的申请被拒（超过上限） | 约 35 |
| 刚来 | 一个申请都没有；提交第一个 | 4 |

管理端（审批、证券采集、关注清单）的样例没有录：管理端是另一个前端，第 8 步做它的页面时用同一个记录器录。

### knowledge

只有机制，没有业务样例。数据目录的接口要到第 9 步才做，做出来之后再录。

## 四、文件

| 位置 | 内容 |
| --- | --- |
| 网页端 `app/preview/server.mjs`、`lib/` | 前门与样例的匹配。四个仓库逐字相同 |
| 网页端 `app/preview/preview.config.mjs` | 这个应用是谁、端口、默认情景、预览里别的应用在哪。各应用自己的 |

| 后端 `tests/test_preview_fixtures.py` | 造各种状态并录下来。平时就是一个测试；给了输出目录才写进网页端的仓库 |
| investment 后端 `tests/preview_replay.py`、`preview_samples.py`、`preview_tapes/` | 重放的假对面、专家各步的样例、磁带 |
| investment 后端 `tests/drivers/workbench_tape_driver.py`；k8s `scripts/local-integration/workbench-tape.sh` | 重新录磁带（要真的 Codex，花一点模型费用） |

## 五、录样例时查出来的

把真接口的返回摆出来看，看出了几处后端的问题。

| # | 问题 | 处理 |
| --- | --- | --- |
| 1 | 沙箱列表接口把沙箱令牌的引用返回给了浏览器。按需拉起的沙箱，这个引用就是令牌本身。第一期留下的；原来的测试还断言了它在返回里 | 已改：不给浏览器。测试改为断言它不在任何返回里 |
| 2 | 专家首页里，等我决定的委托同时又出现在「进行中」 | 已改：等我决定的只列一处。等机器回来的没有待办，仍在「进行中」 |
| 3 | 委托结束的原因是内部的英文词（`user stopped` 等），页面没法直接给用户看 | 已改：加一句给用户看的话（`reason_text`） |
| 4 | 预算可能被最后一步超出。样例里上限 1.00，实际花了 1.20：做第 4 步之前还剩 0.10，够预留的 0.05，做完才知道这一步花了 0.30 | **所有者 2026-10-04 定了另一条路**：不设预算上限，改成实时显示花费加随时能停，见 [`0001-workbench-projects`](0001-workbench-projects.md) 第十节。样例里「预算用完」这个情景换成了「做到一半被用户停下」；每段对话多录了一份花费（`…/usage`） |
| 5 | 沙箱列表、拉起沙箱的返回里还有沙箱的内部地址。不是密钥，但浏览器用不着 | 没有改：旧页面在显示它。第 7 步重做页面时去掉（账本 H42） |
| 6 | 旧的工作台页面认不得新接口的数据（不属于项目的聊天没有机器，旧契约当成必填），列表显示为空 | 不改旧页面。第 7 步整个重做 |
| 7 | 录磁带时项目目录放在代码仓库里，Codex 读了上级目录的 `AGENTS.md`，把仓库的说明带进了对话 | 录磁带改在仓库之外的目录。这是 Codex 的正常行为：用户自己的 `AGENTS.md` 本来就该生效 |

第 4 项的两种做法：

| 做法 | 说明 |
| --- | --- |
| 甲 改说法 | 页面写「到了上限会停下来问你」，并写明「最后一步可能略超」。不动后端 |
| 乙 给每一步设硬上限 | 每一步发给 Codex 时带上这一步最多能用多少（按剩余预算算），超了就中断这一步。要查 Codex 支持不支持按轮次设上限；中断的那一步白花 |

（以下两种做法都没有采用，留作记录。）远程当时的建议：先甲。乙要先查清 Codex 的能力，而且中断一步也是花了钱没有结果。

## 八、预览说明不了什么

| 项 | 说明 |
| --- | --- |
| 整套东西连起来能不能跑 | 说明不了。登录、权限、实时推送、沙箱、Codex、本地代理要到集群上才验得到 |
| 新页面 | 还没有做。目录页上列的是页面将来的地址，现在点进去是「没有这个页面」。第 7 步起逐个做出来 |
| 专家的交回物是不是模型真能交出来的样子 | 说明不了。样例是照格式写的，过了同一套验收，但不是模型跑出来的。专家在真数据上从头到尾跑一遍，还没有做过 |
