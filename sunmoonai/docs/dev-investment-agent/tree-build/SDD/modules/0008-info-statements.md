## 探针的结论

### 年报抽取

| 项 | 一家公司（600009） | 十四家公司 |
| --- | --- | --- |
| 年报份数 | 9 | 116 |
| 抽到的表 / 应有的表 | 27 / 27 | 339 / 348 |
| 勾稽不平 / 检查次数 | 0 / 162 | 15 / 1860 |
| 与第三方数据相同 / 能比的数 | 836 / 885 | 9214 / 9995 |
| 不同的里面没解释的 | 0 | 127，其中 121 个是抽取时单位认错（比亚迪） |

| 档 | 公司 |
| --- | --- |
| 顺利（10 家） | 上海机场、贵州茅台、五粮液、恒瑞医药、海康威视、长江电力、中国中免、宁德时代、紫金矿业、贝特瑞 |
| 有小问题（2 家） | 万科、中芯国际 |
| 没解决（2 家） | 美的集团（成本写成负数）、比亚迪（单位不写在报表页上） |

结论：这条路走得通，但要**按版式逐类处理**。换公司后遇到并处理了八种情况：

| # | 情况 |
| --- | --- |
| 1 | 标题前带序号：「1、合并资产负债表」（深交所的公司普遍如此） |
| 2 | 附注编号的三种写法：「（六十一）」「五（一）」「七、1」 |
| 3 | 金额单位是千元、万元，数字不带小数 |
| 4 | 同一家公司不同年份换了单位 |
| 5 | 表的标题在页面最底部，那一页只有一两行数字 |
| 6 | 合并报表与母公司报表并排印在一张表里，四列数字 |
| 7 | 期间与标题印在同一行；续页标题带「(续)」 |
| 8 | 单位写在标题上方，或只在财务报表开头说一次 |

没处理的：成本、费用写成负数（只做了识别）；资产负债表有三列数字（多一列准则变更后的期初数）；金融类公司；2017 年以前的年报；半年报与季报。

### 三个发现

| 发现 | 依据 | 对设计的要求 |
| --- | --- | --- |
| 第三方数据系统性地用了后一份年报重新归类后的数 | 2018 年营业总成本、2017 年管理费用，几乎每家公司都与年报原文不同；宁德时代 2020 年的数在第三方那里全是整百的 | 口径要标到科目，不能只标到整行 |
| 年报原文的质量好于第三方数据 | 年报原文勾稽 1860 次不平 15 次且原因清楚；第三方数据在原规则下 11 家全部被拦 | 年报原文应成为主来源，第三方用于核对 |
| 勾稽发现不了单位认错 | 整张表同比例放大一千倍仍然是平的 | 要有量级上的兜底，例如与官方摘要数据比 |

### 别的数据来源

| 来源 | 结论 |
| --- | --- |
| 交易所的完整 XBRL 文件 | 没找到公开的入口。上交所旧址跳转到只有八九个指标的概览页；深交所旧平台的域名解析不到；证监会平台的 XBRL 专区只有基金 |
| 上交所概览、巨潮网站的三表摘要 | 公开可取，科目少、精度到万元。不能替代解析，可以作为量级上的核对 |
| 深证信数据服务 | 据介绍有完整报表接口，要注册；收费与条款没查 |
| 微软 Qlib | 财务数据只有两个指标，来自 baostock；价格数据的官方数据集停用，数据来自雅虎或社区。借方法，不当数据源 |

| # | 问题 | 影响 | 处理 |

| 1 | 下载大小上限默认 10 MB | 13 家里 7 家第一次采集失败 | 段六 |

## 三条路：数、文、原件

| 用途 | 要什么 | 走哪条路 |
| --- | --- | --- |
| 取数：报表数字 | 一分不差，能追到页码 | info，确定性抽取，不平就拒绝 |
| 取文：附注、公告、研报、用户资料 | 版面与表格保留，能引用到页 | 知识服务。交给 RAGFlow 解析还是自己解析，未定 |
| 原件 | 一份不丢 | 对象存储；本机放一部分，其余在外存储 |

数字不走大模型，也不走检索。RAGFlow 能认出表格，但它的产出是文字段落，给不出能计算、保证精确的数。

知识服务现在只收文本与 Markdown 制品。取文要走 RAGFlow 直接解析 PDF 的话，制品的允许类型要加上 PDF。

### 数与文之间的关系

所有者 2026-09-28 提出：采数和采文都要，而且要能连起来。

| 层 | 靠什么连 | 可靠程度 |
| --- | --- | --- |
| 同一份年报、同一页 | 每个数、每段文字都记「哪份年报、第几页」 | 确定 |
| 附注编号 | 报表每一行后面标着附注编号，附注里按同样的编号展开 | 确定 |
| 内容相关 | 管理层讨论里谈到收入的段落，与收入这个数 | 不确定，交给检索 |

附注编号是公司自己给出的、从数字指向说明文字的链接。抽取时要留下，不能当干扰去掉。

没验证的：RAGFlow 切段之后还认不认得「这一段属于附注七、47」。

## 统一的科目表

远程的建议，未定。

| 项 | 建议 |
| --- | --- |
| 骨架 | 财政部发布的报表格式与通用分类标准，不从各家年报的原始叫法里归并 |
| 各家年报里的叫法 | 对到骨架上的标准科目 |

其中大部分是长科目名折行后的残片和叫法差异。

骨架里有上下级关系，所以每一个小计都可以做勾稽，比现在的九条规则细。

没核实的：财政部的分类标准能否公开取到完整清单。

## 主档

远程的建议，未定。研究稿见 [`research-where-to-keep-structured-data.md`](0008-info-probe/research-where-to-keep-structured-data.md)。

现状：SQLite 只是数据集文件的格式。采集批次、原文、登记表已经在 PostgreSQL 与对象存储里。
真正缺的是：抽出来的财务数字没有主档，只存在于生成的文件里。

```text
原文（对象存储）
   ↓ 解析
info 的数据库：财务数字的主档，一行一个数，带口径、出处、来源
   ↓ 质量检查通过后按版本导出
快照文件 + 登记
   ↓ 契约
知识服务给专家查
```

| 项 | 建议 | 理由 |
| --- | --- | --- |
| 主档放哪 | info 自己的数据库 | 规则 `C-D1`、`C-D2`：每类数据一个主档；禁止跨 App 直接读表 |
| 怎么存 | 一行一个数 | 口径、出处能标到每个数；同一年同一科目的两种口径能并存；新增科目不用改表结构 |
| 三张大表 | 由主档生成 | 所有者要的全量三大表照样有，是主档的视图与导出 |
| 专家的查询落在哪 | 先继续用本地文件 | 模型写的 SQL 不直接打在共用的数据库服务器上 |
| 金额 | 精确的十进制 | 现在的文件格式里是浮点数 |

验证过：语义层的引擎能为 PostgreSQL 做规划。没验证：在 PostgreSQL 上实际执行。

## 风险

- **版式的长尾**：14 家就有 8 种情况和 2 家没解决，五千多家只会更多。目标是大部分自动通过，其余进待处理的队列。
- **勾稽不是万能的**：发现不了单位认错，也发现不了整行漏抽之后仍然平衡的情况。
- **第三方网站的接口没有稳定性承诺**，数据的使用权没确认，只能内部用（`D1`、`D2`）。
- **外存储只有一份**：只放在那台机器上的原件，那台机器的硬盘坏了会丢；可以从来源网站重新采，用校验值核对。
- **备份靠人开机**：间隔越长，主机硬盘出事时丢的越多。
