# 通道

> 部件见 [组成](components.md)，机器见 [拓扑](topology.md)。

| # | 两端 | 协议 | 内容 | 安全要点 |
| --- | --- | --- | --- | --- |
| ① | 浏览器 ⇄ 工作台 | HTTPS 同源 `/api/` + 事件流（cursor 续传），经边缘隧道 | 登录会话；工作区与项目选择；发 turn 与看事件（第一层）；求助、进度、审查、底稿、取消（第二层）；key 录入；费用 | Casdoor OIDC 会话 cookie + CSRF；每次读取重新授权（`I3`） |
| ② | 工作台 ⇄ 沙箱 app-server | JSON-RPC over WebSocket，内网 | `thread/start`、`turn/start`、事件、`item/*/requestApproval`、`turn/interrupt`、`environment/*` | 内网；每用户一个 app-server；工作台是唯一客户端 |
| ③ | 沙箱 ⇄ 本地代理 | Codex 远端环境协议（exec-server JSON-RPC over WS），经会合点透传 | 进程启动、读写文件、命令执行、结果与退出码 | 两端各持令牌向会合点认证；exec-server 本身只监听 127.0.0.1（它在 listen 模式没有认证） |
| ④ | 本地代理 ⇄ 会合点 | WSS，代理主动外连 | 注册、心跳、③ 的透传、代理版本 | 按用户 + 代理签发的短期令牌 |
| ⑤ | 沙箱 ⇄ 会合点 | WSS，沙箱出站 | 找该用户的代理、③ 的透传 | 按用户 + 沙箱签发的短期令牌 |
| ⑥ | Codex ⇄ 知识服务 | HTTPS（MCP），经边缘 `/mcp/` 或内网直连 | 检索、领域工具、口径、SQL 执行、用户资料 | 按用户 + 沙箱发 token，限流 |
| ⑦ | Codex ⇄ 模型厂商 | HTTPS，从沙箱出站 | 推理 | 用户的 key，只在沙箱进程环境 |
| ⑧ | 本地代理 ⇄ 工作台 | HTTPS，经边缘 | 本地上限声明、根目录白名单、审批弹窗的结论 | 同④令牌；结论带请求摘要 |

**没有"工作台 → 本地代理下发任务"这条通道。**顾问只对沙箱发 turn（②）；工具到用户机器的路只有 Codex 自己的协议（③）。这是旧树"跨网派发"退役后最大的简化。

设计上要落实：

| 交互 | 设计要点 |
| --- | --- |
| 提交 | 浏览器生成幂等键，工作台在可靠边界内建单并写首事件 |
| 事件与结果 | 先持久化后通知；网页按 cursor 续传，重复事件幂等 |
| 审批 | 工具级审批请求经②回到工作台；按策略处置或转 Interaction（①）；扩本地上限只在⑧ |
| 结果 | 明文入库；同时落用户工作区（经③）；网页从工作台读 |
| 版本 | ②③④⑤ 的协议版本随发布清单成对钉（`C-R8`） |
