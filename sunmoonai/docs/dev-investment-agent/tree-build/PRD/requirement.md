## 一、做的是什么产品

**投研专家。**用户已经能用 AI 助手（Codex）做很多事；我们存在的理由是**在裸 AI 做不好的地方做好**。
所有者的原话：「AI 如何一切都能做好，那还要我们这些产品干啥？」

"做好"由三样撑着，缺一样就退化成一份能抄走的提示词：

| 支撑 | 是什么 | 谁提供 |
| --- | --- | --- |
| **专业知识** | 数据、口径、引用、领域工具 | 知识服务，经 MCP 给 Codex |
| **方法** | 怎么拆步、每步给什么料、何时停下问人、做对没有、不对怎么返工 | 顾问（supervisor + 专家包） |
| **评测闭环** | 金标准、分段判定、每次改动回归、真实委托沉淀为样本 | 评测 |

方法文本本身抄得走；可守的是三样捆在一起。方法按易损件对待，模型每升一代重写一遍，评测是护栏。

**不做投资咨询。**产出是研究底稿：事实、数据、按用户假设的计算、方法应用的结果；结论由用户填。这条是法律边界，与下面的隐私裁定无关。

### 1.1 两层决策权，同一个 Codex 实例

产品内部的组织原则是**人和 AI 对解决问题的决策权怎么分配**，分两层：

| | 第一层：用户自驾 | 第二层：顾问驾驶 |
| --- | --- | --- |
| 谁握方向盘 | 用户 | 顾问 |
| AI 在哪 | 用户专属的 Codex 实例（沙箱里的 app-server） | **同一个实例、同一个 thread** |
| 工具在哪执行 | 用户机器上的执行环境（exec-server） | 同 |
| 云端建单 | 不建 | 用户交出方向盘那一刻建 Task |
| 触发 | 默认 | 用户求助；或本机质量信号提示后用户求助 |

决策权按行分配，中间几行顾问拿走，两头永远在用户手里：

| 决定什么 | 第一层 | 第二层 |
| --- | --- | --- |
| 问什么、要什么结果 | 用户 | 用户；顾问可要求澄清，不能替他改 |
| 拆几步、每步做什么 | 用户或 Codex | **顾问** |
| 每步用什么数据、方法、工具 | Codex 自己找 | **顾问**下发，一次只给这一步 |
| 什么时候停下来问人 | Codex 的审批回调 | **顾问**的 interrupt 策略；越出本地上限的动作仍由本机当面确认 |
| 做对没有 | 用户看 | **顾问**验收，用户终审 |
| 返工几次、什么时候放弃 | 用户 | **顾问**按契约，超限交回 |
| 什么可以离开本机 | 用户授权的根目录 | 同 |
| 花多少钱 | 用户付 token | 用户付 token，**另付顾问费** |
| 最终结论 | 用户 | **用户**，永远不交 |

"同一实例"要求三样连续：同一个运行时 thread（顾问接手时看得到用户已做的）、同一个工作区（资料在原处）、同一个模型账户（用户的 key）。进程在哪台机器上是实现细节。
两层不能同时握方向盘，交接是显式状态（[方向盘](../SDD/architecture/wheel.md)）。

对外可以说"给 AI 助手用的投研数据与口径，需要时提供可验收的研究流程"；两层分配是内部设计语言，不是宣传语。

### 1.2 六条前提，定了就不再讨论

| 前提 | 落到哪 |
| --- | --- |
| **隐私不作产品约束**：有"资料不能出本机、不能上传"这类限制的，不是我们的客户 | 云端看得到会话、资料、工作区、每步产出；结果明文存放；验收能读正文 |
| **不垫付 token**：模型费用由用户直接付给厂商 | BYOK：用户的 API key 放在我们的密钥库里，沙箱里的 Codex 用它调厂商；不接受订阅登录搬上云端 |
| **工作区在本地**：用户的文件、Excel、工具、做到一半的东西都在他的机器上 | 执行环境在用户机器上；云端 Codex 按需读写，不要求整机上传 |
| **循环在云、执行在本机**：Codex 的模型循环跑在我们给用户开的沙箱里，工具在用户机器上执行 | [部件](../SDD/architecture/components.md)、[拓扑](../SDD/architecture/topology.md)；已探针验证（`runtime` 仓 `probe/REPORT-2026-09-23-remote-exec.md`） |
| **界面是网页**，本地只装一个签名的小代理 | 现有 `investment-web-frontend` 承担产品界面；不做 Electron |
| **边缘 + 内网**是正式部署拓扑：公网只有薄边缘，业务在我们自己的内网站点，深处的组件只出站 | [拓扑](../SDD/architecture/topology.md)，长期成立，不是过渡 |

## 二、整体要完成的功能

一句话：**用户在网页里用自己的 Codex 做研究；做不好时把方向盘交给顾问，顾问按方法驾驶同一个 Codex，把可验收的底稿交回，结果就在用户的工作区里。**

第二层走[九站](../../pipeline.md)，九站全在工作台后端里：

| 站 | 在哪 | 要做到什么 |
| --- | --- | --- |
| 写 message | 网页 | 求助时写清问题；选专家包；本机质量信号可以先提示 |
| 提交 | 网页 → 工作台 | 幂等键唯一；同键同摘要返回原 `task_id` |
| 受理 | 工作台 | 身份从会话确定，不信任客户端自报；输入充分性与能力匹配；判不出交用户选，不默认 |
| 派发 | 工作台 → 沙箱 | 顾问对同一个 app-server 发 turn；没有跨网派发；方向盘交接显式 |
| 执行 | 沙箱 + 用户机器 | 循环在沙箱、工具在执行环境；预算硬停 |
| 中断 | 工作台 → 网页 / 本地代理 | 工具级与 Task 级都经协议回到工作台；越出本地上限的动作本机当面确认 |
| 封装 | 工作台 | 结果明文入库，同时落用户工作区；内容检查在云端 |
| 验收 | 工作台 | 读正文真验：确定性检查 + 独立验收 Attempt；终态、结果、预算结算原子提交 |
| 交付 | 工作台 → 网页 | 事件按 cursor 续传；交回物契约：做了什么、什么已核实、什么未知、工作区怎么恢复 |

第一层不走九站，不建单；但第一层的每个 turn 都在同一个 thread 里，顾问接手时能读到。

**三件贯穿全程的事**：四本账（幂等、预算、副作用、证据）落 PostgreSQL；状态与账只有一份，所有入口共用同一个转换函数；人的批准点不能自动通过。

## 三、切成几块

按**职责**切，不按信任域（隐私不作约束后，信任域不再是切分依据）。六块加评测，见 [部件](../SDD/architecture/components.md)：

| 块 | 跑在哪 | 一句话 |
| --- | --- | --- |
| [工作台后端](../SDD/modules/0001-workbench.md) | 内网 | 账房、编排、审批分发、验收、交付；app-server 的客户端 |
| [网页](../SDD/modules/0002-web.md) | 边缘（静态）→ 内网 | 用户的脸 |
| [沙箱池](../SDD/modules/0003-sandbox.md) | 内网 | 每用户一个 app-server，BYOK |
| [会合点](../SDD/modules/0004-relay.md) | 边缘 | 三类出站客户的配对与透传 |
| [本地代理](../SDD/modules/0005-agent.md) | 用户机器 | exec-server + 出站连接 + 审批弹窗 + 本地上限 |
| [知识服务](../SDD/modules/0006-knowledge.md) | 内网 | 我们的数据 + 用户上传的资料，同一套检索，MCP |
| [评测](../SDD/modules/0007-eval.md) | 内网 | 金标准、分段判定、三道门 |

## 四、在什么基础上开发

**四块半就是现有平台**，现状见 [项目总览](../../../project-guide/overall-architecture.md)：

| 新块 | 现有的什么 | 要做什么 |
| --- | --- | --- |
| 网页 | `investment-web-frontend`：Next.js 16、同源 `/api/`、OIDC 会话在后端 | 从"只剩官网"改回产品界面；按 `C-R6` 模板优先 |
| 工作台后端 | `investment-backend`：FastAPI 四角色、Run 状态机、事件表、Outbox/Inbox、执行租约 | 状态机改成 Task/Attempt 两层；Pilot 链退役；加 app-server 客户端与审批分发 |
| 身份 | Casdoor：浏览器 OIDC + PKCE、服务身份 | 直接用；放内网，登录页经边缘出去 |
| 知识服务 | `knowledge-app`（检索）、`info-app`（采集） | 加用户资料入库、MCP 封装、按用户限流 |
| 部署 | `k8s`：`infrastructure/` 远程 kubeadm、`kind-infrastructure` 本机、`ingress-platform` Traefik、bundle 与门禁 | 内网站点用 kubeadm 那套；边缘裁一份薄的；沙箱池是新的一类部署单元 |

**真正从零的**：沙箱池、会合点、本地代理（`runtime` 仓）、评测。

**退役的**：桌面应用与 `desktop-app` 仓；本地 runtime 作为"驱动完整 Codex 的执行端"；加密与密钥整族；设备配对与吊销；跨网派发、租约与 fencing、断线暂停与对账（缩成会合点重连与方向盘交接）；三层类别判定与领域识别引导；LangGraph Pilot 链；"让用户能验证"。

**最小实例**：第 23 到 25 课的问数五阶段（rewrite → sql_generate → sql_execute → normalize → final）做第一份专家包，二十题评测随之。它的使命是把整条链设计、展示、跑通，之后换掉；不是卖点。

## 五、范围

- **包含**：各模块 `F-*`、[不变量](../SDD/architecture/invariants.md) `I1` 至 `I14`、[验收矩阵](acceptance.md) 的 `AT-*`；
- **第一期只做第一层客户**（能自己配 key 的个人与小私募），桌面平台 Linux 与 macOS 先行、Windows 随 spike；
- **后置**：离线模式（云端不可达时循环在本地跑）、团队协作与共享、机构私有化站点、企业模型网关、Windows 全量、信创平台；
- **不包含**：[待定决策](../decisions.md) 里还没拍板的事项。
