# BRD 用户消息模板

复制成 turn 里的 `user-message.md`。

这一段在问什么、答要写成什么样，都在 [BRD 规则](brd-rules.md) 里，**用户消息只指过去，不复述**——
把答的提纲抄进这一问，等于替模型把骨架列好了，剩下的只是填空。
写多严见 [任务的生命周期](../lifecycle.md)「用户消息写多严」，字段的含义见同一份的「turn 的固定字段」。

```markdown
---
executor: <派给谁；还没派出去写 unassigned>
verifies: 无
---
# turn <四位号>：<短名>

## 要讨论什么
<一句话说清这次要弄清楚的是什么。一问只谈一件事；有好几件就拆成几个 turn>

## 起因
<触发这一问的原话或现象；现在是怎么做的、卡在哪。分清事实、推断与假设>

## 已有的
<相关的已有决定、材料、上一个 turn 的结论；给出链接与提交。没有写「无」>

## 这一问不谈什么
<明确排除的，免得讨论摊开到收不住。可以写只谈 BRD 规则那张表里的哪几行>

## 约束
<必须遵守的规则、不能动的东西；例如只交文本、不改代码>

## 怎么答
按 `sunmoonai/docs/dev-agent-standards/brd/brd-rules.md`「这一段在问什么」与「response 写什么」。

**交回：写成这个 turn 的 `response.md`，不改代码。人读完定稿成 `PRD/`。**
```

这一段不写验收标准：答得合不合格按 [BRD 规则](brd-rules.md)「response 写什么」判。

不适用的栏写「不适用」及理由——空着与「忘了」无法区分。命中 T2 判据的任务每一栏都要填。
