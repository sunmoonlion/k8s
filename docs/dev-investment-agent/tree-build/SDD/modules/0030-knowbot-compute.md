## 一、问题

- **算**：单季换算（半年报减一季报）、比率、同比、中位数、回测误差，样本八步里有五步要算。内置专家靠 knowbase 的 `run_sql`，所有计算在 SQL 里做；用户的专家不能用数据线（`C-L2`），`read_my_data` 只给分页文字。剩下的路：模型心算（会错、会抄错数），或在用户电脑上跑命令（每条要人批准，测试里就是运营一条条批）。
- **验**：现有验收只核结构（是不是 JSON、有没有某个键、列表够不够长、有没有买卖措辞）。比率是不是由那两个数算出来、恒等式真平还是假平、单季加起来等不等于年报，一样都核不了。模型写一个看着合理的数，验收照样放行。

## 二、目标与边界

- 专家里**每个算出来的数**都由平台的确定性计算产生，带算式与每个输入的出处；输入直接从用户数据里按位置取，**模型不抄数**。
- 验收能核：交回物里的数是不是真由平台算出来的、算式和输入是否就是方法要求的那几个、恒等式与加总是否成立。
- **不做**：任意代码执行（不开 Python 沙箱给模型写程序）；平台不提供任何投资判断（算什么、用什么口径由方法包写死，方法包的规则来自用户，0029）。

## 三、做法

### 3.1 按位置取数：knowlab 加「表格读取」

`knowbot-data/v1` 现在只有「列出」「读一页文字」。加一个**表格读取**：CSV、Excel（每张表）按行列给结构化的格子，每格带地址：

```text
<数据 id>:<表名>!<行标签>@<列标签>        例：d1:利润表!营业收入@2024-06-30
```

- 行标签取第一列（科目名），列标签取表头（报告期）；重名的行按出现次序加 `#2`。
- knowlab 照旧按用途核（专家看交付记录，测试看测试在跑，只开这一版绑定的数据，0027 §3.5）。PDF 没有格子，只能读文字，用于对照少数几项（0029 E3）。

### 3.2 计算工具 `compute`（工作台的工具服务里，和 `list_my_data`、`read_my_data` 并列）

```json
{"task": "<委托号>",
 "name": "2024Q2 单季营业收入",
 "expression": "h1 - q1",
 "inputs": {"h1": "d1:利润表!营业收入@2024-06-30", "q1": "d1:利润表!营业收入@2024-03-31"},
 "round": 2}
```

- `inputs` 每一项是**格子地址**（工作台按委托核过后向 knowlab 取值），或**前一次计算的编号**（`c:<编号>`，用于链式计算，例如先算单季、再算同比）。不接受模型直接写数字——要用常数就写在算式里（`* 100`），会被验收看到。
- `expression` 只许：四则运算、括号、`sum`、`avg`、`median`、`min`、`max`、`abs`，以及对列表的同一组函数（输入可以是一串地址）。用 Python 的语法树白名单解析、十进制精确计算；超长、超深、除以零都回错误（除以零回「分母为零」，方法包据此标「不适用」）。
- 回：`{"id": "c17", "value": 1234.56, "formula": "h1 - q1", "inputs": [{"name": "h1", "address": "…", "value": …}, …]}`。
- 每次计算记进委托的**计算记录**（会话事件，和读项目记录的 `records/read` 同一处），带编号、算式、输入地址与取到的值、结果。计算记录跟着委托走，测试跑完 7 天删（同 0027 §3.4 的测试保留期），用户自己的委托跟委托同生命周期。
- 限流与预算同读数据：每分钟次数封顶；一次计算最多 500 个输入格子。

### 3.3 数值验收（验收规则加三种）

| 规则 | 写法 | 核什么 |
| --- | --- | --- |
| `computed` | `path` 指向交回物里的一串数，每项带 `compute_id` | 每项的 `compute_id` 在这件委托的计算记录里存在，记录里的结果与交回物里的数一致（容差 `tolerance`）；可选 `expression` 要求算式必须是方法包写的那个（例如毛利率必须是 `(rev - cost) / rev`） |
| `identity` | `path` 指向一串 `{left_id, right_id}` | 左右两个计算结果在容差内相等（勾稽四条、单季加总等于年报） |
| `sourced` | `path` 指向一串数，每项带 `address` | 每个地址重新向 knowlab 取一次，与交回物里的数一致（取数步不经计算的原始数） |

- 这三种要访问计算记录与 knowlab，不再是纯函数：验收判定分两层，结构类照旧纯函数，数值类由工作台应用层在判定时查计算记录、需要时向 knowlab 取格子。
- 不过就照方法包的 `on_reject` 走（重做、退回、交人），报告里写明哪个数对不上。

### 3.4 方法包怎么用

- 方法原文写死：「每个算出来的数都调 `compute`，交回物里写它的 `compute_id`；取出来的原始数写 `address`」。
- 步骤的工具里列 `compute`；`KNOWBOT_TOOLS` 加 `compute`（专家能用的工具：`list_my_data`、`read_my_data`、`compute`）。
- 验收里配 `computed` / `identity` / `sourced`。样本的八步：取数配 `sourced`，勾稽配 `identity`，单季与指标配 `computed`（指定算式），预测配 `computed`（回测误差、点估计、区间），成稿只引用前面的编号。

## 四、合规

- 计算工具只做算术，不带任何口径或判断；算什么、用哪几个格子、什么算式，由方法包写，方法包的规则要有用户出处（0029 第二节）。
- 只读用户这一版绑定的数据，和 `read_my_data` 同一套两道核；不碰数据线，不碰别人的数据。

| 处 | 上文 | 实现 | 为什么 |
| --- | --- | --- | --- |
| 契约 | 加「表格读取」 | 加两个接口：`knowbot-data/table`（一张表的行标签、列标签、原文，按页，约 4000 格一页）给模型看地址；`knowbot-data/cells`（一次最多 500 格）给计算与 `sourced` 取值。格子位置在契约里是（数据、表、行、列）四项，地址字符串由工作台拆 | 地址写法是工具层的约定，契约用结构化的四项更稳（表名、科目名里可能有 `!`、`@`） |
| 地址拆法 | — | 表名到第一个 `!`，列标签从最后一个 `@` 起，中间是行标签 | 科目名里偶有 `@`，报告期列标签里没有 |
| 前一次计算 | `c:<编号>` | 直接写编号 `c17` | 回的就是 `c17`，模型照抄不易错；数据 id 带 `-` 与 `:`，不会混 |
| 回的数 | `"value": 1234.56` | 十进制字符串 `"1234.56"` | 不经浮点；交回物里写数字或字符串都认 |
| 编号 | — | `c<会话事件游标>` | 游标在会话内唯一且有锁，不另建序号 |
| 工具 | `KNOWBOT_TOOLS` 加 `compute` | 加 `read_my_table`、`compute`（共四个） | 写地址先要看表 |
| 数能不能读 | — | 千分位、括号负数、全角负号认；百分号、单位不猜（读成「不是数」）；日期列标签写成 YYYY-MM-DD；绝对值大于 1e30 的不当数 | 宁可报「不是数」让方法包处理，不猜口径 |
| 百分号三处读法一致（2026-10-18 审读第 8 条） | — | 读表（knowlab）与测试期望（工作台）都不把带 `%` 的当数：用户要算比率就给小数或原值；期望值要比带 `%` 的，写成字符串期望（equals 按字符串比）。网页导出成稿时 `12%` 照旧存成 0.12 加百分比格式，那是给人看的 | 原来工作台测试期望去掉 `%` 当数（`12%` → 12），同一格在两处一过一不过 |
| 数值验收的空列表 | — | 算通过；要求非空另配 `list_min` | 同 `all_equal` 的约定 |
| 重做时告诉专家哪个数错 | 「报告里写明哪个数对不上」 | 对不上的明细记在步骤的 `step/rejected` 事件（步骤视图可见）与 `failures`；**重做的提示也带上上一次没过的各条**（最多 10 条、每条 400 字，所有验收都这样；所有者 2026-10-17「按你建议」，knowbench 后端 `5f8e39e`） | 专家要知道改哪里 |
| `sourced` 没配 knowlab | — | 判不过，不放行 | 宁严 |

## 九、C2 记录（2026-10-17，Opus）

样本 [`0029-sample-fin-forecast/manifest.json`](0029-sample-fin-forecast/manifest.json) 的工程部分改用本文的做法（规则出处仍是 `pending_user`，等所有者答 K3–K14，K20）：

| 步 | 工具 | 数值验收 |
| --- | --- | --- |
| 数据摸底 | 加 `read_my_table`，交回每张表的数据 id、表名、报告期列 | — |
| 勾稽 | `read_my_table`、`compute`：两边各算一次、差额再算一次 | `identity`：标成平的两边真的相等（容差 1 元）；不平的照实列出，不因此退回 |
| 取数 | `read_my_table`、`compute` | `sourced`：原样取的数与那一格一致；`computed`：单季必须是 `cur - prev` |
| 算指标 | `compute` | 五个 `computed`，各指定算式：毛利率 `(rev - cost) / rev`、净利率 `np / rev`、ROE `np / ((eq_open + eq_close) / 2)`、现金流比 `ocf / np`、同比 `(cur - prev) / prev` |
| 对照官方披露 | `read_my_data`、`compute`：年报上的数写进算式当常数 | `computed`：相对差异由平台算 |
| 预测 | `compute` | 五个 `computed`：点估计 `base * (1 + median(g))`、上下沿 `min(g)`/`max(g)`、回测误差 `abs(f - a) / a`、推算比率 `np / rev` |
| 成稿 | — | 方法原文要求每个数写编号或地址，不自己算、不自己四舍五入 |
