### 1.2 触发事件：所有者提出按正规流程组织

所有者 2026-09-07 提出初步映射：`request-lifecycle` ≈ PRD、`rounds` ≈ ADR、

### 1.3 为什么必须走完整流程

所有者原话：**「鉴于工程巨大，意义重大」**。三条客观理由：

1. **规模**：320 节，是 `runtime-refact` 轮（64 节）的 **5 倍**；
2. **权威层**：重构对象包含**内核** `request-lifecycle.md`——它被 40 份文档引用、
   有 **71 个带行号的锚点**指进去。动它等于动全部取证的地基；
3. **不可逆性**：文档一旦重排，**丢掉的东西不会有人发现**——
   这正是 `runtime-refact` 轮已经栽过的形态（一次通读做融合，整节内容消失，事后才补回）。

### 1.4 一条必须先说的边界

**这一轮不改任何结论，只改组织方式。**
凡涉及「某个设计对不对」的问题，一律不在本轮处理——那是另起工作单元的事。
候选若在重构中**顺手修正了某个结论**，该处按 §4.1 B3 处理。

### 二、先提出组织架构，再动文档

**顺序不可颠倒。**候选必须先给出架构本身（有哪些类别、各装什么、彼此什么关系、
新文档进来时如何判断归属），**再**把现有文档映射进去。
只给映射不给架构的候选，按 §6.3 一票否决。

架构至少要能回答：

| 必答 | 说明 |
| --- | --- |
| 有哪几类文档 | 类别之间**不重叠**，且能覆盖现有全部内容 |
| 每类的**生命周期规则** | 谁能改、怎么改、能不能被取代、旧版怎么办。⚠ 不同类规则不同——例如决定记录**只被取代不被修改** |
| 决定如何可检索 | 现状是 26 条散在 3 个文件且编号撞车。**这是唯一今天就有痛感的问题** |
| 新东西来了往哪放 | 判断规则要**可机械执行**，不靠品味 |
| 与 `protocol/`、`rounds/`、`working/` 的关系 | 四者是否保留、改名、还是并入新类别 |
| **每份文档自己的内部架构** | 见下「三、有机融合」——⚠ **这一条是本轮的重心，不是附加项** |

### 三、有机融合：内容要长进架构，不是堆进架构

⚠ **零丢弃是底线，不是目标。**能证明「一节不缺」只说明没丢东西，**不说明放对了地方**。
本轮真正要交付的是**有机融合**：每一节落在哪里，都要有「**为什么在这里、为什么不在别处**」
的判据；重构后的每份文档要有**自己成立的内部组织逻辑**，而不是「什么都往最大的那份塞」。

**为什么这一条要单列**：零丢弃是**机械可判**的，有落点表就能核；有机融合**不可机械判**，
只能靠论证。⚠ **一份机械判据全绿的稿子，组织方式可以是任意的**——这不是假设，
本仓有一个可复核的实测。

**实测（2026-09-07，起草者做的一次吸收）：**`agent-dev-guide.md` 吸收两份 lifecycle 时，
三级节由 39 增至 76，**而 10 个二级章的划分一次都没有被重新审视**：

| 章 | 原有小节 → 现在 |
| --- | --- |
| §2 一个运行时的结构 | 5 → **12** |
| §3 一次开发 Task 怎样执行 | 5 → **18** |
| §4 人介入、Interaction 与权力 | 4 → **11** |
| §5 可观测性、证据与等效 | 5 → **11** |

每处内容都塞进了**最近的那一章**；该文 §0.2「为什么分成这些章」仍停在二级章一层，
从未解释过 §3 凭什么装这 18 件事。**而这次吸收通过了全部零丢弃检查**——
182 行落点齐全、正文级已验、50 处真缺已补，每一条机械判据都是绿的。

⚠ **这个实测的用途是给候选一把尺子，不是让本轮去评审那次吸收。**
本轮要产出的是**架构**；上面这组数字只说明一件事：**零丢弃不能代替架构判断，
所以本轮必须单独交出归属判据**。候选可以完全不理会现有的章节划分，
也可以沿用——但按 `B12`，沿用要给理由。

**由此给候选三条可判要求：**

1. **归属判据先于归属结果。**先说清「什么样的内容属于这一类/这一节」，再放东西进去。
   ⚠ 只给「§X 装了这些」的清单、不给「凭什么装这些」的判据，按 §6.3 否决；
2. **每份文档的内部结构要被论证，不能继承。**沿用现有章节划分是**允许的**，
   但必须给理由；⚠ **不给理由的沿用等于没做这一部分**——起草者上面那次就是不给理由的沿用；
3. **拆与并都要给代价。**主张把某份拆开或某几份合并时，必须写明：
   谁的引用会断、锚点怎么保全（B2）、读者的检索路径怎么变。
   ⚠ **只说「这样更清楚」不算论证。**
