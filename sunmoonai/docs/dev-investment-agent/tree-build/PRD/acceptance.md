# 产品验收矩阵

> `AT-*` 是产品级验收；每条对应的功能义务 `F-*` 在各模块的 `functions.md` 里，
> 谁负责哪些见 [责任投影](../SDD/architecture/ownership.md)。
> ⚠ **本文件存在不证明能力已落地**：矩阵里尚无实现的场景是规范先于实现的正常状态，
> 只有对应证据完成后，相关能力才可宣称已实现。

宣布某项能力已经实现前，至少提供以下自动化或可复现实验：

| ID | 场景 | 必须证明 |
| --- | --- | --- |
| `AT-01` | 幂等重复提交 | 同作用域、同键、同摘要只创建一个 Task |
| `AT-02` | 幂等异载荷 | 同键异摘要明确冲突，不误复用、不另建 |
| `AT-03` | 协议拒绝 | 未认证或畸形提交不创建业务 Task，不泄露信息 |
| `AT-04` | 受理拒绝 | 已建单 Task 可进入 `REJECTED` 并返回安全理由 |
| `AT-05` | 越权访问 | 不能读取、订阅、恢复、批准或取消其他用户的 Task |
| `AT-06` | 简单问数 | 提交到结构化结果、口径、数据时点与引用的完整闭环 |
| `AT-07` | 澄清恢复 | 令牌原子消费；重复、过期、异键、跨 Task、摘要不符的响应被拒绝 |
| `AT-08` | 投递窗口 | 建单后投递失败可恢复，不形成永久悬空 Task |
| `AT-09` | 执行端离线 | 失去租约即暂停、不产生新副作用；重连后按 fencing 恢复或由新 Attempt 接续；迟到写入被拒绝 |
| `AT-10` | Attempt 重试 | 可重试失败产生新 Attempt，Task 不被过早终结 |
| `AT-11` | 验收失败 | 不合格输出不能使 Task 成功；可按策略产生新 Attempt |
| `AT-12` | 副作用后中断 | 恢复不重复动作；批量与逐条记录的回执、补偿状态可审计 |
| `AT-13` | 预算耗尽 | Attempt 明确终态；Task 按契约等待、重排或失败 |
| `AT-14` | 取消竞争 | 取消意图先持久化；完成与取消只有一个终态胜出；离线执行端重连后不能提交 |
| `AT-15` | 服务重启 | 可重建所有非终态 Task、Attempt 与等待中的 Interaction |
| `AT-16` | 客户端断线 | 按 cursor 回放无缺口，重复事件被去重 |
| `AT-17` | 应用重启与换设备 | 有权用户仍可取回稳定版本的结果密文，并凭密钥解密 |
| `AT-18` | 通知失败 | Task 终态不变，Delivery 独立重试 |
| `AT-19` | 事件升级 | 旧客户端可按 `payload_schema_version` 兼容或明确拒绝 |
| `AT-20` | Profile 升级 | 历史 Task 仍按固定版本解释和复现 |
| `AT-21` | 子 Task | 预算不被放大、权限不扩张、血缘与证据可追溯 |
| `AT-22` | 协调 Task | 图通过后关闭，不等待全部子 Task 完成 |
| `AT-23` | 设备离线派发 | Task 等待设备，设备上线后补投；不擅自改派 |
| `AT-24` | 工具级审批 | 所有命令与文件修改进入审批回调；后端无法作出工具级批准；断线时未决审批作废 |
| `AT-25` | 请求升级 | 不可逆动作挂起并经 Task 级批准后才执行；结论与挂起请求摘要不符时拒绝 |
| `AT-26` | 被攻破的后端 | 未签名或未登记的 Profile 被拒绝；运行中指令越出 Profile 能力时被拦截；自报的类别不能扩大可取数据的范围 |
| `AT-27` | 独立工作区 | Attempt 不改用户目录；补偿后用户改动不受影响；合并需经批准 |
| `AT-28` | 加密边界 | 后端存储与管理后台中不存在结果正文、本地资料内容与文件名；任务文本明文可见；密文摘要与内容检查回执一致 |
| `AT-29` | 密钥丢失与迁移 | 迁移后可解密；密钥丢失时无法恢复且已事先告知 |
| `AT-30` | 定位拦截 | 对具体证券的评级、目标价、走势预测、买卖建议或收益承诺被本地检查拦截并留痕 |
| `AT-31` | 凭据与资料不外泄 | 协议、日志、后端中不存在 key、设备私钥与本地资料内容 |
| `AT-32` | 路由与升级 | 三层判定按序生效；未经用户确认的本地预填不算数；判不出来交用户选且不默认通用；`escalate` 使 Attempt 终止并由 supervisor 重新路由，改判入账 |
| `AT-33` | 自有数据下发 | 只按查询返回片段并带来源、时点、版本；超限、异常频率与吊销的 token 被拒绝 |
| `AT-34` | 与用户自装 Codex 并存 | 两者配置与记录互不读写 |
| `AT-35` | Windows 沙箱 | elevated 与 unelevated 两种模式下均不能写出独立工作区、不能未经批准联网 |
| `AT-36` | 对比评测 | 冻结的任务集上，本产品相对原版 Codex 的指标按 Profile 报告，改动后回归 |
| `AT-37` | 工具可见性 | Profile 之外的工具不出现在模型上下文；即使被调用也被 runtime 结构性拒绝 |
| `AT-38` | Profile 熔断 | 同一 Agent Profile 版本连续启动失败达阈值后被熔断，新 Attempt 不再分发到它 |
| `AT-39` | 步骤交回 | 交回物不满足 `output_schema` 时按 `on_reject` 处置且不使 Task 失败；下一步只取固定版本的 Artifact |

此外必须满足：

1. Task 与 Attempt 状态迁移、API schema、① 与 ⑤ 的协议、事件 schema、Profile schema 与错误码有机器可检查的版本；
2. 每个 `F-*` 与 `I*` 登记实现所有者、代码位置、自动测试与当前覆盖状态；
3. 无法自动化的条款登记人工门禁、理由与复核证据；
4. 至少一个真实 Task 在 Windows 上跑通提交、路由、工具级审批、执行、失败重试、本地检查与加密、结果持久化、断线回放与换设备取回；
5. 项目事实与目标规范分开，未实现能力不写成已有。
