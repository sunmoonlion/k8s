# 虚拟机操作（所有者向）

本地机上的 VMware 虚拟机 `sunmoon-prod`（Ubuntu 24.04，IP `192.168.80.10`，用户 `sunmoon`）平时怎么开、怎么进、怎么关、出事怎么看。怎么**建**它见 [README-vmware](../../infrastructure/environments/prod/vm/README-vmware.md)。

一句话原则：**虚拟机的控制台窗口只用来救急，日常工作在 Windows 终端里 SSH 进去。** 两者进的是同一个 shell，差别只在终端好不好用（字体、剪贴板、多标签、回滚历史）。

## 一、开机与关机

| 要做的 | 怎么做 |
| --- | --- |
| 开机（有界面） | 打开 VMware Workstation → 左边「我的计算机」→ `sunmoon-prod` → 开启此虚拟机。窗口可以最小化，虚拟机照样跑 |
| 开机（不弹窗） | PowerShell：`& "C:\Program Files (x86)\VMware\VMware Workstation\vmrun.exe" -T ws start "C:\VMs\sunmoon-prod\sunmoon-prod.vmx" nogui` |
| 正常关机 | SSH 进去 `sudo poweroff`；或 PowerShell：`vmrun -T ws stop "C:\VMs\sunmoon-prod\sunmoon-prod.vmx" soft` |
| 看在不在跑 | `vmrun -T ws list` |
| 挂起（像合上笔记本） | VMware 窗口「暂停」按钮，或 `vmrun -T ws suspend …`。下次开机秒回；集群跨挂起偶尔会有时钟漂移，关机重开更干净 |

不要点的：**「关闭客户机电源」**（等于拔电源，数据库可能坏）、**「从磁盘中删除」**（虚拟机连文件一起没了）。

`vmrun` 路径以你的安装为准，装在默认位置就是上面那个；嫌长可以在 PowerShell 配置里起个别名。

## 二、进去干活

从 Windows 终端或 WSL：

```
ssh sunmoon@192.168.80.10
```

第一次会问要不要信任主机指纹，答 `yes`。luna 用的是公钥免密；你自己的 Windows 终端要免密，把 `C:\Users\<你>\.ssh\id_ed25519.pub` 的内容追加到虚拟机里的 `~/.ssh/authorized_keys`，或者让 luna 加。

改文件、传文件也走 SSH，对照你现在用 WSL 的方式：

| 现在在 WSL 里 | 到虚拟机里换成 |
| --- | --- |
| VS Code 装 WSL 插件直接打开 WSL 目录 | VS Code 装 **Remote - SSH** 插件，连 `sunmoon@192.168.80.10`，打开 `/home/sunmoon/…`，编辑、终端、Git 面板都在里面 |
| 资源管理器打开 `\\wsl$\…` 拖文件 | **WinSCP**（免费）左 Windows 右虚拟机拖拽；或命令行 `scp 文件 sunmoon@192.168.80.10:~/` |
| 终端里 `vim` / `nano` / `cat` | 一样 |
| 复制终端输出到 Windows | 一样，双向 |

区别只有一个：WSL 的文件系统 Windows 能当本地盘直接挂，虚拟机的要经过 SSH 工具。用上 Remote - SSH 之后基本感觉不到。

连不上时按顺序查：

| 顺序 | 查什么 | 怎么查 |
| --- | --- | --- |
| 1 | 虚拟机开着吗 | `vmrun -T ws list` |
| 2 | 转发开了吗（Windows 重启后会掉） | 见第四节，重跑那两行 |
| 3 | 虚拟机网通吗 | 控制台登录后 `ip a`，看 `192.168.80.10` 在不在；`ping 192.168.80.2` |
| 4 | Windows 防火墙拦了吗 | 管理员 PowerShell 临时 `Test-NetConnection 192.168.80.10 -Port 22`；通而 WSL 不通，多半是防火墙对 WSL 网卡的规则 |

## 三、控制台（救急用）

| 按键 | 作用 |
| --- | --- |
| Ctrl+G，或在画面里点一下 | 键盘鼠标交给虚拟机 |
| Ctrl+Alt | 键盘鼠标还给 Windows |
| Alt+F1 ～ F6 | 切换虚拟机里的几个文字终端 |

控制台登录用用户 `sunmoon` 和控制台密码（luna 给你的那个，只在 `~/private/prod-vm/` 里，不在仓库里）。装好系统后 `open-vm-tools` 自带，鼠标移进移出自动切换，不用再按 Ctrl+G。

什么时候用控制台：SSH 进不去、网络配坏了、系统起不来。修好就回终端。

## 四、让 WSL 连得上（Windows 重启后可能要再做）

管理员 PowerShell：

```powershell
Get-NetIPInterface -AddressFamily IPv4 | Where-Object { $_.InterfaceAlias -like 'VMware Network Adapter VMnet8' -or $_.InterfaceAlias -like 'vEthernet (WSL*' } | Set-NetIPInterface -Forwarding Enabled
Get-NetIPInterface -AddressFamily IPv4 | Where-Object { $_.Forwarding -eq 'Enabled' } | Select-Object InterfaceAlias
```

第二行列出的里面要同时有 `VMware Network Adapter VMnet8` 和 `vEthernet (WSL…)`。原理：WSL 和虚拟机各挂在不同的虚拟交换机上，宿主机默认不在两张网卡之间转发，这两行把宿主机当成路由器。

## 五、开 Windows 就自动开虚拟机（可选，以后要用再做）

任务计划程序 → 创建任务：

| 项 | 填 |
| --- | --- |
| 触发器 | 登录时 |
| 操作 | 程序 `C:\Program Files (x86)\VMware\VMware Workstation\vmrun.exe`，参数 `-T ws start "C:\VMs\sunmoon-prod\sunmoon-prod.vmx" nogui` |
| 常规 | 勾「使用最高权限运行」 |

再加一个同样的任务跑第四节那两行（程序 `powershell.exe`，参数 `-Command "…"`），转发就不用每次手开。做了这一步以后，开电脑 → 开 Windows 终端 → `ssh` 进去，VMware 的界面基本不用再打开。

## 六、磁盘、快照、搬家

| 要做的 | 怎么做 | 注意 |
| --- | --- | --- |
| 数据盘不够了 | 关机 → 设置 → 硬盘 2 → 扩展 → 填新大小；开机后在虚拟机里 `sudo growpart /dev/sdb 1 && sudo resize2fs /dev/sdb1`（设备名以 `lsblk` 为准） | 有快照时不能扩，先删快照 |
| 做危险操作前 | 关机 → 虚拟机 → 快照 → 拍摄快照 | 快照会让磁盘变慢、占空间，用完就删（删快照是合并，不丢数据） |
| 换存放目录 | 关机 → 库里「从库中移除」（不是从磁盘删除）→ 资源管理器把整个文件夹剪切走 → 文件 → 打开 → 选新位置的 `.vmx` → 开机时问「移动还是复制」答**已移动** | 别放 OneDrive 同步目录；盘里留够 360 GB 给按需增长 |
| 改 CPU / 内存 | 关机 → 设置 → 处理器 / 内存 | 开着机改不了 |

两块盘的按需增长：建的时候写 60 GB + 300 GB，宿主机上实际只占已写入的量，会随使用慢慢长，不会缩。

## 七、这台机器的身份会变

| 阶段 | 它是什么 | 你在哪工作 |
| --- | --- | --- |
| 现在 → D'（虚拟机上冷建完成） | 生产机彩排，luna 从 WSL 远程操作它 | WSL |
| D' 之后 | 你的开发机兼运行机，luna 的工位搬进去，WSL 与老 kind 回收 | Windows 终端 `ssh` 进虚拟机 |
| 有真用户后 | 再分一台 dev，这台专做 prod | dev 那台 |

顺序定在《架构总纲》§六 9，待办见 [pending-after-migration](../design/pending-after-migration.md) 151。
