## 一、三项是什么

| 项 | 一句话 | 真源在哪 | 第几期 |
| --- | --- | --- | --- |
| 本地知识库 | 用户电脑上的一个目录，放他自己想留的资料；跨项目，Codex 在工作与专家对话里可读 | 用户电脑 | 一 |
| 信息采集 | 替用户到公网上取资料，取回来放进他的本地知识库 | 任务在云端，结果落用户电脑 | 一（基本型） |
| 长期记忆 | 跨对话、跨项目记住的关于这个用户的几条事实 | 工作台数据库（唯一一处云端的用户私有数据，只有几百字） | 一（只做第一种） |

底部从上到下：待我决定、本地知识库、信息采集、长期记忆、设置。

## 二、本地知识库

| 项 | 规则 |
| --- | --- |
| 是什么 | 本地代理白名单里标为「知识库」的一个目录（每台电脑至多一个）。在代理的设置窗口里选，和选工作区同一处 |
| Codex 怎么读 | 工作与专家对话的 `reads` 加上这个目录（跨项目），`writableRoots` 不加：Codex 只读不写。聊天不读 |
| 网页上 | 侧边栏「本地知识库」打开一页：文件树（根 = 这个目录），和 0017 右边栏同一套 `fs/readDirectory` / `fs/readFile` 经代理；点文件看内容；电脑离线则灰并说明 |
| 往里放 | 用户自己在电脑上放；信息采集放入（第三节）。网页不做上传 |
| 检索 | 第一期靠 Codex 自己读目录；本地索引（代理侧建、按意思找）第二期 |
| 多台电脑 | 各一个，互不同步；侧边栏按当前电脑显示 |
| 没有电脑 | 这一项灰，点开一句「接入电脑后，在代理里选一个目录作为本地知识库」 |

## 三、信息采集

| 项 | 规则 |
| --- | --- |
| 用户填什么 | 新建一次采集：几个网址，或一个站点 + 深度，或一个关键词 + 来源范围；可选「每天 / 每周重取」 |
| 在哪跑 | **云端一个采集服务**（复用 info-app 的抓取与原文留存机制，加按用户的配额与隔离），不在用户电脑跑，也不开沙箱网络。理由：代理不执行用户指定的进程；沙箱 `networkAccess=false` 不动 |
| 结果去哪 | 电脑在线：经本地代理 `fs/writeFile` 写进本地知识库目录下 `采集/<日期>-<名字>/`（原文、整理后的 Markdown、来源清单）。这是代理白名单里**唯一**允许云端写入的位置，且只限这个子目录。电脑离线：云端暂存 7 天，上线后补写，过期丢弃 |
| 页面 | 清单（名字、来源、状态、取到多少、放进了没有）、新建、一次采集的详情（来源逐条、失败原因）、重取、删 |
| 边界 | 只取公开网页；守 robots 与频率；不替用户登录任何网站；不取需要登录才能看的内容；单次与每日配额另定 |
| 与管理端「申请入库」的区别 | 那是用户向我们申请把公共数据入公共库；这是用户自己的资料，只进他自己的电脑 |

## 四、长期记忆（远程提的两条，所有者「以后再研究」）

| | 第一种：关于用户的事实 | 第二种：用户认下的判断 |
| --- | --- | --- |
| 装什么 | 关注的行业与公司、口径偏好（例：看扣非、按季）、风险偏好、输出习惯（例：先结论后依据、表格优先） | 专家交回后用户点「记住这条」的结论，带出处（哪个项目、哪位专家、何时） |
| 谁写 | 模型在对话里发现后**提议**，用户点确认才存；用户可直接在页面上增删改 | 用户在交回处点「记住」 |
| 谁读 | 每种对话开头 compose 带一段「关于这位用户」（≤ 300 字） | 专家编排时可按关键词取；聊天里用户问「我之前怎么看 X」时取 |
| 第几期 | 一 | 二 |
| 存哪 | 工作台数据库 `workbench_memories`（用户、类型、文本、来源、时间、启用），可导出、可一键清空 | 同表 |
| 不做 | 不用 Codex 自带的 memories / goals（`THREAD_CONFIG` 已关），不自动写 | |

页面：一张清单，按两种分组；每条可停用、改、删；顶部一句「这里的内容会放进每段对话的开头，只有你能看」。
