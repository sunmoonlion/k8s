## 二、代码怎么放（所有者 2026-10-04 定，`I10`）

```text
app/            页面。只把功能拼起来，不写逻辑
features/
  <功能>/
    api/        取数：请求、缓存、改动之后让谁重取
    model/      状态：纯函数与状态库。不取数、不渲染
    ui/         渲染：组件。不自己发请求
    index.ts    出口。页面只从这里拿
lib/workbench/  几个功能共用的：收发、地址、共用的清单、一段对话的事件流
components/     共用的界面件：ui/（shadcn）、common/、workbench/
contracts/      接口的写法（zod）
```

| 规矩 | 谁拦着 |
| --- | --- |
| 功能之间不互相引用 | `tests/unit/feature-boundaries.test.ts` |
| 公共的部分不引用功能 | 同上 |
| 页面只从功能的出口拿东西 | 同上 |
| `model/` 不取数、不渲染；`api/` 不渲染；`ui/` 不自己发请求 | 同上 |
| 契约认得真接口的每一份返回 | `tests/unit/workbench-contract-samples.test.ts`，对着预览样例（真后端录的）逐份检查 |

一个功能要用另一个功能的东西时，由页面递进去。例：聊天页顶部的花费钮属于「花费」这个功能，是页面作为一个插槽交给聊天页的。

现在有五个功能：`shell`（框架与侧栏）、`home`（首页）、`chat`（聊天页）、`work`（工作页）、`usage`（花费钮）。

聊天页和工作页都要用的东西不放在哪个功能里，放在公共的位置：把 Codex 的一件事变成一行（`lib/workbench/items.ts`）、一段对话上能做的动作（`lib/workbench/conversation.ts`）、输入框、一行命令或一次查数据的样子、「没有数据」卡片、对话的名字（都在 `components/workbench/`）。

这套放法先在 investment 里用。info、knowledge 做页面时（第 8、9 步）照此办，届时把检查搬进模板。

## 三、第 1 段做了什么

截图在 [`PRD/apps/screens/`](../../PRD/apps/screens/)：`step7-1-home.png`、`step7-1-home-expert.png`、`step7-1-chat.png`、`step7-1-chat-open.png`。

| 页 | 有什么 |
| --- | --- |
| 框架 | 左边侧栏：三个功能的切换；新建；工作区（下拉）与它下面的项目；最近的对话（专家在处理的带一个点）；底部是待我决定（带数字）、数据目录、数据申请（去别的应用）、我的机器（带灯）、设置、退出。中间那一段自己滚，底部的条目一直看得见 |
| 首页 | 三个功能的切换与各一句说明；一个大输入框；项目就在输入框的角上选（`I11` 第 1 条）；待我决定；最近的对话 |
| 聊天页 | 顶部：对话的名字（点了能改）、未归入项目与「放进项目」、花费钮。对话：用户的话在右，模型的回答在左（Markdown）；过程收成一行，点开才看细节（`I11` 第 2 条）；「没有数据」卡片，带去申请入库的链接。输入框：回车发送；旁边是「转为工作」「请专家」 |
| 花费钮 | 这段对话到现在花了多少，模型每调用一次跳一次，一直带着「估算」。点开：每一轮调用几次、多少 token、多少钱；用的单价与查价的日期。没有单价的模型只显示 token 数 |
| 停止钮 | 模型在答的时候，发送钮变成停止钮。点了就停，不用知道是哪一轮 |

还没做的页，在侧栏和首页里显示出来但不是链接；首页选了「工作」「专家」时发不出去，并写明「这一页还在做」。做好一页，在 `lib/workbench/routes.ts` 的清单里加一项。

留给后期的三样（技能、连接器、助理）要守的三条（`PRD/apps/investment.md` 11.3）：侧栏底部的条目由一份清单生成（做了，`features/shell/model/nav.ts` 的 `FOOT`）；工具调用有通用的样子（做了：哪个服务、哪个工具、参数、结果）；不假设对话只从网页来（事件里记着谁发的，页面没有写死）。

## 三之二、第 2 段做了什么

截图：`step7-2-work.png`（工作页，一条命令等批准）、`step7-2-work-open.png`（点开了一段过程）、`step7-2-project-chat.png`（项目里的聊天）、`step7-2-work-expert.png`（专家正在处理时的工作页）、`step7-2-home-work.png`（首页选了「工作」）。

| 项 | 有什么 |
| --- | --- |
| 工作页的时间线 | 不是气泡。用户的话是一个灰底的块；模型的回答是正文。**一段过程收成一行**（`I11` 第 2 条）：它先说一句要做什么、接着跑了几条命令，那句话就是这一行的标题，后面写「2 条命令」，点开才看每条命令、退出码、输出 |
| 一直摆在外面的三样 | 改文件（哪个文件、增删几行，点开看改了什么）；等你批准；「没有数据」卡片 |
| 审批卡 | 命令、在哪个目录、它的理由都摆出来；能选什么、每一项怎么说由后端给（允许一次、这段对话里都允许、拒绝）；就地答复。答过之后收成一行，写着你答了什么 |
| 状态带 | 「你在操作」加这会儿的状态（它正在做、它在等你批准、上一轮被你停下了）；专家拿着的时候是「专家正在处理」 |
| 右边的「改动」栏 | 这段对话改了哪些文件，同一个文件改了几次合成一行，点开看每一次改了什么（`I11` 第 3 条）。窄屏时收起 |
| 专家正在处理时 | 输入框禁用，写明原因（`F-WEB-03`）。专家每一步交回的原样（给验收看的 JSON）不显示：那是下一段专家页的事。专家那一段里要用户批准的命令仍然显示、仍然能答 |
| 项目里的对话 | 同一个地址，是聊天就用聊天页，是工作就用工作页 |
| 打开一段对话 | 停在最后，新的内容出来跟着往下 |
| 首页 | 「工作」可以开始了：选项目，写要它做什么，进工作页 |

## 五、做的时候查出来的

| # | 问题 | 处理 |
| --- | --- | --- |
| 1 | 正式构建下，每一页都有一条内容安全策略的报错：「加载中」那一页的脚本没有带随机数，被浏览器拦了。没动过的旧页面上也有 | **没有改**。是底座的问题，页面照常显示。记在账本 H52 |
| 2 | 字体没有生效：样式里无衬线字体的变量指向它自己，页面用的是浏览器默认的衬线字体。模板与三个应用的网页端都这样 | 已改：用系统自带的字体，不下载字体文件。模板、info、knowledge、investment 四个网页端都改了。管理端没有改（账本 H53） |
| 3 | 第 6 步录的聊天样例里，「问到没有数据的公司」那一轮是坏的：工具调用的类型名被替换坏了，所以没有「没有数据」的事件，也没有花费。第 6 步汇报时没有发现 | 已改，并加了检查。原因：拼出来的那一轮用单个字母当编号，回放时把别的词里的字母也换掉了 |
| 4 | 开发模式下改了样式文件，页面还是旧的 | 是开发服务器的缓存。删掉 `.next/dev` 再开。只影响本机调试 |

| 5 | 第 2 段：真 Codex 录的磁带里，模型（kimi-k3）改文件走的是命令行（重定向写文件），不是 Codex 的补丁工具。这种改动 Codex 不单独报，「改动」栏列不出来 | 「改动」栏下面写明了这一点。样例里加了一轮照协议拼的「用补丁改文件」，页面才有东西可看。记在账本 H56 |
| 6 | 第 2 段：审批的选项写着「本会话都允许」 | 已改成「这段对话里都允许」。给用户看的字眼不用「会话」 |
