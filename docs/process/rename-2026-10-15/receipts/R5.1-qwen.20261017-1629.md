### 根因（只读核实）

```
fatal: [localhost]: FAILED! => {
  "assertion": "release_receipt_path.stat.isreg | default(false)",
  "changed": false, "evaluated_to": false,
  "msg": "Upload and verify the installer before setting download_available=true."
}
```

- `gitops/components/app-platform/knowbench-app/knowbench-backend/agent-releases/config.yaml` 第 6 行：`download_available: true`
- `prepare.yaml` 第 15–28 行：当 `download_available=true` 且 `mode == 'object-storage'` 时，断言 `services_config_dir/knowbench-agent-release-published.json` 必须存在（`stat.isreg`），否则 fail_msg = "Upload and verify the installer before setting download_available=true."
- `sudo ls /etc/sunmoon/services/sunmoon-kind/ | grep knowbench` → 无输出（该 json 不存在）

**结论**：knowbench 的本地代理安装器（sunmoon-link 0.5.0）尚未上传到 `services_config_dir`，但 `config.yaml` 已把 `download_available` 设为 `true`。按手册 R5.3 的安排，安装器上传在 R5.3 才做（「R5.3 本地代理 0.5.0（Windows 与 Linux 包）」），而 R5.1 的 stage 在 R5.3 之前——**存在先后矛盾**，需 Opus 决定：
1. 把 `config.yaml` 的 `download_available` 改回 `false`，R5.1 stage 先过，R5.3 上传安装器后再改回 `true` 并重新 stage knowbench；或
2. 先做 R5.3 的安装器上传，再回来做 R5.1 的 stage。
