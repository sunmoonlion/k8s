## 一、上次为什么粗糙

| 上次的样子 | 问题 |
| --- | --- |
| 专家是会话页侧栏里的一个面板 | 我们最不一样的东西，被放在了最不起眼的地方 |
| 专家包是三个代号：`SMOKE`、`DATA_QUERY`、`FIN_REVIEW` | 用户不知道它们是什么、能解决什么 |
| 处理中只显示「第几步」和状态词 | 看不出专家在按方法做，和普通 AI 没有区别 |
| 每一步的验收只存在后端 | 「做对没有」是专家的核心，用户却看不到 |
| 底稿页把交回物按 JSON 显示 | 不像一份研究底稿 |
| 专家停下来问人时，只有一个问题两个按钮 | 用户不知道为什么停、停在哪、选了会怎样 |

## 二、专家比普通 AI 多做了什么

界面的任务，是让用户**看见**下面这六件事。每一件都要在页面上有固定的位置。

| # | 专家多做的 | 普通 AI | 在哪里让用户看见 |
| --- | --- | --- | --- |
| 1 | 按方法拆成有名字的步骤 | 想到哪做到哪 | 步骤轨 |
| 2 | 每一步做完都要过验收，逐条检查 | 做完就算完 | 每一步的验收清单 |
| 3 | 验收不过：重做、退回前一步、或停下来问人。**不往下编** | 硬着头皮答 | 步骤轨上的返工与退回；等你决定 |
| 4 | 每个数都有出处：哪个数据集、哪个版本、数据到哪一天 | 说不清数从哪来 | 数字的角标；底稿的出处 |
| 5 | 有预算，用完就停 | 花多少不知道 | 预算条 |
| 6 | 不下结论。结论栏留给用户 | 常常给建议 | 底稿最后的「我的结论」 |

设计原则只有一条：**把专家的认真做给用户看**。专家慢、贵，用户愿意等、愿意付，是因为看得见它每一步都验过。

## 三、四个页面

| # | 页面 | 路径 | 用户在这里的问题 |
| --- | --- | --- | --- |
| E1 | 专家首页 | 侧栏选「专家」 | 有哪些专家？我交出去的事怎么样了？ |
| E2 | 请专家 | `/workbench/projects/{项目}/expert/new` | 它会怎么做？要花多少？我交出去的是什么？ |
| E3 | 专家处理中 | 项目里的对话页，专家接手期间 | 做到哪了？每一步验过没有？有没有事等我？ |
| E4 | 底稿 | `/workbench/projects/{项目}/tasks/{委托}` | 结果是什么？凭什么信它？哪些它没做到？ |

另有审查面（专家停下来问我时），见第八节。

## 五、E2 请专家

分左右两栏：左边是用户填的，右边是专家的承诺。用户填一项，右边跟着变。

```text
┌────────────────────────────────────┬────────────────────────────────┐
│ 请专家：财报体检                     │ 它会这样做                      │
│                                    │                                │
│ 要解决什么问题                       │ 1 定范围                        │
│ ┌────────────────────────────────┐ │   认出公司、期间、报告类型        │
│ │ 恒瑞医药 2023 到 2025 年的盈利   │ │   认不出 → 停下来问你            │
│ │ 能力怎么样？                    │ │ 2 数据摸底                      │
│ └────────────────────────────────┘ │   确认有这家的数据、数据到哪天    │
│ 写清公司和期间，专家才接得住          │   没有数据 → 停下来，可申请入库   │
│                                    │ 3 勾稽                          │
│ 在哪个项目里                         │   三张表之间对不对得上           │
│ [恒瑞医药研究 ▾]                     │   对不上 → 停下来问你，不往下算   │
│                                    │ 4 取数                          │
│ 预算上限                            │   不合格 → 退回第 2 步           │
│ [ 2.00 ] 元                         │ 5 算指标                        │
│ 用完会停下来问你，不会超               │   不合格 → 重做，最多 2 次       │
│                                    │ 6 对照官方                      │
│ 专家看得到                           │   和公司年报里的数对不上 → 停下来 │
│ ✓ 这段对话（12 轮）                   │ 7 成稿                          │
│ ✓ 项目里的文件（只读，用到才读）       │   结论栏留空                    │
│ ✓ 项目里别的 3 段对话、1 份底稿        │ ────────────────────────────── │
│                                    │ 它不会做                        │
│                                    │ 预测、估值、评级、买卖或仓位建议   │
│                                    │ ────────────────────────────── │
│                                    │ 做完交回                        │
│                                    │ 底稿：数据摸底、勾稽结果、取数表、 │
│                                    │ 指标表、与官方的对照、观察与提醒   │
├────────────────────────────────────┴────────────────────────────────┤
│ 专家会接着做：恒瑞医药 2023 到 2025 年的盈利能力怎么样？                  │
│ 最多花：2.00 元                                                       │
│ 做完把底稿交回给你，期间你可以随时取消                                   │
│                                              [取消]  [交给专家]        │
└─────────────────────────────────────────────────────────────────────┘
```

| 区块 | 规则 |
| --- | --- |
| 要解决什么问题 | 必填。从对话里来时带入最近一句。下面一行提示因专家而异，取自专家包的「输入」 |
| 它会这样做 | 专家包的每一步：名字、一句白话、不通过时怎么办。**不显示方法的原文** |
| 不通过时怎么办 | 三种说法：「重做，最多 n 次」「退回第 k 步」「停下来问你」 |
| 它不会做 | 取自专家包的「不解决什么」 |
| 做完交回 | 取自专家包的「输出」 |
| 专家看得到 | 列出数量，不列内容 |
| 底部三行 | 交出前的确认，固定文案 |
| 换专家 | 左上角可以换；右栏随之整个换掉 |

| 状态 | 页面 |
| --- | --- |
| 问题与专家不匹配（受理拒绝） | 留在这一页，问题框下面显示原因，例如「这位专家只做已入库的 A 股非金融公司」 |
| 机器离线 | 「交给专家」禁用，旁边：「你的机器没在线，专家要在上面干活」 |
| 这个项目里已有专家在做 | 禁用，旁边：「这个项目里有一件事专家还在做」，带链接 |
| 没有模型 key 或没有沙箱 | 禁用，指到设置 |

为什么不显示方法的原文：方法是我们的东西，也是易损件。用户要知道的是「它会做什么、不过怎么办」，不是提示词。

### 6.1 步骤轨（左）

| 记号 | 含义 |
| --- | --- |
| ○ | 还没做 |
| ● | 正在做 |
| ✓ | 做完，验收通过 |
| ↻ n | 验收没过，正在重做；n 是第几次 |
| ↩ | 验收没过，退回到了前面的某一步 |
| ⏸ | 停下来等你 |
| ✕ | 这一步失败，委托终止 |

| 规则 | 说明 |
| --- | --- |
| 点哪一步，中间就显示哪一步 | 默认跟着当前这一步走；用户点了别的步骤就不再自动跳 |
| 返工与退回不隐藏 | 一步重做过，记号旁边写「重做过 1 次」。这是专家认真的证据，不是丢人的事 |
| 每一步旁边的小字 | 做完的：花了多少；没做的：不显示 |

### 6.2 这一步（中）

固定四块，顺序不变。

| 块 | 内容 | 数据从哪来 |
| --- | --- | --- |
| 标题 | 第几步、名字、一句白话 | 专家包 |
| 用了什么 | 前面哪几步的交回物；用了哪些工具、各几次；哪个数据集、哪个版本、数据到哪天 | 专家包的输入；这一步的事件 |
| 交回了什么 | 这一步的交回物。是表就画成表；是列表就画成列表；都不是才显示原样 | 这一步的交回物 |
| 验收 | 每条检查一行：通过打勾，不通过打叉并写原因 | 事件里的检查结果 |
| 过程 | 默认折叠。展开是这一步的时间线：每次查询、每次读文件 | 事件 |

| 这一步的状态 | 中间显示 |
| --- | --- |
| 还没做 | 标题、它会用什么、它要过哪些验收。交回了什么：空 |
| 正在做 | 「用了什么」随着做实时增加；「交回了什么」显示「正在做」；验收清单是灰的 |
| 做完通过 | 四块齐全 |
| 验收没过，在重做 | 上一次的交回物与验收结果保留，标「第 1 次，没有通过」；下面是这一次 |
| 等你决定 | 验收清单里不通过的那几条标红；下面直接是审查面（第八节） |

### 6.3 委托单（右）

| 项 | 内容 |
| --- | --- |
| 问题 | 用户交出去的原话 |
| 预算 | 一根条：已花、预留、上限。数字带币种 |
| 数据 | 用到的数据集与数据时点。第 2 步做完之前显示「还不知道」 |
| 已用时间 | 从交出算起 |
| 专家看得到 | 与交出时相同 |
| 看底稿 | 进行中也能看，只有做完的部分 |

窄屏时右栏收进顶部状态带下面的一行。

### 6.4 三种打断

| 打断 | 顶部状态带 | 中间 | 用户能做 |
| --- | --- | --- | --- |
| 等你决定 | 「专家停下来了，等你决定」 | 停住的那一步，下面是审查面 | 答复 |
| 预算用完 | 「预算用完了，已停下」 | 做到哪一步、还剩几步、每步预留多少 | 追加；不追加则交回已做完的部分 |
| 机器断线 | 「你的机器断开了，专家在等它回来」 | 当前这一步，标「暂停」 | 打开本地代理；取消 |

### 6.5 「没有数据」

财报体检的第 2 步发现公司没有入库时：

| 项 | 内容 |
| --- | --- |
| 验收清单 | 「✕ 有对应的数据集 — 这家公司未入库」 |
| 下面 | 「没有数据」卡片：「600519 还没有数据」「申请入库」「看看有哪些数据」 |
| 审查面 | 两个选项：「数据已经入库了，接着做」「停止」。也可以先不答：委托停在这里不花钱，72 小时内回来接着做。页面要把这一句写在选项上面 |
| 重做 | 不重做。没有数据，重做也不会有 |

原先写的两个选项是「先停在这里，等数据入库后我再来」「停止」。做的时候改了：「先停在这里」一旦提交，这件待办就用掉了，委托却还在等，没有东西可等。

### 6.6 取消

点「取消」先问一句：「取消之后专家会停下，已经做完的部分会交回给你。已花的 0.18 元不退。确定取消吗？」

## 七、E4 底稿

底稿要像一份研究底稿，不像程序的输出。从上到下读下来，是「问了什么 → 答了什么 → 凭什么 → 哪些没做到 → 我怎么看」。

### 7.1 不同的专家，底稿不一样

| 专家 | 「二、数据」 | 「三、专家验过什么」 |
| --- | --- | --- |

| 问数 | 结果表 | 查询用的口径、数据版本 |

| --- | --- |
| 每个专家包登记自己的底稿怎么排 | 哪几块、每块取交回物里的哪一项 |

| 任何时候都不直接显示原样的 JSON 作为主体 | 原样只在「每一步的交回物」里，折叠着 |

### 7.2 没做完的底稿

| 终态 | 抬头 | 内容 |
| --- | --- | --- |

| 失败、取消 | 「做到第 k 步停下了」加原因 | 做完的步骤照常显示；没做的块写「没有做到这一步」；已发生的费用 |
| 停在没有数据 | 「这家公司没有数据」 | 「没有数据」卡片 |
| 进行中 | 「专家还在做」 | 做完的步骤；其余是灰的 |
