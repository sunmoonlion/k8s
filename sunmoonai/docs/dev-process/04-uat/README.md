# UAT：用户验收测试（User Acceptance Testing）

## 判据与完成

- **验收判据先于产出冻结**，出题的人与答题的人分开；实现者完工后不能改验收题。
- **验收不能外推。**在一类任务上跑通的便宜验收（可用测试、diff 机械复算），不能证明判断昂贵的另一类任务也过关。
- **完成条件逐条满足才叫完成。**缺项时只能称相应的中间状态（已受理、候选完成、待验收……），不能笼统说完成。
- **先核前提。**比较方案之前，先顺着真实调用链核实：要控制的动作是否一定经过所说的强制点；查不到就标假设。

## 证据采信

- 自述只是待验证的主张；结论由验证方从冻结的产物独立重算。
- 采信程度取各项中最低的一项（来源、可见范围、隔离强度、验收独立性、覆盖），任一项未知就降级，不取平均。
- 覆盖声明同时写查了什么、没查什么；零命中只有在输入集合被完整枚举时才算通过，否则是「不可判」。

## 检查本身也必须接受检查

每个检查都输出「通过 / 失败 / 不可判」三种结论，并写明查了什么、没查什么。
缺输入、权限不足、枚举失败不能被吸收为通过；聚合前先判输入集合是否完整、是否允许为空。
**不让空集合、空 diff、吞掉的退出码或「0 个文件通过」代替完成条件。**

新增或修改检查时至少核查适用的边界用例：正常通过、真正失败、输入缺失、命令失败、
空集合、引用对象不可达、否定句与历史引用。误报要区分是解析问题还是内容问题，
不能为了消掉一个红字删掉失败标准；假失败偏安全，也不是长期保留误报的理由。

文档复核分四层：链接可达；标题有对应；对应正文真正承载原主张及其边界；证据本身支持该主张。
**空标题、只有结论没有证据、映射到同名异义的段落，都不算吸收。**链接和表格一类的机械检查
不能替代正文层与证据层。

机械状态校验从明确的状态表取词与边，不对全文盲搜：历史反例、否定句和属性值不应被误认成状态。
覆盖声明和不可判的输入与结果并列，不让下游把窄范围的通过外推成完整正确。

## 覆盖声明：查了、没查、不能排除

覆盖声明要能装下「不确定」，不是只有「查了」「没查」两档。凡「不能排除某事发生过」，
就如实写进来，不要因为难看就压成「没查」：

| 写法 | 含义 |
| --- | --- |
| 查了 | 有观测，有结论 |
| 没查 | 没有观测，**明知自己不知道** |
| **不能排除** | **有观测但不足以定论**，或存在自己控制不到的路径 |

「没查」还要按类别分列，不能混成一段：

| 类别 | 例 | 性质 |
| --- | --- | --- |
| **环境事实** | 主机名、身份、命名空间映射 | **可当场复跑**；没查是因为没跑，跑了就有结论 |
| **远端与授权** | 远端分支、分支保护、部署密钥 | 部分可读，**写授权不能只靠读取来验证** |
| **执行者内部** | 界面里选的模型、沙箱内的工具调用 | **结构上够不着**，换接入方式才可能有结论 |

第三类是唯一「不改变接入方式就永远查不了」的；把它和前两类并排写成「没查」，
会让人以为再跑几条命令就能补上。

**如实写「不能排除」不扣分，隐瞒才扣。**
