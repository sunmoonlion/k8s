# knowledge-app 摘要

> 快层：三分钟把握本 App。深刻层见同目录 `架构.md`；App 之间关系见 `baseline/overall/`。
> 仓库路径 `/home/zymun/knowledge-app`。

## 1. 定位

知识库域 App，Info→Knowledge→Investment 数据链的**中枢**：消费 info 分发的不可变 artifact，
校验后入库到检索提供方（RAGFlow），向 investment 提供受契约约束的检索/引用服务。父仓
`contracts/` 是摄入与检索 **provider 契约的唯一可编辑真源**（Info/Investment 仓只有消费锁）。

## 2. 仓库拓扑

- `contracts/artifact/v1`：摄入契约（producer=Info，provider=Knowledge）。
- `contracts/retrieval/v1`：检索契约（provider=Knowledge，consumer=Investment + 浏览器投影）。
- `knowledge-backend` + `knowledge-admin-frontend` + `knowledge-web-frontend`。

## 3. 关键入口

- 摄入链 `knowledge_ingestion_service.py` + `ragflow.py`：idempotency_key 幂等受理 →
  artifact 安全解析（s3 bucket/前缀白名单、手写 SigV4、version/size/content-type 双次校验、
  sha256 比对）→ RAGFlow ensure/upload/parse 轮询 → **同事务原子提交**领域身份 +
  provider binding。
- 检索链 `knowledge_retrieval_service.py`：三重授权（dataset 白名单 / tenant 一致 /
  `knowledge:retrieve` scope）→ RAGFlow 检索 → token_budget 截断 → uuid5 稳定派生
  evidence/citation。
- 双关系 Service Identity：ingest（info→）与 retrieve（investment→）两个独立验证器，各自
  audience/subject allowlist；关系 scope 由本地 subject allowlist 授予。
- 边界：RAGFlow id 只是私有 binding，永不是领域身份；浏览器只见 citation 投影 + 同源
  source_href。

## 4. 数据与迁移

三表：ingestion_job / document / document_version；Alembic head `20260811_0005`
（含遗留数据 uuid5 回填迁移）。

## 5. 运行与验证

与模板同套命令；RAGFlow 未启用时摄入降级为 artifact 契约验证器（`artifact_verified`）。

## 6. 与 tpl 的差异

双契约真源治理、RAGFlow 适配与解析轮询、artifact S3 只读消费安全链、双关系服务身份配置段、
检索白名单策略；前端与模板同构。
