## 怎么用

`C-D12`–`C-D15`、`C-C9`–`C-C11`、`C-R10` 与反模式末两行（2026-10-15 从旧体系 `app-platform/docs/` 的数据所有权、集成规范、生产就绪三份吸收）；「发布」一节同日按新体系改写。


按**你要动什么**取对应的组，把相关条目和结论写出来，两三行的小表：

| 你要动 | 读哪节 |
| --- | --- |
| 表、迁移、存储 | [数据](#数据) |
| 跨 App 接口、契约 | [契约](#契约) |
| 登录、权限、服务间调用、令牌 | [身份](#身份) |
| 仓库、组件、运行角色、站点 | [拓扑](#拓扑) |
| 部署、发版、镜像 | [发布](#发布) |
| 沙箱、执行环境、顾问、专家包 | [智能体](#智能体) |

**「谁在执行」那一栏是重点。**标 ⚠ 的没有自动载体，只能靠自检和评审守住。

### 做数据迁移时

`expand → backfill → reconcile → switch read → switch write → observe → contract`。旧写路径切换必须 fail-closed，不得无期限双写；六条验收缺一不可：可恢复备份加实际恢复演练、回填计数对账、新旧读路径对比、旧凭据被拒、`migration current` 单 head、回滚与重新前滚通过。**这一节无自动载体。**

## 合规

knowlab 总原则（所有者 2026-10-16 定，设计见 [`0026-knowlab`](../SDD/modules/0026-knowlab.md)）：投资逻辑来自用户，数据来自用户，我们只做工程化与测试，用户做出的**分身**（knowbot，下表的「bot」）只给用户自己。我们自己也当普通用户，不走后门。

| # | 规则 | 谁在执行 |
| --- | --- | --- |
| C-L1 | **平台不带投资逻辑**：用户 bot 的投资逻辑只来自用户的 idea 或 skill；工程化只翻译不发明，方法缺的投资判断（选股条件、阈值、结论口径）回头问用户；平台不提供选股、评级、目标价、买卖时点之类的模板；每条规则的来源留记录 | ⚠ 自检 |
| C-L2 | **平台不给数据**：用户 bot 只读该用户自己上传的数据；不接我们的数据服务（knowbase、knowfeed）；我们自己的 bot 要用这些数据，也按普通用户的方式上传 | ⚠ 自检 |
| C-L3 | **测试只测运行正确**：用用户的数据、按用户定的验收标准测算得对、照方法走、不编数、能复现；不出投资效果、胜率、收益结论，不拿测试结果宣传 | ⚠ 自检 |
| C-L4 | **bot 只归用户自己**：绑定创建它的账号，只在我们平台运行；knowmart 私有模式下，后端对一切列出与「请」都强制按所有者过滤，对外上架的能力不做或锁死，不靠界面隐藏；没有导出 bot 包、分享、转让、发布、按次收费的入口，不能以别人名义运行或嵌给第三方；用户导出自己的分析结果自用不受限 | ⚠ 自检 |
| C-L5 | **按工具收费、按工具说话**：按工程化、测试、算力、存储收费，不按信号、建议、效果收费；产品与宣传不出现「顾问」「推荐」「荐股」「投资专家」；工作台里没有对全体用户可选的内置专家，每个 bot 都归某个用户（我们的「财务分析与预测」归我们这个普通用户的账号） | ⚠ 自检 |

## 设计原则的具体化

`P0`–`P6` 的真源是 [SDD「设计必须满足」](../../turn/sdd/finalize.md)。本项目取值：`P0` 状态机是 Task / Attempt 两层，Profile 不得新增状态词，方向盘是对象属性不是状态词；`P1` 对应 `I5`；`P5` 见"保证这些被遵守的三层"；`P6` 未核前提记在 [待定决策](../decisions.md)。

## 反模式

| 反模式 | 失败方式 |
| --- | --- |
| Task 与 Attempt 合并 | 一次执行失败过早终结用户请求 |
| 先推送后落库 | 用户看见无法回放的幽灵事件 |
| 用户与顾问同时发 turn | 同一 thread 两个写入者，产物互相覆盖 |
| 执行环境断了改在沙箱里跑 | 工具跑在错的机器上，静默 |
| 云端能提高本地沙箱权限 | 云端被攻破等于每台用户机器被远程控制 |
| 边缘存业务状态 | 边缘一坏数据跟着丢；边缘被攻破拿到数据 |
| 内网开入站端口 | 拓扑不变量失效 |
| 同幂等键异载荷静默复用 | 用户得到另一请求的结果 |
| 顾问自行加步、加预算 | 用户账单失控 |
| 方法库写入买卖标准 | 系统替用户下判断 |
| 把 Codex thread 当 Task 真源 | 两个真源 |
| 规范只有文字没有测试映射 | 「必须」无法执行 |
| 用部署顺序代替运行时容错 | 依赖晚起或重启一次，整条链就挂；每个 App 自备超时、有界重试、幂等、对账与降级 |
| 以 Redis、检索索引或消息队列当主数据 | 派生物一丢，事实跟着丢 |
