# 本地 runtime：必须做到什么

> 本地 runtime 必须做到的功能义务。`F-*` 的 ID **全局唯一、跨文件不复用、不因搬动而重排**；合同的验收矩阵 `AT-*` 按这些 ID 勾。
一条义务跨两个模块时，定义放在主要承担方这一份，另一方只注明边界。

## 执行（执行端）

- **F-EXEC-01**：只使用执行策略与 Agent Profile 允许的能力、数据源、工具与自动放行范围；
- **F-EXEC-02**：工具输入输出摘要、模型与工具版本、证据关联到 Attempt；
- **F-EXEC-03**：每次高风险动作前重新校验授权与批准；
- **F-EXEC-04**：持续扣减 Task 总预算，在越限前停止；
- **F-EXEC-05**：可恢复进度以后端持久的 Artifact 与独立工作区引用为准，不依赖进程内记忆或运行时 thread 记录；
- **F-EXEC-06**：区分事实、推断、假设、缺失与不确定性；
- **F-EXEC-07**：无法满足完成契约时请求输入或明确失败，不伪造完整结果；
- **F-EXEC-08**：计划只是可选 Artifact；复杂 Task 可以要求计划先经批准，简单任务不得为走流程而制造空计划；
- **F-EXEC-09**：每个 Attempt 在独立工作区执行，不直接修改用户正在使用的目录（[`discipline.md`](../../0003-runtime/PRD/discipline.md)）；
- **F-EXEC-10**：失去租约即暂停（[`discipline.md`](../../0003-runtime/PRD/discipline.md)）；
- **F-EXEC-11**：执行中发现需要领域能力时调用 `escalate`，不自行扩大能力；
- **F-EXEC-12**：Agent Profile 之外的工具不进入模型上下文（会话组装时就不挂载）；runtime 对未授权的工具调用结构性拒绝，两层不得互相替代；
- **F-EXEC-13**：研究产出遵守定位约束（F-POS-01 至 F-POS-04）。

## 工具级与 Task 级审批

- **F-APPROVE-01**：命令执行与文件修改必须进入审批回调；自动放行只限只读动作与独立工作区内的写入；网络访问、独立工作区外的写入、任何不可逆动作必须交用户确认或升级为 Task 级。
  ⚠ **「所有」这个量词目前是假设，不是已核实的事实**（`C-P6`）。审批请求是否出现，受 approval policy、sandbox 设置与动作类型影响；
  监听 `ExecCommandApproval` / `ApplyPatchApproval` 只能证明**这两类**请求会到，证明不了每个实际动作都曾经过回调。
  **验证办法**：在钉定的 Codex 版本与完整配置上做能力探针（见 [`engine-adapter.md`](engine-adapter.md)「能力探针」），
  按动作类型逐类列出「是否必然产生回调」。拦不住的动作**改执行模型或明令禁止**，不得靠这条义务的措辞兜住；
- **F-APPROVE-03**：审批内容（命令原文、改动、路径）只在本地展示，上报只含摘要与结论；
- **F-APPROVE-04**：断线时未决的工具级审批作废，不自动通过；
- **F-APPROVE-05**：审批页面以业务语言呈现，按策略能决定的不打扰用户。

## 后端被攻破时仍要成立的

- **F-GUARD-01**：Agent Profile、workflow 与方法由不在在线派发服务里的密钥签名；runtime 只接受签名有效且本地已登记的版本；
- **F-GUARD-02**：执行前必须在本地确认要执行的内容摘要（Task、Profile、工作区、能力范围）；确认粒度与免确认范围由用户在本地设置；
- **F-GUARD-03**：按 Profile 限定能力与自动放行范围是主防线：运行中生成的指令无法预先签名，Profile 没授权的工具、目录、网络，指令写什么都用不上；
- **F-GUARD-05**：厂商预设与取数工具规则的更新必须带签名。

## 交付

- **F-CRYPTO-01**：结果密钥**对**在用户设备上生成，**私钥存桌面应用侧系统钥匙串、runtime 只拿公钥**；加密在执行端完成，发生在本地内容检查之后——runtime 加密得了，**解密不了**（逐跳见 [数据流与信任边界](../../../architecture/trust.md)「三把东西的逐跳归属」）；
- **F-DELIVERY-11**：结果正文只以密文离开执行端；本地资料内容与文件名不离开执行端；管理后台与事件流不含正文。

## 本地检查

- **F-ACCEPT-02**：**本地结构与内容检查**：凡是需要读正文的检查——输出 schema 与未声明字段、必填证据字段、F-POS-04 的判断拦截、验收条目中需要读正文的部分——都在执行端、加密之前完成，合成一张签名回执；后端核对回执与密文摘要一致；
  ⚠ **核对**回执与密文摘要一致是后端 `0006-acceptance` 的事，不在这里。
