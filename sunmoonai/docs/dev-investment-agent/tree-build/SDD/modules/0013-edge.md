# 0013 · 公网边缘第一期：东京 VM 上的 frps + Traefik

> 2026-10-09 远程（Fable）定稿；所有者同意开放范围。拓扑原则见 [architecture/topology](../architecture/topology.md)，本文是它的第一期落地，偏离处写明理由。
> 分工：边缘一侧远程做（就在这台 VM 上）；集群里的 frpc 由 luna 照第五节在 luna 分支实现、Cursor 发布；DNS 与云安全组由所有者在后台配置。

## 一、第一期做成什么样

```text
外部用户浏览器 / 本地代理
  └─ https / wss  investment|casdoor|relay.sunmoonai.com:30443
       ▼
东京 VM 43.153.135.74（边缘）
  Traefik：30443 公网 TLS 终止（Let's Encrypt）+ 80 端口只做签证书与跳转
       └─▶ frps vhostHTTP 127.0.0.1:8080（只绑本机）
              ══ frp 隧道（frpc 主动连 7000，TLS + 令牌）══
                                                        ▼
所有者机器上的 KIND 集群：frpc（Deployment）─▶ 集群 Traefik（websecure）─▶ 现有 IngressRoute
```

- **端口沿用 `:30443`**：现有网页、Casdoor 回调、会合点地址里都写着 `:30443`。边缘也在公网听 30443，应用配置一行不改；所有者本机经 hosts 照旧直连本地集群。改成标准 443 另起一轮（第七节）。
- **会合点第一期仍在集群里**，经隧道对外（topology 设计里它最终放到边缘上）。理由：先把隧道与证书跑通，搬会合点牵涉管理通道与公钥推送，单独做。
- 外部用户拿到的是 Let's Encrypt 公共证书：网页无警告，一行命令安装与代理连接都**不用导入开发 CA**。

## 二、开放范围（所有者 2026-10-09 同意）

| 公网开放（边缘 Traefik 只放这三个 Host） | 不开放（只在所有者本机可达） |
| --- | --- |
| `investment.sunmoonai.com`（网页与 `/api/`） | 三个应用的管理后台 `*-admin`、tpl、info/knowledge 用户网页 |
| `casdoor.sunmoonai.com`（登录） | harbor、aistor、pgadmin、kibana、flower、rabbitmq、redisinsight、neo4j、mongo-express |
| `relay.sunmoonai.com`（会合点 wss） | |

未列出的 Host 一律 404（边缘不设兜底路由）。frpc 端只为这三个域名注册代理，frps 侧用 `subDomainHost` 不开、按完整域名注册，双重限制。

## 三、边缘一侧（远程实现，`infrastructure/edge/`，fable 分支）

**运行方式：** 两个容器，`network_mode: host`，由一个 systemd 单元管理的 docker compose 启停；配置由 `infrastructure/edge/deploy.yaml`（Ansible，本机 `connection: local`）渲染。镜像按摘要钉住：`traefik:v3.7.13`（与集群同版）、`fatedier/frps:v0.71.0`。

**frps（`/etc/sunmoon/edge/frps.toml`）：**

| 项 | 值 |
| --- | --- |
| `bindAddr` / `bindPort` | `0.0.0.0:7000`（只给 frpc） |
| `proxyBindAddr` | `127.0.0.1`（vhost 与任何代理端口只绑本机） |
| `vhostHTTPPort` | `8080`；`vhostHTTPTimeout = 120` |
| 认证 | `auth.method = "token"`，令牌从环境变量读（systemd 环境文件 `/etc/sunmoon/edge/frp.env`，root 0600），不写进 toml、不进日志 |
| 传输 | `transport.tls.force = true` |
| 端口白名单 | `allowPorts` 为空（不开任何 tcp/udp 代理） |
| 面板 | 不开 `webServer` |
| 日志 | `log.level = info`，到 journald，不记请求路径 |

**Traefik（静态配置 `/etc/sunmoon/edge/traefik.yml`，动态配置文件提供三条路由）：**

- 入口：`web` :80（只服务 ACME HTTP-01 挑战，其余 308 跳 `https://<host>:30443`）；`websecure` :30443。
- 证书：`certificatesResolvers.le.acme.httpChallenge`，存 `/etc/sunmoon/edge/acme.json`（root 0600）；三个域名各一张。先对 Let's Encrypt **staging** 跑通再切正式，避免撞频率限制。
- 路由：`Host(investment|casdoor|relay.sunmoonai.com)` → `http://127.0.0.1:8080`，`passHostHeader: true`；中间件：按来源 IP 限速（平均 50 rps、突发 100）、写 `X-Forwarded-For/Proto/Host`。
- 长连接：`websecure.transport.respondingTimeouts.readTimeout = 0`、`idleTimeout = 3600s`（SSE 与 WebSocket）；不缓冲响应。
- 访问日志**关闭**（安装凭证在 URL 路径里）；只留错误日志。
- 不开 Traefik 面板与 API。

**主机加固：**

- `ufw`：默认拒绝入站；放行 **1022（SSH，先放这条再启用）**、80、30443、7000。
- 边缘文件全在 `/etc/sunmoon/edge/`，root 0700；与远程开发目录、`~/private` 隔离。
- 资源：本机 3G 内存、磁盘余 11G——只跑这两个容器；镜像拉完清理旧层（**不 prune 别的**）。

**验收（边缘单独）：** `make -C infrastructure edge-smoke`——临时令牌 + 临时 frpc + 替身 HTTPS 后端，13 项：三个 Host 走通、`X-Forwarded-Proto=https` 与真实来源保留、未列 Host 404、80 跳 30443、SSE 不被缓冲、WebSocket 101、错令牌被拒、vhost 与健康口只绑本机、日志无令牌；结束全部清理。**2026-10-09 已在东京 VM 上 13/13 通过。** 公网端口扫描待安全组放行后再做。

## 五、集群一侧（luna 在 luna 分支实现，Cursor 发布）

1. **集群内解析（2026-10-10 已核实，不需要固定）：** 原担心集群里的后端直连 `https://casdoor.sunmoonai.com:30443`，一加公网 A 记录就会改连东京。luna 只读核实（runtime `9af90a1` 卡 B 回执）加远程查配置后结论：**集群内没有任何组件按这三个公网名连接**——后端访问 Casdoor 一律走 `CASDOOR_BACKCHANNEL_ENDPOINT` / `*_BACKCHANNEL_ENDPOINT`（集群内 Service，公网名只作 Host 头与校验用）；会合点走 `WORKBENCH_RELAY_ADMIN_URL`、沙箱分配器 `RELAY_URL`（都是集群内 Service）；网页服务端走 `BACKEND_INTERNAL_URL`。公网名只出现在交给浏览器与本地代理的地址里。现网 Pod 里这三个名字解析为 `127.0.0.1`（来自所有者机器的 hosts，经上游转发），本来就连不上、也没人连；加公网 A 记录后所有者机器的 hosts 仍优先，不变。**所以不改 CoreDNS**；以后新增组件不得在集群内按公网名连接（要连就加 backchannel 变量）。
2. **frpc 组件** `gitops/components/ingress-platform/frpc/`：Deployment 2 副本，镜像 `fatedier/frpc:v0.71.0` 按摘要钉住、经 Harbor 中转；令牌放 SOPS Secret（来源：私有输入 `edge-frp.yaml`，首次生成 ≥48 字符随机，主备两份）；`serverAddr = 43.153.135.74`、`serverPort = 7000`、`transport.tls.enable = true`、`loginFailExit = false`。
3. 三个代理，`type = "http"`、`customDomains` 各一个域名、`loadBalancer.group` 同组（两副本互备；**每个副本必须 `user = "<Pod 名>"`**，否则同名代理第二个副本被 frps 拒绝 `proxy [x] already exists`，2026-10-10 实测），本地插件 `http2https` 指向集群 Traefik 的 websecure Service（`localAddr` 用 Service 的集群内 DNS 名与端口），`hostHeaderRewrite` 不设（保留原 Host，集群 Traefik 按 Host 路由）。
   **2026-10-09 边缘冒烟实测补充（照抄 `infrastructure/edge/smoke/frpc.toml.tmpl` 的写法）：**
   - 插件里必须加 `requestHeaders.set.x-forwarded-proto = "https"`：`http2https` 插件会把它改成 `http`，后端会误以为用户走的是 http（影响 Cookie 与跳转）。
   - `http2https` 插件连本地 HTTPS **不校验证书**（冒烟里对自签后端直接通了）。这一跳在集群内（frpc Pod → Traefik Service），第一期接受，记账；不要为此另开 http 入口。
   - `loadBalancer.group` 需要 `groupKey`：用私有输入里另一个随机值（≥32 字符，与 frp 令牌分开），同样走 SOPS。
   - `X-Forwarded-For` 到后端时形如「真实来源, 127.0.0.1, <frpc Pod IP>」：后端「可信转发网段」要包括 `127.0.0.1/32` 与集群 Pod 网段，从右往左剥掉可信跳，取剩下最右的那个。
4. 集群 Traefik `websecure` 增加 `forwardedHeaders.trustedIPs` = 集群 Pod 网段（frpc 来自这里），使后端看到真实来源 IP；投资后端的「可信转发网段」（卡 B 的配置项）同样填这一网段。
5. NetworkPolicy：frpc 只允许出站到 `43.153.135.74:7000` 与集群 Traefik；不接受入站。
6. 不改任何应用的 origin、回调地址与 IngressRoute。
