## 四、一次发布在代码里走的路

概念见 [`总纲/运行拓扑.md`](../总纲/运行拓扑.md) 第二部分；这里对到文件。

| 步 | Make 目标 | 剧本 | 读什么 | 写什么 |
| --- | --- | --- | --- | --- |
| 改钉 | 人改 | — | — | `applications/sources.yaml` |
| 构建 | `platform-build OBJECT=app-platform/<app>-app` → `application-build-{backend,web,admin}` + `application-publish-*` | `applications/build.yaml` + `artifacts/publish.yaml` | `sources.yaml`、应用仓 Git 对象、`upstream-images.lock.json`（基础镜像）、Harbor publisher | Harbor `platform/<repo>@sha256:…`；`gitops/.../image.lock.yaml`（`application-lock-*`） |
| 暂存 | `platform-stage OBJECT=…`（= `components-stage` + `topology-stage`） | `components/render.yaml`（`components_action=stage`）、`components/topology.yaml` | 组件 `config.yaml`、`stage.yaml`、`*.j2`、`prepare.yaml`、`image.lock`、私有输入 `services_config_dir/*`、SOPS 公钥 | `.build/components/` 候选 → 拷进 `gitops/components/<对象>/`；`gitops/clusters/kind/stages.yaml` |
| 计划 | `application-deployment-plan APP=` | `applications/deploy.yaml`（plan） | 组件 config、`image.lock`、钉住后端的 alembic 链 | 只打印；`expected_schema_revision` 对不上就停 |
| 提交 | 人 `git commit` | — | — | Git |
| 发布 | `flux-release` | `flux/source.yaml`（publish） | `HEAD:gitops`、Harbor publisher | Harbor `platform/deployments-kind:git-<sha>`；`.build/flux/source-candidate.yaml` |
| 晋级 | 人改并提交 | — | 候选五个字段 | `environments/kind/flux-source.yaml`；tag `release-<日期>-<序号>` |
| 部署 | `flux-source-apply` | `flux/source.yaml`（apply） | `flux-source.yaml`、集群身份回执 | 集群里 OCIRepository/Kustomization `platform`；等所有阶段 Ready |
| 检查 | `application-check APP=`、`platform-check OBJECT=` | `applications/verify.yaml`、`services/verify.yaml`、`host/lifecycle.yaml status` | 集群、Harbor、私有输入 | 只读探针（会建临时对象并清理） |

卡在任何一步停下的规矩、`gitops/` 必须干净、发布器只打包已提交对象、晋级的 revision 必须是 OCI 包对应的 Git SHA，这些约束都在上面两份剧本的 assert 里，不是文档口头约定。

## 五、对象选择：`OBJECT` 怎么变成「跑哪些」

`host/deployment.yaml` 把 `OBJECT`（环境变量，Make 总会导出）、动作、阶段图（`components/stages.py graph` 扫全部 `stage.yaml`）、应用名、五个宿主模块的开关（host、registry、entry、jenkins、cluster、flux）喂给 `components/stages.py select`，得到：选中的阶段与依赖闭包、选中的服务对象、每个应用选中的组件、选中的模块。结果写成 `.build/host/selections/<OBJECT>.json` 和 `.mk`（`PLATFORM_REGISTRY := true` 这类布尔），`platform-deploy-selected`、`platform-check-selected` 按这些布尔决定调哪些模块目标。`OBJECT` 只能是阶段图里的对象、它们的前缀分组、模块名或 `all`，否则拒绝。这套机制是整个仓的「总开关」，却放在 `host/` 里，第三节说过。

### 2. 组件约定（`infrastructure/components/stages.py` 定死的）

`stage.yaml` 顶层只许 `defaults | stages | prepare`；阶段字段只许 `name path dependsOn enabled images wait timeout healthChecks resources render volume`（默认 `path: .`、`wait: true`、`timeout: 15m`）；`enabled`、`dependsOn`、`resources` 可以是 Jinja 表达式。一个组件目录里：

| 文件 | 手写 / 生成 |
| --- | --- |
| `stage.yaml`、`config.yaml`、`prepare.yaml`、`*.j2`、`README.md`、专用 `*.py` | 手写 |
| `workload.yaml`、`kustomization.yaml`（恰好等于 `resources`）、`storage.yaml`（由 `foundations/volume.yaml.j2` 按 `volume:` 渲染）、`*.sops.yaml`（prepare 产出的密文） | **生成，但提交进 Git**（发布器只打包已提交的） |
| `image.lock.yaml` | 发布链写回的锁（`repository / digest / source_revision / deployment_id`） |

### 5. 换 Helm/Kustomize + Argo CD 时必须带走的（D 段清单）

1. **依赖图语义**：94 个阶段的 `dependsOn`、`wait`、`healthChecks`（Job 名带修订号）、`prune: false`/`Orphan`。Argo 要用 sync wave 或 app-of-apps 表达同一张图，现网对象不能被 prune。
2. **SOPS 布局**：137 份密文、`gitops/.sops.yaml` 的 `encrypted_regex: ^(data|stringData)$`、单一 age 收件人。换 ksops 时文件名族与 Secret 名不能变，否则 Job 与 Deployment 的引用全断。
3. **带摘要的 Job 名**：迁移 Job 与四种身份 Job 名字含后端镜像摘要（待办 46）和 `*_revision`。Argo 的不可变 Job 替换策略要对齐。
4. **`image.lock.yaml` 三件套**与 `deployment_id`、`source_revision`：发布链写、模板读；Helm values 要有同一来源，`bind.yaml` 的 alembic 头核对也要搬。
5. **prepare 里的宿主侧「首次创建身份」状态机**（私有输入主备、不覆盖、TLS、服务客户端凭据）：不是渲染，Argo 不会替你做，留在 Ansible 或改成集群内 Job。
6. **保留卷**（`volume:` → `storage.yaml`，节点 worker/worker2、uid 白名单）与节点目录创建。
7. **OCI 包投递与晋级**：现在集群只认 Harbor 里的 OCI 包加指针，`revision` 必须等于 Git SHA；换 Argo 钉提交号后这条审计约束要以别的方式保留。
8. 顺手清掉：`components/core/`；两套服务身份收成一套；六个应用 `config.yaml` 键集统一成一个 schema 再写 values。
