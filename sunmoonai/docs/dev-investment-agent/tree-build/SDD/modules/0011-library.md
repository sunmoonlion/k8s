# 知识库：用户的私有资料库（0011）

> 状态：设计定稿，2026-10-07。第十一节五件所有者已按远程建议定下；第一期和账 54、56 一轮做。
> 来源：所有者 2026-10-07 的几次裁定（`decisions.md`「知识库分三层」「公共数据的入口放管理后台」）和对 WorkBuddy、千问资料库做法的查证（见第十三节）。

## 一、定位

对用户的 Codex 来说，四处都是「可读的资料」，只是来路和边界不同：

| 层 | 谁的 | 放哪 | 谁能读 | 怎么进来 | 页面上叫什么 |
| --- | --- | --- | --- | --- | --- |
| 公共数据 | 我们 | 服务器 | 所有用户的 Codex、所有专家 | 我们在管理后台采集、建库、登记 | 不以库的面目出现。用户「问就有」 |
| **知识库（本模块）** | 每个用户 | 服务器上该用户的私有区 | 只有这个用户的 Codex，和他请的专家在那次委托里 | 专家交回的底稿、工作交回的东西自动归入；用户自己上传（第二期） | 侧栏「知识库」 |
| 工作区文件 | 每个用户 | 用户机器的白名单目录 | 这个用户的 Codex，经本地代理就地读 | 不上传，原则 | 「项目」「我的机器」 |
| 专家知识库（后话） | 每位专家 | 服务器上该专家的私有区 | 只有这位专家在工作时 | 我们或专家维护 | 不在用户侧 |

知识库是什么：**用户在我们这里的资料，每一份在服务端有一份只属于他的副本**。它不是工作区的镜像，不是公共库的一部分，也不是对话记录。

五条规矩（功能义务在第十节）：

1. 进知识库只有两条路：专家 / 工作交回的东西自动归入；用户自己上传。白名单文件不会自动进来。
2. 知识库里的东西不会进公共库。公共库由我们在管理后台维护，与用户无关。
3. 每一份都写明来路（哪个项目、哪次委托或哪段对话、哪个版本）和「在服务端有专属副本」。
4. 版本不可改写：同一份资料的新内容是新版本，旧版本留着，直到用户删。
5. 读取只经两条路：用户自己登录的网页，和他的沙箱用按用户签的令牌经 MCP 读。专家只在该用户的委托期间、以该用户的身份读。

## 二、里面有什么

| 种类 | 从哪来 | 第几期 | 说明 |
| --- | --- | --- | --- |
| 底稿 | 专家做完一次委托交回的整份底稿（回答、数据、证据、局限、交回物、怎么做的、我的结论） | 一 | 每次委托一份；用户填了结论算新版本 |
| 交回物 | 工作、专家过程中产出的文件：表、Markdown、HTML、CSV（现在的 `workbench_artifacts`） | 一 | 按任务归组；同名新版本接在后面 |
| 上传的文件 | 用户在知识库页上传：PDF、Word、Excel、PPT、Markdown、文本、CSV、HTML、图片 | 二 | 单文件 50 MB 以内；每人配额见第十一节 |
| 剪藏、收藏 | 网页剪藏、从对话里「收进知识库」 | 三 | |

不在里面的：工作区文件（在用户机器上）、对话记录（项目页另有列表）、公共数据。

## 三、用户看到什么

侧栏一项「知识库」。

| 页 | 内容 |
| --- | --- |
| 清单 | 一行一份：名字、种类（底稿 / 交回物 / 上传）、来路（项目 · 对话或委托）、版本数、最近更新、大小。按项目、种类筛；按名字找。顶部一句：「这里是你在我们这里的资料，每一份在服务端有一份只属于你的副本。你电脑上的文件不在这里，专家在你机器上就地读。」 |
| 一份资料 | 预览（Markdown、表格、HTML 原样渲染；PDF、Office 第二期先给下载）；版本列表，每版有时间、来路、校验值；「去底稿」「去对话」的链接；改名；下载；删除 |
| 空状态 | 「还没有资料。专家交回的底稿、工作交回的文件会自动出现在这里。」第二期加「上传」 |
| 结果边栏（账 54）里 | 专家做完、工作交回时，边栏上写一行「已归入知识库」并给链接 |

删除：底稿与交回物删的是「从知识库里拿掉」，原任务记录不动（它属于对话历史）；上传的文件是真删，默认 30 天后清除存储（第十一节待定）。

## 四、Codex 怎么用

沙箱里的 Codex 已经经 `sunmoon_workbench` 这个 MCP（记录工具）读项目里的对话和底稿。知识库加三个工具，同一条通道、同一把按用户签的令牌：

| 工具 | 做什么 | 返回 |
| --- | --- | --- |
| `list_library` | 列这个用户知识库里的资料，可按种类、项目筛，按名字找 | 名字、种类、来路、版本、大小、标识 |
| `read_library_item` | 读一份资料的某个版本；大文件分页 | 内容（文本类原文；表格给行；二进制给摘要与下载提示），加一条**引用**：`{library_item_id, version, sha256}` |
| `search_library`（三期） | 按意思找 | 命中的段落与出处 |

Codex 在回答和底稿里引用知识库资料时用上面的引用三元组，和引用公共数据的 `{dataset, data_version}` 一样可核对、可回溯。专家包在委托期间拿到的是同一把用户令牌，所以读得到，不需要别的授权；委托结束令牌作废。聊天不选项目时也能读知识库，这是它比工作区多出来的用处。

## 五、存储与隔离

| 项 | 做法 |
| --- | --- |
| 第一期 | 不新建存储。底稿与交回物已经在 investment 的数据库和对象存储里，知识库是对它们的归档清单（第六节的表），加上用户的改名、删除状态 |
| 第二期上传 | 对象存储，investment 自己的桶里前缀 `library/<用户>/<资料标识>/v<版本>/<sha256>`；版本不可改写；记录 sha256、大小、类型；传输 TLS，存放用平台的加密；每人配额，超了拒收并提示 |
| 类型白名单 | PDF、DOCX、XLSX、PPTX、MD、TXT、CSV、HTML、PNG、JPG。可执行文件、压缩包不收 |
| 读取路径 | 只经 investment-api：网页用登录态；沙箱用按用户签的 MCP 令牌。对象存储不对外暴露 |
| 隔离 | 查询一律带 `owner_actor_id`；MCP 令牌里的用户就是 owner；跨用户的地址都看不到（同 `AT-INV-15`） |
| 审计 | 专家读了哪份资料记成对话里的「读资料」事件（折叠一行），和「读文件」一样 |
| 删除 | 软删，`deleted_at`；上传的对象 30 天后由定时任务清除；导出全部（zip）第二期 |

## 六、数据

两张表，都在 investment 后端。

```text
workbench_library_items
  id, owner_actor_id, kind(dossier|deliverable|upload), title, project_id?, source_task_id?, source_session_id?,
  current_version, created_at, updated_at, deleted_at
workbench_library_versions
  item_id, version, source(artifact_id | object_key), sha256, size_bytes, mime, created_at, note?
```

第一期由工作台管理者（manager）在委托交回、任务产出交回物时写入；对已有的历史任务做一次回填。第二期上传写同两张表。为以后的专家知识库留一列 `owner_kind(user|expert)`，默认 user，不在第一期暴露。

## 七、接口

网页（登录态）：

| 接口 | 做什么 |
| --- | --- |
| `GET /workbench/library?kind=&project=&q=` | 清单 |
| `GET /workbench/library/{id}` | 一份资料与版本列表 |
| `GET /workbench/library/{id}/versions/{n}/content` | 预览或下载 |
| `PATCH /workbench/library/{id}` | 改名 |
| `DELETE /workbench/library/{id}` | 删除（软删） |
| `POST /workbench/library/uploads`（二期） | 上传，multipart，50 MB 以内，类型白名单，配额 |

MCP：第四节的三个工具，加进 `sunmoon_workbench` 的工具表，受同样的限流与审计。

## 八、和别的东西的关系

| 东西 | 关系 |
| --- | --- |
| 结果边栏（账 54） | 做完时写「已归入知识库」，点过去是这份资料 |
| 项目页的底稿列表 | 不变；底稿同时出现在项目页和知识库里，知识库是跨项目的总览 |
| 公共数据 | 没有关系。知识库里的东西不会进公共库；用户想让某家公司入库也不是从这里 |
| 专家知识库（后话） | 同两张表，`owner_kind=expert`，owner 是专家包；读取时按正在运行的专家包过滤 |
| 语义检索（三期） | 用知识服务已有的能力，每个用户一个独立的索引；只索引知识库里的东西，不索引工作区 |
| 本地索引（独立的事） | 让本地代理在用户机器上给工作区建索引，是另一件事，不在本模块 |

## 十、功能义务与验收

| 编号 | 义务 |
| --- | --- |
| `F-LIB-01` | 只有两条进路：交回自动归入、用户上传。白名单文件不进 |
| `F-LIB-02` | 知识库里的东西不进公共库 |
| `F-LIB-03` | 每份资料写明来路与版本，页面写明「服务端有专属副本」 |
| `F-LIB-04` | 版本不可改写 |
| `F-LIB-05` | 只经网页登录态与按用户签的 MCP 令牌读；跨用户看不到 |
| `F-LIB-06` | 专家读知识库记「读资料」事件 |
| `F-LIB-07` | 上传有类型白名单、单文件上限、配额；拒收要说原因 |
| `F-LIB-08` | 删除后 Codex 立刻读不到；上传的对象到期清除 |

| 编号 | 做什么 | 要看到 |
| --- | --- | --- |
| `AT-LIB-01` | 专家交回一份底稿 | 知识库清单里多一行，种类底稿，来路是那次委托 |
| `AT-LIB-02` | 工作交回一个文件，再交回同名新内容 | 一份资料两个版本，旧的还在 |
| `AT-LIB-03` | 聊天不选项目，问「我上次让专家做的 600009 结论」 | Codex 调 `list_library`、`read_library_item`，回答带引用三元组 |
| `AT-LIB-04` | 用户甲打开用户乙的资料地址；乙的沙箱令牌读甲的资料 | 都看不到 |
| `AT-LIB-05` | 删除一份资料 | 清单消失；Codex 再读报不存在；原任务记录还在 |
| `AT-LIB-06`（二期） | 上传 60 MB 的 PDF；上传 .exe | 都拒收，说明原因 |
| `AT-LIB-07`（二期） | 上传到配额 | 拒收并显示用了多少 |
| `AT-LIB-08` | 专家委托期间读了一份上传的资料 | 对话时间线里有「读资料」一行 |

## 十一、已定（所有者 2026-10-07「按你的建议」）

| 编号 | 事 | 定法 |
| --- | --- | --- |
| `L1` | 每人配额多大 | 第二期起 2 GB，会员档位以后再说 |
| `L2` | 删除后多久清除存储 | 30 天 |
| `L3` | 聊天（不选项目）里 Codex 生成的文件要不要自动归入 | 不自动，给「收进知识库」按钮（三期） |
| `L4` | 要不要像 WorkBuddy 那样让 AI 直接改库里的文档 | 不做；我们的产出走底稿与交回物 |
| `L5` | 上传的 PDF 要不要走 info 的抽取流程变成可查数据 | 值得做，但那是「私有资料变数据」另一个模块，不在本模块 |

## 十二、不做

团队空间、发布成网页、同步用户机器的文件夹、AI 在库里直接编辑文档、把知识库里的东西并进公共库。

## 十三、查证记录（2026-10-07）

WorkBuddy 官方文档：资料库在云端（办公与本地文件由腾讯网盘存，WorkBuddy 里生成的存 WorkBuddy 云端），「我的文档」只自己可见、「团队空间」给成员；本地文件是上传不是索引，容量按会员档位 5 到 50 GB；AI 可在文档里直接改，Markdown 的改动以批注等人确认；隐私声明「除此之外不会主动共享给第三方」。读本机文件夹是另一条路，还能接腾讯 ima 云知识库。千问电脑版：上传 PDF、Word、TXT 建知识库，也是云端。结论：市面做法就是「云端私有副本 + 本机就地读」两部分，与本模块一致；他们给用户的理由是沉淀 AI 产出、随手整理、换设备也在，不是「保管」。
