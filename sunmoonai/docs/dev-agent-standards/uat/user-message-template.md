# UAT 用户消息模板

复制成 turn 里的 `user-message.md`。**栏目是从 [UAT 规则](uat-rules.md) 里长出来的**：
规则要求验收给出什么样的结论与证据，问里就把判它所需的对象、判据与可用证据摆出来。
写多严见 [任务的生命周期](../lifecycle.md)「用户消息写多严」，字段的含义见同一份的「turn 的固定字段」。

```markdown
---
executor: <派给谁；不能是实现这份 SDP 的那一个>
verifies: <验收哪个 turn，写「thread 号/turn 号」，如 0004/0001>
---
# turn <四位号>：<短名>

## 验收对象
- turn：<thread 号/turn 号>
- 分支与提交：<被验的分支名与提交，写完整提交号>

## 按哪几条判
<逐条照抄被验 turn 的用户消息里那几条完成条件；它们在派工时已冻结，不在这里改、不在这里加>

## 哪些能机器判、哪些只能靠纪律
<逐条标：机器已能判（给出能跑出非平凡结果的命令）／将来可机器化（登记欠账）／只能靠纪律（标 ⚠）>

## 可用的证据
<能跑的命令、测试入口、日志与产物的位置；跑不到的环境事实要点明，免得被当成「没查」>

## 工作区
- worktree：<在被验的 worktree 之上再开一个>
- 测试写在：`test/`
- 不得修改被验的产物

## 范围
- 包含：<这次要验哪几条>
- 不包含：<不在本次验收范围内的>
- 不包含的归谁：

## 不要做的
- **不改、不添完成条件**：它们在派工时已冻结；判定为「标准本身过期」时写明理由交回，由人决定改标准还是改产出；
- **不替被验方修**：发现问题写进结论，不在被验的产物上动手；
- **不外推**：在一类上跑通的便宜验收，不能证明另一类也过关。

## 怎么判
按 `sunmoonai/docs/dev-agent-standards/uat/uat-rules.md`「判据与结论」「门的三档」「证据采信」「覆盖声明：查了、没查、不能排除」。

**交回：测试在 worktree 的 `test/` 里，这个 turn 里不放 `response.md`；交回时在 `turn.md` 记分支与提交，结论写进回执正文与那条提交。不通过就是打回——开新的 turn，理由写进它的 `user-message.md`。**
```

## 栏目对着规则的哪一条

| 栏目 | 为什么有它 |
| --- | --- |
| 验收对象（写完整提交号） | 规则「载体各能证明什么」：分支是会被快进、重置、强推的指针，只有提交是稳定的验收对象 |
| 按哪几条判 | 「判据与结论」：验收依据是被验 turn 派工时的完成条件，照抄、不改不加 |
| 哪些能机器判、哪些只能靠纪律 | 「门的三档」：三档不得混进同一张「已保证」清单；问里不分档，答会把纪律条目写成「已验证」 |
| 可用的证据 | 「证据采信」与「覆盖声明」：结论要从冻结的产物独立重算；够不着的路径要能如实写成「不能排除」 |
| 工作区 | 审核者在被审的 worktree 之上再开一个；不得修改被验的产物 |
| 范围三行 | 覆盖声明要写清查了什么、没查什么 |
| 不要做的 | 三条直接面向动手的人：不改判据、不替对方修、不外推 |
| 怎么判 | 三种结论、采信分级、覆盖声明的写法在规则里，不在这一问里 |

执行者不能是实现这份 SDP 的那一个。不适用的栏写「不适用」及理由。
