## A. 阻塞项（建议合并前解决）

### A1. 总览存在一处坏链

`overall-architecture.md` 第 8 行：

```
> 它**不**试图覆盖全部细节——细节在 [`architecture/`]()，每节末尾给出指路。
```

链接地址为空。总览自称"进入这个项目的唯一入口"，入口处坏链会直接削弱该声明。
修法：改为指向本目录 `README.md`，或删去链接只留目录名。

复核：

```bash
grep -rn ']\(\s*\)' architecture/   # 应仅命中这一处
```

### A2. 过期 `CLAUDE.md` 的处置必须有明确去向

`verify.md` §5 已证明四仓 8 份 `CLAUDE.md` 严重过期**且会被助手自动注入**——
其危害优先级高于本文档集的任何警告：不读本文档集的助手照样拿到错误上下文。
合并本套文档**不能替代**对它们的处置，两条路至少选一条，并写进合并记录：

1. **本轮处置**：把 8 份 `CLAUDE.md` 改为三行指针（"本文档已过期，以
   `k8s/sunmoonai/docs/project-guide/` 为准"）——需按子仓先、父仓后的顺序推送；
2. **登记请求**：立一条 REQ，写明八份文件的位置与过期证据（引 `verify.md` §5）。

不选任何一条，则本轮合并后"过期注入"问题原样保留。

## B. 补充建议

### B1. 缺「旧文档目录」的边界声明（建议本轮消化）

`docs/` 下与本集并存着：`architecture-v2/`（R0–R7 重构结果，2026-08）、
`recursive-architecture/`（2024-10 旧设计）、`evidence/v5`、以及约 20 份散落的
主题 md。`architecture/README.md` 声明自己是唯一入口，但**全目录没有任何一处**
说明这些旧目录与本集的关系（被取代？保留作参考？待清理？）。

后果：助手读 `docs/` 会同时撞到多份"权威文档"，入口声明形同虚设——
这正是本集在 `CLAUDE.md` 上批评过的失效方式。

建议：在 `README.md` 顶部加一段「本集之外的目录」，逐目录一句话定性；
清理动作本身可另立请求。

取证：

```bash
ls sunmoonai/docs/
grep -rl 'architecture-v2\|recursive-architecture' architecture/
# 仅命中 repos/k8s.md 与 decisions/0013，均非边界声明
```

### B2. 综合留痕：本集如何代表「各助手」

按 `multi-assistant-workflow.md` §1–§4，并行提案 → 比较 → 综合应有痕迹。
当前文档集没有记录：哪些助手出了提案、关键分歧点、取舍结论。
**缺了这份记录，本集是 opus 的综合投影，但无法被证实"代表各助手"。**

建议合并提交附一份简短综合记录：参与助手、各家关键分歧、最终取舍与理由
（不必全文搬运提案，指针即可）。这也是 R6 双向登记的直接应用。

### B3. 行号锚点是本集自己反对的「易腐值」

`verify.md` §2 与 `repos/*.md` 含大量 `sed -n '232,236p'`、`sed -n '45,60p'`
式取证。行号与镜像 digest 同质：代码一动即失效，而写作约定第 2 条恰好禁止
这类值进正文。建议逐步改为模式锚定（`sed -n '/<模式>/,/<模式>/p'` 或符号名），
`verify.md` §2 已有部分条目是模式式的，可照该样式统一。

### B4. 「已知未实现」的发现应登记，而非仅记录

以下发现目前只存在于文档，既无对应请求、也无"已决策接受"的 ADR，
按 R6 是单向悬挂：

| 发现 | 出处 |
| --- | --- |
| RAGFlow `CANCEL` 被当成功 | `repos/knowledge-app.md` §7 |
| `RunBudget` 生产未接线 | `repos/investment-app.md` |
| 共享 Outbox/Inbox 零业务调用 | 总览 §9.2 |
| 四仓均无 `beat_schedule` | 总览 §9.2 |
| `2.0.0.dev0` 与 `formal_release: true` 矛盾 | 总览 §9.1 |

建议：每条要么立 REQ，要么写一条 ADR 声明"已知并接受"。合并记录里
至少给出分类去向。

### B5. 文档保鲜门禁（轻量）

本集保真度全靠"重写时只读代码"的自律，无机械防线。建议加一条脚本：
比对各文档"取证时点"与五仓最近一次提交时间，落后即输出提示。
量级是一个几十行的 shell，可放 `k8s` 仓 utils。

### B6. 合并提交应声明验证边界

`verify.md` §6 已自陈：集群运行态、NetworkPolicy 实际生效、远程集群均未验证。
**合并入 `master` 不等于架构已验证。**建议合并提交信息明确写一句
"运行态断言未经集群验证"，避免后续读者把"已合并"误读为"已背书"。
