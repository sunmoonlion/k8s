## 二、后端

| 接口 | 作用 | 谁能调 |
| --- | --- | --- |
| `GET /api/web/v1/catalog/datasets`，可带 `q` | 数据集列表；按证券代码、名字或数据集标识找，包含就算，不分大小写 | 登录的用户 |
| `GET /api/web/v1/catalog/datasets/{数据集}` | 摘要、来源说明、表与列、口径、局限 | 登录的用户 |
| `GET /api/admin/v1/knowledge/datasets` | 登记表：每个数据集的现行版本、一共几个版本 | knowledge 管理员 |
| `GET /api/admin/v1/knowledge/datasets/{数据集}/versions` | 一个数据集的各个版本，现行的排最前 | knowledge 管理员 |

管理接口的路径比设计里多了一段 `v1`：和这个后端别的管理接口一致。

| 规矩 | 怎么守 |
| --- | --- |
| 页面列的与工具 `list_datasets` 列的是同一份（`F-KNOW-11`） | 数据集目录原来是在工具（MCP）那一面里建的，网页接口引用不到（接口层三个面互不引用）。现在挪到装配层 `app/bootstrap/datasets.py`，一个进程只有一份，工具与页面共用。工具的返回一个字没变 |
| 表与列、口径用的是工具背后的同一套查询 | `describe_schema`、`metric_definitions`；语义层开着、关着都一样能用（两种都试过） |
| 说明从哪来 | 数据集文件自带的说明表：`dataset_metadata`（来源、核对范围、局限）、`field_dictionary`（列的中文名与单位）。老的数据集没有这些表，就显示没有 |
| 不返回任何一行数据、不返回存放位置（`AT-KNOW-05`） | 网页接口的返回里只有结构。测试拿数据集里的真实数值逐个去找，一个都找不到；桶名、对象路径、校验值也找不到 |
| 存放位置只有管理端看得到 | 只在管理接口的返回里 |
| 限流与工具的分开计 | 页面接口有自己的一份计数（配置 `KNOWLEDGE_CATALOG_RATE_PER_MINUTE`，默认每人每分钟 120 次） |
| 内部错误不给页面 | 登记表查不了、文件取不到时答「暂时打不开」，细节只进日志 |
| 不新增表、不新增存储 | 没有数据库迁移。登记表多了一个「列出全部版本」的读法 |

| 顺带 | 说明 |
| --- | --- |
| 默认数据集的显示名 | 新配置 `KNOWLEDGE_DATASET_TITLE`。不配就显示它的标识 |
| 「被取代的时间」 | 用登记表那一行最后一次变动的时间。一个版本被取代后又被重新启用、再被取代，显示的是最后一次 |
| 「文件取回来没有」 | 看缓存目录里有没有这个版本的文件。文件名就是校验值，取回时核对过才会落到这个名字上，所以「在」就是「取回过并且校验过」。**没有**在每次打开页面时重算校验值（文件最大 512 MB） |
| 口径「用到的表」 | 数据集里写成 `cash_flow+income_statement` 的，拆开列 |

## 三、用户的两页

截图在 [`PRD/apps/screens/`](../../PRD/apps/screens/)，`step9-` 开头的 6 张。

| 页 | 有什么 |
| --- | --- |
| 数据目录 | 一句说明（这里列的是专家和代理查得到的数据）；搜索框（按证券代码或名字，回车或点「找」）；每个数据集一行：证券代码、名字、现行版本、数据从哪天到哪天、更新时间；默认数据集标「默认」。搜不到：写明没有这家的数据，按钮「申请入库」去 info 的申请页，搜的是六位代码就带上代码。只有默认数据集时照常列出，另加一句原因。从别的应用来的有「回到原处」 |
| 一个数据集 | 摘要（时间范围、现行版本、更新时间、标识、来源说明）；一句「这里只显示结构，不显示数据」；表（名字、几行、几列，点开看每一列的名字、中文名、类型、单位）；口径（中文名、英文名、说明、算式、用到的表、单位、时间口径、不适用的情形）；局限（数据集自己写的每一条）；最下面是数据集自带的说明表。动作：「申请更新」去 info（带着这家公司的代码）；「回到原处」 |

| 守住的规矩 | 怎么守 |
| --- | --- |
| 只显示结构，不显示数据（`F-KNOW-09`、`AT-KNOW-04`） | 接口就没有给数据；页面只画接口给的 |
| 去 info 的链接（`F-KNOW-10`、`AT-KNOW-03`） | 用统一的跨应用链接：新标签页，带 `from=knowledge`，不带身份与回跳地址。info 的地址没有配时不给一个点不了的链接，写明原因 |
| 没登录先登录（`AT-KNOW-06`） | 登录完回到原来那一页，`q`、`from`、`ref` 还在 |
| 多数据集没打开（`AT-KNOW-08`） | 只有默认数据集，页面不报错 |
| 后端答不上来 | 写「暂时打不开」，不说成「没有数据」 |

搜索是向后端要的（规则只在后端一处）。在目录里走动时 `from`、`ref` 一直带着，「回到原处」才不会丢。

登录之后默认到数据目录（原来是模板的占位页）。

## 四、所有者的一页

| 页 | 有什么 |
| --- | --- |
| 数据集登记 | 每个数据集一行：名字、代码、标识、现行版本、数据范围、登记时间与登记人、文件大小、校验值（前 12 位，悬停看完整的）、存放位置、文件取回来没有。按钮「版本历史（几个）」：点开看这个数据集的每个版本，现行的在前，被取代的写明什么时候。多数据集没打开时写明原因，不画空表 |

只读，没有任何改的动作。只给 knowledge 管理员：页面一道，后端另有一道（`AT-KNOW-07`）。

## 五、样例

| 情景 | 内容 |
| --- | --- |
| `default` 有几个数据集 | 默认数据集；上海机场（info 实采建出来的那个数据集文件，表、列、口径、说明都是真的）；贵州茅台（**为预览现编的**，它自己的说明里写着是样例） |

样例里只有结构，没有任何数值。重录的办法写在 knowledge-backend `tests/test_preview_fixtures.py` 开头。管理端的样例要真数据库。

预览里搜没录过的词，预览的前门会拿整份列表来答（这是预览的规矩，不是页面的毛病）。录了的词：`600009`、`机场`、`600519`、`000001`、`平安银行`。

## 六、代码怎么放

和 investment、info 一样：`features/<功能>/{api,model,ui}`，由同一份测试守着。网页端两个功能：`shell`、`catalog`。管理端一个：`registry`。契约都对着真后端录下来的返回逐份检查。
