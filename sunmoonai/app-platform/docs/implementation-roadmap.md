# App Platform 实施路线

## 1. 目标

本路线把长期投资管理平台拆成可独立验收的建设阶段。阶段控制实施范围，不改变已经确定的领域边界和数据所有权。

执行原则：

- 先建立主档和证据链，再增加智能处理。
- 先形成模块边界，再根据真实压力拆服务。
- 先保证可恢复和可审计，再追求复杂自动化。
- 每个阶段都交付可运行闭环，不长期维护半成品链路。

## 2. 阶段 A：架构基线

交付物：

- 总体架构及五个 App 架构文档。
- 数据所有权、集成规范和生产就绪标准。
- 核心 ADR。
- 架构评审和变更流程。

完成条件：

- 新功能可以明确领域归属和数据所有者。
- 跨 App 集成有统一规则。
- 当前实现和目标架构可以清楚区分。

状态：文档基线已建立。

## 3. 阶段 B：Info App 主档闭环

### B1 工程骨架

- 创建 `info-app` 目录。
- 建立 Backend、Frontend、Worker 和统一部署入口。
- 注册到 App Platform 总部署。
- 建立 PostgreSQL、MinIO、RabbitMQ 和 Redis 配置。

### B2 文件主档

- 实现上传会话和对象存储写入。
- 实现 RawArtifact、InformationItem 和 InformationVersion。
- 保存内容哈希、来源、时间、权限和版本。
- 建立管理端查询。

### B3 处理与 RAG

- 接入 Tools App 文档转换。
- 生成规范化内容和处理产物。
- 通过 LLM App Adapter 同步 RAGFlow。
- 完成状态跟踪、重试、对账和全量重建。

阶段验收：

- 上传文件形成唯一 Info App 主档。
- 删除 RAGFlow 后能够完整重建。
- Investment App 能稳定引用 `info_id + version_id`。

## 4. 阶段 C：Investment Research 闭环

### C1 Security Master

- 建立证券、公司、市场、币种和标识映射。
- 确定外部主数据来源和版本策略。

### C2 Research

- 建立研究项目、笔记、观点、评级和报告版本。
- 建立 Info App 证据引用。
- 建立 LLM 推理运行引用。
- 保存人工确认和审计。

阶段验收：

- 研究结论能重现使用的资讯和模型版本。
- 不复制 Info App 原文主档。
- AI 内容和人工内容可以区分。

## 5. 阶段 D：组合、估值和风险

### D1 Portfolio

- 账户、组合、持仓和流水。
- 历史时点持仓和组合对账。

### D2 Valuation

- 价格、汇率、估值批次、收益和损益。
- 规则版本、输入快照和黄金样例测试。

### D3 Risk And Decision

- 风险暴露、限额、预警和压力测试。
- 决策状态机、审批和证据链。

阶段验收：

- 任一历史业务日可以重现组合、估值和关键风险。
- 金融计算通过确定性基准测试。
- 投资决策关联研究、资讯、风险和审批。

## 6. 阶段 E：生产平台能力

可以与 B-D 阶段并行逐步建设，但生产上线前必须完成：

- 可观测平台：指标、日志、链路和告警。
- Secret 管理和密钥轮换。
- 数据备份、异地副本和恢复演练。
- Namespace、NetworkPolicy、RBAC 和 Pod Security。
- GitOps、环境晋级、回滚和发布审计。
- 镜像扫描、签名、SBOM 和依赖治理。

阶段验收使用 [生产就绪标准](./production-readiness.md)。

## 7. 服务拆分决策

默认不因模块名称创建微服务。只有满足以下一种或多种条件时才拆分：

- 独立团队需要独立发布。
- 扩缩容和资源特征显著不同。
- 故障隔离或安全隔离有明确要求。
- 发布频率冲突已经影响交付。
- 模块契约稳定且拆分收益大于分布式复杂度。

拆分必须新增 ADR，说明数据迁移、契约、故障处理和回滚方案。

## 8. 近期执行顺序

```text
1. 确认架构文档基线
2. 创建 Info App 工程与部署骨架
3. 配置 Info App PostgreSQL 和对象存储
4. 实现人工上传与版本主档
5. 接入 Tools App 文档转换
6. 封装 LLM App RAGFlow Adapter
7. 完成同步、对账和重建
8. 建立 Investment Security Master 和 Research
9. 补齐可观测、备份和安全基线
10. 进入组合、估值、风险与决策建设
```

每一步完成后更新对应 App 文档中的“当前实现”，并记录影响长期架构的新增 ADR。
