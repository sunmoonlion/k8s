## 1. 产品定位

### 1.1 定位

本产品提供 **AI 研究能力与数据**，类似金融数据终端，**不做投资咨询**：用户用自己的资料、在自己的电脑上、借助我们的数据与研究流程编排做投资研究，投资判断由用户自己作出。

这一定位有架构上的支撑：

| 事实 | 落点 |
| --- | --- |
| 用户的资料与研究成果在用户电脑上 | 本地知识库（§2）；结果端到端加密（[`invariants.md`](../dev-agent/SDD/architecture/invariants.md)「问题侧明文，资料侧加密」） |
| 执行在用户电脑上，由用户发起和主导 | 执行端（[`0003-runtime/PRD/codex.md`](../dev-agent/SDD/submodules/0003-runtime/PRD/codex.md)） |
| 模型由用户自选、开通、付费 | [`0003-runtime/PRD/models-and-keys.md`](../dev-agent/SDD/submodules/0003-runtime/PRD/models-and-keys.md) |
| 我们提供的是数据，不是观点 | 自有数据（§2） |
| 我们的编排与方法库只写方法，不写判断规则 | supervisor 与方法库（[`control-plane.md`](../dev-agent/SDD/submodules/0001-backend/SDD/architecture/orchestration-boundary.md)、[`methods.md`](../dev-agent/SDD/submodules/0001-backend/SDD/architecture/methods.md)） |
| 系统不替用户下判断 | 输出检查（[`0007-delivery`](../dev-agent/SDD/submodules/0001-backend/SDD/modules/0007-delivery.md) 与 [runtime 的本地检查](../dev-agent/SDD/submodules/0003-runtime/PRD/functions.md)） |

定位约束：

- **F-POS-01**：自有数据只包含事实与数据（结构化财务数据、产业链关系、另类数据、标签与指标），不包含评级、目标价、景气判断等观点；
- **F-POS-02**：研究流程与方法库只写研究步骤与计算方法，不写判断规则（如买卖标准、打分阈值）；用户自己的判断规则由用户编写，只对该用户可见；
- **F-POS-03**：研究产出是研究底稿：事实、数据、按用户给定假设的计算、方法应用的结果由 AI 给出；结论由用户填写，或明确标为用户的草稿；
- **F-POS-04**：对具体证券给出评级、目标价、走势预测、买卖建议或收益承诺的输出，必须由系统检查并打回或拦截，不能只靠提示词约束；拦截留痕；
- **F-POS-05**：必须留存定性依据：数据流图、「后端不保存哪些内容」清单、日志策略、方法库评审记录。

定位的法律边界存在模糊地带，以法务结论为准（附录 A 的 D17）。

### 1.2 服务对象

- 按**投资经理**的使用方式设计；能自己开通并配置模型 key 的个人投资者同样适用。不能自行配置模型 key 的用户不在服务范围内。
- 两类用户都不是开发者，都以**电脑桌面**为主要工作场所。
- 用户界面只有桌面应用：用户侧不做网页端，不做手机端。

### 1.3 范围

- 只做**下载即用**，不做私有部署；
- 平台 Windows 优先，macOS 其次；
- 后置：私有部署、企业模型网关、团队协作与共享（先按个人使用）、统一分发、Linux 与信创平台。本文涉及后置能力的条款在该能力启用时适用。

### 1.4 核心价值与价值检验

核心价值是**自有数据**与**编排**：

| 类别 | 内容 | 由谁提供 |
| --- | --- | --- |
| 领域数据与工具 | 自有数据、持续更新、封装成工具的计算、用户本地资料的接入与检索 | 知识服务与本地知识库 |
| 领域流程与验收 | 按领域流程拆步骤、按标准验收并打回重做、规定何时停下问人与哪些动作要批准、跨 Task 记住项目背景 | 后端 supervisor |
| 可靠性与可追溯 | 断点恢复、审批记录、证据与引用可追溯、多方竞争择优、全程审计 | 后端 supervisor 与持久化账 |

**价值检验**：去掉知识服务与编排，用户用原版 Codex 能否得到同样的结果？答案为「能」的功能不作为卖点投入。

**对比评测**必须作为价值证据：同一批领域任务，由原版 Codex（同一模型、同一用户配置）与本产品各做一遍，比较准确率、验收通过率、返工次数、引用完整度与耗时。任务集、金标准、指标与预算在运行前冻结；结果按 Task Profile 分别报告；编排、方法库、知识服务的改动都必须重跑回归。评测集在第一个 Task Profile 开发时一并建立，同一套数据用于推荐模型清单（[`0003-runtime/PRD/models-and-keys.md`](../dev-agent/SDD/submodules/0003-runtime/PRD/models-and-keys.md)）。

**评测集的最小形状**（做到这一步时再实现）：

| 层 | 至少要有 |
| --- | --- |
| 每道题 | 题目、数据时点、这一问要覆盖什么（目标、指标、维度、时间范围、对比）、**真值查询**（查询语句、期望列、键列与值列、容差）与其结果指纹、必须引用哪几条证据、必须给出哪几条结论 |
| 每次运行 | 按步骤分段判定，每段分机器检查与语义检查；第一个失败的步骤、端到端结论、真值指纹、事件数、模型请求数、用量是否可观测 |
| 每次发布 | 质量、安全、可靠性、成本四道门取与；**任何一道判不了（`undecidable`）也关闭发布**，不折成通过 |

关键在于**真值定在查询层，不定在文字答案层**：结论依赖的数值必须能机械比对，
「这条结论引没引对证据」要靠规则绑定证据来判，不靠人读。口径（指标怎么算、按什么时间基准）
另立一张表，随数据一起版本化——没有它，结论无法复核（I11）。

参照实现与逐项差异见仓外 `~/AI-Application-Development-Lessons/lessons/24_Eval与上线门禁——从运行事实到分段优化/`
的对照文件；那套东西的执行模型与本文不同（它在服务端跑完整条链），可借的是判据格式与分段方式，不是位置。

### 1.5 让用户能验证

**让用户能验证**：runtime 应该开源；二进制必须签名，应该可复现构建；必须公开 runtime 与 Codex 会连接的全部域名，以及 ① 与 ⑤ 的协议文档，证明不存在上传 key 与资料的途径。后端对仍能看到的内容（查询、元数据）以服务条款、隐私政策与数据处理协议约束。

## 2. 资料与知识服务

| 资料 | 存放 | 如何给 Codex |
| --- | --- | --- |
| 用户自己的资料（研报、纪要、表格、内部数据） | 用户电脑上的本地知识库 | runtime 的本地 MCP |
| 公开资料（公告等） | 由 Codex 从官方渠道取回，存入本地知识库；我们不提供这类内容 | runtime 提供取数与解析工具；联网按白名单放行 |
| 自有数据 | 我们的云：info-app 采集，knowledge-app 建库 | 知识服务的远程 MCP，按查询以上下文下发，不整批同步 |

- **本地知识库**：资料不出用户电脑；向量化可调用用户所选厂商的 embedding 接口，或在本地运行小模型；团队共享与跨设备迁移后置；
- **公开资料取数**：取数与解析工具（按公司、日期、类型下载公告，解析 PDF 表格）由我们提供并随 runtime 更新，不让 Codex 临时编写爬虫；runtime 限速，遵守站点访问规则；
- **自有数据**：来源必须合法可追溯；只装数据不装观点（F-POS-01）；
- **按上下文下发**：每次只给最相关的片段，片段数与 token 有上限；每个片段带来源、时点与数据版本，进入证据账；
- **防批量抓取**：按设备发 token，可吊销，随设备配对签发；限流并监控异常调用；只返回所需字段与片段，不返回原文全文；必要时加水印；
- 核心检索与领域计算做成 MCP 工具；需要严格步骤的领域流程封装在工具内部，用固定逻辑执行。

## 4. 风险与应对

| 风险 | 应对 |
| --- | --- |
| 被认定为提供投资分析（大模型输出易带观点） | 定位约束 F-POS-01 至 F-POS-05；法务确认 |
| 被攻破的后端借 Attempt 在用户电脑上执行命令 | 按 Profile 限定能力与自动放行（主防线）；派发签名与本地确认（[`approval.md`](../dev-agent/SDD/architecture/approval.md)） |
| runtime 与 Codex 同一用户身份，策略保护依赖沙箱 | 配置与策略放工作区外并校验完整性；Windows 默认 elevated 沙箱；沙箱实测通过才上线 |
| Windows 沙箱设置被杀毒软件或 IT 策略拦截 | 实测主流杀毒软件；代码签名与厂商报备；拦截时退回 unelevated 并收紧自动放行 |
| 与用户自己安装的 Codex 互相干扰 | 独立二进制路径与 `CODEX_HOME` |
| 个人电脑恶意软件窃取 key、篡改 runtime | key 只放系统钥匙串；配置完整性校验；建议用户为本产品单独建 key 并设用量上限 |
| 补偿回滚误伤用户自己的改动 | 独立工作区；批准后才合并 |
| 副作用逐条记账抵消本地执行的好处 | 独立工作区内按运行时 turn 批量记账 |
| 钓鱼：仿冒网页或链接骗用户输入 key | key 只在桌面应用里输入；应用只放行产品域名 |
| 类别判错，把专业任务当通用跑，绕过 workflow 与验收 | 三层判定；判不出来交用户选、不默认通用；`escalate` 兜底 |
| 客户端自报类别以取得更大能力或更多数据 | 类别不授予数据权限（F-GUARD-04）；能力按签名 Profile 限定 |
| 本地预填把资料内容带进明文字段 | 预填只输出封闭清单里的类别；F-CRYPTO-07；明文字段 schema 校验 |
| 只拖文件不写说明的任务判不出类别 | 提交界面上一行候选让用户点选；历史选择作为默认 |
| 自有数据经查询被整库拿走 | 只给片段；按设备 token、限流、监控、水印 |
| 编排逻辑被看光 | 后端按步下发；核心计算在 MCP 工具内部 |
| 用户所选模型质量不受控 | 经评测的推荐模型清单；清单外标「未验证」 |
| 强依赖 Codex，上游变化快 | 编排与知识服务不绑定 Codex；更换执行引擎只改 runtime 的适配层；钉版与锚点 |
| Task 绑定单台设备，离线即停 | 界面显示「等设备上线」；Profile 允许时改派 |
| 密钥丢失导致结果无法找回 | 恢复码与设备间迁移；事先告知 |
| 本地知识库受电脑性能限制、换电脑要迁移 | 向量化可调用户厂商接口；迁移与共享后置 |
| 开发概念让用户困惑 | 业务语言呈现（F-APPROVE-05） |
| 新发布的应用被 SmartScreen 或杀毒软件拦截，用户放弃安装 | EV 代码签名、积累信誉、厂商报备 |

## 5. 反模式

| 反模式 | 失败方式 |
| --- | --- |
| Task 与 Attempt 合并 | 一次执行失败过早终结用户请求，或被迫重开终态 |
| 先推送后落库 | 用户看见无法回放的幽灵事件 |
| 事件推送是唯一结果载体 | 断线或重启后结果丢失 |
| 直接写 `CANCELLED` | 与正在完成的执行端竞争，副作用未收敛 |
| 无 fencing 的租约 | 离线后重连的执行端用迟到结果覆盖新执行 |
| 离线时先在本地记账再同步 | 权威记录分叉 |
| 同幂等键异载荷静默复用 | 用户得到另一请求的结果 |
| 盲目重试执行中失败 | 已发生的外部动作被重复执行 |
| Attempt 直接改用户正在用的目录 | 补偿时抹掉用户自己的改动 |
| 后端替用户作出工具级批准 | 用户电脑被远程操控 |
| 在网页里解密结果 | 服务器下发的代码能读走明文与密钥 |
| 后端保存结果明文 | 内容外泄，定位失守 |
| key 经由协议或配置文件传递 | 凭据外泄 |
| 让 Codex 开工前自判类别再转回 | 路由取决于用户模型，白跑一轮且可能先动手 |
| 类别判不出来就按通用跑 | 专业任务绕过 workflow 与验收 |
| 把任务类别当数据授权 | 客户端改一个字段就取到不该取的数据 |
| 被拒绝的工具存在但被禁止 | 模型反复尝试、错误信息泄露能力面；一层失效即越权 |
| 把资料内容或文件名搬进问题侧明文字段 | 加密边界名存实亡 |
| 方法库写入买卖标准 | 系统替用户下判断 |
| 完整 workflow 一次下发到执行端 | 编排逻辑外泄 |
| 自有数据整批下发 | 数据资产被整库拿走 |

| `AT-31` | 凭据与资料不外泄 | 协议、日志、后端中不存在 key、设备私钥与本地资料内容 |
| `AT-32` | 路由与升级 | 三层判定按序生效；未经用户确认的本地预填不算数；判不出来交用户选且不默认通用；`escalate` 使 Attempt 终止并由 supervisor 重新路由，改判入账 |
| `AT-33` | 自有数据下发 | 只按查询返回片段并带来源、时点、版本；超限、异常频率与吊销的 token 被拒绝 |
| `AT-34` | 与用户自装 Codex 并存 | 两者配置与记录互不读写 |
| `AT-35` | Windows 沙箱 | elevated 与 unelevated 两种模式下均不能写出独立工作区、不能未经批准联网 |
| `AT-36` | 对比评测 | 冻结的任务集上，本产品相对原版 Codex 的指标按 Profile 报告，改动后回归 |

| `AT-38` | Profile 熔断 | 同一 Agent Profile 版本连续启动失败达阈值后被熔断，新 Attempt 不再分发到它 |

此外必须满足：

1. Task 与 Attempt 状态迁移、API schema、① 与 ⑤ 的协议、事件 schema、Profile schema 与错误码有机器可检查的版本；
2. 每个 `F-*` 与 `I*` 登记实现所有者、代码位置、自动测试与当前覆盖状态；
3. 无法自动化的条款登记人工门禁、理由与复核证据；
4. 至少一个真实 Task 在 Windows 上跑通提交、路由、工具级审批、执行、失败重试、本地检查与加密、结果持久化、断线回放与换设备取回；
5. 项目事实与目标规范分开，未实现能力不写成已有。
