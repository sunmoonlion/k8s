## 一、它的界面

| 区域 | 内容 |
| --- | --- |
| 整体 | 三栏：左边任务列表，中间对话，右边结果面板 |
| 左栏 | 任务列表，按文件夹分组，可搜索 |
| 新建任务 | 一个输入框。输入框里选文件夹（工作目录）、模型、模式、权限；`@` 引用文件，贴截图，拖文件 |
| 中间 | 执行时显示一句阶段说明，中间步骤默认收起、可展开；执行中有「停止」 |
| 右栏 | 四个标签：产物、全部文件、变更、预览 |
| 模式 | 工作模式、编程模式；计划模式：先出计划，确认后再动手 |
| 权限 | 默认权限（工作目录内自动做，高风险的弹窗问）、完全访问（不再问） |
| 专家中心 | 专家是带领域知识和提示词的角色，按领域分类，有热门榜，点「召唤」启用；多个专家可组成专家团并行 |
| 其他 | 技能市场、连接器、定时任务、记忆 |

## 二、同名不同义的两个词

| 词 | 它的意思 | 我们的意思 |
| --- | --- | --- |
| 专家 | 一个角色（人设加提示词），从市场里挑 | 一套方法：分步做、每步验收、不过就重做或问人、有预算、交回带出处的底稿、不下结论 |
| 项目 | 一个团队共用的容器：成员、共用的资料、指令、专家、技能、定时任务 | 用户机器上的一个文件夹，加上围绕它的对话与底稿；属于一个用户、一台机器 |

它另有「空间」一词，指任务读写文件的工作目录。和我们对得上的是这个，大致相当于我们的「工作区加项目」。

用过它的人带着这两个词的印象来，会以为我们的专家是「挑一个角色来聊」、项目是「团队协作」。页面上要把区别说在前面。

## 三、所有者的决定（2026-10-04）

| 事项 | 决定 |
| --- | --- |
| 我们的「项目」要不要往团队共用那个方向靠 | **不靠，定义不动**（「按你的建议，项目定义不动」）。我们的定义是所有者 2026-09-29 参照 OpenAI 那一路定的：项目是围绕一件事的一组对话，可以转入专家 |
| 项目页 | 开头加一句白话：「一个项目是你电脑上的一个文件夹，加上你围绕它聊过的、做过的、专家交回的」 |
| 团队共享 | 第一期不做 |

## 四、远程建议第 7 步借鉴的四处（所有者还没有点头）

| # | 改动 | 代价 |
| --- | --- | --- |
| 1 | 首页输入框的角上直接选项目，不另起一步 | 只动页面 |
| 2 | 聊天与工作里，过程默认收成一行阶段说明，点开才看细节 | 只动页面 |
| 3 | 工作页右边加「改动」栏：这段对话改了哪些文件、改了什么 | 只动页面；事件里已有改动的内容 |
| 4 | 专家卡片上把「几步、每步验收、不下结论」放到最显眼处 | 只动页面；与已定的样稿方向一致 |

不跟的：完全访问的开关（投研不该有一键放开）、技能市场、连接器、记忆、「全部文件」（文件在用户机器上，工作台不读）。
