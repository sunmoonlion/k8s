# 0001-ledger：账房

**承担**：状态与账的**唯一权威写入面**。合同的原话是「**状态与账只有一份，在后端自己的库里**」——这一块就是那一份。

它是**出口不是入口**：客户端的 message 由 `0002-router` 接住并变成 Task，这一块见不到 message。
其余六块只「决定做什么」，决定完了以「请求做一次转换」的形式递给它落——**只有它能动库**。

- Task 与 Attempt 两层状态机，**所有入口共用同一个转换函数**，以状态版本比较交换；
- 事件表，只追加（`I4`）；
- **四本账**：幂等、预算、副作用、证据；
- **outbox 这张表**：派发意图与状态改**在同一个事务里**落，否则会出现「状态说已派发、实际没发」
  或「发了两次」。**投递器不在这里**——它另跑，归 [`0004-bridge`](0004-bridge.md)；
- 重启恢复：后端不驻留内存状态，扫非终态对象即可恢复。

**不承担**：

- **不决定做什么**——路由归 `0002-router`，下一步是什么归 `0003-orchestrator`；
- **不投递**：outbox 的表在这里，读它、送出去的那个 worker 在 `0004-bridge`；
- 不与外界通信。它不朝任何一侧，其余六块都经它改状态与写账。

**注意不要和「产品内核」混**：那个词在本项目里指 Task、Attempt、Interaction、Artifact、Event、
Side Effect、Delivery 这套**对象模型与状态机语义**，是跨三个模块的抽象契约（见 [`objects.md`](../../../../architecture/objects.md)）。
这一块是后端里**实现**那套语义的地方，不是那套语义本身。

**为什么单列**：四本账与状态机是其余六块的公共依赖。不单列，「同一事实只有一个权威写入面」
（`P1`）就只能靠纪律守——最典型的是**预算**：派发时扣、验收时结算，分在两块就是两处写同一本账。
提出来之后，终态、结果、预算结算的原子提交（`F-ACCEPT-05`）由这一块一处保证。

**为什么不叫 state**：`state` 在本项目里满地都是——Task 状态、Attempt 状态、`state_version`、状态机，
拿它当模块名指不准这一块，而且容易被读成「把 message 转成状态的入口」，那是 `0002-router`。
账房是个**角色**：唯一有权记账的人，别人只能来报账。四本账是明账、事件表是流水、
状态是账的投影（`task-contract.md`：「`state` 是事件流的受约束投影」）、outbox 是待发的记账、
唯一转换函数是记账规则——一个词全罩住，且不会被误当成受理窗口。

**边界要点**：任何状态改动都是「某块请求这一块做一次转换」，**不是自己写表**。
引入图执行框架会多出一份 checkpoint 状态，与这里的状态机成为两个真源（`I13`）——所以不引入。
