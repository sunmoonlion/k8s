# Architecture v2 R7.1 旧运行面退役收口

状态：`DONE`

日期：2026-08-13

前置条件：R7 `2.0.0` 正式发布已完成，三 App 正式工作负载及真实跨 App 竖线持续通过。

## 1. 决策

R7 发布时为了保留短期原生回滚能力，旧 Info、Knowledge、Research V1 工作负载以零副本
方式留在 KIND。观察窗现已明确关闭，继续保留它们会造成四类问题：平台目录出现已经退役的
`research-app`，统一 Backend 与旧双 Backend 同时存在，旧 Secret/PVC 被误认为正式依赖，
平台总入口仍可能错误发现旧 App。

R7.1 因此完成一次严格白名单退役：

1. 删除 K8s Git 真相源中的旧 V1 部署树，保留 Git 历史与 R5/R7 证据；
2. 将正式 Info/Knowledge 仍引用的旧命名 Secret/ConfigMap 复制为统一 Backend 名称并重新部署；
3. 验证 15 个正式 Deployment 全部 Ready、声明式 bundle 零漂移后，删除旧 Deployment、
   Service、ConfigMap、Secret、ServiceAccount 和 PVC；
4. 保留三个业务数据库、正式身份、正式 TLS、Harbor 拉取 Secret、Casdoor 和 RAGFlow Provider；
5. `research` 只允许出现在历史证据、迁移说明和投资研究领域语义中，不再允许作为活动 App
   或 Kubernetes 资源前缀。
6. 浏览器门禁使用正式 `architecture-v2-browser-operator` 身份，不再依赖任何 `p0-*` Secret。

## 2. 不可变发布边界

R7.1 关闭时仍以 R7 发布指针验收。随后在平台 `2.0.0` 最终冻结前，经明确批准执行一次
可审计的 Knowledge 协同版本重发；重发完成后三个 App 的 `2.0.0` 永久不可变。旧运行代码可从
Git 历史和冻结记录审计，但不在活动树中保留第二套部署入口。

验收期间发现 Knowledge 源码与 R7 镜像之间仍存在两处小版本差异：服务身份默认值仍带旧
Research 语义，RAGFlow 明确解析失败会被归入宽泛的 `external_api_error`。二者已作为
Knowledge 后端过渡镜像 digest 为
`sha256:1abc6081ae02900744b9f86aeaeb4eeb2a49663fd0d897ee10ad5e7cfe384b57`。最终正式
`2.0.0` digest 为
`sha256:38ef7c29a43e4a47a339ba06c6dd77bd0a31277035d1df31b0fc2ca69cd862c0`，release id 为
`v20-knowledge-formal-001`；旧、新 Git 与镜像指针见 `R7.2-knowledge-2.0.0-refreeze.md`。

## 3. 唯一执行入口

```bash
cd /home/zymun/k8s
bash sunmoonai/docs/architecture-v2/scripts/run_r7_1_retirement_gate.sh
```

总入口依次执行正式浏览器身份收敛、幂等退役、三 App 零漂移、三套严格 TLS/真实 Casdoor
浏览器门禁、真实跨 App 竖线和最终聚合验证。跨 App 竖线对外部 embedding provider 的瞬态故障
最多重试一次，每次失败均保留独立证据；持续失败仍然关闭门禁。

底层脚本也可单独用于诊断：

```bash
python3 sunmoonai/docs/architecture-v2/scripts/retire_r7_legacy_kind.py \
  --kubeconfig "$HOME/.kube/kind-config" \
  --namespace app-platform-dev

python3 sunmoonai/docs/architecture-v2/scripts/verify_r7_1_retirement_kind.py \
  --kubeconfig "$HOME/.kube/kind-config" \
  --namespace app-platform-dev \
  --output sunmoonai/docs/architecture-v2/evidence/R7.1-retirement/result.json
```

两个脚本都禁止输出 Secret 内容。退役脚本只操作内置精确白名单，不接受任意资源名参数。

## 4. 完成条件

- `sunmoonai/app-platform` 只有 `info-app`、`knowledge-app`、`investment-app` 三个当前业务 App；
- 平台总入口只发现并部署上述三个 App，检测到活动 `research-app` 时失败关闭；
- 15 个正式 Deployment Ready，三份正式 bundle `drift=false`；
- 所有白名单旧资源不存在，KIND 中不再存在以 `research` 开头的活动资源；
- Casdoor、RAGFlow 及其 PVC 未被改变；
- 新统一 Backend 依赖资源存在且正式 Pod 不再引用旧命名资源；
- 源码、文档、证据和 GitHub/Gitee `architecture-v2` 完全一致。

## 5. 验收结果

2026-08-13 实际验收结果：

- KIND 中旧资源白名单剩余为零，`research` 前缀活动资源为零；
- Casdoor、RAGFlow 及其 PVC 均保留，业务数据库未删除；
- `sunmoonai/app-platform/research-app` 与 Info/Knowledge V1 源树已从活动目录移除。

机器证据位于 `evidence/R7.1-retirement/`。本阶段至此结束；下一阶段开始前暂停，先重新设计
