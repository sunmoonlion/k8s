# SDP：软件开发计划（Software Development Plan）

SDP 阶段把定稿的设计做出来。**本规则只讲一件事：一个执行者在自己的 worktree 里动手，怎么不踩坏别人、怎么留下能验收的证据。**

对每一段都成立的八条纪律见 [任务的生命周期](../lifecycle.md)「交给 agent 的活，八条都成立」。
实施记录写在 worktree 里，随代码一起提交。多个执行者各交一份候选时，按
[多方竞争协议](../detailed-rules/protocol/competition-rules.md) 比较选定，档位也在那里定。

## 这一段的用户消息

**这一段的问没有模板**，但比讨论段要说清的多——执行者是另一个进程，**它只知道用户消息里写了的东西**。
除了要什么与范围，这几样不写就没法开工，也过不了下面的两道门禁：

- **完成条件**：做到哪算完。不写，八条纪律里的第五条「无法满足完成条件时明确失败」就无从执行；
- **工作区**：在哪里建 worktree、分支名、从哪个提交起（基线）、可写的范围、不得触碰什么；
- **工作单元**：拆成哪几个，每个的目标、实施、完成条件、回滚；
- **预算与上限**：步骤数、时长、并发、费用——没写执行者不会知道；
- **需要人批准的动作**：推送、合并、发布、迁移、删除远端资产等逐项列出，没有写「无」。

这一段不交 `response.md`。写多严见 [任务的生命周期](../lifecycle.md)「用户消息写多严」。

## 工作单元

SDP 把工作拆成单元，每个单元都要说清下表的内容；最严格时逐栏写成表，平时用几句话说清即可。
**目标、实施、验收、回滚里缺了会影响结果的一项，就不算可开工的单元**。单元耗尽预算不得静默借用；
连续一轮没有关闭阻断问题或新增可验证价值，就停下来问，不接着往下做。

| 栏 | 写什么 |
| --- | --- |
| 类型与优先级 | 如 `ARCH` / `FEAT` / `FIX` / `OPS` 加 `P0`–`P2` |
| 范围 | 涉及哪些仓或模块——跨仓任务必须列全，否则漏交 |
| 前置 | 依赖哪些任务或哪条未决项定了才能开工 |
| 目标 | 一句话说清做完之后什么变了 |
| 实施 | 具体动什么。**不写「完善 X」这种没有终点的表述** |
| 测试 | 适用的测试层次（由各任务定义），**不能只写「补测试」** |
| 验收 | 可判定的条件，做完能一条条对着勾 |
| 回滚 | 出问题怎么退回去 |
| 状态 | `NOT_STARTED` / `IN_PROGRESS` / `BLOCKED` / `ACCEPTED`，加日期与证据 |

## 工作区与分支

能由执行环境保证的由环境保证；**要执行者自己遵守的，必须写进用户消息**——模型只知道用户消息里写了的东西。
各任务写明自己的路径、分支命名与工具，并链接回来。

- **一个独占 worktree、一条命名分支**；分支名与 `turn.md` 的 `worktree` 字段一致。多家并行时各建各的，见 [多方竞争协议](../detailed-rules/protocol/competition-rules.md)「候选、整合与发布」。
- 复用 worktree 前同时确认：归属本任务、没有未提交改动、HEAD 等于基线；任一不满足就新建，**不暂存、不重置别人的修改**。
- worktree 只隔离写入，不阻止读取。隔离强度如实登记为「强制」或「约定」，目录不同不等于安全隔离；
  只靠约定隔离时，涉及敏感数据的访问必须经网关，不给裸凭据。
- 同一分支不能被两个 worktree 同时检出；删除 worktree 不等于删除证据，需要保留的提交必须仍然可达。
- 开工前确认 Git 真的能提交；身份判别失败立即报错，**不根据产品或界面猜「我是谁」**——目录名是归属线索，不是经鉴别的身份。
  能写文件但不能提交时，保留在私有 worktree，报告摘要、基线与原因，由有授权者代提交，并区分内容作者与提交者。
- 多仓任务逐仓固定提交；父仓不留指向未推送子仓提交的引用。

## 两道门禁

- **开工门禁**（首次执行前）：用户消息已持久化；worktree 唯一归属本任务；来源与摘要可取得；初始状态符合预期；
  凭据与无关材料未进入版本库；清单与实际文件一致；工具、权限、预算不超授权；归属与可写根明确。
  失败时**不把半成品 worktree 交给执行者「尽量执行」**。
- 清单证明实际给了什么；材料在 worktree 里可见，不自动构成使用授权；上一任务的 worktree 不复用给下一任务。
- **写入前门禁**（每次落笔前，一票否决）：当前目录是本 worktree；当前分支是独占分支；目标路径解析软链和 `..` 后仍在可写根内；
  目标路径上没有他人产物；本次不是宽泛写入（批量生成、重定向、脚本扫写、先删后建）。**宽泛写入和「归属不明仍继续写」是覆盖事故的两个主因。**
- 每次开始执行做冷启动核对：用户消息里说清了什么、没说清什么（范围、验收、批准点、预算与停止条件）；目录、分支、HEAD 与工作树状态；
  清单与实际文件；生效的指令；依赖与权限是否仍有效；哪些判断是事实、推断、假设、缺失或未验证。没说清或不匹配、又会改变结果时，停下并发起询问。

## 并发与事故

- **以提交认主**，不以磁盘最后一版、时间戳最新或最后推上去为准；**「后到者赢」在任何场景都不成立**。
- 常见场景的处置原则：同名文档各在自己分支改；只能共享目录时用归属命名空间；
  多仓先让子仓对象可达再更新父仓引用；重试开新的 turn、旧现场冻结；冻结后修订用新提交并记取代关系；
  **人的工作区已有未提交改动视为人所有，不暂存、不重置、不覆盖**；执行中发现共享路径被改，立即停写转事故规程；
  并行测试各写独立输出；共享缓存按输入摘要寻址，疑似覆盖一律丢弃重建；敏感产出按泄露处理，不能靠删文件了事；
  外部写入只有唯一的副作用负责者并带幂等键；远端各推各的引用，**不强推回滚**；批准后又新增提交的，原批准作废、重新审核；
  失败或取消先冻结现场再回收；崩溃后从检查点在新 worktree 恢复，不接管半写目录；
  已交回的提交需要修改时用新提交，不改写。
- **事故规程**：先走四步——保全现场、恢复归属、由**非当事方**判定关系、留痕；任一条件不成立（来源不明、涉及发布面或远端、
  已有外部副作用、同一路径反复被改）立即升级为八步——停写、保全、分流、溯源（修改时间只作线索）、恢复、裁决（不由最后写入者自动获胜）、
  回归、记录。来源无法确认的文件不进最终结果；恢复过程不得破坏他人的未提交内容。

## 跨运行时 thread 续接

执行段常常跨好几个运行时 thread，交接靠的是落盘的东西，不是记忆。

- 判据只有一句：**把今天的记忆抹掉，另一个人只读持久载体能否接着做？不能，就是没落盘。**
- 当前推进什么、卡在哪、下一步，写进单写者的交接面；不能倒退的输入必须写下来。交接投影不是第二真源；检查点是恢复输入，**不保存凭据**。
- 检查点至少保存：任务、turn、工作单元、负责者、worktree；当前提交与基线；已完成与剩余范围；决定与证据引用；命令、测试与原始输出引用；
  预算消耗与剩余；副作用与幂等引用；阻塞、下一步、需要重新核实的事实。
- 恢复前重新确认任务未终态、授权仍有效、输入与依赖未漂移，并先查预算与副作用账。

## 交付与保留

- 交回物与验收都绑定**不可变提交**；冻结后替换必须产生新提交并登记。主线采纳后，在途结果标为过期，
  不得覆盖主线、执行副作用或推翻已交付结果。
- **取消**：先持久化意图，再停止调度、终止执行、盘点副作用、固定需保留的提交，最后回收 worktree。
  **取消与完成只能一个终态胜出**；取消必须显式停止执行者，不能只靠标状态。
- 机械检查先跑，验收方再判机器判不了的要求；验收失败在预算允许时开新的 turn，**不改窄标准换取通过**。
  不可逆动作经人确认后才写共享路径；结果、验收、预算结算和终态原子提交，交付通知在之后，断线可回放重取。
- 清理只删本任务的私有产物；删除旧的权威文档前，先完成逐节迁移、引用清零、门禁、实跑验证与人的确认——「历史可恢复」不等于新读者找得到。
  **清理失败单独告警与重试，不能把已成功的任务改成失败**；交付通知失败同样处理。
- 保留按状态区分：已采纳的留最终提交、来源映射、验收与证据；被拒绝的留提交、理由与必要证据；过期或被取代的留血缘与摘要；
  失败的留最小复盘证据、副作用状态与检查点；取消的留依据、已产生副作用与需补偿项；敏感临时物尽快安全销毁。
  **回收是显式阶段，不是执行者退出的副作用**；删除前逐项验证发布结果可重取、提交可达、摘要可校验、副作用已收敛、没有活跃引用。
- **「已派工」「全部返回」都不等于完成**；失败、超时或缺席也要进入记录，不能被成功路线覆盖。
  逾期用冻结的、可观测的判据，数据不足时记「不可判」，不自行宣布弃权；未经人确认不发布。
- 完成的任务留去敏后的证据：结果、测试输出、关键请求与响应、迁移版本、镜像摘要；**不得提交令牌、Cookie、密码或密钥**。
- 发现重复且可能漂移的定义时，**删副本改引用**，禁止两处同步维护。

## 反模式

每行左边是做法，右边是它怎样失败——没有失败方式的条目不该进表。

| 反模式 | 失败方式 |
| --- | --- |
| 只保存整理稿，不保存原话 | 原始意图不可追溯 |
| 用户消息未持久化就建仓或派工 | 无主 worktree，不可恢复执行 |
| 把所有资料塞进 worktree | 越权、泄密、上下文污染 |
| 执行者猜仓库、分支或目录 | 修改落错可写面 |
| 运行时 thread 隔离当作文件隔离 | 多个执行者仍写同一物理文件，最后保存者覆盖前者 |
| 用 `-new`、时间戳、执行者名当隔离 | 文件名不是工作区，共享路径上照样后写覆盖先写，还制造虚假安全感 |
| 把人的主检出当原件投放点 | 覆盖人的未提交改动与他人草稿，被覆盖方无痕消失 |
| 交回报路径不报提交 | 路径会漂移、会被覆盖，验收对象丢失 |
| 把运行时的上下文或人脑当状态账、只靠自律执行纪律 | 接手者无法恢复现场；换人或换一个运行时 thread 后纪律蒸发 |
| 删除分支或 worktree 前不建立持久引用 | 提交与证据变成不可达 |
| 「已派工」或「全部返回」当作完成 | 内部动作冒充结果 |
| 静默扩大范围、伪造完整结果掩盖缺口 | 越权副作用无人批准；验收被污染 |
| 人当协调者就跳过隔离与角色分离 | 协调者身份不豁免纪律 |

多家并行时另有一张竞争专用的反模式表，见 [多方竞争协议](../detailed-rules/protocol/competition-rules.md)「候选、整合与发布」。
