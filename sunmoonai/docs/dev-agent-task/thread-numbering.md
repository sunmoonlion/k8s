# thread 与 turn 的编号

> 依据的通用规范：[任务的生命周期「turn：一问一答」](../dev-agent-standards/lifecycle.md)

本任务树下的每个任务目录，`thread/` 的编号都按这里写的来。

## 要分开表达的三件事

编号要同时表达三件事，它们互不相干，所以各用各的写法：

| 事情 | 用什么表达 |
| --- | --- |
| **先后**：这是第几次派工 | turn 号 `01`、`02`… |
| **并行**：同一问同时发给几家 | turn 目录下的尝试 `a`、`b`、`c`… |
| **会话**：哪些 turn 共用一个上下文 | 任务书里的 `thread` 字段 |

三件事挤进一个编号，就会出现「一问变成几份任务书」和「看不出返工是接着问还是重问」两种含糊。

## 目录形状

一次普通派工，turn 目录直接放任务书、回执与交回物；同一问并行发给几家时，任务书仍只有一份，
放在 turn 目录下，各家各占一个尝试子目录：

```text
<任务目录>/thread/
├── 01/                  一次普通派工
│   ├── user-message.md  任务书
│   ├── turn.md          回执
│   └── <交回物>
├── 02/
└── 03/                  同一问并行发给三家
    ├── user-message.md  这一问只有一份
    ├── a/               turn.md 与交回物
    ├── b/
    └── c/
```

- 单 turn 目录下不得有尝试子目录；并行 turn 目录下不得直接放 `turn.md` 或交回物。
- 引用时写 `turn 03` 指整次派工，写 `turn 03b` 指其中第 b 次尝试。定稿设计写明以哪一个为底。
- 验收 turn 的 `verifies` 填被验的 turn 或尝试，如 `03` 或 `03b`。

## 编号怎么给

- turn 号两位数字，按**派出顺序**递增，从 `01` 起。它只表示先后，不表示时间。
- **不跳号、不复用**：中断、失败、被替换的 turn 照样占住自己的号，目录与回执都留着。
- 并行尝试用小写字母，从 `a` 起连续；尝试数在派出时定，之后不再追加。
- 返工、改判、验收都是新的 turn，按同一个序列往下编，不另起一套编号。

## 会话写在字段里

`user-message.md` 的 YAML 头加一项 `thread`：本任务目录内的本地会话号，两位数字，默认 `01`。

| 怎么派的 | 编号怎么走 |
| --- | --- |
| 接着原来的上下文追问或返工 | 新 turn，`thread` 不变 |
| 换一个干净的上下文重问 | 新 turn，`thread` 加一 |
| 同一问并行发给几家 | 新 turn，各家各自的会话记在各自的 `turn.md` 里 |

与执行环境的对应：同一个 `thread` 号下各 turn 的 `provider_thread_id` 必须相同，不同 `thread` 号必须不同；
并行的 `a`、`b`、`c` 对应执行环境同一次派工下的第 1、2、3 次尝试。本地号只管人读和排序，回溯原始记录一律按
`provider_thread_id`、`provider_turn_id`、`provider_record` 去查。

## executor 写在哪

并行时一问有几个执行者，所以 `executor` 写在**每个尝试的 `turn.md`** 里；单 turn 写在 `user-message.md` 里。
两处只填一处，不重复写。

## 门禁查这几条

编号规则要能被机器判，[`../tools/doc-gate.py`](../tools/doc-gate.py) 查：

| 查什么 | 判据 |
| --- | --- |
| 目录形状 | 单 turn 与并行 turn 两种形态之一，不得混 |
| 编号连续 | turn 号从 `01` 起不跳号、不复用；尝试字母从 `a` 起连续 |
| 会话一致 | 同一 `thread` 号下 `provider_thread_id` 相同，不同号不同 |
| 验收指向 | `verifies` 指到存在的 turn 或尝试 |
