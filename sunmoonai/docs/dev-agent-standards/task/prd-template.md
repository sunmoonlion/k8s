# PRD 模板（任务书）

任务书就是交给 agent 的那一问，由人写。复制下面的模板作为任务目录里的 `task.md`，
尖括号处按说明填写；不适用的栏写「不适用」及理由——空着与「忘了」无法区分。

```markdown
# <任务编号>：<短名>

- 父任务：<父任务目录；根任务写「无」>
- 由什么产生：<父任务 SDD 的哪一版（提交号）、哪一节；根任务写「人提出」>
- 谁写的：<人；子任务写「来自父任务 SDD 第 n 版，经人批准」>
- 交付物清单：<SDD / SDP / UAT 中的哪几项>；每项的形态：<只交文本 / 会改文件，可改的范围是……>
- 需要人批准的动作：<列出；没有写「无」>
- 返工上限：2

## 要什么
<做完之后什么变了；为什么要做>

## 范围
- 包含：
- 不包含：
- 不包含的归谁：

## 验收标准
1. <可判定的条件，做完能一条条对着勾>

## 约束
<必须遵守的规则、不能动的东西>
```

## 填写规则

- **根任务由人写**；子任务的任务书来自父任务 SDD 拆出的那一节，随那份 SDD 一起经人批准后生效，人在批准前可以修改。
- **写清边界**：含什么、不含什么、不含的归谁——否则执行者会自行扩大范围，或漏掉本该做的。
- **给可判定的验收标准，不给倾向性结论**——否则产出向写任务书的人的结论收敛，等于白问。
- 验收标准在派工前定下；**出题的人与答题的 agent 分开**。agent 不改任务书，发现任务书有问题时停下来问。
- 派工之后再改任务书就是新版本：按 [总则「改判」](../README.md) 写清触发、原判断错在哪、新判断；已交回的交付物按新版本重新验收。
- 人这一侧的其余义务见 [人的批准点](../approvals.md)「人这一侧的义务」；任务的目录、状态与返工见 [任务的生命周期](README.md)。
