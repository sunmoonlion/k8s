# 部署整体架构

当前部署以“源码仓构建不可变镜像，k8s 仓保存已门禁 release bundle”为边界。旧的逐组件
generate.conf/envsubst、可变 tag、双 Backend 与独立 worker 源码工程不再是活动方式。

## 业务 App

每个领域 App 固定为一个统一 FastAPI Backend 和两个 Next.js 前端。Backend 同一镜像运行
API、Worker、Scheduler、Migration 四种角色；角色使用不同命令、ServiceAccount、数据库和
broker principal、资源与扩缩容策略。

```text
app-platform/<app>-app/
├── deploy-<app>-app-all/       # App 总入口、正式 .conf 与环境 profiles
├── deployment/                 # 唯一 release bundle 与组件部署入口
├── <app>-backend/              # Provider/领域补充部署声明（如有）
├── <app>-admin-frontend/
└── <app>-web-frontend/
```

App 总入口和单组件入口读取同一 bundle；单组件部署不会复制第二份 YAML。镜像只能使用
repository@sha256:...。

## 身份与平台 Provider

`auth-app` 当前只部署 Casdoor。Casdoor 颁发身份，领域 Backend 自己管理 Admin/Web session、
scope 和资源授权。RAGFlow、对象存储、文档转换等 Provider 维护独立 release 与数据生命周期，
业务 App 通过受控契约访问。

## 配置分层

- App .conf：release id、镜像 digest、Origin、副本数、bundle/部署入口；
- profile：kubeconfig、超时和环境是否已门禁；
- bundle：ConfigMap、资源、探针、HPA/PDB、NetworkPolicy、Ingress 与依赖声明；
- 外部 Secret：数据库、broker、OIDC、S3 和 Provider 凭据；
- Provider 配置：Provider 自身 Helm values、存储与备份策略。

详细转换流程见各源码父仓的 `dev-to-prod-deploy/`。
