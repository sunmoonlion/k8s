# knowlab：用户的想法与数据做成自己的分身 knowbot（0026，骨架）

> 状态：**骨架，未实施**。所有者 2026-10-16 定：名字 **knowlab**（「就用knowlab」）；用户提供 idea（最好是 skill）与数据，我们只提供工程化与测试，交付物是 bot，bot 只给用户自己用、只在我们平台上测试和运行、不得出售（「逻辑来自用户idea，数据来自用户上传的数据，我们仅仅是提供工程化和测试服务」「限定bot只能在我们平台测试，不得出售」）；**之后只开发 knowlab，我们自己也当一个普通用户**（「我们之后只开发knowkit，但是，我们把自己假设为一个普通的用户」——knowkit 是口误，名字已定 knowlab）；现在的工作台作为测试平台（「现在的工作台会作为测试平台」）。knowmart 改为持牌后的下一步（[0018](0018-advisor-market.md)）。

## 一之二、knowlab、knowmart、工作台怎么分

| | knowlab-app（创建） | knowmart-app（存放与请，现为私有模式） | knowbench 工作台（使用） |
| --- | --- | --- | --- |
| 数据 | 用户的 idea/skill 原文、上传的数据集、规则来源记录、工程化过程、测试记录与报告 | 分身登记（所有者、名字、说明）、各版本的可执行清单、版本与它能读的该用户数据之间的绑定 | 对话、项目、底稿、运行记录 |
| 动作 | 受理、工程化、测试；验收后把版本交付给 knowmart | 按所有者列出、给工作台「请」：返回选定版本的清单与运行时可读数据的授权 | 用户请自己的分身，在对话里按它跑 |
| 账号 | 同一个 sunmoonai 账号登录，第一次登录各自建本地用户（用户不用注册两次） | 同左 | 同左 |

各自一个逻辑库、一条迁移链、自己的对象存储（`C-D2`、`C-D4`）；之间走版本化同步接口与事件（`C-C1`），只存对方的稳定标识与版本（`C-D14`）。用户上传的原始数据归 knowlab，knowmart 的版本只引用它；分身运行时读的数据按用户授权经 knowmart 的「请」接口给那一次运行，不经 knowbase（`C-L2`）。工作台里「请」沿用 [0018](0018-advisor-market.md) 的「跳到 knowmart → 选定 → 跳回」，私有模式下列表里只有这个用户自己的分身（`C-L4`）。

## 二、一个 bot 怎么做出来

```text
用户：idea / skill（方法）＋ 上传的数据集（含测试用的标准答案）
  │
  ├─ 1 受理：方法要说得清——输入、步骤、每步的判断规则、输出长什么样、怎样算对
  ├─ 2 工程化：把方法变成能跑的 bot（步骤、工具、每步验收）；凡是涉及投资判断的空缺回头问用户，不替他定
  ├─ 3 测试：工程测试（能不能读、会不会出错、边界、回归）可以用我们的数据，结果只给我们；
  │         验收测试只用用户的数据、按用户定的验收标准（算得对、照方法走、不编数、能复现），结果给用户
  ├─ 4 交付：用户验收后，版本交付给 knowmart（私有，只有他看得见）
  └─ 5 使用：用户在工作台「请」自己的分身，每次给新的输入自己跑；要改方法就回到 1 提新版本
```

每条规则谁写的（用户原文、用户确认过的工程化改写）留记录，做成 bot 的版本清单的一部分。

## 三、硬边界（每一条都要有技术手段，不只写在协议里）

| 边界 | 怎么守 |
| --- | --- |
| 投资逻辑只来自用户 | 工程化只翻译、不发明：方法缺的投资判断（选股条件、阈值、结论口径）一律问用户；平台不提供选股、评级、目标价、买卖时点之类的模板 |
| 运行数据只来自用户 | 用户的 bot 运行时只读他自己上传的数据；不接我们的数据服务（knowbase、knowfeed）；我们的数据只用于工程测试 |
| 测试只测运行正确 | 两种测试分开（见本节末表）；交给用户的报告叫「运行正确性报告」，只有验收测试的结果和工程测试的通过与否，不出投资效果、胜率、收益之类的结论，不拿测试结果宣传 |
| bot 只归用户自己 | bot 绑定创建它的账号；没有导出 bot 包、分享、转让、发布、按次收费的入口；不能以别人的名义运行，不能嵌给第三方。用户导出**自己的分析结果**自用不受限 |
| 只在我们平台运行 | bot 只在工作台（沙箱或用户自己接入的电脑）里跑 |
| 收费按工具 | 按工程化、测试、算力、存储收费；不按信号、建议、效果收费，不做业绩提成 |
| 口径 | 产品与宣传只说「把你的研究方法做成你自己的工具」；不出现「顾问」「推荐」「荐股」「投资专家」等字眼 |

两种测试（2026-10-16 所有者定：「测试时我们可以用自己的数据」，限定用途后同意）：

| 测试 | 用谁的数据 | 结果给谁 |
| --- | --- | --- |
| 工程测试：格式、步骤会不会出错、边界、改版回归 | 可以用我们的数据 | 只给我们；用户只看到通过与否和出错处，不含个股分析结果 |
| 验收测试：是不是按他的方法正确跑他的数据 | 只用用户的数据 | 给用户，作验收依据 |
| 调投资判断（阈值、条件、口径） | 不拿我们的数据调 | 涉及就问用户（`C-L1`） |

## 五、合规分析（Opus 2026-10-16，不是法律意见）

**结论**：结构是对的；下面几条做实了，判断是站得住的。正式对外收费前取得书面法律意见。

依据：证券投资咨询的认定核心是谁、有偿、向投资者提供对具体证券的分析、预测或建议（《证券法》对证券投资咨询的核准要求；证监会 2012 年关于「荐股软件」的规定把具备个股分析、选股、买卖时机建议功能的软件工具有偿提供给投资者也算作投资咨询，并禁止以软件名义变相开展）。knowlab 里方法与数据都是用户的、结果只给用户自己，我们提供平台、工程化与测试，性质接近云平台加软件测试，不同于厂商自带选股逻辑把结论卖给投资者。

风险点（按重要性）：

1. **「逻辑来自用户」必须是真的**：用户只说一句「帮我做个选股 bot」、规则由平台补出来，投资逻辑实质就是我们的。→ 受理要求方法说得清；投资判断的空缺回头问用户；留规则来源记录。
2. **bot 运行时由大模型生成内容**，可能说出超出用户方法的个股判断。→ 模型用用户自己的 key（BYOK，已是现状，`C-A9`）；平台不提供推荐模板；是否在输出层面限制「买卖、目标价」类表述，请律师定。
3. **收费方式**：只按工具收。
4. **「不得出售」要靠技术保证**：没有导出、分享、发布入口。
5. **测试只测运行正确**：不出投资效果结论。
6. **与投顾无关但同样要办**：生成式 AI 服务备案或登记；收费在线服务的 ICP 经营许可证；用户上传数据的个人信息保护与数据权利（用户保证对上传的数据有权使用）；宣传遵守广告法、不承诺收益。
7. **「测试平台」这个叫法不改变实质**：用户真拿结果做投资决定，监管看实际；好在只给自己用，这本身没问题。
8. **孵化里模型参与写方法包**（补于 2026-10-17，`knowbot-todolist` K27；孵化的做法见 [0029](0029-pack-authoring.md) 第四、六节）：辅助孵化、自动孵化让模型把用户的想法写成方法包，最容易在这一步「顺手」补进用户没说的判断，那时投资逻辑实质上就是平台的（碰 `C-L1`，也是第 1 条风险的放大版）。守法：
   - **模型只做三件事**：把用户原文重排成步骤与规则、把空白写成问题（可以附提议，但提议只有用户确认后才算数）、做工程化（切步、交回物形状、验收、工具、额度）。不引入没有用户出处的口径、阈值、方法或期望值。
   - **程序守「没出处不放行」**：清单的每条规则要有 `user_text`（用户原文）或 `user_confirmed`（用户确认过的提议）出处，建雏形与交付两处的程序都核（现已如此）；孵化再加一道「原话核对」——`user_text` 引的原话必须逐字出现在种子里，`user_confirmed` 必须指向用户答过的那一问（0029 第六节）。
   - **模型用用户自己的 key、在用户自己的沙箱里跑**（所有者 2026-10-17 定，K22、K28）：孵化是替用户把他的想法写成他的工具，费用与模型调用都在用户名下，平台不垫付、不用自己的 key 产出方法内容。
   - **孵化用的「孵化方法」是我们的**：它只规定怎么拆、怎么问、怎么工程化，不含任何投资判断；它本身不进用户的分身。
   - **留痕**：每次孵化的输入、模型产出、运营的改动、用户的答复都留版本，作为「逻辑来自用户」的证据链（保留多久待定，K26）。
   - 对外收费前的法律意见要覆盖这一点（下面第 7 问）。

**请律师确认的问题**：

1. 方法与数据都由用户提供、结果只给用户自己、平台按工具收费——这个形态是否构成证券投资咨询或「荐股软件」？
2. 运行时由用户自己的模型 key 生成个股分析，是否需要在平台层面限制买卖建议、目标价类输出？
3. 收费可以按哪些项目收（工程化、测试、算力、存储、订阅），哪些不能收？
4. 生成式 AI 服务备案或登记、ICP 许可，我们需要办哪几项？
5. 用户协议里用途限制、数据权利保证、免责的写法。
6. 以后的 knowmart（开发者上架 bot 给别人用）需要哪类牌照、由谁持牌（平台还是开发者），平台对开发者有哪些审核义务？
7. 平台用大模型把用户的想法整理成可执行的方法（模型只重排、提问与工程化，每条规则须有用户原文或用户确认的出处，模型调用用用户自己的 key），这种「辅助孵化、自动孵化」是否改变第 1 问的结论？留痕要做到什么程度、保留多久？
