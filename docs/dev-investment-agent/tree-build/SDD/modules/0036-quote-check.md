# 引文由平台核：专家引的原文，平台回原件那一页去找（0036）

> 状态：**设计稿，待所有者审**。Opus 2026-10-19 起草；所有者「好，先写补充方法和引文核的设计」。和 [0035 补充方法](0035-method-amendment.md) 一起做，排在建第 3 稿之前。
> 起因：K19 第 2 稿第 6 步「对照官方披露」的核法是同一来源自己核自己（所有者：「用户上传的是年报，我们抄，抄完核年报时还是解析年报再比对，因此要错都错，要对都对啊」），抄得准不准改归入库时核（[`数据拓扑.md`](../../../../数据拓扑.md) §十之一）。所有者要的对照是：「应该时根据分析的结论到年报里找公司管理层讨论，让模型判断我们的财务分析和公司管理层在年报里自己的披露是否一致」。支持不支持是模型判断；**模型引的那段话年报里有没有、在哪一页，平台要核得了**，不然又成了专家自己说了算。

## 一、要解决什么

现在平台能核的是数（0030）：数是表里的一格就回去取那一格（`sourced`），是算出来的就查计算记录（`computed`）。**文字没有对应的核法**：专家说「年报第 25 页写了某某」，平台不知道真假。

本页只给平台加这一种能力。第 6 步怎么改是方法，归用户，经 0035 的补充方法进第 3 稿。

**拿什么核什么**（所有者 2026-10-19：「我认为时拿专家的分析的结论，但是改结论不一定在管理层讨论里提及。所以为了不挡住后面的步骤，验收时应该时支持还是不支持」）：核的对象是专家前面步骤得出的**分析结论**，参照是年报的**管理层讨论与分析**（所有者先问「好像不止是管理层讨论，能否改成年报的文字？」，Opus 答检索建好前要读全文、一份年报十万 token 上下、几年几倍；所有者：「不能那么贵，那么只读管理层讨论吧」）；每条结论只判**支持**或**不支持**，管理层讨论里没提到的算不支持。**判成哪一种都不挡后面的步骤**：不支持是结果，写进成稿给用户看，不是验收没过。平台只核证据：判「支持」的必须引到原文，引的原文必须真在年报那一页。

## 二、做法

### 1. 谁做什么

| 谁 | 做什么 |
| --- | --- |
| 专家（模型） | 读年报（`read_my_data`），判断，交回物里每段引文写明哪份数据、PDF 第几页、原话 |
| knowbench（工作台） | 验收时把引文交给 knowlab 核，按结果判这一项过不过 |
| knowlab（数据的提供方） | 在这一版绑定的那份原件里，找那一页有没有这段字 |

文字和抽取在 knowlab，所以「找」放在 knowlab：knowbench 不用知道抽取的文字长什么样、怎么分页，和取格子（`cells`）同一个做法。

### 2. 页码指什么

knowlab 抽 PDF 时每页前面有一行 `## Page N`，N 是 **PDF 的第几页**（从 1 数，阅读器里显示的页码），**不是年报上印的页码**（封面、目录让两者差几页）。模型读 `read_my_data` 时看得到这一行，引文写的就是这个 N。人拿 PDF 打开翻到第 N 页就能对。

`read_my_data` 返回的「第几页」是按字节切的阅读页（knowlab `PAGE_BYTES`），和 PDF 页不是一回事；引文不用它。

### 3. knowlab：契约 `knowbot-data/v1` 加一个接口

`POST /api/internal/v1/knowlab/knowbot-data/quotes`（服务身份 `knowlab:read`，同 `cells`）

请求：

| 字段 | 说明 |
| --- | --- |
| `contract` | `knowbot-data/v1` |
| `purpose` | 同其他四个接口（分身或测试） |
| `quotes` | 1–100 条，每条 `{dataset_id, page, text}`；`page` 是 PDF 第几页；`text` 原话，规整后 10–1000 字 |

结果：`quotes` 按请求的次序，每条 `{found, reason, page, version, sha256}`。`found` 为假时 `reason` 是下面之一：`not_found`（这一页没有这段字）、`no_pages`（这份数据不是带页的 PDF）、`page_out_of_range`（没有这一页，或在抽取截断之后）、`too_short`、`too_long`。`version`、`sha256` 是核的那一版原件。

**怎么算找到**（写进契约说明，两边一致）：

- 两边都先规整：Unicode NFKC（全角半角统一），去掉所有空白（PDF 抽出的中文常被断行、插空格）。
- 规整后的原话是第 N 页规整后文字的子串，或是第 N 页接第 N+1 页（引文跨页）的子串。
- 只做精确匹配，不做「相似度够高就算」。

**范围与拒绝**同 `cells`：只能核这一版清单绑定的、属于这个所有者的、没删的数据；不符一律 404，不区分「没有」与「不是你的」。

契约 v1 里加接口是只加不改：原有四个接口、字段都不动。knowlab 先发，knowbench 后发（同 qwen-013 的次序）。

### 4. knowbench：验收加一种 `quoted`

- 验收规则 `AcceptanceRule.kind` 加 `quoted`，必须写 `path`；和 `sourced` 一样归工作台应用层判（要调 knowlab），不在纯函数 `judge` 里。
- `path` 处是一串结论（或一项），每项带 `quotes`：一串 `{dataset_id, page, text}`。空的一串结论算通过，要求非空另配 `list_min`。
- 规则可以写 `field` 与 `equals`（`AcceptanceRule` 现有的两个字段），如 `field: "verdict"`、`equals: "支持"`：这样的结论 `quotes` **至少一条**；别的结论（不支持）可以不引。
- 引了的都要 `found`，不管判的是哪一种（不支持也不许引假话）。有一处不满足这条验收就不过，明细列出前几项：`#3 判支持但没有引文`、`#5 第 25 页没有这段字`。重做时专家看得到哪一条。
- **判支持还是不支持，这条验收不管**：全判不支持也过（只要格式对）。
- knowlab 不可达、拒了（关系没配、这一版没绑数据）：这一项记 `platform`，测试结果里那条用例记**出错**不记没过，同 `sourced`（审读第 3 条）。
- 端口 `KnowbotDataSource` 加 `quotes(purpose, quotes)`；knowbench 的契约锁 `knowlab-knowbot-data-lock.json` 跟着更新。

### 5. 核得了什么、核不了什么（P4）

| 核得了 | 核不了 |
| --- | --- |
| 这段话在这一版原件的第 N 页（或跨到 N+1 页）真有 | 这段话支不支持专家的结论（「支持」判得对不对） |
| 页码没编、原件没换（带 `version`、`sha256`） | 判「不支持」的，管理层讨论是不是真没提（证明不存在做不到） |
| 引的是这一版绑定的用户数据，不是别处 | 专家有没有漏掉更相关的段落 |

核不了的三样靠：用户读成稿时自己看引文（每段都带页码，翻得到）；测试用例里人核过的例子写进期望（比如某年管理层讨论明确写了毛利率下降的原因，用例期望专家对「毛利率下降」这条结论判「支持」并引到那一页）。成稿里引文旁边写明「引文平台核过在原件里；判断是模型做的」。

## 三、取舍

| 路 | 为什么不选 |
| --- | --- |
| knowbench 用现有 `read` 把页取回来自己找 | 要懂 knowlab 抽出来的文字格式和分页，一次核要取好几页；格式一改两边一起坏 |
| 相似度匹配（差几个字也算） | 阈值定多少都能被凑过；先精确匹配，规整只去掉 PDF 抽取造成的空白和全半角差异。表格里的字抽出来常错位，引文应引叙述性的段落，数走表（数据拓扑 §十之一） |
| 按年报印的页码 | 抽取拿不到可靠的印刷页码；PDF 第几页人和程序都对得上 |
| 让模型自报「已核对原文」 | 就是现在要去掉的做法 |
| 等文字检索建好再做 | 核引文不需要检索：给了页码，回那一页找就行。检索是帮模型找段落的，第 5 步搬家时做 |

## 四、这一版不做

- 文字检索（按意思找段落）：随数据拓扑第 5 步做。在那之前模型按页读，只读管理层讨论那一节；**按标题找，不按第几节找**（所有者：「要不是第三节呢」）：节号随年份、格式准则变（近几年多是第三节「管理层讨论与分析」，早几年叫「经营情况讨论与分析」「董事会报告」，排在第四节），看目录按标题找到它在 PDF 的哪几页；哪个标题都找不到，照实写「没找到管理层讨论这一节」，不悄悄全判不支持。怎么写进方法由用户定；不读全文：一份年报全文三十多万字节（2025 年报按 6 万字节切成 11 页），读一遍十万 token 上下，几年就几倍。检索建好后要不要扩到年报其他文字，到时再问用户。
- 非 PDF 的原文（Word、网页）：没有可靠的页，`no_pages`；要用时另定定位方式。
- 第 6 步本身的改写：经 0035 由用户提出，进第 3 稿。

## 五、测试

knowlab 后端：

1. 原话在第 N 页：找到，回 `version`、`sha256`；同一段话写成第 N+1 页：`not_found`。
2. 原话跨第 N、N+1 页：按第 N 页找到。
3. 原话里多了空格、换行，全角半角不同：找到；改了一个字：`not_found`。
4. 不是 PDF：`no_pages`；页码超出、在截断之后：`page_out_of_range`；太短、太长：对应的 reason。
5. 没绑在这一版的数据、别人的数据：404；超过 100 条：拒。
6. 契约文件由模型生成，测试核文件与模型逐字一致（同现有四个接口）。

knowbench 后端：

1. `quoted` 必须写 `path`，没写清单校验不过。
2. 全部找到：过；有一项没找到：不过，明细带页码；空的一串：过（配了 `list_min` 的不过）。
3. knowlab 不可达：这一项记 `platform`，用例记出错。
4. 契约锁与 knowlab 一致（现有锁测试）。

## 六、发版

- knowlab：加接口，**无迁移**；和 0035 的 knowlab 部分同一张卡（0035 有迁移，那张卡要改 `expected_schema_revision`）。
- knowbench：加验收种类、端口方法、契约锁，**无迁移**；knowlab 上线之后再发。
- 上线后先拿第 2 稿用过的年报做一次小验证：手写几条引文（对的、页码错的、改了字的）走一遍，结果对了再出第 3 稿。

## 七、代价

knowlab 一个接口和一段规整加查找；knowbench 一种验收、一个端口方法。每次验收多一次 knowlab 调用（最多 100 条一次）；抽取有缓存（`CachedTextExtractor`），同一份年报不重复解析。
